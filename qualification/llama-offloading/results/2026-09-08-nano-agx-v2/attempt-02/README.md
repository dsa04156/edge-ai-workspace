정상 구간 p95 TTFT는 103.03~379.47ms로 S 548.41ms 이내다. AGX 활성화와 겹친 요청의 최대 TTFT는 2,407.42ms로 별도 예산 22,846.53ms 이내다. 위 감소율은 회차별 p95 전체 응답시간 비교이며 예측식의 평균 비용 이득과 다른 지표다.

실제 AGX 준비·probe 완료는 22.132~22.547초였고, 10회 모두 모델 다운로드는 0ms였다. 실행 최대치는 기준선 최대 22.298초를 약 0.249초 초과했다. 기준선 최대를 절대 상한으로 보장하지 않는다. Nano가 준비 중 계속 응답한 결과 요청 지연 기준은 모두 통과했다.

종료 시 Nano는 추론 가능, AGX는 CACHED·모델 VRAM 0·active/queue 0이다. SD 공간 점검과 7개 노드 Ready/무압박 상태를 확인했고, 기존 Llama 및 EdgeX Pod의 UID·컨테이너 ID·재시작 횟수는 시작과 같았다. 93개 자동시험을 통과한 코드와 live controller 해시가 일치하고 미완료 원장은 없다.

이 결과는 격리된 CLI의 개발 자격시험이다. 범용 외부 서비스 gateway, NEXUS 운영 제어, 전체 Nano 전원/네트워크 장애, 긴 생성이나 다른 모델, 실제 SD 재부팅/실행 중 분리 검증까지 포함하지 않는다. AGX Pod와 GPU 공유 슬롯은 유지하고 모델 메모리만 해제한다.
