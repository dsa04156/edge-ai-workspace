# 쿠버엣지 디바이스 모델과 엣지엑스 디바이스 프로필 매핑

## 목적과 현재 권위

이 문서는 legacy KubeEdge/MapperFramework 모델을 EdgeX로 이관할 때 참고할 resource 대응 관계를 정리한다. KubeEdge `DeviceModel`, `Device`, `DeviceStatus`, `mqttvirtual`과 MapperFramework는 과거 물리 연동 자료이며 현재 유지되는 status/control plane, EdgeX와 병행하는 plane 또는 fallback이 아니다.

현재 물리 디바이스 권위는 다음과 같이 단일화한다.

| 영역 | 현재 원본 | 주요 필드/계약 |
|---|---|---|
| inventory/state | EdgeX Core Metadata Device와 Device Profile | `name`, `profileName`, `serviceName`, `protocols`, `adminState`, `operatingState` |
| telemetry | EdgeX MessageBus와 Core Data Event/Reading | Event `deviceName`, `sourceName`, `origin`; Reading `resourceName`, `valueType`, typed value |
| command | protocol을 소유한 EdgeX Device Service의 Device Profile command | profile command와 Device Service response |
| node/workload 진단 | Kubernetes/KubeEdge node와 workload | placement/resource 진단 전용; physical availability gate가 아님 |

MapperFramework direct-to-InfluxDB 및 KubeEdge desired/twin 경로를 current ingestion/command 경로로 확장하지 않는다. AI services, storage, state-aggregator, dashboard는 EdgeX MessageBus/Core Data 이후의 consumer다.

## Current EdgeX API 예시

Core Metadata Device 응답에서 physical inventory/state에 필요한 형태는 다음과 같다.

```yaml
name: vib-arduino-acceleration-01
profileName: vibration-arduino-mqtt
serviceName: device-mqtt
protocols:
  mqtt:
    Host: 127.0.0.1
    Port: "1883"
    Topic: factory/devices/vib-arduino-acceleration-01/telemetry
adminState: UNLOCKED
operatingState: UP
```

Core Data Event/Reading consumer는 legacy mapper timestamp나 `DeviceStatus` freshness 대신 Event `origin`을 사용한다.

```yaml
deviceName: vib-arduino-acceleration-01
sourceName: Acceleration
origin: 1784016000000000000
readings:
  - resourceName: AccelerationX
    valueType: Float64
    value: "0.125"
  - resourceName: AccelerationY
    valueType: Float64
    value: "-0.031"
  - resourceName: AccelerationZ
    valueType: Float64
    value: "0.992"
```

위 예시는 repository의 MQTT canary 계약을 설명하며 live cluster cutover 완료를 주장하지 않는다.

## Availability와 command 경계

physical availability는 Core Metadata와 Core Data만으로 판정한다.

1. `adminState=LOCKED` 또는 `operatingState=DOWN`: unavailable
2. `operatingState=UNKNOWN`: degraded
3. `operatingState=UP`이고 최신 Event `origin`이 freshness 기준 이내: available
4. `operatingState=UP`이지만 Event가 없거나 stale: degraded

Kubernetes node readiness, mapper Pod 상태, KubeEdge `DeviceStatus`는 이 결과를 승격하거나 강등하지 않는다. node/workload 데이터는 placement 후보와 장애 진단의 보조 정보로만 노출한다.

Command는 해당 endpoint를 독점 연결하는 EdgeX Device Service를 통해 실행한다. legacy KubeEdge desired property나 mapper command topic은 current command fallback이 아니다.

## Protocol-wave boundary

현재 delivered repository scope는 MQTT canary `vib-arduino-acceleration-01`과 EdgeX-backed aggregator/dashboard다. repository artifact의 존재는 live deployment 완료를 의미하지 않는다.

Serial, Modbus, OPC-UA, RTSP는 Device Service/Profile 선택, 실제 endpoint 연결, typed Reading, state/freshness, command/실패 동작, downstream consumer, live cutover를 각각 검증한 뒤에만 완료로 표시한다. MQTT canary 성공을 다른 protocol의 완료 근거로 사용하지 않는다.

`virtual-device/` Serial JSON runtime은 독립 프로토타입이다. 이 prototype을 EdgeX Serial Device Service로 부르거나 Serial protocol wave가 완료됐다는 근거로 사용하지 않는다.
