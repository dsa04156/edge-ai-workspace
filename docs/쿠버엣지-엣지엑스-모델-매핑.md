# 쿠버엣지 디바이스 모델과 엣지엑스 디바이스 프로필 매핑

## 목적과 현재 권위

이 문서는 legacy KubeEdge/MapperFramework 모델을 EdgeX로 이관할 때 참고할 resource 대응 관계를 정리한다. KubeEdge `DeviceModel`, `Device`, `DeviceStatus`, `mqttvirtual`과 MapperFramework는 과거 물리 연동 자료이며 현재 유지되는 status/control plane, EdgeX와 병행하는 plane 또는 fallback이 아니다.

현재 물리 디바이스 권위는 다음과 같이 단일화한다.

| 영역 | 현재 원본 | 주요 필드/계약 |
|---|---|---|
| inventory/state | EdgeX Core Metadata Device와 Device Profile | `name`, `profileName`, `serviceName`, `protocols`, `adminState`, `operatingState` |
| telemetry | EdgeX Device Service와 Core Data Event/Reading | Event `deviceName`, `sourceName`, `origin`; Reading `resourceName`, `valueType`, typed value |
| command | EdgeX Core Command | Serial 6개와 Sense HAT I2C 6개 Device의 latest-value GET만 활성; actuator 실행 아님 |
| node/workload 진단 | Kubernetes/KubeEdge node와 workload | placement/resource 진단 전용; physical availability gate가 아님 |

MapperFramework direct-write 및 KubeEdge desired/twin 경로를 current ingestion/command 경로로 확장하지 않는다. AI services, storage, state-aggregator, dashboard는 Core Data 이후의 consumer다.

## 과거 EdgeX API 형식 예시

아래 `sensehat-001`/`edge-telemetry-agent` 값은 퇴역한 fixture다. field mapping 예시로만 읽고 현재 Metadata 등록이나 live 상태로 해석하지 않는다.

Core Metadata Device 응답에서 physical inventory/state에 필요한 형태는 다음과 같다.

```yaml
name: sensehat-001
profileName: etri-sensehat
serviceName: edge-telemetry-agent
protocols:
  i2c:
    Bus: "1"
    Adapter: edge-telemetry-agent
adminState: UNLOCKED
operatingState: UP
```

Core Data Event/Reading consumer는 legacy mapper timestamp나 `DeviceStatus` freshness 대신 Event `origin`을 사용한다.

```yaml
deviceName: sensehat-001
sourceName: orientation
origin: 1784016000000000000
readings:
  - resourceName: pitch
    valueType: Float64
    value: "0.125"
  - resourceName: roll
    valueType: Float64
    value: "-0.031"
  - resourceName: yaw
    valueType: Float64
    value: "0.992"
```

위 aggregate 예시는 과거 Sense HAT fixture 형식을 설명하며 현재 live 계약이 아니다. 현재 직접 I2C 경로는 `device-sensehat-raspi`와 환경/IMU Profile·Device 6개로 분리되어 있고 `sensehat-001`은 protocol/tag source ID로만 남는다.

| env / rpi-env | `humidity` | `Humidity` | Core Data typed Reading |

| env / rpi-env | `humidity_status` | `HumidityStatus` | 필요하면 EdgeX derived resource/event로 모델링 |
| env / rpi-env | `health` | `Health` 또는 `DeviceHealth` | 필요성과 계산 주체를 profile/consumer 계약에서 명시 |
| env / rpi-env | `sampling_interval` | `SamplingInterval` | 지원 시 EdgeX profile command/config resource |
| vib / rpi-vib | `vibration` | `Vibration` | Core Data typed Reading |
| vib / rpi-vib | `acceleration_x` | `AccelerationX` | Core Data typed Reading |
| vib / rpi-vib | `acceleration_y` | `AccelerationY` | Core Data typed Reading |
| vib / rpi-vib | `acceleration_z` | `AccelerationZ` | Core Data typed Reading |

| act / rpi-act | `current` | `Current` | Core Data typed Reading |

## Availability와 command 경계

physical availability는 Core Metadata와 Core Data만으로 판정한다.

1. `adminState=LOCKED` 또는 `operatingState=DOWN`: unavailable
2. `operatingState=UNKNOWN`: degraded
3. `operatingState=UP`이고 최신 Event `origin`이 freshness 기준 이내: available
4. `operatingState=UP`이지만 Event가 없거나 stale: degraded

Kubernetes node readiness, mapper Pod 상태, KubeEdge `DeviceStatus`는 이 결과를 승격하거나 강등하지 않는다. node/workload 데이터는 placement 후보와 장애 진단의 보조 정보로만 노출한다.

현재 Serial 6개 가상 Device는 각각 `temperature`, `light`, `magnetic`, `acceleration_x`, `acceleration_y`, `acceleration_z`, Sense HAT I2C 6개 가상 Device는 `temperature`, `humidity`, `pressure`, `compass`, `orientation`, `gyroscope` read-only GET을 제공한다. 후속 write command는 해당 endpoint를 소유한 Device Service의 인증·TTL·dedupe·실패 동작을 검증한 뒤 별도 활성화한다.

## Protocol-wave boundary

현재 target scope는 Jetson의 `device-serial-jetson`, Raspberry Pi의 `device-sensehat-raspi`, 각 Profile/가상 Device 6개와 중앙 Core Data/PostgreSQL 및 EdgeX-backed aggregator/dashboard다. 물리 `arduino-001`, `sensehat-001`은 protocol/tag source ID이며 Metadata Device가 아니다. 과거 loopback Agent/SQLite/HTTPS plane은 현재 배포나 fallback이 아니다.

Serial과 Sense HAT 직접 I2C는 정상 수집 경로만 완료로 표시하며 실제 분리·복구는 남아 있다. Modbus, OPC-UA와 다른 I2C 장비·주소는 Device Service/Profile, 실제 endpoint, typed Reading, freshness와 downstream consumer를 각각 검증한 뒤에만 완료로 표시한다. RTSP는 Workflow Pod 직접 구독 경로로 별도 검증한다.

`virtual-device/` Serial JSON runtime은 독립 프로토타입이다. 현재 Serial 완료 근거는 이 prototype이 아니라 `edgex/device-serial/`, root Kustomize와 live readback이다.
