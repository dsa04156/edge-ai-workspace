## 쉽게 설명하면

물리 장비와 가상 디바이스의 등록 카드를 한 화면에서 관리한다. 가상 카드는 CPU·GPU·메모리
프로파일과 ID를 먼저 갖고, 실행할 때 컨테이너 자원을 배치한다. 정지 카드도 목록에 남는다.
**등록 수와 현재 실행 중인 수는 다르며, 관측 실패는 정지가 아니다.**

## 화면 계약

NEXUS `디바이스 → 물리·가상 통합`, `/#devices`에서 제공한다.

- 상단: 등록 수, 상태 조회 가능 수, 동작·실행 중 수, 정지 수, 확인 불가 수.
  준비·정리·차단·사용 불가 상태는 보조 수치로 표시한다.
- 물리 영역: 컴퓨팅 노드와 EdgeX 센서 디바이스를 각각 한 행으로 펼친다.
  같은 Arduino/Sense HAT의 기능도 EdgeX Device별로 유지한다. source ID가 없어도 숨기지 않는다.
- 가상 영역: 영속 논리 객체와 기존 독립 시험 정의를 표시한다. 서비스 템플릿·Pod를 자동 등록하지 않는다.
- 두 목록은 360px 고정 높이의 내부 스크롤, 700px 이하 화면은 280px다.
  전체 수와 검색 결과 수를 분리하며 갱신 때 선택·검색·스크롤과 입력 초안을 보존한다.
- 일반 시스템·애플리케이션 워크로드는 기존 별도 접힌 목록에 표시하고 총합에서 제외한다.
- 가상 등록: CPU·메모리 요청/제한, 구조, NVIDIA GPU 정수 개수의 프로파일을 먼저 등록한다.
  기존 서비스 계약은 선택 사항이다. ID 접두어·프로파일·개수로 각각 독립 정의를 생성한다.
  부분 실패 시 이미 성공한 등록은 남고 진행 수와 오류를 표시한다. 자동 전체 재실행은 없다.
- 가상 상세: UUID·프로파일·상태·RuntimeService 연결, 개별 실행/정지, 이름·연결 설정, 영속 이력.
  자원만 정의한 객체는 실행 버튼이 비활성이다. 설정 저장과 실제 실행 접수를 구분한다.
- 센서 상세: 기존 측정값 상세 및 장비 등록·개별 관리 화면을 연다.
  컴퓨팅 노드는 읽기 전용이며 임의 노드 전원/host 명령을 추가하지 않는다.
- 연결 장비 상세·EdgeX 등록 항목·관측 트윈 보조 화면과 기존 `/#physical-virtual-devices` 연결은 유지한다.

## 집계와 상태

전체 = 컴퓨팅 노드 + EdgeX 등록 디바이스 + 독립 가상 정의다. 물리 source의 조회용 트윈,
`physical-vd:*`, 서비스 정의, 실행 Pod, 일반 워크로드는 추가 집계하지 않는다.
EdgeX 기능별 등록 수는 실제 하드웨어 대수와 별개이며 시험 보고서에 단위를 명시한다.

| 표시 | 판정 |
|---|---|
| 등록 수 | 모든 등록 원천 조회가 성공한 경우의 중복 제거한 전체 |
| 상태 조회 가능 | 현재 상태가 unknown이 아닌 객체; 정지·준비·차단·사용 불가 포함 |
| 동작·실행 중 | 노드 Ready, 센서 UP+fresh, 가상 최신 serving+ready |
| 정지 | 실행 자원 미할당 논리 정의 또는 관측된 완전 Suspended; 센서는 EdgeX LOCKED |
| 확인 불가 | 원천 장애·15초 만료·실행 관측 누락·UID 불일치 |

센서 LOCKED는 관리 잠금이다. DOWN은 사용 불가이며 정지로 바꾸지 않는다.
실행을 한 번도 요청하지 않은 논리 객체는 원장 자체가 미할당을 증명하므로 정지로 조회한다.
실행 요청을 보낸 뒤 binding 결과를 모르는 객체는 확인 불가다.
원천 실패 시 마지막 항목은 보존하되 해당 원천의 상태·실행 위치를 확인 불가로 바꾸고
전체 등록 수는 확정하지 않는다. 성공한 다른 원천의 정지 상태는 유지한다.
화면 전체 응답이 실패·만료되면 보존한 모든 항목을 확인 불가로 전환한다.

## API·구현 경로

`GET /api/managed-devices`가 `edgeai.managed-devices/v1` 목록과 summary, sourceErrors,
profiles, countingPolicy, mutationEnabled, observedAt/maxAgeSeconds를 제공한다.
독립 EdgeX·노드·기존 가상·새 논리 등록부를 동시에 읽으며 각 원천 제한시간은 12초다.
NEXUS가 5초마다 갱신하고 상태 응답은 no-store다.

`app/managed_devices.py`와 `runtime_operator/logical_devices.py`가 집계·영속 관리를 소유한다.
`static/nexus/managed-devices.js`는 기존 `device-map.js`·CSS·GET store·workload 상세를 재사용한다.
물리 권위는 EdgeX, 노드/배치는 Kubernetes/KubeEdge다. 쓰기 API와 자원 할당 조건은
[서비스형 가상 디바이스 설계](서비스형-가상-디바이스-설계.md)를 따른다.

기존 `/api/service-virtual-devices`는 서비스 계약/정책 조회용으로 남는다.
RuntimeService 한 행을 가상 디바이스 한 개로 집계하던 앞선 화면 규칙은 대체했다.
실행 revision의 active/preparing/retiring 위치는 배치 관측이며 Pod 수가 아니다.
