NVIDIA device plugin 장애 조사

kubeadm 기반 KubeEdge PoC 클러스터에서 NVIDIA device plugin DaemonSet이 available 상태가 되지 않는 문제를 조사한 기록이다. 결론은 device plugin manifest보다 GPU 서버의 NVIDIA kernel driver module 미로드 문제에 가깝다.

날짜
2026-05-11
범위
Kubernetes / GPU / device plugin
상태
원인 후보 확인
관련 노드
etri-ser0001-cg0msb, etri-ser0002-cgnmsb

요약

NVIDIA device plugin이 죽은 직접 원인은 pod spec 자체보다 GPU 노드에서 NVIDIA driver가 현재 커널에 로드되지 않아 NVML 초기화가 실패한 것으로 판단한다. 두 GPU 서버 모두 nvidia-driver-580-open 패키지는 설치되어 있지만, 현재 커널 6.17.0-23-generic 기준 modinfo nvidia가 실패했다.

배경

이 PoC는 KubeEdge 기반 혼합 디바이스 엣지 AI 플랫폼으로, x86 서버 GPU와 edge node를 함께 운영한다. NVIDIA device plugin은 Kubernetes가 서버 GPU를 nvidia.com/gpu 자원으로 인식하도록 하는 보조 구성이다.

이번 조사는 서비스 데모와 통합 운영 가시화 관점에서 GPU 서버의 사용 가능 여부를 확인하기 위한 운영 기록이다.

현재 상태

항목 상태 운영 해석
DaemonSet Desired 2 / Available 0 GPU 서버 2대에 pod를 띄우려 하지만 정상 available pod가 없다.
Pod RunContainerError / CrashLoopBackOff 애플리케이션 실행 후 실패가 아니라 컨테이너 생성 단계에서 실패한다.
GPU resource nvidia.com/gpu capacity/allocatable 0 Kubernetes scheduler가 현재 GPU를 사용 가능한 자원으로 보지 못한다.
Network FlannelIsUp 과거 flannel event는 있었지만 현재 직접 원인은 network로 보지 않는다.

설치된 NVIDIA 관련 패키지

nvidia-driver-580-open         580.126.09-0ubuntu0.24.04.2

현재 커널에서 확인된 nvidia 관련 module 파일

아래 파일들은 kernel 기본 module 성격이며, device plugin/NVML에 필요한 실제 NVIDIA GPU driver module인 nvidia.ko, nvidia_uvm.ko, nvidia_modeset.ko, nvidia_drm.ko는 확인되지 않았다. 

hid-nvidia-shield.ko.zst
nvidiafb.ko.zst
i2c-nvidia-gpu.ko.zst
nvidia-wmi-ec-backlight.ko.zst
typec_nvidia.ko.zst

판단

  1. device plugin pod는 내부 로직 실행 이후가 아니라 OCI runtime create 단계에서 실패한다.
  2. 실패 메시지는 failed to initialize NVML: Driver Not Loaded다.
  3. 두 GPU 서버 모두 현재 커널에서 modinfo nvidia가 실패한다.
  4. 따라서 우선순위는 device plugin 재배포가 아니라 host NVIDIA driver/kernel module 복구다.

현재 상태에서 kubectl rollout restart 또는 device plugin manifest 재적용만 수행해도 해결 가능성은 낮다. 먼저 노드에서 nvidia-smi와 modinfo nvidia가 정상화되어야 한다.

조치 후보

조치 전 재확인

uname -r
dpkg -l | grep -E 'linux-headers|nvidia-driver|nvidia-container-toolkit|libnvidia-container'
dkms status | grep -i nvidia || true
modinfo nvidia
lsmod | grep nvidia
nvidia-smi
find /lib/modules/$(uname -r) -iname 'nvidia*.ko*'

승인 후 검토할 복구 작업

sudo apt install linux-headers-$(uname -r)
sudo apt install --reinstall nvidia-driver-580-open
sudo update-initramfs -u
sudo reboot

open kernel module 계열이 현재 커널과 맞지 않을 경우 일반 NVIDIA driver 패키지로 전환하는 방안도 별도 검토한다. containerd NVIDIA runtime 설정 변경이나 reboot는 노드 작업 영향이 있으므로 사전 승인 후 진행한다.

검증

driver 복구 후 아래 조건이 만족되면 device plugin 복구를 다시 판단한다.

nvidia-smi
lsmod | grep nvidia
modinfo nvidia
kubectl get pods -n kube-system -o wide | grep -Ei 'nvidia|gpu|device-plugin'
kubectl get nodes -o custom-columns=NAME:.metadata.name,GPU:.status.allocatable.'nvidia\.com/gpu'

정상 기준은 GPU 서버에서 nvidia-smi가 성공하고, Kubernetes node allocatable에 nvidia.com/gpu가 다시 표시되는 것이다.
