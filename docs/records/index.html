운영 기록

Markdown으로 길게 남기던 조사/판단/운영 기록을 브라우저에서 읽기 쉬운 HTML 문서로 정리하는 공간이다. 문서는 과장된 랜딩페이지가 아니라, 운영자가 빠르게 판단할 수 있는 구조화된 기록을 목표로 한다.

  • 한국어 운영자 기준
  • semantic HTML
  • 공통 CSS
  • Git diff 유지
  • JS 최소화

최근 기록

  • NVIDIA device plugin 장애 조사 2026-05-11 · GPU 서버의 NVIDIA driver/kernel module 미로드로 인한 NVML 초기화 실패 기록

기록 작성 규칙

  1. 새 기록은 docs/records/YYYY-MM-DD-topic.html 형식으로 작성한다.
  2. 공통 스타일은 docs/assets/record.css만 사용한다.
  3. 문서 안에는 article, section, time, dl, pre, code 같은 의미 중심 태그를 쓴다.
  4. 운영 판단을 흐리는 장식, 임의 지표, 과한 JavaScript는 넣지 않는다.
  5. 명령 출력은 필요한 부분만 발췌하고, credential/API key/token/password/connection string은 [REDACTED] 처리한다.

기본 섹션

섹션 목적
요약 운영자가 먼저 알아야 할 결론을 한 문단으로 정리한다.
배경 왜 이 기록이 생겼는지, 어떤 시스템 범위와 관련되는지 적는다.
현재 상태 노드, pod, API, dashboard 등 현재 관측된 상태를 정리한다.
증거 명령과 핵심 출력, 로그, event를 남긴다.
판단 증거를 바탕으로 원인 또는 운영 판단을 적는다.
조치 후보 바로 실행한 조치와 아직 승인 전인 조치 후보를 구분한다.
검증 완료 기준과 재발 시 확인할 명령을 남긴다.
