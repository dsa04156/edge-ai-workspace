# 서비스 배치 지도

장비를 방처럼, 실행 중인 워크로드를 방 안의 카드처럼 보여준다. 카드를 선택하면 어떤
센서 입력을 이용하고 어느 위치에서 추론하는지 확인한다. 화면의 이동 표현은 관측된
배치 변화 또는 명시적인 설명용 예시이며 장비를 제어하지 않는다.

## 진입과 사용

- NEXUS `AI 서비스 → 서비스 목록·배치`, 직접 주소 `/#service-map`.
- `/state/services`의 등록 목록에서 서비스를 먼저 선택한다. 실행 Pod가 없어도 등록 서비스는 유지된다.
- 선택한 서비스의 Git 주 실행체·서버 추론과 실제 입력 EdgeX Device의 수집기만 표시한다.
- 상단 선택 상자로 다른 서비스로 전환하고 `← 서비스 목록`으로 돌아간다. 선택은
  `?service=<service_id>#service-map` 주소와 브라우저 뒤로/앞으로 가기에 유지한다.
- 상세·결과 탭도 선택한 서비스를 따른다. 제거된 ID는 다른 서비스로 대체하지 않는다.
- 목록 하단 `전체 워크로드 지도`는 카탈로그에 등록되지 않은 Running 워크로드도 표시한다. 이를
  운영 AI 서비스나 옥동 실증 완료 서비스로 분류하지 않는다.
- `빈 장비도 표시`로 현재 필터에 해당하는 실행체가 없는 노드도 볼 수 있다.
- 카드를 선택하면 입력 source, 실행 위치, 모델, 유효한 지연·처리량과 자원 합계를 본다.
- `움직임 예시 보기`는 별도 예시 장비에서 로컬 처리 → 서버 추론 → 로컬 복귀 →
  다른 엣지로 실행 위치 전환을 표현한다. 다음 장면·재생·일시정지·실제 관측 복귀를
  지원하며 실제 요청, 배포, 이동, 증강 API를 호출하지 않는다.

## 관측 계약

| 표시 | 읽는 근거 | 제한 |
|---|---|---|
| 워크로드·노드 배치, Pod 준비 | `/state/service-resource-profiles` | Running Pod만 포함. Pending·정지 Deployment inventory가 아님 |
| 서비스 식별·모델·입력·실행 권한 | `/state/services` | namespace와 workload 이름의 정확한 계약 연결 |
| 노드 상태·자원 사용률 | `/api/resources` | Kubernetes와 Prometheus의 권위·시각 유지 |
| 센서 수집기 연결 | `/state/devices` | 승인된 `edgex-edge` Device Service와 물리 source 연결 |
| 추론 경로·저장 결과 증가·서비스 성능 | `/state/service-demo` | 현재 연결한 상세 관측은 `sensor-anomaly-demo` 한 개 |

조회는 지도가 보이는 동안 15초 간격, HTTP GET만 사용한다. 동일 조회는 합치고 각
요청은 12초 timeout을 둔다. 실패 시 마지막 응답을 보존하고 해당 관측을 확인 불가로
표시한다. profiles/services의 원 생성 시각과 노드 사용률의 측정 시각도 확인한다.
조회 회복 직후에는 단절 동안의 변화를 실시간 이동으로 재생하지 않는다.

동일 워크로드의 여러 노드 배치는 노드별 카드로 유지한다. 공유 실행체는 여러 이용
서비스를 보존하며 상세에서 서비스를 선택한다. 자원 사용량은 워크로드 합계이고 이를
각 노드의 사용량으로 복제하거나 합산하지 않는다.

## 움직임과 상태의 의미

- `Pod 준비됨`과 실제 서비스 실행 권한은 별도 표시한다. 만료 Lease와 STANDBY를
  실제 처리 중으로 표시하지 않는다.
- 첫 조회는 배치 변화 이벤트를 만들지 않는다. 이후 유효한 두 스냅샷의 노드 집합을
  비교해 추가 관측·배치 변경·Running 목록에서 사라짐을 기록한다. 이 차이는 migration
  성공, 삭제, 무중단 전환 또는 실행 권한 이전의 증거가 아니다.
- 배치 변화는 브라우저 메모리에 최근 24건만 유지하며 페이지 새로고침 시 초기화한다.
- 최신 저장 결과의 시각 증가, 입력·모델 준비, 유효한 실행 권한과 결과의 추론 경로가
  확인될 때만 처리 선을 짧게 강조한다. 개별 패킷, 실시간 요청 수, 네트워크 속도는 표현하지 않는다.
- 실행 위치 카드 이동은 260ms의 관측 변화 강조다. `prefers-reduced-motion`에서는
  카드 이동과 요청 흐름 애니메이션을 제거하고 상태·텍스트를 유지한다.
- 기존 프로파일 reader가 수집 실패를 빈 목록으로 반환할 수 있으므로 빈 결과만으로
  전체 정지·삭제를 단정하지 않는다. 지도에도 이 경계를 표시한다.

## 서비스별 탐색 — 2026-09-08

등록 목록 → 개별 서비스 배치 → 상세·결과 순으로 구성했다. 실행체가 없는 서비스도
목록에 남고, 동일 이름의 다른 namespace나 다른 입력 수집기는 해당 지도에 섞이지 않는다.
공유 서버는 각 이용 서비스에서 볼 수 있다. 서비스 선택은 주소와 조회 갱신에 유지한다.

서비스 두 개를 주입한 브라우저 시험에서 선택 전환, 미배치 서비스, HTTP 503 보존,
등록 제거 시 다른 서비스로 대체하지 않는 동작을 확인했다. 이 주입은 UI 검증 전용이며
실제 두 번째 서비스를 등록하거나 배포하지 않는다.

최종 검증: 관련 JavaScript 32개 통과. 실데이터 등록 서비스 1개·연결 실행체 3개,
390px 가로 넘침 없음, 브라우저 오류 0·쓰기 요청 0. 서비스별 관측 경로가 없는 경우
다른 서비스의 추론·성능을 가져오지 않는다.

## 전체 장비 지도

상단 `전체 장비 지도`에서 `/?workloads=all#service-map`으로 진입한다. 전체 노드를
기본 표시하고 `등록 서비스·수집기`와 `전체 워크로드` 필터로 카드 밀도를 조절한다.
노드 목록은 Kubernetes/Prometheus 관측, 물리 입력 장비는 EdgeX Device의
physical_device_id로 묶어 표시한다. 등록 기능 수를 물리 장비 대수로 합산하지 않는다.
node_name이 없거나 여러 위치로 충돌하면 `연결 노드 확인 필요`에 따로 둔다.
등록 위치는 통신 성공의 증거가 아니다. 노드·입력 장비의 서비스 링크에서 개별 서비스로
이동하고, 상단 목록과 전체 지도를 오갈 수 있다.

2026-09-08 브라우저 검증: 노드 7개, 물리 입력 2개, 빈 노드 표시·갱신·deep link·서비스
연결 이동·전체 워크로드 필터·390px 넘침 없음, JavaScript 오류 0·쓰기 요청 0.

## 연결 그래프와 오프로딩 방향

기본 지도 표현은 `연결 그래프`이며 `장비 카드`로 전환할 수 있다. 전체 장비와 서비스별
보기 모두 지원하고 `view=cards` 주소로 카드 표현을 유지한다. 그래프는 물리 입력,
현장 엣지, 서버의 3열이며 확대·축소와 내부 가로·세로 스크롤을 지원한다.

- 입력 → 노드: EdgeX 등록 연결을 점선으로 표시한다. 통신 성공이나 실시간 전송량이 아니다.
- 엣지 → 서버: Git target_workload의 Running 배치를 연결한 추론 요청 방향이다.
- 서버 → 엣지: 같은 서비스의 결과 반환 방향이다.
- 기본은 설정 점선이다. 해당 서비스의 최신 routing, 유효한 입력·모델·실행 권한,
  정확한 source_node/remote_node와 유효한 서비스·배치 관측이 모두 있어야 원격 실선으로
  강조한다. 다른 서비스의 demo 관측을 빌리지 않는다.
- LOCAL_FALLBACK 관측은 주황 점선과 로컬 복귀 문구로 표시한다. 원격 활성으로 표현하지 않는다.
- 서버 실행체 위치가 없으면 임의 노드로 연결하지 않는다. 여러 위치는 각각 보존한다.
- 예시 데이터의 원격·복귀 상태는 실제 관측과 분리된다. 그래프는 제어 API를 호출하지 않는다.

상세 버튼은 기존 서비스/실행체 상세로 연결한다. 그래프에서 워크로드 버튼은 노드당
최대 2개를 표시하고 전체 목록은 장비 카드에서 확인한다. 선은 경로 관측이며 패킷별
전송이나 성공 응답 횟수를 시각화하지 않는다.

카드 전환·줌·갱신 스크롤 유지·모바일·reduced-motion 확인. 브라우저 오류0·쓰기0.

## 인터랙티브 실행 관측

그래프 위 `현재 실행 관측`에서 서비스 버튼을 누르면 해당 서비스의 주 실행체와
추론 연결선이 선택된다. 실행체 수·준비 수는 Running Pod 관측이며 실제 처리 성공과
별도 표시한다. 최근 결과 시각, 유효한 추론 경로, 유효 성능 지표를 나란히 확인한다.

새 저장 결과의 증가와 freshness, 모델 버전·실행 모드·출발/도착 노드 일치, 서비스와
상세 API 양쪽의 실행 권한, 유효한 배치 관측을 모두 확인해야 결과 강조를 만든다.
로컬 결과는 출발 노드, 원격 결과는 노드와 요청·반환 선을 약 2초 강조한다. 첫 조회,
중복 결과, 만료 권한, 오래된 결과, 조회 실패·90초 이상 단절 후 복구는 새 결과로
재생하지 않는다. `결과 강조`로 모션만 끌 수 있으며 조회는 계속된다. 사용자 상호작용으로
화면을 다시 그려도 같은 강조의 남은 시간만 재생한다. reduced-motion에서는 움직임을 없앤다.

최근 실행 관측은 새 결과·처리 상태·추론 경로 관측 변화이며 브라우저 메모리 최근18건,
선택 서비스 최근8건만 표시한다. 페이지 새로고침 시 초기화되며 영속 실행 감사 로그가 아니다.
15초 polling 사이의 모든 요청이나 stage 실행을 추적하는 기능은 아니다.

관측할 서비스 선택, 새 결과 강조, 중복·복구 재생 방지, 강조 끄기, 모바일·reduced-motion을
브라우저에서 확인했다. 새 결과 시험은 응답 주입 UI 시험이며 실제 서비스 실행/오프로딩
시험이 아니다. 브라우저 오류0·쓰기0.
