# EdgeX 디바이스 조회 단일 실행 설계

## Problem

`state-aggregator`의 `/state/devices`, `/state/dashboard`, 운영 보조 API가 같은 시점에
호출되면 각 요청이 Core Metadata inventory와 device별 Core Data Event를 다시 조회한다.
Core Data 4.0.2의 기본 PostgreSQL pool은 `MaxConns=4`다. 동시 Event 요청이 pool을 모두
점유한 상태에서 Reading 조회용 연결을 기다리면 Event API가 `503 request timeout`으로
고착되고 Core Data를 재시작하기 전까지 device 관측이 복구되지 않는다.

확인한 증거는 다음과 같다.

- Core Data `/api/v3/ping`은 `200`이지만 Event API는 pod localhost에서도 `503`이다.
- PostgreSQL에는 Core Data client의 Event SELECT 4개가 `idle / ClientRead`로 남는다.
- Core Data를 재시작하면 Event API와 dashboard가 복구된다.
- 동시에 30개 dashboard 요청을 보내면 같은 상태가 다시 재현된다.

## Decision

`StateAggregatorService.get_devices()`에 in-flight single-flight 경계를 둔다. 한 번의 EdgeX
device 관측이 실행 중일 때 들어온 다른 호출자는 새 EdgeX 요청을 만들지 않고 같은
`asyncio.Task`를 기다린다. 작업이 끝나는 즉시 참조를 제거한다.

이 설계는 결과 TTL cache가 아니다. 마지막 성공 inventory나 Reading을 보관하거나 다음
관측에 재사용하지 않으므로 `device_observation_error` 계약과 “stale device 값을 정상
데이터로 표시하지 않는다”는 기존 정책을 유지한다.

## Alternatives

1. Core Data `MaxConns`만 늘린다.
   - 평상시 여유는 늘지만 더 큰 동시 요청에서 같은 pool 고갈이 재현될 수 있다.
2. EdgeX Core Data를 포크하거나 다른 버전으로 교체한다.
   - 저장소와 운영 범위를 크게 넓히고 현재 PoC 검증보다 위험이 크다.
3. 동일 관측을 single-flight로 합친다.
   - aggregator가 만드는 중복 부하를 원천적으로 제한하며 stale cache를 만들지 않는다.

현재 PoC에는 3번을 적용한다. `MaxConns` 조정이나 Core Data 교체는 별도 성능 검증 작업으로
남긴다.

## Data Flow

1. 첫 호출자가 `_fetch_devices()` task를 만든다.
2. task는 Core Metadata inventory를 한 번 읽고 등록 device별 최신 source Reading을 읽는다.
3. task가 진행 중일 때 들어온 호출자는 `asyncio.shield()`로 같은 task를 기다린다.
4. 성공 시 각 호출자는 결과 list의 얕은 복사본을 받는다.
5. 성공 또는 실패 후 active task 참조를 제거한다. 다음 호출은 새 관측을 수행한다.

`asyncio.shield()`를 사용해 한 HTTP client의 취소가 공유 중인 EdgeX 관측을 취소하지 않게
한다.

## Error Handling

- EdgeX 오류는 기존 `EdgeXError` 계층 그대로 호출자에게 전달한다.
- 실패 결과를 cache하지 않는다.
- `/state/dashboard`는 기존 source failure isolation에 따라 device 영역만 관측 불가로
  표시한다.
- `/state/devices`는 기존처럼 오류를 성공한 빈 inventory로 바꾸지 않는다.

## Tests

- 다수의 동시 `get_devices()` 호출이 Core Metadata와 Core Data backend를 각각 한 번만
  호출하는지 검증한다.
- 첫 관측이 완료된 뒤 다음 호출은 backend를 다시 읽는지 검증해 TTL cache가 아님을
  보장한다.
- 공유 관측 실패 후 다음 호출이 재시도 가능한지 검증한다.
- 전체 state-aggregator Python/JavaScript suite와 live burst smoke를 실행한다.

## Scope

포함 범위는 state-aggregator의 read-only EdgeX 관측 중복 제거와 회귀 테스트다. EdgeX
metadata/state mutation, command publish, actuator command, workflow 실행, Core Data fork는
포함하지 않는다.
