# 젯슨 아두이노 EdgeX Serial Device Service 설계

## 상태와 목표

이 문서는 `etri-dev0001-jetorn`에 연결된 Arduino Uno를 공식 EdgeX Go Device SDK
기반의 read-only Serial Device Service로 연결하는 첫 서비스 데모 수직 슬라이스를
정의한다.

완료 경로는 다음 하나다.

```text
Arduino Uno USB CDC
  -> Jetson /dev/serial/by-id/...
  -> device-serial-jetson
  -> EdgeX SDK AsyncValues
  -> edgex-messagebus.edgex-system.svc.cluster.local:1883
  -> Core Data -> PostgreSQL
  -> state-aggregator -> dashboard
```

기존 `edge-telemetry-agent`, SQLite outbox, local MQTT 변환, KubeEdge Device/Mapper
경로는 사용하지 않는다. KubeEdge는 Device Service Pod를 Jetson에 배치하고
관찰하는 역할만 가진다.

## 확인된 물리 계약

2026-07-21 live 진단에서 다음을 확인했다.

- node: `etri-dev0001-jetorn`
- 장치: Arduino Uno USB CDC ACM
- vendor/product: `2341:0043`
- 현재 장치 파일: `/dev/ttyACM0`
- 안정 식별 경로:
  `/dev/serial/by-id/usb-Arduino__www.arduino.cc__0043_75035303230351E0D171-if00`
- baud rate: `115200`
- framing: UTF-8 JSON object 한 개와 CRLF 한 줄
- 포트를 연 직후 잘린 line이 나타날 수 있음

실측한 정상 payload는 다음 네 종류다.

```json
{"device_id":"arduino-001","sensor":"temperature","raw":297}
{"device_id":"arduino-001","sensor":"light","value":304}
{"device_id":"arduino-001","sensor":"magnetic","value":0}
{"device_id":"arduino-001","sensor":"acceleration","x":298,"y":266,"z":278}
```

첫 line에서 `{"device_id":"arduino-001","sensor":"light","v}`처럼 잘린 JSON과
`_id":"arduino-001",...`처럼 중간부터 시작한 line도 관찰했다. 이 line은 Event로
만들지 않고 다음 newline 이후의 완전한 JSON부터 수집을 계속한다.

## 접근안 비교와 선택

### 선택: 전용 privileged Device Service Pod

현재 KubeEdge/containerd에서는 `hostPath`로 char device를 마운트해도 비특권
컨테이너가 device cgroup에서 `Operation not permitted`로 차단된다. 노드에는
Serial/USB Device Plugin도 없다.

첫 PoC는 `device-serial-jetson` 컨테이너 하나에만 `privileged: true` 예외를 둔다.
위험 범위를 줄이기 위해 다음 제한을 동시에 적용한다.

- exact Jetson node selector와 `replicas: 1`
- `Recreate` 배포 전략으로 Serial endpoint 단일 소유
- 확인된 `by-id` char device 하나만 `/dev/arduino-001`로 mount
- `hostNetwork: false`
- ServiceAccount token 자동 mount 금지
- read-only root filesystem과 `/tmp` emptyDir
- 중앙 EdgeX와 DNS에 필요한 포트만 허용하는 NetworkPolicy
- write command와 actuator 동작 없음

이 예외는 서비스 데모를 위한 명시적 기술부채다. 후속 hardening wave에서는
Serial Device Plugin이 `etri.io/arduino-uno` 같은 extended resource를 광고하고
Device Service가 이를 요청하도록 바꾼다.

### 보류: Serial Device Plugin

Device Plugin은 device node를 runtime에 명시적으로 할당해 비특권 Pod를 만들 수
있지만, plugin lifecycle·health·kubelet 재등록·resource scheduling까지 별도
컴포넌트를 구현해야 한다. 현재의 서비스 데모 1종 범위를 넘으므로 후속으로 둔다.

### 제외: host systemd 서비스

systemd 서비스는 device 접근은 단순하지만 KubeEdge workload 관리와
`edgex/k8s` GitOps 단일 진입점 원칙을 깨므로 사용하지 않는다.

## EdgeX 구성과 identity

호환성은 중앙 Core와 같은 EdgeX 4.0 계열로 고정한다.

- Go Device SDK: `github.com/edgexfoundry/device-sdk-go/v4 v4.0.2`
- Go toolchain: `1.25.x`
- Serial library: `go.bug.st/serial v1.8.0`
- Device Service: `device-serial-jetson`
- Device Profile: `etri-arduino-serial`
- Device: `arduino-001`
- protocol: `serial`
- Device Service HTTP port: `59910`

Device Service는 local profile과 device 파일을 SDK preload 경로로 읽고 Core
Metadata에 등록한다. Device의 protocol properties는 다음 값을 가진다.

```yaml
serial:
  Port: /dev/arduino-001
  BaudRate: "115200"
  DeviceID: arduino-001
```

서비스는 다음 DNS 이름만 사용한다.

```text
edgex-core-keeper.edgex-system.svc.cluster.local:59890
edgex-core-metadata.edgex-system.svc.cluster.local:59881
edgex-messagebus.edgex-system.svc.cluster.local:1883
device-serial-jetson.edgex-edge.svc.cluster.local:59910
```

고정 ClusterIP, PodIP, node IP를 manifest와 runtime 구성에 넣지 않는다. EdgeMesh
설정과 기존 Service label은 변경하지 않는다.

## 컴포넌트 구조

새 코드는 `edgex/device-serial/` 아래에서 책임별로 나눈다.

```text
cmd/device-serial/main.go
  EdgeX SDK bootstrap entrypoint

internal/driver/config.go
  serial protocol properties 검증

internal/driver/framer.go
  byte stream을 최대 길이가 제한된 CRLF/LF line으로 분리

internal/driver/parser.go
  strict JSON validation과 sensor/resource mapping

internal/driver/serial.go
  serial open/read/close와 bounded reconnect loop

internal/driver/driver.go
  EdgeX ProtocolDriver lifecycle, latest cache, AsyncValues publish, read command
```

각 parser와 framer는 실제 장비 없이 단위 테스트할 수 있는 순수 로직으로 둔다.
Serial opener와 clock은 인터페이스로 주입해 disconnect/reconnect와 origin을 테스트한다.

## 수집과 Event 변환

SDK bootstrap이 끝난 뒤 `Driver.Start()`가 `sdk.Devices()`의 Serial Device를 읽고
각 Device에 reader를 하나 시작한다. runtime Device 추가·변경·삭제 callback은 해당
reader만 시작·교체·정지한다.

reader는 `115200 8N1`로 port를 열고 최대 1초 read timeout을 사용한다. 받은 byte는
line framer에 넣는다. 최대 line 크기는 `1024` bytes다. newline 전 1024 bytes를
넘으면 해당 line 전체를 다음 newline까지 버린다.

정상 line은 strict parser를 통과한 뒤 수신 시각의 Unix nanoseconds를 origin으로
사용한다. firmware가 단위와 source timestamp를 제공하지 않으므로 값을 섭씨, lux,
tesla 또는 g로 변환하지 않는다.

| `sensor` | Event `sourceName` | Reading | `valueType` |
|---|---|---|---|
| `temperature` | `temperature` | `temperature_raw` | `Int32` |
| `light` | `light` | `light_raw` | `Int32` |
| `magnetic` | `magnetic` | `magnetic_raw` | `Int32` |
| `acceleration` | `acceleration` | `acceleration_x_raw`, `acceleration_y_raw`, `acceleration_z_raw` | `Int32` |

각 완전한 정상 line은 `sdkModels.AsyncValues` 하나가 된다. 동일한 값이 연속되어도
firmware sequence가 없으므로 중복으로 추정해 제거하지 않는다. SDK
`AsyncValuesChannel`의 backpressure를 따르며 첫 slice에는 SQLite outbox나 자체
durable queue를 추가하지 않는다. 중앙 단절 중 sample 보존을 완료 기능으로
주장하지 않는다.

## GET과 command 경계

driver는 device/source별 최신 정상 sample을 memory에 보관한다. Device Profile은
`temperature`, `light`, `magnetic`, `acceleration` read-only Device Command를
정의한다. Core Command GET이 `HandleReadCommands`를 호출하면 요청 resource의 최신
값과 원래 sample origin을 반환한다.

아직 수신한 값이 없으면 명시적 `latest sample is unavailable` 오류를 반환한다.
`HandleWriteCommands`는 항상 read-only 오류를 반환한다. Arduino firmware 변경,
actuator command, desired state mutation은 이번 범위에 없다.

## validation과 장애 동작

다음 입력은 Event와 latest cache에 넣지 않는다.

- UTF-8 또는 JSON object가 아닌 line
- 알 수 없는 JSON field나 뒤따르는 두 번째 JSON 값
- `device_id != arduino-001`
- 지원하지 않는 `sensor`
- sensor별 필수 field 누락 또는 다른 sensor field 혼입
- boolean, string, float 또는 Int32 범위 밖의 값
- 최대 line 크기 초과

invalid sample은 port 연결 상태를 DOWN으로 바꾸지 않고 경고와 counter만 남긴다.
port open/read 실패는 해당 Device를 `DOWN`으로 갱신하고 1초부터 최대 30초 bounded
exponential backoff로 재연결한다. 재연결 성공 시 `UP`으로 복구한다. 프로세스 종료,
Device 삭제 또는 update 시 port를 닫고 goroutine이 끝날 때까지 기다린다.

## Kubernetes와 네트워크

`edgex/k8s/base/device-serial-jetson/`을 만들고 root
`edgex/k8s/kustomization.yaml`에서 포함한다.

배포 리소스는 다음으로 제한한다.

- ConfigMap: SDK config, Device Profile, Device preload 파일
- Service: `ClusterIP`, port `59910`; IP를 consumer 구성에 기록하지 않음
- Deployment: Jetson exact placement, privileged exception, stable char device mount
- NetworkPolicy: DNS와 중앙 Keeper/Metadata/MessageBus egress, 중앙 EdgeX ingress

local MQTT broker, hostNetwork, PVC, Agent Secret, SQLite volume은 추가하지 않는다.
중앙 Core/PostgreSQL/MessageBus와 EdgeMesh manifest는 수정하지 않는다.

## 검증 기준

### 자동 검증

- 네 실측 JSON payload가 정확한 source와 Int32 Reading으로 변환된다.
- partial/invalid/unknown/mixed/oversize line이 Event가 되지 않는다.
- CRLF와 여러 line이 chunk 경계와 무관하게 복원된다.
- 연속 동일 sample도 서로 다른 origin Event로 전달된다.
- fake port disconnect 뒤 bounded reconnect와 수집 재개가 동작한다.
- read command는 latest value/origin을 반환하고 write command는 거절한다.
- SDK callback add/update/remove가 reader를 누수 없이 관리한다.
- manifest는 exact node/device, `Recreate`, privileged 예외, token 차단,
  non-hostNetwork와 제한적 NetworkPolicy를 가진다.
- manifest와 runtime에 Agent, local MQTT, SQLite, 고정 IP가 없다.
- Kustomize render, server dry-run, 기존 EdgeX 테스트와 문서 검증이 통과한다.

### live 검증

- ARM64 immutable image가 내부 registry에 push된다.
- Argo CD `edgex-telemetry`가 목표 Git revision으로 `Synced/Healthy`다.
- Device Service Pod가 Jetson에서 Ready이고 stable device path를 연다.
- Core Metadata에 Service/Profile/Device binding이 각각 한 개 존재한다.
- Core Data에서 네 source와 여섯 typed Reading을 실제 값으로 확인한다.
- Core Command GET이 latest sample을 반환하고 write command는 노출되지 않는다.
- state-aggregator/dashboard가 `arduino-001`, `device-serial-jetson`, profile,
  protocol과 fresh latest Event를 표시한다.
- 중앙 Core/PostgreSQL/MessageBus와 EdgeMesh가 계속 정상이다.

## 완료 경계

완료는 실제 Serial sample이 Core Data/PostgreSQL에 저장되고 dashboard freshness와
read-only GET까지 같은 실행에서 확인된 경우에만 주장한다. Pod Running, 장치 mount,
Metadata 등록 또는 unit test만으로 물리 연동 완료를 주장하지 않는다.

이 완료는 offline replay, local workflow recent API, Modbus/OPC-UA/I2C/RTSP,
actuator command, Serial Device Plugin hardening 또는 동적 오프로딩 완료를 뜻하지 않는다.
