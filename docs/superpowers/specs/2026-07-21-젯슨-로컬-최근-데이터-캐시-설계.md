# 젯슨 로컬 최근 데이터 캐시 설계

## 상태

- 승인일: 2026-07-21
- 구현 대상: Jetson `device-serial-jetson`과 6개 Arduino 가상 디바이스
- 배포 경로: Argo CD Application `edgex-telemetry`가 동기화하는 `edgex/k8s`

## 목표

Jetson에서 실행되는 Workflow Pod가 중앙 EdgeX Core Data를 왕복하지 않고도 6개
가상 디바이스의 최신값과 최근 시간 구간을 조회할 수 있게 한다. 캐시는
`device-serial-jetson` 프로세스 안에 두고, 시리얼에서 정상 파싱·라우팅된 것과 같은
typed sample을 반환한다.

이 캐시는 저지연 로컬 조회용이다. 중앙 미전송 Event를 보존하거나 장기 이력을
대체하지 않는다.

## 선택한 접근

### 채택: Device Service 내장 메모리 링버퍼

- 이미 파싱·표준화된 sample을 Event 발행 직전에 한 번 저장하므로 중복 수집이 없다.
- 중앙 MessageBus와 Core Data가 일시적으로 접근 불가능해도 로컬 조회를 계속할 수 있다.
- 별도 Pod, broker, PVC와 데이터 동기화 경로를 만들지 않는다.
- Pod 재시작 시 캐시가 초기화되는 동작을 명시적으로 허용한다.

### 제외: MessageBus 구독 사이드카

사이드카는 Device Service와 캐시 API를 분리할 수 있지만, 별도 이미지·배포·상태 관리가
필요하고 중앙 MessageBus 접근 실패가 곧 로컬 캐시 실패가 된다. 현재 PoC의 로컬
저지연 목적에 맞지 않는다.

### 제외: SQLite 최근 이력

SQLite는 재시작 후 데이터 보존에 유리하지만 쓰기 증폭, 파일 수명, PVC, 스키마와
복구 정책이 추가된다. 사용자가 최근 캐시의 재시작 비보존을 승인했으므로 이번 범위에
포함하지 않는다. 추후 SQLite Outbox를 구현하더라도 최근 조회 캐시와는 별도 책임으로
유지한다.

## 데이터 흐름

```text
Arduino Uno (/dev/arduino-001)
  -> 공유 Serial reader
  -> parser / resource-to-device route
  -> 가상 디바이스별 RecentCache append
     +-> Core Command GET: latest sample
     +-> Local Data API: latest/recent samples
  -> EdgeX SDK AsyncValues
  -> 중앙 MessageBus -> Core Data -> PostgreSQL
```

캐시에 들어가는 단위는 다음과 같다.

```json
{
  "origin": 1784600000000000000,
  "valueType": "Int32",
  "value": 283
}
```

cache key는 `(deviceName, resourceName)`이다. 따라서 같은 물리 Arduino에서 수집해도
`virtual-temperature-001/temperature_raw`와
`virtual-light-001/light_raw`는 서로 다른 시계열이다.

## 보존 정책

- 각 `(deviceName, resourceName)` 시계열은 최근 10분만 보존한다.
- 각 시계열은 최대 10,000 sample을 보존한다.
- 시간과 개수 한도 중 먼저 도달한 조건으로 오래된 sample을 제거한다.
- 시간 판정은 EdgeX Event와 같은 nanosecond `origin`을 사용한다.
- 조회 결과는 `origin` 오름차순으로 반환한다.
- 조회 범위의 sample이 `limit`보다 많으면 가장 최근 `limit`개를 선택한 뒤 오름차순으로 반환한다.
- Device가 LOCKED/삭제되거나 binding에서 제거되면 해당 Device cache를 제거한다.
- Pod 재시작 시 cache는 빈 상태로 시작하며 첫 정상 sample 이후 다시 채워진다.

기본값은 이번 Serial 수직 슬라이스의 고정 계약으로 둔다. 보존 기간이나 용량을 운영 중
동적으로 변경하는 기능은 이번 범위에 넣지 않는다.

## Local Data API 계약

Device SDK의 기존 HTTP 서버와 `59910` 포트를 재사용한다.

### 최신값

```text
GET /api/v3/localdata/device/name/{device}/resource/name/{resource}/latest
```

- 알려진 Device/resource이고 sample이 있으면 `200`과 sample 한 개를 반환한다.
- 알려진 Device/resource이지만 아직 sample이 없으면 `404`를 반환한다.
- 등록되지 않은 Device 또는 Profile에 없는 resource도 `404`를 반환한다.

### 최근 구간

```text
GET /api/v3/localdata/device/name/{device}/resource/name/{resource}
    ?from={origin_ns}&to={origin_ns}&limit={1..10000}
```

- `from`과 `to`는 선택적 nanosecond Unix timestamp이며 양끝을 포함한다.
- 생략 시 현재 시각 기준 캐시 보존 구간 전체를 대상으로 한다.
- `limit` 기본값은 1,000이고 허용 범위는 1~10,000이다.
- 알려진 Device/resource에 대상 sample이 없으면 `200`과 빈 `samples`를 반환한다.
- 숫자가 아니거나 범위를 벗어난 query, `from > to`는 `400`을 반환한다.
- 결과는 중앙 Core Data로 fallback하지 않는다. 로컬 API의 의미를 조용히 바꾸지 않는다.

성공 응답 형태는 다음과 같다.

```json
{
  "apiVersion": "v3",
  "statusCode": 200,
  "deviceName": "virtual-temperature-001",
  "resourceName": "temperature_raw",
  "count": 2,
  "retention": {
    "maxAge": "10m0s",
    "maxSamples": 10000
  },
  "samples": [
    {"origin": 1784600000000000000, "valueType": "Int32", "value": 283},
    {"origin": 1784600001000000000, "valueType": "Int32", "value": 284}
  ]
}
```

API는 raw frame, command, 중앙 history를 제공하지 않는다. 카메라는 계속 Workflow Pod가
RTSP를 직접 구독하고, 장기 이력은 Core Data API를 사용한다.

## 네트워크와 접근 경계

- 기존 Service FQDN
  `device-serial-jetson.edgex-edge.svc.cluster.local:59910`을 사용한다.
- manifest와 client 설정에 고정 ClusterIP, Pod IP 또는 node IP를 기록하지 않는다.
- `hostNetwork`, edge-local MQTT broker와 EdgeMesh 설정을 추가하거나 변경하지 않는다.
- 기존 `edgex-system` Core Service 접근은 유지한다.
- Workflow Pod는 `edge-ai.io/local-data-client=true` label이 있을 때만 ingress
  NetworkPolicy를 통과한다.
- Workflow Pod는 대상 Runtime과 같은 Jetson에 배치하는 것을 binding/execution plan의
  선행 조건으로 둔다. 이 기능이 Workflow 실행 오케스트레이션을 구현했다는 뜻은 아니다.

현재 EdgeX security secret store가 비활성화되어 있으므로 custom route는 Device SDK의
unauthenticated route로 등록하되, Kubernetes NetworkPolicy로 호출 주체를 제한한다.

## 오류와 상태 동작

- malformed Serial payload와 다른 physical `device_id`는 기존과 같이 폐기하며 cache에도 넣지 않는다.
- route가 없는 resource는 cache와 중앙 Event 모두 생성하지 않는다.
- 캐시 저장은 메모리 연산이며 중앙 Event 발행의 성공 여부와 분리한다.
- 중앙 MessageBus 송신이 지연돼도 이미 정상 파싱된 sample의 로컬 조회는 가능하다.
- stale sample을 현재값처럼 꾸미지 않는다. 응답의 원본 `origin`을 보존해 Workflow가 age를 판단하게 한다.
- cache API 오류가 Serial reader와 중앙 Event 발행 루프를 중단시키지 않는다.

## 구현 경계

### 포함

- 동시성 안전한 bounded recent cache
- 기존 최신값 map을 cache의 latest 조회로 통합
- Device SDK custom route 두 개와 JSON 응답
- 6개 가상 디바이스별 독립 cache
- Workflow client label을 허용하는 ingress NetworkPolicy
- 단위·통합·manifest 테스트, ARM64 이미지 build/push, Argo 배포와 live readback
- 활성 문서와 생성 HTML 최신화

### 제외

- SQLite Outbox와 offline replay
- Pod 재시작 후 cache 복구
- 중앙 history proxy 또는 Core Data fallback
- actuator/write command
- MQTT broker, 별도 cache sidecar, InfluxDB
- EdgeMesh 구성 변경
- Workflow apply/delete/restart 또는 동적 오프로딩 실행
- Modbus, OPC-UA, 추가 I2C와 RTSP adapter 구현

## 테스트 전략

1. `RecentCache` 단위 테스트에서 device/resource 격리, 최신값, 시간 만료, 10,000개
   capacity eviction, 구간 filter, 최신 `limit` 선택과 동시 read/write를 검증한다.
2. HTTP handler 테스트에서 latest/recent 성공 응답, 빈 recent, 미등록 Device/resource,
   잘못된 timestamp/limit과 정렬 순서를 검증한다.
3. Driver 테스트에서 한 Serial sample이 6개 독립 cache에 fan-out되고 Core Command GET이
   같은 latest sample을 반환하는지 검증한다.
4. Kustomize 테스트에서 기존 Service/FQDN, workflow client label ingress, 고정 IP·PVC·
   SQLite·broker 부재를 검증한다.
5. 전체 Go race test, vet, EdgeX manifest test, Kustomize render, 문서 검증을 통과한다.
6. ARM64 이미지를 digest로 고정하고 Argo CD 동기화 후 Jetson 배치 Pod에서 latest와
   recent API를 호출해 6개 Device 분리, 증가하는 origin과 cache window를 확인한다.
7. 중앙 Metadata/Core Data/Core Command와 dashboard가 계속 정상인지 회귀 검증하고
   EdgeMesh generation이 바뀌지 않았음을 확인한다.

## 완료 기준

- 6개 `(deviceName, resourceName)` 시계열이 서로 섞이지 않는다.
- 최신값과 최근 구간 API가 위 계약대로 응답한다.
- 각 시계열이 10분과 10,000개 한도를 넘지 않는다.
- Workflow label이 없는 Pod는 새 ingress 허용 대상이 아니다.
- 중앙 Core Data 저장, Core Command GET과 dashboard freshness가 기존대로 동작한다.
- live manifest에 fixed ClusterIP/PodIP/node IP, SQLite/PVC, InfluxDB, local broker가 없다.
- EdgeMesh를 변경하지 않는다.
- 테스트, render, live readback, 문서 일관성 검증이 모두 통과한다.
