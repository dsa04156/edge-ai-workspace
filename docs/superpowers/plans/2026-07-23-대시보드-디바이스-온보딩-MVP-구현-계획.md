# 대시보드 디바이스 온보딩 MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 설치되어 실행 중인 EdgeX Device Service에 새 Device Profile과 Device를 대시보드에서 안전하게 등록·수정하고, Metadata readback과 첫 Core Data Event를 분리해 검증한다.

**Architecture:** 기존 `state-aggregator`의 read-only `/state/*` 경로와 별도로 `/management/*` router, onboarding domain service, EdgeX Metadata mutation client를 둔다. 정적 Adapter Catalog가 입력 form과 protocol 제약을 정의하고 EdgeX Core Metadata의 Device Service/Profile/Device가 실제 권위가 된다. mutation은 기본 비활성화, 관리자 Bearer token, HMAC 기반 idempotency와 bounded memory operation store로 보호한다.

**Tech Stack:** FastAPI, Pydantic v2, httpx, EdgeX v3 Core Metadata/Core Data API, vanilla JavaScript/CSS, Node test runner, pytest, Kustomize, Argo CD

## Global Constraints

- EdgeX Core Metadata의 Device/Profile/Device Service와 Core Data Event를 권위로 유지한다.
- KubeEdge는 node/workload 관리에만 사용하고 KubeEdge Device CRD를 추가하지 않는다.
- 관리 API는 `state-aggregator` 내부에 두되 기존 read-only client/service와 mutation client를 분리한다.
- `DEVICE_MANAGEMENT_ENABLED=false`가 기본값이며 이 상태에서 create/patch는 닫혀 있어야 한다.
- Device 삭제, Profile 강제 삭제, command publish, actuator command, Kubernetes workload mutation을 구현하지 않는다.
- Dashboard는 adapter를 자동 설치하거나 Deployment를 변경하지 않는다.
- 초기 installed adapter는 `device-serial-jetson`, `device-sensehat-raspi`뿐이다.
- Modbus, OPC-UA, MQTT, RTSP는 실제 Device Service와 endpoint 검증 전까지 `unsupported`다.
- raw idempotency key와 관리자 token을 response, audit, browser storage에 남기지 않는다.
- 고정 ClusterIP, PodIP, node IP를 저장하지 않고 EdgeX service identity와 Kubernetes Service DNS만 사용한다.
- EdgeMesh 리소스를 조회·수정하지 않는다.
- live Metadata mutation은 별도 승인 없는 자동 검증에서 실행하지 않는다.

- [ ] **Step 2: idempotency 실패 테스트 작성**

```python
first = await service.create_device(request, idempotency_key="retry-1", actor="dashboard-admin")
same = await service.create_device(request, idempotency_key="retry-1", actor="dashboard-admin")
assert same.request_id == first.request_id

with pytest.raises(IdempotencyConflict):
    await service.create_device(changed_request, idempotency_key="retry-1", actor="dashboard-admin")
```

HMAC request ID는 raw key를 포함하지 않고 canonical payload SHA-256은 key order에 독립적이어야 한다.

- [ ] **Step 3: saga와 compensation 실패 테스트 작성**

순서를 `validate → add profile → readback → add device → readback → first Event`로 고정한다. Device add 실패 시 이번 operation이 만든 Profile이고 `devices_by_profile=[]`일 때만 delete한다. 기존 Profile과 사용 중 Profile은 삭제하지 않는다.

- [ ] **Step 4: operation store와 restart reconstruction 실패 테스트 작성**

bounded `OrderedDict`는 설정 limit을 넘으면 가장 오래된 operation을 제거한다. memory miss일 때 Device reserved tags와 Core Data latest Event로 동일 request를 재구성한다.

- [ ] **Step 5: 최소 domain service 구현**

`create_device()`는 Metadata readback 성공 뒤 Event 유무에 따라 `verified` 또는 `waiting_for_event`를 반환한다. `get_operation()` polling 때 Event가 새로 생기면 `verified`로 전이한다. Event가 없는 passive 장비의 Metadata는 되돌리지 않는다.

`patch_device()`는 description, labels, user tags, protocol properties, `adminState`만 허용하고 reserved tags를 보존한다. name/profile/service 변경 입력은 Pydantic DTO 단계에서 금지한다.

- [ ] **Step 6: 구조화 audit와 redaction 구현**

`logger.info(json.dumps(event))`에 request ID, actor, action, target, redacted before/after, 상태와 timestamps를 기록한다. token, raw idempotency key와 secret field는 포함하지 않는다.
