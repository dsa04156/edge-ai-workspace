# Jetson 엣지 텔레메트리 에이전트 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `etri-dev0001-jetorn`에 broker-free direct-mode telemetry agent와 독립 SQLite outbox를 배치하고, 중앙 DB를 보존한 채 mTLS/HMAC heartbeat 경로를 검증한다.

**Architecture:** 현재 Sense HAT의 노드별 Deployment/PVC 패턴을 Jetson에 한 인스턴스 추가한다. Arduino Serial adapter와 Metadata 등록은 이번 범위에서 제외하고, telemetry-only Secret 교체로 중앙 gateway와 두 edge identity를 함께 재발급한다.

**Tech Stack:** Kubernetes, Kustomize, Argo CD, POSIX shell, OpenSSL, Python/pytest, EdgeX v4 Core Data, FastAPI telemetry plane, SQLite WAL

## Global Constraints

- root 운영 진입점은 `edgex/k8s/kustomization.yaml`을 유지한다.
- Jetson identity는 `etri-dev0001-jetorn`, Sense HAT identity는 `etri-dev0003-raspi5`다.
- edge northbound는 DNS 기반 `https://edgex-ingest-gateway.edgex-system.svc.cluster.local:8443`만 사용한다.
- 고정 ClusterIP/PodIP, edge-local broker, `device-mqtt`, MQTT agent 환경변수를 추가하지 않는다.
- Arduino `/dev/ttyACM*`, Serial adapter, Device Profile/Device와 command는 이번 단계에서 변경하지 않는다.
- EdgeMesh와 기존 MQTT/legacy workload를 변경하지 않는다.
- PostgreSQL credential과 PVC 데이터는 telemetry 인증 교체 중 유지한다.
- live 완료 기준은 Jetson Pod Ready/PVC Bound와 인증된 gateway heartbeat이며 `source_seen=false`는 예상 상태다.

```yaml
metadata:

    edge.etri.io/id: etri-dev0001-jetorn

metadata:
  name: edgex-edge-agent-jetson

  replicas: 1

    type: Recreate

      hostNetwork: true
      dnsPolicy: ClusterFirstWithHostNet
      nodeSelector:
        kubernetes.io/hostname: etri-dev0001-jetorn
      containers:
        - name: telemetry-edge-agent
          env:
            - name: EDGE_ID
              value: etri-dev0001-jetorn

              valueFrom:
                secretKeyRef:
                  name: edgex-edge-agent-jetson-credentials

          persistentVolumeClaim:
            claimName: edgex-edge-agent-jetson-outbox
        - name: gateway-mtls
          secret:
            secretName: edgex-edge-agent-jetson-gateway-mtls
```

- [ ] **Step 3: provisioning argument와 생성 계약 구현**

argument mode를 다음으로 고정한다.

```sh
mode=create
case "${1:-}" in
    "") ;;
    --replace) mode=replace_all ;;
    --replace-telemetry) mode=replace_telemetry ;;
    *)
        printf '%s\n' "usage: $0 [--replace|--replace-telemetry]" >&2
        exit 64
        ;;
esac
```

telemetry generation은 두 edge HMAC과 client certificate를 만든다.

```sh
random_hex >"$secret_tmp/sensehat-auth"
random_hex >"$secret_tmp/jetson-auth"
printf '{"etri-dev0001-jetorn":"%s","etri-dev0003-raspi5":"%s"}' \
    "$(tr -d '\n' <"$secret_tmp/jetson-auth")" \
    "$(tr -d '\n' <"$secret_tmp/sensehat-auth")" \
    >"$secret_tmp/edge-auth-secrets.json"

issue_edge_certificate etri-dev0001-jetorn jetson
issue_edge_certificate etri-dev0003-raspi5 sensehat
```

`mode=replace_telemetry`이면 DB 파일을 생성하거나 DB Secret을 apply하지 않는다. 그 외 mode는 기존 DB provisioning을 유지한다. telemetry Secret 네 묶음과 중앙 auth/TLS는 모든 mode에서 apply한다.
