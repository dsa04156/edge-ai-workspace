# 센서 이력 그래프 연결 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** EdgeX Device 12개 중 하나를 대시보드에서 선택하면 Core Data/PostgreSQL 기반 실제 이력을 범위별 resource 시계열 그래프로 표시한다.

**Architecture:** 브라우저는 기존 `state-aggregator` telemetry endpoint만 호출하고 backend는 EdgeX Core Data API를 통해 PostgreSQL-backed Event/Reading을 읽는다. 프론트는 선택별 request sequence를 관리해 늦은 이전 응답을 폐기하며, chart는 history state만 사용한다.

**Tech Stack:** FastAPI, EdgeX Core Data v3 API, vanilla JavaScript, inline SVG, CSS, Node test runner, pytest, Kubernetes/Argo CD

## Global Constraints

- PostgreSQL 직접 SQL client와 브라우저 DB 연결을 추가하지 않는다.
- Device inventory/state/telemetry 권위는 EdgeX로 유지한다.
- Device 선택 시에만 이력을 조회하며 12개 Device 전체 이력을 선로딩하지 않는다.
- 기본 범위는 `-30m`, Event 상한은 `1000`이다.
- 범위 control은 `-5m`, `-30m`, `-1h`, `-24h`만 제공한다.
- 빈 이력을 `latest_readings`로 대체하지 않는다.
- 고정 ClusterIP, PodIP, node IP와 EdgeMesh 변경을 추가하지 않는다.
- 현재 service demo와 Workflow Builder read-only 경계를 유지한다.

```javascript
const DEVICE_TELEMETRY_LIMIT = 1000;

function deviceTelemetryHistoryUrl(deviceName, window, limit = DEVICE_TELEMETRY_LIMIT) {
  return `/state/devices/${encodeURIComponent(deviceName)}/telemetry?window=${encodeURIComponent(window)}&limit=${limit}`;
}

async function fetchDeviceTelemetryHistory(deviceName, window, fetchFn = fetch) {
  const response = await fetchFn(deviceTelemetryHistoryUrl(deviceName, window), {cache: "no-store"});
  if (!response.ok) throw new Error(`telemetry history request failed: ${response.status}`);
  const payload = await response.json();
  if (!Array.isArray(payload)) throw new Error("telemetry history response must be an array");
  return payload;
}
```
