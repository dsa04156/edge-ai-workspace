# 아두이노 6개 가상 디바이스와 InfluxDB 제거 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Jetson의 Arduino 시리얼 포트를 한 번만 읽어 여섯 EdgeX 가상 디바이스로 Event를 분리하고, 활성 배포와 `state-aggregator`에서 InfluxDB를 완전히 제거한다.

**Architecture:** `device-serial-jetson`은 `(Port, BaudRate, DeviceID)`별 공유 connection 하나와 `ResourceName -> EdgeX DeviceName` route를 관리한다. EdgeX Core Metadata에는 1-resource Profile/Device 여섯 개만 등록하며, telemetry 저장과 조회는 Core Data/PostgreSQL로 단일화한다.

**Tech Stack:** Go 1.23, EdgeX Device SDK Go v4, YAML/Kustomize, Python 3/FastAPI/pytest, Argo CD, Kubernetes, Harbor

## Global Constraints

- EdgeMesh 리소스와 설정은 변경하지 않는다.
- 고정 ClusterIP, PodIP 또는 node IP를 사용하지 않고 Kubernetes service FQDN만 사용한다.
- 중앙 EdgeX Core Service, MessageBus와 PostgreSQL은 유지한다.
- MQTT broker, edge agent, SQLite outbox를 추가하지 않는다.
- 물리 source ID는 `arduino-001`, EdgeX inventory는 정확히 여섯 가상 Device다.
- Jetson node selector는 `etri-dev0001-jetorn`을 유지한다.
- root 운영 배포 진입점은 `edgex/k8s`다.

- [ ] **Step 3: 최소 공유 connection 구현**

`SerialConfig`에 route를 추가하고 connection identity를 분리한다.

```go
type SerialConfig struct {
    Port         string
    BaudRate     int
    DeviceID     string
    ResourceName string
}

type connectionKey struct {
    port string
    baudRate int
    deviceID string
}

func (config SerialConfig) key() connectionKey {
    return connectionKey{config.Port, config.BaudRate, config.DeviceID}
}
```

Driver는 다음 책임으로 교체한다.

```go
type managedConnection struct {
    reader managedReader
    cancel context.CancelFunc
    config SerialConfig
    routes map[string]string
    state models.OperatingState
    hasState bool
}

type deviceBinding struct {
    config SerialConfig
    connection *managedConnection
}
```

- `connections map[connectionKey]*managedConnection`
- `bindings map[string]*deviceBinding`
- connection 최초 route에서만 reader 생성
- sample Reading마다 route Device를 찾아 1-reading Event 생성
- `temperature_raw -> temperature`, `acceleration_x_raw -> acceleration_x` source map 사용
- connection state를 현재 route Device 전체에 반영
- 마지막 route 제거 시 reader cancel/close
