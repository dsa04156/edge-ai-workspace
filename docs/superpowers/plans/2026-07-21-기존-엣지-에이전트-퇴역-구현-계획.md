# 기존 엣지 Agent 퇴역 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 개발 단계의 `edgex-edge-agent-jetson`과 `edgex-edge-agent-sensehat`, 두 SQLite outbox PVC와 Agent 전용 Metadata bootstrap을 Git/Argo CD/live cluster에서 제거하고, 중앙 EdgeX와 EdgeMesh를 그대로 보존한다.

**Architecture:** root Kustomize 진입점에서 기존 `sensor-gateways` overlay를 제거하고 `edgex-edge` Namespace와 기본 deny 정책만 가진 중립 base로 교체한다. 이후 정식 EdgeX Device Service가 들어올 자리를 남기되, 아직 구현되지 않은 Device Service나 telemetry를 현재 기능으로 주장하지 않는다. Argo CD는 자동 prune/self-heal이므로 Git 커밋을 먼저 push한 뒤 Application의 고정 revision을 새 커밋으로 전환한다.

**Tech Stack:** Kubernetes, Kustomize, Argo CD, Python/pytest, Git/GitHub, EdgeX 4.0.2

## 고정 경계

- `edgex-system`의 Core Keeper, Core Metadata, Core Data, Core Command, MessageBus, PostgreSQL, ingest gateway는 변경하지 않는다.
- EdgeMesh 리소스와 설정은 조회·수정·재시작하지 않는다.
- 고정 ClusterIP, PodIP, node IP를 추가하지 않는다.
- `edgex-edge` Namespace는 다음 Device Service 배포를 위해 유지한다.
- Agent Deployment와 전용 PVC는 삭제한다. 사용자가 개발 데이터 유실과 일시 중단을 승인했다.
- Agent 이름이 붙은 기존 Secret과 중앙 gateway 인증 계약은 이번 퇴역에서 회전·삭제하지 않는다. 정식 Device Service 전환 시 인증 경로와 함께 별도 정리한다.
- `edgex/telemetry-plane`의 중앙 gateway 코드는 유지한다. edge Agent 실행 경로만 운영 render에서 제거한다.
- 혼합 작업 트리의 기존 변경은 stage하지 않는다.
