## 서비스 데모 상태

[`sensor-anomaly-demo`](펌프-모터-이상감지-서비스.md)의 입력 계약은
`okdong.pump-motor.telemetry/v1`이다. 현재 Arduino raw 입력은 플랫폼 연결 기준선이며 옥동
설비 단위가 아니다.

- 가속도 X/Y/Z는 같은 `origin`으로 frame을 구성한다.
- 온도는 허용 시간차 안의 가장 가까운 sample만 결합한다.
- 진동 20개, 온도 10개 window와 30개 warm-up을 사용한다.
- 현재 backend는 학습된 고장 분류기가 아닌 `online-baseline`이다.
- Server1 후보는 같은 기준선의 CUDA backend이며 HAMi GPU 할당과 CUDA probe를 readiness에 포함한다.
- 결과와 alert transition은 서비스 소유 SQLite에 idempotent하게 저장한다.

실제 설비 고장 분류 정확도와 생산성 개선 효과는 옥동 현장 데이터로 별도 검증해야 한다.

## 자원 증강 상태

자원 증강 판단은 설비 이상 판단과 분리한다. `anomaly_score`는 evaluator 입력이 아니다.

```text
입력·모델·메트릭 유효
AND 자원 압박 5분
AND 서비스 압박 3분
AND Server1 endpoint/model/resource 준비
→ 증강 권고
```

센서 stale, schema 오류, model not ready, metric 부족/stale 또는 Server1 준비 실패는
`BLOCKED`와 reason으로 기록한다. 승인 ID가 없는 기본 경로는 local inference를 유지한다.
