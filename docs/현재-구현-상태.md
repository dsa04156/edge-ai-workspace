# 프로토콜 독립형 디바이스 발견·등록 현재 구현 상태

> 기준일: 2026-08-03
> 판정 기준: 실제 코드, 테스트, `edgex/k8s` render
> “구현”과 “실장비 운영 검증”을 구분한다.

## 요약

Serial은 PTY 후보 발견부터 승인, 검증 Runtime 재사용, EdgeX Profile/Device idempotent 등록,
Core Data 첫 Event 확인까지 자동화된 코드와 fake backend 통합 테스트가 있다. 2026-07-24
실제 Jetson Arduino stable 후보를 운영자가 승인했고 기존 Device Service Runtime을 재사용해
aggregate Device `arduino-75035303230351e0d171-57fc03a907`의
`EVENT_CONFIRMED`와 Core Data Event까지 live 확인했다.

I2C는 allowlist bus/address와 여러 read-only identity register를 하나의 물리 보드
identity로 묶는 composite probe까지 구현했다. 2026-07-28
`etri-dev0003-raspi5`의 Sense HAT v1에서 `0x1c=0x3d`, `0x5c=0xbd`,
`0x5f=0xbc`, `0x6a=0x68`을 확인해 후보를 승인했고, 기존
`device-sensehat-raspi`, Profile `etri-sensehat-gyroscope`, Device
`imu-sensehat-gyroscope-01`을 재사용한 뒤 신규 Core Data Event로
`EVENT_CONFIRMED`까지 live 검증했다. 이어서 등록 연결을 decommission하고 다음 30초
탐색 주기에 같은 candidate ID가 `PENDING_APPROVAL`로 자동 복귀하는지 확인했으며,
재승인 뒤 다시 `EVENT_CONFIRMED`가 됐다. 기존 EdgeX Device 13개와 Sense HAT Device
6개는 삭제되거나 중복 생성되지 않았다.

고정 서비스 데모는 2026-08-03 Jetson에 복합 센서 image
`sensor-anomaly-demo@sha256:1a86c54a1a0692a682258b4a9c8a6f7a24e13f98000610afa56c04f95d52af68`을
rollout했다. 가속도 X/Y/Z와 온도 네 Local Data source를 정렬해 실제 origin/frame 증가,
누락 0, 약 11~12ms 정렬 차이를 확인했고 중앙 BFF와 외부 dashboard도 같은 진동·온도
개별 점수와 0.7/0.3 종합 점수를 표시했다. 이는 고정 read-only consumer이며 범용 workflow
실행이나 실제 고장 분류 완료를 뜻하지 않는다.

같은 날 일반 Discovery DaemonSet의 Serial-only passive inventory를 dev0003까지
확장했다. Raspberry Pi에 연결된 CH340 계열 USB Serial 장비를
`/dev/serial/by-id/usb-1a86_USB_Serial-if00-port0`(VID/PID `1a86:7523`)에서
후보 `candidate-fb7190f...`로 반복 관측했다. 이후 exact Raspberry Pi hardware binding,
`mpu6050-imu-v1` Profile/parser, Controller 배포 template과 MPU6050 6축 Float64
JSON-line 처리를 구현했다. exact 후보 승인부터 Runtime, Profile/Device, first Event까지의
fake backend 통합 테스트는 통과했다. live 승인도 실행했지만 당시 Serial telemetry가 없어
첫 Event timeout으로 `FAILED`가 됐고 Controller가 자신이 만든 동적 Runtime을 rollback했다.
이후 보드를 `ESP32-D0WD-V3 revision 3.1`로 식별하고 운영 firmware를 compile·flash해
115200 baud 상태 JSON까지 확인했다. firmware는 MPU6050을 1초마다 재탐색하지만 ESP32의
일반 I2C pin pair와 Raspberry Pi bus 1에서 `0x68`, `0x69` 모두 ACK가 없었다.
2026-07-30 MPU6050 실물을 분리했고 후보는 `STALE`/`ignored` 감사 이력으로 정리했으며
동적 Runtime은 없는 상태다.
Profile/parser/template과 자동 테스트는 재연결 실험을 위한 dormant 지원 코드로 남기되
현재 연결 장비나 완료된 telemetry 경로로 표시하지 않는다. Serial Agent와 I2C Agent가
같은 node를 보고해도 서로의 후보를 `STALE` 처리하지 않도록 report에
`scannedProtocols` scope를 추가했고, Sense HAT 후보는 계속 `EVENT_CONFIRMED`를 유지했다.
MQTT 자기등록 subscriber는 아직 없다. 대신 공식 `device-mqtt:4.0.2` immutable image,
노드별 network binding, allowlist broker/topic/QoS Runtime 설정, Device command
topic/resource와 bundled `edgeai-mqtt-temperature-v1` Profile을 묶은 개발용 웹 연결
package를 구현했다. 대시보드의 `검증하고 연결` 한 번으로 validation, Runtime
재사용/배포, Profile/Device readback과 first Event 확인을 진행한다. anonymous
broker/publisher는 root 운영 render 밖의 선택적 development fixture다. 이 경로는 자동
테스트와 manifest render뿐 아니라 2026-07-30 실제 클러스터 웹 canary도 통과했다.
Jetson에 `adapter-mqtt-978887c832`를 배포하고
`mqtt-temperature-sim-001` Device와 `edgeai-mqtt-temperature-v1` Profile을 등록한 뒤
Core Data의 `temperature` Float64 Event와 `ACTIVE` operation을 확인했다. 첫 Event 뒤
`operatingState=UP` Metadata readback까지 성공해야 연결 완료로 판정한다.
Modbus는 네트워크 discovery 없이 운영자가 선언한 고정 개발 endpoint에 한해 공식 EdgeX
`device-modbus:4.0.2` Runtime, read-only Profile, Modbus TCP simulator와 승인 Saga를
연결했다. 2026-07-28 Unit 2 가상 온도 센서를 승인해 Controller-owned Runtime,
Core Metadata Device, 1초 AutoEvent, Core Data 저장과 대시보드 `available` 상태까지 live
확인했다. 개발용 Modbus endpoint simulator Deployment는 root 운영 render 밖에 남아
있지만 해당 Controller Device Service Runtime은 검증 뒤 퇴역했으며 현재 live EdgeX
inventory에는 포함되지 않는다. 이는 개발 simulator 수직 경로의 과거 증거이며 실제 PLC
지원 완료가 아니다. OPC-UA와 ONVIF는 확장 contract와 명시적 `not implemented` 상태만 있다.

대시보드는 전역 `간편 보기`/`전체 보기` 토글을 제거했다. 기본 화면에는 핵심 상태만 두고
기술 KPI, 서비스 연결 근거, 후보 세부정보와 개별 EdgeX Device는 클릭해 펼친다. 등록
목록은 기본 운영 경로의 Core Metadata 13개 Device identity를 유지하면서 `arduino-001`과
`sensehat-001` 물리 source별 카드로 묶는다. 375px, 768px, 1024px 실제 브라우저
viewport와 MQTT 연결 마법사의 1440px viewport에서 문서 가로 overflow와 잘린 텍스트가
없음을 확인했다.

`서비스 설계` 캔버스는 실제 `/state/dashboard` Device/node와
`/state/device-profiles` DeviceResource 계약을 읽어 센서 입력·전처리·추론·결과 단계를
구성한다. 왼쪽은 EdgeX 입력 2종, 전처리 6종, 추론 3종, 점수 결합 1종과 결과 1종을
검색하는 13종 서비스 카탈로그이며 EdgeX 입력 가능 Device 수와 실행되지 않는 `설계용`
계약을 구분한다.
단계 이동·추가·삭제, 포트 연결, 속성 편집, DAG·타입·노드 배치 validation,
dry-run 실행 계획과 versioned localStorage 초안을 구현했다. 중앙 캔버스는 pan·zoom,
fit view, 미니맵, 24px grid·정렬선 snap, `Shift` 축 고정·`Alt` 자유 이동과 방향키
미세 이동을 제공한다. 드롭 뒤 viewport를 다시 이동하지 않으며
390/768/1024/1440px에서 문서·캔버스 가로 overflow가 없음을 브라우저로 확인했다.
이는 브라우저 설계 프로토타입이며 서버 저장, Kubernetes/EdgeX mutation과 실제
Workflow 실행은 미구현이다.

| 서비스 설계의 실제 Workflow 실행 | 구현하지 않음. 현재 캔버스는 Kubernetes/EdgeX mutation이 없는 dry-run 프로토타입 |

## 실장비 검증 필요

- MPU6050을 다시 범위에 넣는 경우에만 ESP32 `3V3/GND/GPIO21(SDA)/GPIO22(SCL)` 연결,
  `0x68` 또는 `0x69` ACK, 6축 JSON-line, exact device mount, Device Service telemetry와
  first Event를 처음부터 다시 검증
- dev0003 CH340 USB Serial의 실제 분리·재연결과 같은 candidate ID 복구
- Sense HAT 보드의 실제 분리·재연결과 같은 candidate ID 복구
- Sense HAT 외 I2C 장비의 identity rule과 실장비 Event
- 외부 인증 운영 endpoint
- 실제 PLC의 Modbus TCP/RTU register map과 연결·재연결
- Modbus 개발 fixture의 강제 장애와 ownership-aware rollback
- 운영 TLS/auth MQTT 장비는 broker CA/credential Secret, topic ACL과 실제 payload
  계약을 포함한 별도 Catalog package로 검증
- ONVIF/OPC-UA 실장비는 구현 후 별도 검증

기존 `device-serial-jetson`과 센서별 6개 virtual Device의 live telemetry를 신규 aggregate
등록의 완료 증거로 대신 사용하지 않는다. 신규 candidate는 운영자 승인 전 Core Metadata에
추가되지 않는다.

## 보안·운영 주의

- Controller base는 `ADAPTER_AUTH_MODE=external`로 fail-closed한다. 현재 root testbed만
  `overlays/development/adapter-management`에서 `development-mock`을 적용하며 운영
  profile이 아니다.
- Catalog API는 read-only이며 임의 image 실행 API가 없다.
- 일반 `edge-device-discovery`는 dev0001/dev0002/dev0003에서 비권한 상태로 read-only
  `/dev`, `/sys` Serial inventory만 수행한다. dev0003의 `edge-device-discovery-i2c`는 container
  device cgroup 때문에 `privileged` 예외가 필요하지만 non-root UID/GID, exact
  `/dev/i2c-1` CharDevice 하나와 보조 group 988만 사용한다. 이 값은 현재 testbed
  host 권한에 종속되며 다른 노드에 그대로 복사하지 않는다.
- Controller SQLite는 1Gi RWO PVC를 사용해 단일 replica 기준이다. 다중 replica HA를
  활성화하지 않는다.
- SQLite PVC를 삭제하면 candidate, 전이 이력, 승인, Saga와 audit를 복구할 수 없다.
- Service는 ClusterIP 객체와 DNS를 사용하지만 고정 ClusterIP 우회는 없다.
- EdgeMesh manifest는 수정하지 않았다.
- 현재 PoC의 `/management/*` mutation은 browser 관리자 token이나 `Authorization`
  header를 요구하지 않는다. 기능 플래그, allowlist 검증, `Idempotency-Key`와 내부
  HMAC은 유지하지만 이는 운영자 인증이 아니다. 접근이 제한된 개발 테스트베드 경계이며
  운영 노출 전 별도 사용자 인증·인가가 필요하다.
