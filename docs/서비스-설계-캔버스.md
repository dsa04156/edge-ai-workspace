# 서비스 설계 캔버스

## 목적

`state-aggregator` 대시보드의 `서비스 설계`는 현재 EdgeX 센서 입력을 전처리·추론·결과
단계에 연결하고 실행 전에 계약을 확인하는 브라우저 기반 설계 프로토타입이다.

이 화면은 Kubernetes workload를 만들거나 EdgeX Metadata를 변경하는 실행 도구가 아니다.
현재 서비스 데모인 `sensor-anomaly-demo`를 동적 workflow로 대체하지도 않는다.

## 현재 데이터 경계

```text
EdgeX Core Metadata
  ├─ Device --------------------------┐
  └─ Device Profile / DeviceResource -┤
                                      v
state-aggregator read-only API -> 서비스 설계 캔버스
                                      |
                                      +-> 브라우저 localStorage 초안
                                      +-> validation
                                      +-> dry-run 실행 계획 미리보기
```

사용 API:

| API | 용도 |
|---|---|
| `GET /state/dashboard` | 현재 EdgeX Device 상태와 KubeEdge/Kubernetes node 관측 |
| `GET /state/device-profiles` | Device Profile의 안전한 읽기 전용 DeviceResource 계약 |

`/state/device-profiles`는 resource `name`, `valueType`, `readWrite`, `units`만 노출한다.
protocol address나 DeviceResource `attributes`는 브라우저 설계 입력으로 전달하지 않는다.

## 단계

| 단계 | 현재 설정 | 출력 |
|---|---|---|
| 센서 입력 | EdgeX Device, DeviceResource, 데이터 접근 방식 | Profile의 `valueType`으로 계산한 타입 |
| 전처리 | 그대로 전달, 표준화, 이동 평균, 벡터 크기, 실행 노드 | 숫자 또는 입력과 같은 타입 |
| 추론 | 온라인 이상 점수 또는 임계값 판정, 실행 노드, 임계값 | 숫자 또는 Boolean |
| 결과 | 대시보드 결과 | 최종 결과 |

단계 추가는 검색 가능한 왼쪽 패널에서 수행하고, 캔버스의 출력 포트와 입력 포트를
차례로 눌러 연결한다. 삭제·입출력 포트를 제외한 단계 박스 전체를 드래그해 배치하며
연결선을 두 번 누르면 삭제한다. 선택한 단계의 설정은 캔버스 위 오른쪽 패널에서
변경하고 닫을 수 있다.

캔버스는 고정 크기 작업 좌표계와 별도 viewport를 사용한다.

- `전체 보기`와 가운데 `◎` 버튼: 현재 graph를 보이는 영역에 맞춤
- `−`/`＋`와 마우스 휠: 캔버스 중심 또는 pointer 위치 기준 확대·축소
- 빈 배경 드래그: 캔버스 이동
- 미니맵: 전체 graph와 현재 보이는 구간 확인, 선택 위치로 이동
- `단계` 버튼: 단계 패널 열기·닫기
- 단계 선택: 현재 배율을 유지하면서 설정 패널에 가리지 않도록 선택 노드만 이동
- 단계 박스 전체 드래그: 삭제·입출력 포트를 제외한 표면을 5px 이상 이동할 때 위치 변경을 시작하고 24px grid 또는 다른 단계의 모서리·중앙 정렬선에 맞춤
- `Shift`+드래그: 처음 위치를 기준으로 가로 또는 세로 한 축에 고정
- `Alt`+드래그: grid와 정렬선 snap 없이 자유 배치
- 방향키: 선택 단계를 1px 이동, `Shift`+방향키는 24px 이동

드래그가 끝난 뒤 발생하는 click은 다시 선택 동작으로 처리하지 않으므로 viewport가
자동 이동하거나 단계가 화면에서 튀지 않는다. 정렬선은 드래그 중에만 표시한다.

브라우저 너비가 좁으면 단계 패널과 설정 패널은 캔버스 위 overlay로 열리며 문서나
캔버스에 별도 가로 scrollbar를 만들지 않는다. 작은 화면의 `전체 보기`는 흐름 전체를
확인하는 overview이므로 세부 편집 시 확대·이동 또는 미니맵을 사용한다.

## 데이터 접근 방식

### 엣지 최근 데이터

`local_recent` 설계는 같은 물리 노드의 Device Service Local Data API와 bounded memory
cache를 사용하는 경로다. 실제 실행 경로를 아직 만들지는 않지만, 설계 검증은 첫 처리
단계가 해당 Device의 `node_name`과 같은지 확인한다.

cache는 최근 10분·Device/resource별 최대 10,000 sample이며 Pod 재시작 시 사라진다.
SQLite outbox나 중앙 장애 replay 저장소가 아니다.

### 중앙 저장 데이터

`core_history` 설계는 중앙 EdgeX Core Data/PostgreSQL의 Event/Reading을 사용하는 경로다.
캔버스는 조회 방식을 설계에 기록할 뿐, 현재 브라우저에서 telemetry를 실행 입력으로
프록시하거나 PostgreSQL에 직접 연결하지 않는다.

## 검증 규칙

`설계 검증`은 최소 다음을 확인한다.

- 센서 입력, 추론, 결과 단계 존재
- 모든 입력·출력 포트 연결
- 순환 연결 차단
- 단계별 최대 입력 수
- EdgeX Device와 DeviceResource의 현재 존재 여부
- Device Profile `valueType`과 다음 단계 입력 타입의 호환성
- 전처리·추론 대상 node 존재 여부
- `local_recent` 첫 처리 단계와 물리 source node 일치
- 모든 센서 입력에서 결과 단계까지 도달 가능 여부

Device가 `Available`이 아니거나 최신 Core Data Event가 `fresh`가 아니면 오류로 가장하지
않고 주의 항목으로 표시한다. 설계 자체가 올바르더라도 실제 runtime health를 대신하지 않는다.

## 초안 저장

`이 브라우저에 저장`은 versioned JSON을 브라우저 `localStorage`의
`edge-ai-service-design-v1` 키에 저장한다. 서버 DB, Git, EdgeX, Kubernetes에는 쓰지 않는다.
브라우저나 origin이 바뀌면 초안이 공유되지 않는다.

## 현재 미지원

- 설계 서버 저장과 사용자별 버전 관리
- 실제 Workflow Pod 생성·삭제·재시작
- 컨테이너 image, command, hostPath 입력
- EdgeX Profile/Device 생성·수정
- actuator command
- runtime migration, placement, offloading
- 카메라 RTSP 실행 경로
- 설계 결과의 운영 실행 이력

## 화면 설계 근거

다른 노드 편집기의 공식 문서에서 공통적으로 확인되는
`검색 가능한 palette → 넓은 중앙 canvas → 선택 기반 설정 panel` 구조를 현재 플랫폼
경계에 맞게 적용했다.

- [Node-RED Editor](https://nodered.org/docs/user-guide/editor/)와
  [Workspace](https://nodered.org/docs/user-guide/editor/workspace/):
  중앙 workspace, node palette와 sidebar, zoom control과 view navigator
- [React Flow built-in components](https://reactflow.dev/learn/concepts/built-in-components)와
  [Viewport](https://reactflow.dev/learn/concepts/the-viewport):
  pan·zoom·fit view, controls, minimap과 background
- [Rete.js Area extensions](https://retejs.org/examples/area-extensions/)와
  [Minimap](https://retejs.org/docs/guides/minimap/):
  선택, 이동, 확대·축소, snap과 minimap을 분리한 editor area
- [ThingsBoard Rule Engine](https://thingsboard.io/docs/paas/user-guide/rule-engine/):
  검색 가능한 node library, 중앙 rule-chain canvas, node 설정과 실행 전 구성 분리
- [Kubeflow Pipelines](https://www.kubeflow.org/docs/components/pipelines/concepts/pipeline/):
  명시적 입력·출력, directed graph, type checking, compile과 run의 분리

현재 구현은 이 패턴 중 palette, 포트, 속성, viewport, minimap, validation과 계획
미리보기만 사용한다. 범용 container workflow 실행이나 임의 플러그인 설치는 포함하지
않는다.

## 검증 명령

```bash
node --check edge-orch/state-aggregator/app/static/service-designer-model.js
node --check edge-orch/state-aggregator/app/static/service-designer-viewport.js
node --check edge-orch/state-aggregator/app/static/service-designer.js
node --test edge-orch/state-aggregator/tests/test_service_designer.js
python -m pytest -q edge-orch/state-aggregator/tests/test_api.py
```

브라우저 회귀는 390, 768, 1024, 1440px에서 문서와 캔버스의 가로 overflow가 없는지,
전체 보기·확대·축소·배경 이동·미니맵·단계 이동, grid snap·정렬선·`Shift` 축 고정·`Alt`
자유 배치, 드롭 전후 viewport 고정, 단계/설정 패널, 추가·삭제·검증·저장이 실제로 반응하는지
확인한다.
