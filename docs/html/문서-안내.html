문서가 따르는 원칙

  1. 실제 코드, root Kustomize, 테스트와 live read-only 증거를 우선한다.
  2. EdgeX는 물리 디바이스 inventory·schema·상태·telemetry의 권위다.
  3. KubeEdge/Kubernetes는 노드와 workload의 권위다.
  4. 대시보드는 두 권위의 값을 읽고 연결 관계와 판단 근거를 보여준다.
  5. 서비스 설계 dry-run, 제한된 Runtime 검증, 운영 traffic 전환과 범용 offloading을 서로

구분하고, 격리 시험이나 로컬 구현을 운영 완료 기능처럼 설명하지 않는다.

  1. 비밀번호, token, URL userinfo와 Secret 값은 문서에 기록하지 않는다.

문서 작성 ELI5 지침

처음 보는 독자도 이해해야 하는 기술·운영·KPI 문서는 필요할 때 ELI5(초등학생에게 설명하듯) 요약을 먼저 둔다. 짧은 일상 비유로 무엇이 문제였는지, 무엇을 바꿨는지, 그래서 무엇이 달라졌는지를 설명한 뒤, 같은 문서에서 정확한 측정 경계·수치·근거·한계를 확인할 수 있게 연결한다.

  • ELI5 요약은 공식 시험 결과, API 계약, 보안·안전 경계를 줄이거나 바꾸지 않는다.
  • 시간·원인·임계값의 관계가 핵심이면 읽기 전용 교육용 시뮬레이터를 추가할 수 있다.
  • 시뮬레이터는 교육용 모델과 실제 시험 결과를 분리해 표시하고, Kubernetes·EdgeX·장비의

상태를 바꾸거나 운영 시험을 대신하지 않는다.

예시는 400 ms 복구 체험하기에서 확인한다.

공개 문서와 내부 이력

문서 웹에는 시작하기, 연결 가이드, 운영, 정책·계약, 개발 참고 문서만 게시한다. docs/archive/와 docs/superpowers/는 과거 실험·설계 이력이며 공개 문서 생성과 검색에서 제외한다. 이력 원본은 비교와 재현에 필요하므로 저장소에는 보존한다.
