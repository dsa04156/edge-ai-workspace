대시보드 판단 정책

기본 원칙

대시보드는 서로 다른 권위의 신호를 하나의 “정상” 값으로 섞지 않는다. 각 상태에는 원본, 계산 기준과 reason을 함께 제공한다.

대상 권위
물리 Device/Profile/Device Service EdgeX Core Metadata
sensor telemetry와 freshness EdgeX Core Data Event/Reading origin
node와 workload Kubernetes/KubeEdge + Prometheus
AI 서비스 정의 Git ServiceDescriptor
AI 결과·알림 해당 서비스 API와 저장소

센서 디바이스 상태

조건 표시
adminState=LOCKED unavailable
operatingState=DOWN unavailable
상태 값 불명 degraded
UP + latest Event fresh available
UP + Event stale 또는 없음 degraded
Metadata/Core Data 조회 실패 unknown + 오류 reason

Kubernetes node placement나 dashboard polling 시각으로 sensor availability를 판정하지 않는다.

AI 서비스 상태

서비스는 다음 축을 독립적으로 표시한다.

  • workload/endpoint Ready
  • 필수 입력 connected·fresh·schema valid
  • input window와 시각 정렬
  • model ready와 model version
  • 결과 저장·알림 sink
  • 현재 실행 target과 최근 처리 비율

Device가 available이어도 필수 resource가 빠졌거나 모델이 준비되지 않으면 서비스는 degraded 또는 blocked다.

설비 이상과 자원 증강

두 판단은 독립이다.

설비 feature/anomaly 증가 → 설비 이상 알림
CPU·Memory·GPU + latency·backlog·throughput 압박 → 자원 증강 판단

anomaly_score는 자원 증강 evaluator에 사용하지 않는다.

Device1의 CPU·Memory·GPU 압박은 Prometheus node-exporter/GPU exporter의 최신 노드 스냅샷을 우선 사용한다. KubeEdge 엣지 노드에서 kubelet/cAdvisor가 제공되는 경우 컨테이너 사용량 프로파일을 보조 근거로 사용할 수 있지만, cAdvisor 부재만으로 최신 node-exporter 지표까지 무효화하지 않는다. latency·backlog·throughput은 AI 서비스 API, 센서 연결·freshness·schema는 EdgeX를 권위로 사용한다.

증강 권고

input_valid
AND model_ready
AND metrics_valid
AND resource_pressure 5분 지속
AND service_pressure(p95 4초 이상 OR backlog > 0 OR throughput 0.8/s 미만) 3분 지속
AND server1_endpoint_ready

증강 차단

  • sensor stale/disconnected
  • 필수 입력 누락 또는 schema 오류
  • model not ready
  • metric 부족 또는 stale
  • Server1 Pod/endpoint/model not ready
  • Server1 여유 자원 부족

차단 시 BLOCKED와 reason을 기록한다. 정상 전이는 NORMAL → OBSERVING → RECOMMENDED → AUGMENTED → COOLDOWN → NORMAL이다.

축소 조건

CPU·Memory 60% 미만, p95 latency 3초 미만, backlog 0이 15분 지속되고 마지막 증강 이후 15분 cooldown이 지났을 때만 축소 후보가 된다.

현재 기준은 약 1Hz인 테스트베드 입력의 최근 실측 정상값(throughput 약 0.99/s, processing p95 약 2.7초)에 20% cadence 여유와 latency hysteresis를 둔 값이다. 옥동 현장 입력 주기와 SLO가 확정되면 서비스별 descriptor 또는 운영 설정으로 분리한다.

운영 KPI

KPI 정의
registered devices Core Metadata Device 수
fresh devices latest Event origin이 freshness window 이내인 Device 수
operator focus degraded + unavailable Device 수
node online ratio unavailable이 아닌 node snapshot 비율
service ready workload·input·model·sink gate를 모두 통과한 서비스 수

누락 metric은 0으로 만들지 않고 N/A 또는 unknown으로 표시한다. 화면은 read-only 판단을 제공하며 Kubernetes·EdgeX mutation을 수행하지 않는다.
