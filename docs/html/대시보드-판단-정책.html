대시보드 판단 정책

1. 상태 원본

물리 센서 디바이스의 상태는 EdgeX Core Metadata와 Core Data만으로 판단한다.

  • inventory: Core Metadata /api/v3/device/all
  • 관리 상태: adminState, operatingState
  • 최신성: Core Data Event/Reading의 origin
  • 노드·Pod 상태: Kubernetes/Prometheus 보조 진단

KubeEdge DeviceStatus, node heartbeat, dashboard polling 시각을 physical telemetry authority로 사용하지 않는다.

2. Device 상태 계산

조건 connection_state overall_status 설명
adminState=LOCKED disconnected unavailable 운영 잠금
operatingState=DOWN disconnected unavailable Device Service/장비 다운
operatingState가 UP/ DOWN 아님 unknown degraded 상태 불명
UP + 최신 Event가 freshness window 이내 connected available 수집·저장 경로 관측
UP + 최신 Event stale connected degraded 수집 또는 입력 지연
UP + Event 없음 connected degraded 첫 Event 미수신

EDGEX_EVENT_FRESH_SECONDS가 freshness window다. 최신 Event 하나가 모든 resource가 최신이라는 뜻은 아니다.

3. KPI 정의

KPI 정의
registered_device_count Core Metadata에서 조회한 Device 수
edgex_connected_device_count connection_state=connected Device 수
device_service_available_count operatingState=UP Device 수
core_data_event_device_count Event가 하나 이상 있는 Device 수
fresh_core_data_event_device_count 최신 Event가 fresh인 Device 수
core_data_freshness_ratio fresh Device 수 / 전체 Device 수
operator_focus_count degraded + unavailable Device 수. workflow/SLA risk는 포함하지 않음
node_online_ratio unavailable이 아닌 Prometheus node 비율

device_telemetry_ratio가 사용되는 경우에는 telemetry가 설정된 Device 비율이지 freshness 비율이 아니다. 최신성은 core_data_freshness_ratio로 표시한다.

4. 노드와 서비스 판단

node_ready는 state-aggregator가 Prometheus 기반 node_health를 보고 계산한 표시값이다. Kubernetes Ready condition과 동일한 값으로 취급하지 않는다.

서비스는 Device가 available이어도 다음 조건을 따로 확인한다.

  • 입력 resource 전체가 fresh인가?
  • input window가 채워졌는가?
  • 모델 container가 Ready인가?
  • 결과 저장·알림 sink가 응답하는가?

5. 자원 풀 판정

자원 풀은 하나의 available 숫자로 서로 다른 권위 소스를 합치지 않는다.

분류 권위·판정 선택 가능 조건
데이터 입력 EdgeX Core Metadata Device/Profile과 Core Data 최신 Reading 필수 입력과 선언형 read-only binding이 모두 ready
노드 진단 Kubernetes/Prometheus node 관측 선택 자원이 아니며 배치 참고로만 표시
특수 실행 후보 state-aggregator registry의 자원 ID와 Kubernetes Pod/Service 관측 ID selector 일치, Pod Ready, Ready Service endpoint, free binding 증거가 모두 확인됨
실행 서비스 Kubernetes workload/endpoint 관측 자원 후보가 아니며 서비스 실행 증거로만 표시

같은 노드에서 일반 Pod가 실행 중이거나 이름에 gpu, redis, jetson 같은 단어가 있다는 이유만으로 특수 실행 자원으로 분류하지 않는다. endpoint 또는 binding 증거가 없으면 확인됨으로 올리지 않는다.

6. 우선 점검 순서

  1. Core Metadata 관측 실패 여부
  2. adminState/operatingState
  3. Core Data latest Event와 origin
  4. edge outbox pending/oldest age
  5. gateway·PostgreSQL 저장 결과
  6. AI service readiness와 입력 schema
  7. 노드·Pod resource 진단

대시보드와 운영 보조 agent는 이 순서를 제안만 하며 명령을 실행하지 않는다.
