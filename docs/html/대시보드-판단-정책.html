대시보드 판단 정책

권위와 표시 경계

대시보드는 물리 디바이스에 EdgeX를 단일 authority로 사용한다.

physical MQTT / Serial / Modbus / OPC-UA / RTSP device
  -> protocol-specific EdgeX Device Service
  -> EdgeX Event / Reading -> Core Data
  -> AI services / storage / state-aggregator / dashboard
  • inventory/state: EdgeX Core Metadata
  • telemetry/freshness: EdgeX Core Data Event와 typed Readings
  • command: 현재 비활성; 후속에는 해당 protocol adapter의 검증된 command 경로
  • node/workload 관찰: Kubernetes/KubeEdge와 Prometheus

Kubernetes/KubeEdge node placement는 별도 display-only diagnostic이다. node 미할당, Node NotReady 또는 mapper Pod 상태로 physical device availability를 강등하지 않는다. KubeEdge Device/DeviceModel/DeviceStatus, MapperFramework, mqttvirtual, mapper direct-write 값은 legacy이며 화면/API의 current physical status/control fallback으로 병합하지 않는다.

이 문서 아래의 virtual-temperature-001 payload는 현재 Serial 수직 슬라이스의 field 정규화 예시다. 물리 source arduino-001은 tag/protocol metadata에만 남는다. 값과 timestamp는 시점에 따라 달라지며 live 판정은 API를 다시 조회한다.

Inventory 표시

Core Metadata의 다음 필드를 device 응답과 detail에 표시한다.

  • name
  • profileName
  • serviceName
  • protocols (secret은 마스킹)
  • adminState
  • operatingState
  • tags/properties의 선택적 node diagnostic

Core Metadata에 없는 KubeEdge Device를 current physical inventory에 합치지 않는다. optional node diagnostic이 없는 것은 inventory 또는 availability 오류가 아니다.

Telemetry와 freshness

Core Data Event에서 다음 contract를 사용한다.

  • deviceName: inventory join key
  • sourceName: telemetry source/resource
  • origin: nanoseconds 단위 event 시각
  • typed Readings: valueType과 값

freshness 기준은 배포 설정의 EdgeX event threshold이며 최신 유효 Event의 nanosecond origin sample 시각에 적용한다. API 조회 시각, legacy DeviceStatus heartbeat 또는 mapper heartbeat로 대신하지 않는다. origin이 없거나 parse 불가하면 fresh로 추정하지 않고 degraded reason을 표시한다.

Telemetry detail은 deviceName과 sourceName, event origin, typed readings를 보존한다. storage graph나 AI 결과는 Core Data 이후 consumer 결과로 표시하며 physical source authority를 바꾸지 않는다.

Availability 판단 순서

State Aggregator와 dashboard는 다음 순서를 동일하게 사용한다.

  1. adminState=LOCKED이면 unavailable / disconnected.
  2. operatingState=DOWN이면 unavailable / disconnected.
  3. operatingState=UNKNOWN이면 degraded / unknown.
  4. operatingState=UP이고 최신 Core Data event가 freshness threshold 안이면 available.
  5. operatingState=UP이지만 event가 없으면 degraded (latest EdgeX event is missing).
  6. operatingState=UP이지만 최신 event가 stale이면 degraded (latest EdgeX event is stale).
  7. 알 수 없는 state나 잘못된 event origin은 degraded와 구체적인 reason으로 표시한다.

node/workload 상태는 별도 card/filter에서 관찰한다. node 장애는 AI workload나 service availability에는 영향을 줄 수 있지만 위 physical availability 계산에는 gate로 넣지 않는다.

KPI

physical-device KPI의 분모는 Core Metadata inventory다.

  • registered device count: Core Metadata Device 수
  • available/degraded/unavailable count: 위 availability 결과
  • event freshness ratio: fresh latest Event device 수 / Core Metadata Device 수
  • operating state breakdown: UP / DOWN / UNKNOWN
  • admin state breakdown: UNLOCKED / LOCKED
  • operator focus count: degraded/unavailable physical device 수. non-healthy node/workload는 별도 범주로 표시

legacy device_status_freshness_ratio, mapper readiness와 mapper direct-write freshness를 current physical-device KPI로 사용하지 않는다.

Explain Panel

Device 선택 시 최소 표시값은 다음과 같다.

  • overall status와 reason
  • Core Metadata name, profileName, serviceName
  • adminState, operatingState
  • latest Event sourceName, origin, age/freshness
  • typed Readings
  • protocol 요약
  • 선택적 node diagnostic

Explain Panel에서 EdgeX state/event 근거와 Kubernetes node/workload 근거를 섞어 하나의 physical availability reason으로 만들지 않는다.

API 응답 필드

/state/devices는 Core Metadata 필드, 계산된 availability/reason, latest Core Data event metadata를 포함한다. EdgeX 필드가 authoritative이며 legacy 값으로 누락을 보충하지 않는다.

/state/devices/{device_id}/telemetry는 선택 device의 최근 Core Data Events/Readings를 event origin 순서로 반환한다. typed value와 deviceName, sourceName, nanosecond origin을 보존한다. /state/virtual-resources는 자원증강형 가상디바이스를 Resource Profile 단위로 반환한다. 이 API는 가상 센서 생성 경로가 아니라 AI HAT/GPU/cache 같은 보강 실행 자원 상태 조회 경로다. 실행 인스턴스가 0개여도 registry에 있는 profile은 숨기지 않으며, 상태는 configured_not_running으로 표시한다.

/state/dashboard는 service resource observation 실패 시 dashboard 전체를 500으로 내리지 않는다. 이 경우 resource_profiles.observation_error에 원인을 남기고 service resource KPI만 0으로 degrade한다. /state/operator-assistant와 /state/operator-chat도 같은 degraded dashboard snapshot을 사용한다. resource observation 실패가 먼저 발생하면 chat은 Qwen 호출 전에 read-only degraded observation 응답을 반환한다.

전달 범위 해석

2026-07-21 기존 Agent/SQLite/HTTPS edge 경로와 sensehat-001 bootstrap은 퇴역했다. dashboard/aggregator는 중앙 Metadata와 Core Data를 authority로 유지하고 6개 가상 Device를 독립 inventory와 최신 Reading으로 표시한다. 각 행의 freshness는 해당 Device latest Event origin으로 계산한다.

Modbus, OPC-UA와 추가 I2C 장비는 각각 독립 adapter wave다. RTSP는 frame을 Workflow Pod가 직접 구독하는 별도 media wave다. 해당 adapter/profile, 실제 장비 연결, typed telemetry, dashboard consumer와 실제 배포를 검증하기 전에는 지원 완료 protocol로 표시하지 않는다. 현재 Serial 정상 경로의 성공을 다른 protocol이나 장애복구 완료 근거로 사용하지 않는다.
