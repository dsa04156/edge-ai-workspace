질문별 이동

알고 싶은 것 바로 볼 문서 코드·배포 근거
2차년도에 무엇을 실증하는가? ETRI 실행계획 옥동 서비스·월별 gate 표
센서 데이터는 어떤 경로로 저장되는가? 데이터 플레인 edgex/telemetry-plane/, edgex/k8s/
실제 현재 데모는 무엇인가? 현재 데모 경로 edgex/k8s/kustomization.yaml
어떤 센서·서비스가 연결되는가? 디바이스-서비스 연결 Core Metadata contract, state-aggregator
available/degraded를 어떻게 판단하는가? 상태 정책, 대시보드 판단 edge-orch/state-aggregator/app/service.py
장애 때 무엇을 확인하는가? 운영 Runbook pod, outbox, gateway, Core Data 점검
workflow와 오프로딩은 구현됐는가? 2차년도 설계 트랙 현재는 브라우저 dry-run/후속 설계

권위 경로 한 장 요약

물리 센서·PLC·장비
  -> Protocol Adapter
  -> edge-telemetry-agent (SQLite outbox)
  -> HTTPS/mTLS ingest gateway
  -> EdgeX Core Data / PostgreSQL
  -> state-aggregator / dashboard / AI consumer
  • Device/Profile, admin/operating state의 권위는 중앙 EdgeX Core Metadata다.
  • Event/Reading과 freshness의 권위는 중앙 EdgeX Core Data와 PostgreSQL이다.
  • 노드·워크로드 배치의 권위는 Kubernetes/KubeEdge지만 physical availability를 대신 판단하지 않는다.
  • 현재 센서 전송은 MQTT broker가 아니라 direct adapter와 HTTPS northbound다. MQTT-only 장비는 별도 검증 후 추가한다.
