현재 데모 흐름

실제 구현 경로

센서·PLC·장비
  -> Protocol Adapter
  -> canonical EdgeX v3 Event
  -> edge-telemetry-agent
       1) SQLite WAL에 먼저 commit
       2) HTTPS/mTLS gateway로 전송
  -> Core Data 영구 저장 확인
  -> state-aggregator API
  -> dashboard와 AI consumer

이 경로는 원시 텔레메트리 데이터 플레인과 edgex/telemetry-plane/src/telemetry_plane/에서 구현한다. 저장 성공 전에는 agent가 ACK를 반환하지 않는다.

현재 배포 단위

위치 배포 역할
중앙 edgex-system Core Keeper/Metadata/Data/Command, MessageBus, PostgreSQL, ingest gateway 등록·저장·중앙 수신
etri-dev0001-jetorn direct telemetry agent overlay Jetson edge 전송 fixture
etri-dev0003-raspi5 direct telemetry agent overlay Sense HAT 검증 fixture
default state-aggregator EdgeX 조회·상태 계산·dashboard API

운영 배포는 root edgex/k8s/kustomization.yaml에서 재현한다. MQTT broker, device-mqtt, MQTT-mode agent는 현재 root 배포에 없다.

장애별 관찰 지점

증상 먼저 볼 곳 해석
source admission 실패 adapter/agent 로그 canonical Event 형식·device 등록 문제
outbox 증가 agent PVC와 metrics 중앙 경로 단절, 데이터는 로컬에 보존
HTTPS 오류 gateway endpoint/TLS/auth 네트워크·인증·예약 상태 점검
Core Data 미저장 gateway reconciliation와 Core Data API persisted ACK 전 단계 실패
dashboard degraded Metadata state + 최신 Event timestamp node Ready만으로 복구 판정 금지

현재 fixture와 후속 승격

현재 Sense HAT fixture는 I2C publisher와 loopback adapter를 통해 typed telemetry를 만든다. Arduino Serial, Modbus, OPC-UA, MQTT-only 장비를 “지원 완료”로 표시하려면 해당 adapter, Profile/Device contract, 실제 또는 pseudo-device Event, 재연결과 장애 테스트가 모두 있어야 한다.

RTSP 영상은 Core Data로 보내지 않고 요청 시 Workflow Pod가 직접 구독한다. Core Data에는 상태·endpoint metadata·분석 결과만 남긴다.

실행 경계

dashboard의 workflow stage 구성, source bind, validation, execution plan preview는 브라우저 안 dry-run이다. Kubernetes apply/delete/restart, EdgeX mutation, command publish, runtime migration/offloading은 현재 이 흐름에 포함하지 않는다.
