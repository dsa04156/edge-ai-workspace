현재 데모 흐름

한 줄 요약

현재 데모의 목표 경로는 Jetson·Raspberry Pi의 Protocol Adapter와 SQLite telemetry agent에서 HTTPS gateway·Core Data·PostgreSQL까지 이어지고, state-aggregator와 대시보드가 중앙 inventory·telemetry를 소비하는 수직 슬라이스다.

목표 운영 경로

물리 센서 / PLC / 장비
  -> Protocol Adapter -> edge-telemetry-agent -> SQLite outbox
  -> HTTPS/mTLS ingest gateway
  -> EdgeX Core Data -> PostgreSQL
  -> Application Service / AI consumer / state-aggregator / dashboard

중앙 ingest gateway, EdgeX Core Keeper, Core Metadata, Core Data, Core Command, 내부 MessageBus, PostgreSQL은 etri-ser0002-cgnmsb에 한 세트만 배치한다. edge telemetry agent는 etri-dev0003-raspi5와 etri-dev0001-jetorn에 direct mode로 각각 배치하고 노드별 SQLite PVC와 identity를 분리한다.

운영 배포의 Kustomize 진입점은 root edgex/k8s/kustomization.yaml이다. HTTPS ingest gateway, edge telemetry agent, SQLite outbox와 edgex/k8s/base/ overlays가 현재 구현·배포 경로다.

권위와 Device 등록

물리 디바이스의 inventory와 관리 상태는 EdgeX Core Metadata가 소유한다. Device Profile과 Device는 사전 등록하며, Protocol Adapter가 endpoint 연결과 profile 기반 Event 정규화를 담당하고 agent가 durable 전달을 담당한다. 현재 command 실행은 비활성이다.

영역 현재 authority 핵심 근거
inventory / 관리 상태 EdgeX Core Metadata name, profileName, serviceName, protocols, adminState, operatingState, tags/properties
telemetry / freshness EdgeX Core Data Event deviceName, sourceName, nanosecond origin, typed Readings
node / workload Kubernetes / KubeEdge node와 workload의 배치·상태 관찰

KubeEdge/Kubernetes는 물리 Device inventory, availability, telemetry, command의 원본이 아니다. node_name은 화면에 표시할 수 있는 선택적 placement 진단 정보이며 physical availability의 gate가 아니다.

/state/devices는 EdgeX 값을 dashboard용 snake_case로 제공한다. 현재 확인 필드는 source=edgex, name, profile_name, device_service_name, protocol_names, admin_state, operating_state, connection_state, device_service_available, latest_event_timestamp, latest_readings, telemetry_freshness, 선택적 node_name이다.

교체 가능한 direct 검증 fixture

현재 sensehat-001은 I2C publisher → loopback HTTP → agent → SQLite → HTTPS → Core Data 경로를 확인하는 교체 가능한 fixture다. Jetson에는 direct agent와 인증 heartbeat 기반만 추가하며 Arduino Serial adapter, Metadata Device/Profile과 Event는 아직 연결하지 않는다. 현재 EdgeX 배포에는 Jetson MQTT agent, device-mqtt, edge-local broker가 없다.

2026-07-14 UNO 네 source와 2026-07-15 Sense HAT 여섯 source의 typed Event/Reading을 확인했다. 이 증거는 장비·profile·Reading 계약의 근거이며 중앙 server2 topology와 대시보드 조회 전환의 완료 증거가 아니다.

1차 수직 슬라이스는 SQLite offline replay와 persisted ACK를 포함한다. Serial, Modbus, OPC-UA와 추가 I2C adapter는 profile·실장비·typed telemetry 증거를 확보하기 전에는 지원 완료로 표시하지 않는다. RTSP frame은 Workflow Pod가 직접 구독하는 별도 경로다.

Service binding과 workflow/augmentation 경계

service binding은 EdgeX Device, Device Service, telemetry source와 서비스 데모 consumer의 관계를 dashboard에서 설명하는 범위다. backend가 binding metadata를 제공하면 frontend는 device 이름을 다시 하드코딩하지 않는다.

edge-orch/workflow-designer/와 augmentation 표면은 read-only 또는 browser 상태의 dry-run planning 범위다. stage 구성, device/resource bind/release, validation, execution-plan preview는 표시할 수 있지만 Kubernetes apply/delete/restart, EdgeX metadata/state mutation, MQTT command publish, actuator command, workload migration/offloading을 실행하지 않는다.

제외한 legacy 경로

다음은 현재 물리 integration의 authority나 fallback이 아니다.

  • KubeEdge Device/DeviceModel/DeviceStatus와 DeviceStatus freshness
  • MapperFramework, mqttvirtual, mapper readiness
  • mapper direct-to-Influx latest sample
  • factory/devices/{device-name}/command, factory/devices/{device-name}/heartbeat, mappers/mqttvirtual/ legacy topic/path

이 자료와 경로는 migration 비교 또는 과거 test/integration 자료로만 이름을 남긴다. current physical health는 EdgeX Core Metadata 관리 상태와 Core Data 최신 Event freshness로만 판단한다.
