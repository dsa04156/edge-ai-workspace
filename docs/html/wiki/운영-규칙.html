위키 운영 규칙

목적

docs/wiki/는 KubeEdge 기반 혼합 디바이스 엣지 AI PoC 문서를 위한 LLM 유지형 지식 지도다. 기존 docs/*.md 원본문서를 대체하지 않고, 여러 문서에 흩어진 판단 기준을 주제별로 압축해 연결한다.

계층

계층 경로 소유 규칙
원본 문서 docs/*.md, docs/ops/*.md, 필요한 프로젝트 README 사람과 구현 작업 source of truth로 유지한다.
Wiki docs/wiki/*.md LLM이 유지하고 사람이 검토 요약, 연결, 충돌 표시, 탐색 지도를 담당한다.
운영 규칙 docs/wiki/운영-규칙.md, 루트 AGENTS.md 사람과 에이전트 문서 갱신 방식과 금지 표현을 고정한다.
HTML 보기 docs/html/ 생성 산출물 python3 scripts/build-docs-html.py로 재생성한다. 직접 편집하지 않는다.

문서 유형

유형 파일 역할
색인 지식-지도.md 위키와 원본문서의 첫 진입점
로그 변경-기록.md 수집, 질의, 점검 변경 이력
합성 문서 <주제>.md 여러 원본문서를 하나의 주제로 요약
개념 문서 <개념>.md 정의, 경계, 관련 문서, 근거 문서 정리
공백 문서 <주제>-공백.md 충돌, 누락, 확인 필요 사항 정리

유지 Workflow

Ingest

원본문서가 바뀌거나 새 문서가 추가되면 다음 순서로 처리한다.

  1. docs/wiki/지식-지도.md를 먼저 읽는다.
  2. 변경된 원본문서를 읽는다.
  3. 영향을 받는 wiki 문서를 찾는다.
  4. 영향을 받은 wiki 문서만 수정한다.
  5. docs/wiki/지식-지도.md의 링크와 설명을 갱신한다.
  6. docs/wiki/변경-기록.md에 변경 이력을 추가한다.
  7. python3 scripts/build-docs-html.py로 HTML을 재생성한다.

로그 형식:

## [YYYY-MM-DD] ingest | 짧은 제목

- 근거: `docs/path.md`
- 갱신: `docs/wiki/page.md`
- 메모: 변경 의미 한 문장

Query

문서 질문에 답할 때는 다음 순서로 읽는다.

  1. docs/wiki/지식-지도.md
  2. 관련 wiki 문서
  3. 세부 명령, API, 정책 문구가 필요할 때만 원본문서

질문 답변에서 재사용할 만한 합성이 생기면 위키에 반영하고 변경-기록.md에 질의 항목을 남긴다.

Lint

주기적으로 다음을 점검한다.

  • 지식-지도.md에서 연결되지 않은 고아 문서
  • 끊어진 링크
  • 중복 요약
  • docs/프로젝트-범위.md와 충돌하는 주장
  • legacy workflow/offloading/agent-assisted planning을 현재 기능처럼 보이게 하는 표현
  • 운영 runbook으로 이어지지 않는 운영 설명

수정이 있으면 변경-기록.md에 점검 항목을 남긴다.

프로젝트 표현 규칙

유지할 표현:

  • 서비스 데모 우선
  • 디바이스-서비스 연결 구조
  • 통합 운영 가시화
  • 실공장 기반 PoC
  • 현장 적용성
  • 생산성 향상 효과
  • 단계적 확장

피할 표현:

  • 완전 자율형 오케스트레이션
  • LLM이 전체 제어를 수행
  • 동적 워크플로우 전체 구현 완료
  • runtime replanning 구현 완료
  • placement/offloading이 현재 데모 경로인 것처럼 보이는 표현
  • agent-assisted planning이 현재 control plane인 것처럼 보이는 표현

물리 디바이스 상태와 텔레메트리 표현은 다음 기준을 지킨다.

  • 물리 디바이스 inventory와 schema는 중앙 EdgeX Core Metadata가 권위다.
  • 원시 텔레메트리는 protocol별 EdgeX Device Service에서 Event/Reading으로 표준화되어 Core Data·PostgreSQL에 저장된다. 2026-07-21 current target은 Jetson device-serial-jetson과 Raspberry Pi device-sensehat-raspi, 가상 Device 각 6개다. Modbus/OPC-UA와 다른 I2C 장비는 별도 검증 전까지 미지원이다.
  • KubeEdge Device/DeviceModel/DeviceStatus와 MapperFramework는 레거시 물리 연동 경로이며 병행 plane이나 fallback으로 사용하지 않는다.
  • adminState, operatingState, Device Service 상태, 최신 Event freshness를 함께 보고 availability를 판단한다.
