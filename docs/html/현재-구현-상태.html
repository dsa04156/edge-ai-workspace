프로토콜 독립형 디바이스 발견·등록 현재 구현 상태

기준일: 2026-07-30 판정 기준: 실제 코드, 테스트, edgex/k8s render “구현”과 “실장비 운영 검증”을 구분한다.

요약

Serial은 PTY 후보 발견부터 승인, 검증 Runtime 재사용, EdgeX Profile/Device idempotent 등록, Core Data 첫 Event 확인까지 자동화된 코드와 fake backend 통합 테스트가 있다. 2026-07-24 실제 Jetson Arduino stable 후보를 운영자가 승인했고 기존 Device Service Runtime을 재사용해 aggregate Device arduino-75035303230351e0d171-57fc03a907의 EVENT_CONFIRMED와 Core Data Event까지 live 확인했다.

I2C는 allowlist bus/address와 여러 read-only identity register를 하나의 물리 보드 identity로 묶는 composite probe까지 구현했다. 2026-07-28 etri-dev0003-raspi5의 Sense HAT v1에서 0x1c=0x3d, 0x5c=0xbd, 0x5f=0xbc, 0x6a=0x68을 확인해 후보를 승인했고, 기존 device-sensehat-raspi, Profile etri-sensehat-gyroscope, Device imu-sensehat-gyroscope-01을 재사용한 뒤 신규 Core Data Event로 EVENT_CONFIRMED까지 live 검증했다. 이어서 등록 연결을 decommission하고 다음 30초 탐색 주기에 같은 candidate ID가 PENDING_APPROVAL로 자동 복귀하는지 확인했으며, 재승인 뒤 다시 EVENT_CONFIRMED가 됐다. 기존 EdgeX Device 13개와 Sense HAT Device 6개는 삭제되거나 중복 생성되지 않았다.

같은 날 일반 Discovery DaemonSet의 Serial-only passive inventory를 dev0003까지 확장했다. Raspberry Pi에 연결된 CH340 계열 USB Serial 장비를 /dev/serial/by-id/usb-1a86_USB_Serial-if00-port0(VID/PID 1a86:7523)에서 후보 candidate-fb7190f...로 반복 관측했다. 이후 exact Raspberry Pi hardware binding, mpu6050-imu-v1 Profile/parser, Controller 배포 template과 MPU6050 6축 Float64 JSON-line 처리를 구현했다. exact 후보 승인부터 Runtime, Profile/Device, first Event까지의 fake backend 통합 테스트는 통과했다. live 승인도 실행했지만 당시 Serial telemetry가 없어 첫 Event timeout으로 FAILED가 됐고 Controller가 자신이 만든 동적 Runtime을 rollback했다. 이후 보드를 ESP32-D0WD-V3 revision 3.1로 식별하고 운영 firmware를 compile·flash해 115200 baud 상태 JSON까지 확인했다. firmware는 MPU6050을 1초마다 재탐색하지만 ESP32의 일반 I2C pin pair와 Raspberry Pi bus 1에서 0x68, 0x69 모두 ACK가 없었다. 2026-07-30 MPU6050 실물을 분리했고 후보는 STALE/ignored 감사 이력으로 정리했으며 동적 Runtime은 없는 상태다. Profile/parser/template과 자동 테스트는 재연결 실험을 위한 dormant 지원 코드로 남기되 현재 연결 장비나 완료된 telemetry 경로로 표시하지 않는다. Serial Agent와 I2C Agent가 같은 node를 보고해도 서로의 후보를 STALE 처리하지 않도록 report에 scannedProtocols scope를 추가했고, Sense HAT 후보는 계속 EVENT_CONFIRMED를 유지했다. MQTT 자기등록 subscriber는 아직 없다. 대신 공식 device-mqtt:4.0.2 immutable image, 노드별 network binding, allowlist broker/topic/QoS Runtime 설정, Device command topic/resource와 bundled edgeai-mqtt-temperature-v1 Profile을 묶은 개발용 웹 연결 package를 구현했다. 대시보드의 검증하고 연결 한 번으로 validation, Runtime 재사용/배포, Profile/Device readback과 first Event 확인을 진행한다. anonymous broker/publisher는 root 운영 render 밖의 선택적 development fixture다. 이 경로는 자동 테스트와 manifest render를 통과했으며 실제 클러스터 연결 검증은 아래 실장비/환경 검증 항목에 별도로 표시한다. Modbus는 네트워크 discovery 없이 운영자가 선언한 고정 개발 endpoint에 한해 공식 EdgeX device-modbus:4.0.2 Runtime, read-only Profile, Modbus TCP simulator와 승인 Saga를 연결했다. 2026-07-28 Unit 2 가상 온도 센서를 승인해 Controller-owned Runtime, Core Metadata Device, 1초 AutoEvent, Core Data 저장과 대시보드 available 상태까지 live 확인했다. 개발용 Modbus endpoint simulator Deployment는 root 운영 render 밖에 남아 있지만 해당 Controller Device Service Runtime은 검증 뒤 퇴역했으며 현재 live EdgeX inventory에는 포함되지 않는다. 이는 개발 simulator 수직 경로의 과거 증거이며 실제 PLC 지원 완료가 아니다. OPC-UA와 ONVIF는 확장 contract와 명시적 not implemented 상태만 있다.

대시보드는 전역 간편 보기/전체 보기 토글을 제거했다. 기본 화면에는 핵심 상태만 두고 기술 KPI, 서비스 연결 근거, 후보 세부정보와 개별 EdgeX Device는 클릭해 펼친다. 등록 목록은 live Core Metadata의 13개 Device identity를 유지하면서 arduino-001과 sensehat-001 물리 source별 카드로 묶는다. 375px, 768px, 1024px 실제 브라우저 viewport에서 문서 가로 overflow와 잘린 텍스트가 없음을 확인했다.

보안·운영 주의

  • Controller base는 ADAPTER_AUTH_MODE=external로 fail-closed한다. 현재 root testbed만

overlays/development/adapter-management에서 development-mock을 적용하며 운영 profile이 아니다.

  • Catalog API는 read-only이며 임의 image 실행 API가 없다.
  • 일반 edge-device-discovery는 dev0001/dev0002/dev0003에서 비권한 상태로 read-only

/dev, /sys Serial inventory만 수행한다. dev0003의 edge-device-discovery-i2c는 container device cgroup 때문에 privileged 예외가 필요하지만 non-root UID/GID, exact /dev/i2c-1 CharDevice 하나와 보조 group 988만 사용한다. 이 값은 현재 testbed host 권한에 종속되며 다른 노드에 그대로 복사하지 않는다.

  • Controller SQLite는 1Gi RWO PVC를 사용해 단일 replica 기준이다. 다중 replica HA를

활성화하지 않는다.

  • SQLite PVC를 삭제하면 candidate, 전이 이력, 승인, Saga와 audit를 복구할 수 없다.
  • Service는 ClusterIP 객체와 DNS를 사용하지만 고정 ClusterIP 우회는 없다.
  • EdgeMesh manifest는 수정하지 않았다.
  • 현재 PoC의 /management/* mutation은 browser 관리자 token이나 Authorization

header를 요구하지 않는다. 기능 플래그, allowlist 검증, Idempotency-Key와 내부 HMAC은 유지하지만 이는 운영자 인증이 아니다. 접근이 제한된 개발 테스트베드 경계이며 운영 노출 전 별도 사용자 인증·인가가 필요하다.
