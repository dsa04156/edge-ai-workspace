서비스 데모 상태

@@INLINE0@@의 입력 계약은 okdong.pump-motor.telemetry/v1이다. 현재 Arduino raw 입력은 플랫폼 연결 기준선이며 옥동 설비 단위가 아니다.

  • 가속도 X/Y/Z는 같은 origin으로 frame을 구성한다.
  • 온도는 허용 시간차 안의 가장 가까운 sample만 결합한다.
  • 진동 20개, 온도 10개 window와 30개 warm-up을 사용한다.
  • 현재 backend는 학습된 고장 분류기가 아닌 online-baseline이다.
  • Server1 후보는 같은 기준선의 CUDA backend이며 HAMi GPU 할당과 CUDA probe를 readiness에 포함한다.
  • 결과와 alert transition은 서비스 소유 SQLite에 idempotent하게 저장한다.

실제 설비 고장 분류 정확도와 생산성 개선 효과는 옥동 현장 데이터로 별도 검증해야 한다.

남은 핵심 작업

  1. 옥동 PLC·MES·센서 endpoint와 field map 확정
  2. 생산품질 label과 펌프·모터 모델 입력·출력 확정
  3. 실제 장애·고장·복구 시나리오 반복 검증
  4. 승인 기반 Server1 경로의 운영 책임과 rollback 검증
  5. 테스트베드 무인증 관리 BFF의 사용자 인증·인가 추가

세부 포함·제외 기준은 프로젝트 범위를 따른다.
