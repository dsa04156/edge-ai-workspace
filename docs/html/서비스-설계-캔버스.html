서비스 설계 캔버스

목적

state-aggregator 대시보드의 서비스 설계는 현재 EdgeX 센서 입력을 전처리·추론·결과 단계에 연결하고 실행 전에 계약을 확인하는 브라우저 기반 설계 프로토타입이다.

이 화면은 Kubernetes workload를 만들거나 EdgeX Metadata를 변경하는 실행 도구가 아니다. 현재 서비스 데모인 sensor-anomaly-demo를 동적 workflow로 대체하지도 않는다.

상단 3축 데모는 기존 고정 sensor-anomaly-demo의 가속도 branch 계약을 캔버스에서 검토할 수 있게 불러온다. 이 예시는 복합 센서 소스 구현에서도 진동 branch로 그대로 유지된다.

가속도 X ─┐
가속도 Y ─┼─> 3축 벡터 크기 -> 온라인 이상 점수 -> 대시보드 결과
가속도 Z ─┘

현재 EdgeX inventory에 virtual-acceleration-x/y/z-001과 각 numeric resource가 있고 세 Device가 같은 물리 노드에 연결되어 있으면 세 입력과 처리 노드를 해당 Jetson에 자동 바인딩한다. 한 축이라도 없으면 빈 입력을 꾸며내지 않고 설계 검증 오류로 남긴다. 이는 실제 Deployment를 새로 만들거나 기존 데모를 실행하는 버튼이 아니다.

복합 점수 예시는 3축 진동과 같은 물리 노드의 보조 센서를 함께 사용하는 설계 계약을 불러온다. 현재 EdgeX inventory에 Jetson 가속도 X/Y/Z와 온도처럼 가속도가 아닌 numeric resource가 있으면 네 입력을 자동 선택한다. 같은 노드에서 네 입력을 찾지 못하면 다른 노드나 임의 값을 섞지 않고 바인딩되지 않은 입력과 검증 오류를 남긴다.

가속도 X/Y/Z -> 진동 특징(RMS·Peak·Kurtosis 계약) -> 진동 점수 ─┐
온도 등 보조 입력 -> 구간 특징(평균·표준편차·변화량 계약) -> 센서 점수 ─┼-> 종합 점수 -> 대시보드 결과
                                                                    ┘

종합 점수는 최소 두 숫자 점수를 입력받아 가중 평균 또는 최댓값으로 결합하는 설계다. 가중 평균을 선택하면 연결된 점수 단계별 가중치를 설정하며, 음수이거나 합이 0인 가중치는 검증에서 거부한다. 같은 시간 구간의 점수가 모두 필요하다는 누락 정책도 설계에 저장한다. 이 예시는 브라우저 dry-run이며 캔버스 graph를 임의 실행하거나 배포한다는 뜻이 아니다. 다만 2026-08-03의 고정 sensor-anomaly-demo 소스는 이 예시와 같은 진동·온도 branch, 2초 이내 nearest-origin 정렬, 개별 online feature 점수와 0.7/0.3 가중 종합 점수를 명시적으로 구현했다. 이는 하나의 고정 서비스 구현이며 범용 workflow runtime이 아니다. 2026-08-03에는 이 고정 서비스의 immutable ARM64 image rollout, 실제 가속도·온도 readback, 중앙 BFF와 dashboard 표시까지 검증했다. 실제 장치 움직임 anomaly와 범용 workflow 실행은 여전히 별도 범위다.

현재 데이터 경계

EdgeX Core Metadata
  ├─ Device --------------------------┐
  └─ Device Profile / DeviceResource -┤
                                      v
state-aggregator read-only API -> 서비스 설계 캔버스
                                      |
                                      +-> 브라우저 localStorage 초안
                                      +-> validation
                                      +-> dry-run 실행 계획 미리보기

사용 API:

API 용도
GET /state/dashboard 현재 EdgeX Device 상태와 KubeEdge/Kubernetes node 관측
GET /state/device-profiles Device Profile의 안전한 읽기 전용 DeviceResource 계약

/state/device-profiles는 resource name, valueType, readWrite, units만 노출한다. protocol address나 DeviceResource attributes는 브라우저 설계 입력으로 전달하지 않는다.

서비스 카탈로그와 단계

왼쪽 패널은 고정된 단계 종류 네 개가 아니라 현재 설계에서 사용할 수 있는 서비스 계약을 카테고리별로 표시한다.

카테고리 서비스
데이터 입력 엣지 최근 데이터, 중앙 저장 데이터
전처리 그대로 전달, 표준화, 이동 평균, 벡터 크기, 진동 특징 추출, 구간 특징 추출
AI 추론 온라인 이상 점수, 임계값 판정, 센서 이상 점수
점수 결합 가중 평균 또는 최댓값 기반 종합 점수
결과 대시보드 결과

EdgeX 입력 항목의 입력 N은 현재 /state/dashboard Device와 /state/device-profiles DeviceResource를 조합해 실제 선택할 수 있는 Device 수다. 선택 가능한 입력이 없으면 해당 입력 서비스는 비활성화한다. 전처리·추론·결과의 설계용 표시는 현재 캔버스에 계약이 있다는 뜻이며 Pod 실행 중이나 배포 완료 상태가 아니다. 검색은 서비스 이름·설명·카테고리를 함께 좁힌다.

서비스를 누르면 해당 연산이나 알고리즘이 미리 설정된 단계가 추가된다. EdgeX 입력은 현재 numeric resource 후보를 함께 선택하되 운영자가 오른쪽 설정 패널에서 다른 Device와 DeviceResource로 바꿀 수 있다. 임의 image나 command를 서비스 카탈로그에 추가하는 브라우저 경로는 없다.

단계 현재 설정 출력
센서 입력 EdgeX Device, DeviceResource, 데이터 접근 방식 Profile의 valueType으로 계산한 타입
전처리 기본 수치 연산 또는 구간 특징 계약, 실행 노드와 윈도우 크기 숫자, 입력과 같은 타입 또는 feature_vector
추론 온라인 점수·임계값 또는 센서 특징 점수 계약, 실행 노드, 임계값 숫자 또는 Boolean
점수 결합 결합 방식, 실행 노드, 누락 정책, 입력별 가중치 숫자
결과 대시보드 결과 최종 결과

단계 추가는 검색 가능한 왼쪽 패널에서 수행하고, 캔버스의 출력 포트와 입력 포트를 차례로 눌러 연결한다. 삭제·입출력 포트를 제외한 단계 박스 전체를 드래그해 배치하며 연결선을 두 번 누르면 삭제한다. 선택한 단계의 설정은 캔버스 위 오른쪽 패널에서 변경하고 닫을 수 있다.

캔버스는 고정 크기 작업 좌표계와 별도 viewport를 사용한다.

  • 전체 보기와 가운데 ◎ 버튼: 현재 graph를 보이는 영역에 맞춤
  • −/＋와 마우스 휠: 캔버스 중심 또는 pointer 위치 기준 확대·축소
  • 빈 배경 드래그: 캔버스 이동
  • 미니맵: 전체 graph와 현재 보이는 구간 확인, 선택 위치로 이동
  • 서비스 버튼: 서비스 카탈로그 열기·닫기
  • 단계 선택: 현재 배율을 유지하면서 설정 패널에 가리지 않도록 선택 노드만 이동
  • 단계 박스 전체 드래그: 삭제·입출력 포트를 제외한 표면을 3px 이상 이동하면 박스가 pointer를 1:1로 따라가며, 확대·이동 상태에서도 박스 전체를 현재 보이는 캔버스 안에 유지
  • 정렬: 다른 단계의 같은 모서리·중앙에 가까우면 정렬선을 미리 표시하고 놓을 때만 해당 선에 맞춤
  • Shift+드래그: 처음 위치를 기준으로 가로 또는 세로 한 축에 고정
  • Alt+드래그: 정렬선 snap 없이 완전히 자유롭게 배치
  • 방향키: 선택 단계를 1px 이동, Shift+방향키는 24px 이동

드래그가 끝난 뒤 발생하는 click은 다시 선택 동작으로 처리하지 않으므로 viewport가 자동 이동하거나 단계가 화면에서 튀지 않는다. 설정 패널은 드래그 도중 열지 않고 단계를 누를 때만 연다. 정렬선은 드래그 중에만 표시한다.

드래그 중 박스는 translate3d로 즉시 반영한다. 연결선 전체와 미니맵 전체를 매 pointermove마다 다시 만들지 않고, 이동한 단계에 연결된 선과 미니맵 사각형만 animation frame 단위로 갱신한다. 전체 graph 반영은 놓는 순간 한 번 수행한다. EdgeX inventory나 Device Profile 응답이 드래그 도중 도착해도 상태만 보관하고 캔버스 전체 갱신은 놓은 뒤 한 번 수행하므로 포인터 캡처와 이동 위치를 유지한다.

브라우저 너비가 좁으면 서비스 카탈로그와 설정 패널은 캔버스 위 overlay로 열리며 문서나 캔버스에 별도 가로 scrollbar를 만들지 않는다. 작은 화면의 전체 보기는 흐름 전체를 확인하는 overview이므로 세부 편집 시 확대·이동 또는 미니맵을 사용한다.

데이터 접근 방식

엣지 최근 데이터

local_recent 설계는 같은 물리 노드의 Device Service Local Data API와 bounded memory cache를 사용하는 경로다. 실제 실행 경로를 아직 만들지는 않지만, 설계 검증은 첫 처리 단계가 해당 Device의 node_name과 같은지 확인한다.

cache는 최근 10분·Device/resource별 최대 10,000 sample이며 Pod 재시작 시 사라진다. SQLite outbox나 중앙 장애 replay 저장소가 아니다.

중앙 저장 데이터

core_history 설계는 중앙 EdgeX Core Data/PostgreSQL의 Event/Reading을 사용하는 경로다. 캔버스는 조회 방식을 설계에 기록할 뿐, 현재 브라우저에서 telemetry를 실행 입력으로 프록시하거나 PostgreSQL에 직접 연결하지 않는다.

검증 규칙

설계 검증은 최소 다음을 확인한다.

  • 센서 입력, 추론, 결과 단계 존재
  • 모든 입력·출력 포트 연결
  • 순환 연결 차단
  • 단계별 최대 입력 수
  • 진동 특징은 숫자 입력 정확히 3개, 점수 결합은 숫자 점수 최소 2개
  • 가중 평균의 입력별 가중치가 0 이상이고 전체 합이 0보다 큰지 확인
  • EdgeX Device와 DeviceResource의 현재 존재 여부
  • Device Profile valueType과 다음 단계 입력 타입의 호환성
  • 전처리·추론 대상 node 존재 여부
  • local_recent 첫 처리 단계와 물리 source node 일치
  • 모든 센서 입력에서 결과 단계까지 도달 가능 여부

Device가 Available이 아니거나 최신 Core Data Event가 fresh가 아니면 오류로 가장하지 않고 주의 항목으로 표시한다. 설계 자체가 올바르더라도 실제 runtime health를 대신하지 않는다.

초안 저장

이 브라우저에 저장은 versioned JSON을 브라우저 localStorage의 edge-ai-service-design-v1 키에 저장한다. 서버 DB, Git, EdgeX, Kubernetes에는 쓰지 않는다. 브라우저나 origin이 바뀌면 초안이 공유되지 않는다.

다른 노드 편집기의 공식 문서에서 공통적으로 확인되는 검색 가능한 palette → 넓은 중앙 canvas → 선택 기반 설정 panel 구조를 현재 플랫폼 경계에 맞게 적용했다.

  • React Flow built-in components와

  • Rete.js Area extensions와

검색 가능한 node library, 중앙 rule-chain canvas, node 설정과 실행 전 구성 분리
