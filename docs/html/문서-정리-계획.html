문서 정리 계획

이 문서는 docs/프로젝트-범위.md와 docs/저장소-구조.md를 기준으로 최신 문서, 탐색용 요약, 운영 절차, 설계 이력, 보관 자료의 노출 순서를 정한다. 원본 Markdown의 한국어 파일명·제목 통일, 진입점 단순화, 검색 노이즈 축소를 우선하며 원본 삭제는 별도 승인 대상으로 둔다.

정리 원칙

  1. 원본 Markdown은 계속 기준 자료로 유지한다.
  2. Markdown 파일명과 최상위 제목은 한국어로 작성하되 EdgeX, KubeEdge, MQTT, API 같은 고유 기술명은 유지한다.
  3. 정적 HTML은 scripts/build-docs-html.py로 재생성되는 보기용 산출물로 두고 직접 편집하지 않는다.
  4. docs/wiki/는 질문과 탐색의 첫 진입점으로 둔다.
  5. 최신 기준 문서는 현재 시스템 구축 목표와 직접 연결되는 원본문서로 둔다.
  6. 운영 문서는 운영 점검, 장애 대응, 데모 실행에 필요한 원본문서로 둔다.
  7. superpowers/는 설계·구현 계획 이력이며 현재 완료 상태의 근거로 사용하지 않는다.
  8. 보관 문서는 과거 연구·논문·레거시 오케스트레이션 맥락으로만 둔다.
  9. 중복 문서는 최신 기준 문서로 내용을 통합한 뒤 원본의 삭제 여부를 별도로 승인한다.
  10. 워크플로·오프로딩·에이전트 보조 계획 계열은 현재 방향으로 보이지 않게 분리한다.

레거시·보관 자료 처리

레거시 코드의 README와 docs/archive/ 문서는 현재 PoC 판단 기준이 아님을 명시한다. 문서 파일명과 제목은 한국어로 통일하되, 내용은 이력 보존을 위해 임의로 현재 아키텍처에 맞춰 고쳐 쓰지 않는다.

처리 기준:

  • 최신 정책과 구조는 프로젝트-범위.md, 원시-텔레메트리-데이터-플레인.md, 저장소-구조.md에만 반영한다.
  • 과거 문서의 잘못된 현재형 표현은 보관 안내로 차단하고, 역사적 사실 자체는 보존한다.
  • 중복 문서와 대형 로그는 기본 검색에서 제외한다.
  • 원본 삭제는 링크·인용·실험 재현 필요성을 확인한 뒤 별도로 승인한다.
