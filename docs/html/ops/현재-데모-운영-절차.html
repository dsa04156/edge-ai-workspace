현재 서비스 데모 운영 절차

목적

이 문서는 엣지 Device Service → 중앙 EdgeX MessageBus → Core Data·PostgreSQL → state-aggregator·대시보드 경로를 읽기 중심으로 점검한다. telemetry의 EdgeX 라벨 자원 전체 재생성이 필요하면 중앙-메시지버스-재구축-절차.md를 사용하고 별도 승인을 받는다. 공유 namespace 자체는 삭제하지 않는다.

현재 배치 기준

구분 기준
namespace telemetry
중앙 노드 etri-ser0002-cgnmsb
Jetson etri-dev0001-jetorn
Raspberry Pi etri-dev0003-raspi5
중앙 workload Core Keeper, Core Metadata, Core Data, Core Command, MessageBus, PostgreSQL
Jetson workload edgex-device-mqtt
Raspberry Pi workload edgex-device-mqtt-sensehat
현재 프로토콜 MQTT
운영 배포 진입점 edgex/k8s/kustomization.yaml

데이터 흐름

arduino-001 / sensehat-001
  -> 각 노드의 southbound MQTT endpoint
  -> EdgeX Device MQTT
  -> 중앙 edgex-messagebus:1883
  -> Core Data
  -> PostgreSQL
  -> state-aggregator
  -> dashboard

southbound broker와 중앙 EdgeX MessageBus를 혼동하지 않는다. MessageBus와 Core API는 ClusterIP와 cluster DNS로만 접근한다.

1. 렌더와 노드 확인

kubectl get node etri-ser0002-cgnmsb etri-dev0001-jetorn etri-dev0003-raspi5 -o wide
kubectl kustomize edgex/k8s >/tmp/edgex-central-messagebus.yaml
kubectl apply --dry-run=server -f /tmp/edgex-central-messagebus.yaml

정상 기준:

  • 중앙 Core, MessageBus, PostgreSQL의 node selector는 etri-ser0002-cgnmsb다.
  • edgex-device-mqtt의 node selector는 etri-dev0001-jetorn이다.
  • edgex-device-mqtt-sensehat의 node selector는 etri-dev0003-raspi5다.
  • 엣지 노드에는 Core, MessageBus, PostgreSQL workload가 없다.

2. workload와 service 확인

kubectl -n telemetry get pod -l app.kubernetes.io/part-of=edgex-telemetry -o wide
kubectl -n telemetry get deploy,statefulset,job
kubectl -n telemetry get service,endpoints
kubectl -n telemetry get pvc

정상 기준:

  • 중앙 workload와 두 Device MQTT deployment가 Ready다.
  • edgex-messagebus는 ClusterIP 1883을 제공한다.
  • Core Metadata와 Core Data service endpoint가 존재한다.
  • PostgreSQL StatefulSet과 PVC가 Ready/Bound다.

3. Core Metadata 확인

kubectl get --raw \
  '/api/v1/namespaces/telemetry/services/http:edgex-core-metadata:59881/proxy/api/v3/device/all?offset=0&limit=100'
kubectl get --raw \
  '/api/v1/namespaces/telemetry/services/http:edgex-core-metadata:59881/proxy/api/v3/deviceservice/all?offset=0&limit=100'

확인 항목:

  • arduino-001과 sensehat-001의 Device/Profile/Device Service binding
  • adminState, operatingState, protocol properties
  • 두 Device Service가 서로 다른 instance와 node 역할을 갖는지

4. Core Data와 PostgreSQL 확인

장비 publisher로 새 MQTT payload를 발행한 뒤 Core Data를 조회한다.

kubectl get --raw \
  '/api/v1/namespaces/telemetry/services/http:edgex-core-data:59880/proxy/api/v3/event/device/name/arduino-001?limit=1'
kubectl get --raw \
  '/api/v1/namespaces/telemetry/services/http:edgex-core-data:59880/proxy/api/v3/event/device/name/sensehat-001?limit=1'

정상 기준:

  • Event의 deviceName, sourceName, origin이 발행한 sample과 일치한다.
  • Reading의 valueType과 값이 Device Profile 계약과 일치한다.
  • PostgreSQL에 Event/Reading이 저장된다.

5. state-aggregator와 대시보드 확인

kubectl get --raw \
  '/api/v1/namespaces/default/services/http:state-aggregator:8000/proxy/state/devices'
kubectl get --raw \
  '/api/v1/namespaces/default/services/http:state-aggregator:8000/proxy/state/dashboard'

정상 기준:

  • inventory source는 중앙 EdgeX Core Metadata다.
  • latest_event_timestamp, latest_readings, telemetry_freshness가 Core Data Event와 일치한다.
  • Kubernetes node/workload 정보는 물리 availability와 분리된 진단 정보다.
  • Serial, Modbus, OPC-UA, RTSP는 검증 전까지 완료로 표시하지 않는다.

6. 장애 원인 좁히기

Event가 없으면 다음 순서로 확인한다.

  1. 장비 publisher와 southbound MQTT endpoint
  2. 해당 EdgeX Device MQTT deployment와 로그
  3. 엣지 노드에서 중앙 edgex-messagebus service DNS·ClusterIP 연결
  4. 중앙 MessageBus와 Core Data 로그
  5. PostgreSQL 상태와 저장 결과
  6. state-aggregator의 중앙 Core endpoint 설정
  7. 대시보드 consumer와 freshness 판정

현재 장애 계약

현재 1차 수직 슬라이스에는 SQLite offline replay가 없다.

  • 중앙 MessageBus 또는 네트워크 장애 시 telemetry가 유실될 수 있다.
  • 복구 성공 기준은 연결 회복 뒤 새 Event 수집 재개다.
  • 누락분 자동 재전송과 at-least-once 전달을 주장하지 않는다.
  • SQLite replay와 PostgreSQL persisted acknowledgement는 별도 승인된 후속 설계다.

완료 판정

저장소의 manifest와 문서만으로 live cutover 완료를 주장하지 않는다. 중앙 배치, 실제 MQTT Event 저장, state-aggregator 중앙 조회, 대시보드 표시를 같은 실행 증거로 확인한 뒤 완료로 판정한다.
