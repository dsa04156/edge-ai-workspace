현재 서비스 데모 운영 절차

목적

이 문서는 Jetson Arduino Uno → EdgeX Serial Device Service → 중앙 MessageBus/Core Data/PostgreSQL → state-aggregator/dashboard로 이어지는 현재 정상 경로를 점검한다. 기존 Agent, SQLite outbox, Sense HAT bootstrap과 edge-local MQTT broker는 현재 경로가 아니다.

배치 기준

구분 현재 기준
중앙 namespace edgex-system
edge namespace edgex-edge
중앙 노드 etri-ser0002-cgnmsb
중앙 workload Core Keeper/Metadata/Data/Command, internal MessageBus, PostgreSQL, 유지 중인 ingest gateway
edge workload device-serial-jetson 1 replica
physical node etri-dev0001-jetorn
Device/Profile/Service arduino-001 / etri-arduino-serial / device-serial-jetson
운영 진입점 edgex/k8s/kustomization.yaml
Argo CD Application edgex-telemetry

EdgeMesh 리소스는 이 절차의 변경 대상이 아니다. Kubernetes ClusterIP Service 객체는 정상 서비스 디스커버리에 사용하지만 고정 ClusterIP, PodIP와 node IP를 설정에 넣거나 우회 경로로 사용하지 않는다.

1. 로컬 render 검증

kubectl kustomize edgex/k8s >/tmp/edgex-current.yaml
kubectl apply --dry-run=server -f /tmp/edgex-current.yaml

정상 기준:

  • 중앙 Core/MessageBus/PostgreSQL/gateway가 render된다.
  • Namespace/edgex-edge, default-deny와 Device Service별 최소 NetworkPolicy가 render된다.
  • Service와 Deployment/device-serial-jetson이 render된다.
  • Device Service는 etri-dev0001-jetorn에 고정되고 hostNetwork: true를 사용하지 않는다.
  • host의 Arduino by-id CharDevice만 Pod의 /dev/arduino-001에 마운트된다.
  • 중앙 Keeper/Metadata/MessageBus는 .svc.cluster.local FQDN으로 참조된다.
  • edgex-edge-agent-*, Agent PVC/ConfigMap/bootstrap, device-mqtt와 edge-local broker가 없다.

현재 PoC의 Serial 장치 접근은 단일 Pod에 privileged: true, UID/GID 0을 허용한다. 이 예외는 정확한 CharDevice mount, Recreate 전략, service-account token 비마운트와 최소 NetworkPolicy로 제한한다. 후속 운영 강화에서는 Device Plugin 또는 더 좁은 장치 권한으로 대체한다.

2. Argo CD 상태

kubectl -n argocd get application edgex-telemetry \
  -o jsonpath='{.spec.source.targetRevision}{"\n"}{.status.sync.status}{"\n"}{.status.health.status}{"\n"}{.status.operationState.phase}{"\n"}'

정상 기준은 대상 revision이 의도한 Git commit이고 Synced, Healthy, Succeeded인 것이다. Application은 prune/self-heal을 사용하므로 live 리소스를 임의 수정하지 않고 Git의 root Kustomize를 고친다.

3. live workload와 장치 mount

kubectl -n edgex-system get deploy,statefulset,job,pod,service,pvc -o wide
kubectl -n edgex-edge get deploy,pod,service,pvc,configmap,networkpolicy -o wide
kubectl -n edgex-edge get deployment device-serial-jetson \
  -o jsonpath='{.spec.template.spec.nodeSelector.kubernetes\.io/hostname}{"\n"}{.spec.template.spec.hostNetwork}{"\n"}{.spec.template.spec.containers[0].image}{"\n"}'

정상 기준:

  • 중앙 Core 서비스와 PostgreSQL이 Ready다. common-config bootstrap Job은 Completed일 수 있다.
  • device-serial-jetson Pod가 Jetson에서 1/1 Running이다.
  • image는 immutable ARM64 digest다.
  • Pod restart가 반복 증가하지 않는다.
  • edgex-edge에 Agent outbox PVC와 local broker가 없다.

로그에서 시작 중 잘린 Serial line 1~2개가 malformed로 폐기될 수 있다. 이후 metric 등록, reader restart, Metadata update가 반복되거나 ERROR가 계속 나오면 정상으로 보지 않는다.

4. Core Metadata binding

kubectl get --raw \
  '/api/v1/namespaces/edgex-system/services/http:edgex-core-metadata:59881/proxy/api/v3/deviceservice/name/device-serial-jetson'
kubectl get --raw \
  '/api/v1/namespaces/edgex-system/services/http:edgex-core-metadata:59881/proxy/api/v3/deviceprofile/name/etri-arduino-serial'
kubectl get --raw \
  '/api/v1/namespaces/edgex-system/services/http:edgex-core-metadata:59881/proxy/api/v3/device/name/arduino-001'

정상 기준:

  • Device Service base address는 http://device-serial-jetson.edgex-edge.svc.cluster.local:59910이다.
  • Device는 UNLOCKED, UP, service/profile binding이 일치한다.
  • Serial protocol은 /dev/arduino-001, baud 115200, DeviceID arduino-001이다.
  • Profile은 temperature_raw, light_raw, magnetic_raw, acceleration_x_raw, acceleration_y_raw, acceleration_z_raw 6개 Int32 read-only resource를 갖는다.

5. Core Data Event/Reading

kubectl get --raw \
  '/api/v1/namespaces/edgex-system/services/http:edgex-core-data:59880/proxy/api/v3/event/device/name/arduino-001?limit=20'

정상 기준:

  • temperature, light, magnetic, acceleration source가 모두 관측된다.
  • 6개 Reading의 valueType이 Int32, units가 raw다.
  • Event/Reading origin이 계속 증가한다.
  • API readback으로 저장을 확인하며 중앙 MessageBus의 MQTT ACK만으로 persistence를 주장하지 않는다.

6. read-only Core Command

kubectl get --raw \
  '/api/v1/namespaces/edgex-system/services/http:edgex-core-command:59882/proxy/api/v3/device/name/arduino-001/temperature'
kubectl get --raw \
  '/api/v1/namespaces/edgex-system/services/http:edgex-core-command:59882/proxy/api/v3/device/name/arduino-001/acceleration'

정상 기준은 Device Service가 보관한 최신값과 origin을 반환하는 것이다. Profile에는 writable resource가 없으므로 PUT이나 actuator command를 보내지 않는다.

7. dashboard API

kubectl get --raw \
  '/api/v1/namespaces/default/services/http:state-aggregator:8000/proxy/state/devices'
kubectl get --raw \
  '/api/v1/namespaces/default/services/http:state-aggregator:8000/proxy/state/dashboard'

arduino-001의 정상 기준:

  • source=edgex
  • device_service_name=device-serial-jetson
  • profile_name=etri-arduino-serial
  • protocol_names=[serial]
  • admin_state=UNLOCKED, operating_state=UP, connection_state=connected
  • overall_status=available, telemetry_freshness=fresh
  • 6개 typed latest_readings

Kubernetes node/workload 상태는 별도 진단이며 위 physical availability를 덮어쓰지 않는다.

8. 남은 장애 검증

parser의 malformed line 복구, reader backoff와 동일 Metadata update의 no-op 동작은 단위 테스트했다. 실제 케이블 분리 → DOWN/degraded → 재연결 → 새 Event 발행은 아직 현장 시연이 남아 있다. 현재 Device Service에는 SQLite outbox와 offline replay가 없으므로 중앙 단절 중 데이터 보존을 완료 기능으로 설명하지 않는다.
