물리 디바이스 상태 정책

권위와 경계

물리 디바이스의 inventory, state, telemetry, command에 대한 권위는 EdgeX다.

physical MQTT / Serial / Modbus / OPC-UA / RTSP device
  -> Protocol Adapter -> edge-telemetry-agent -> SQLite outbox
  -> HTTPS/mTLS ingest gateway -> EdgeX Core Data REST
  -> AI services / storage / state-aggregator / dashboard

RTSP frame은 이 telemetry 경로에 넣지 않는다. Workflow Pod가 stream을 직접 구독하고 상태·결과 metadata만 Event로 전달한다. 중앙 EdgeX 내부 MessageBus는 Core Data 이후의 중앙 consumer용이며 물리 노드의 전송 경로나 장애 버퍼가 아니다.

KubeEdge는 Kubernetes edge node와 workload에만 사용한다. KubeEdge Device, DeviceModel, DeviceStatus, MapperFramework와 mqttvirtual은 legacy physical integration 경로이며 current status/control plane, 병행 plane 또는 EdgeX 장애 시 fallback이 아니다. mapper가 InfluxDB로 직접 쓰는 경로도 legacy다.

Inventory와 state

Core Metadata Device가 물리 inventory의 원본이다. consumer는 다음 필드를 보존하고 노출한다.

  • name
  • profileName
  • serviceName
  • protocols
  • adminState
  • operatingState
  • tags와 properties의 선택적 node diagnostic/placement

Protocol Adapter는 protocols의 endpoint를 연결하고 Device Profile에 맞는 canonical Event를 만든다. edge-telemetry-agent는 Event schema와 SQLite admission을 검증하고 중앙 persisted ACK 전까지 보존한다. Core Metadata의 serviceName=edge-telemetry-agent는 이 수집 경로를 나타내는 논리 Device Service다.

Kubernetes node placement는 display-only 진단 정보다. placement 누락, Kubernetes Node NotReady, mapper Pod 상태를 물리 디바이스 availability의 gate로 사용하지 않는다.

Telemetry와 timestamp

Core Data Event가 physical telemetry의 원본이다. event의 다음 값을 손실 없이 사용한다.

  • deviceName: Core Metadata Device와의 결합 key
  • sourceName: Device Profile resource/source
  • origin: nanoseconds 단위의 sample/event 시각
  • Readings: EdgeX valueType과 typed value

freshness는 최신 유효 Event의 origin으로 계산한다. 수집 API 호출 시각, 데이터베이스 query window, Kubernetes heartbeat 또는 legacy DeviceStatus timestamp로 대체하지 않는다. storage와 AI consumer는 Core Data 이후에 위치하며 mapper direct-to-Influx로 Core Data를 우회하지 않는다.

전달 성공의 기준은 MQTT PUBACK이나 gateway 수신이 아니다. Core Data가 PostgreSQL 저장을 확인한 응답을 gateway가 검증하고, agent가 정확한 Event ID의 persisted ACK를 받은 뒤에만 outbox row를 삭제한다.

Availability

physical device availability는 다음 우선순위로 계산한다.

  1. adminState=LOCKED이면 unavailable / disconnected.
  2. operatingState=DOWN이면 unavailable / disconnected.
  3. operatingState=UNKNOWN이면 degraded / unknown.
  4. operatingState=UP이고 최신 Core Data event가 freshness 기준 안이면 available.
  5. operatingState=UP이지만 event가 없거나 stale이면 degraded.

알 수 없는 enum이나 parse할 수 없는 origin은 정상으로 추정하지 않고 degraded와 명시적 reason으로 노출한다. node/workload 관찰 정보는 별도로 표시할 수 있지만 위 결과를 승격하거나 강등하지 않는다.

명령과 상태 변경

현재 command 실행은 COMMAND_ENABLED=false로 비활성이다. Device Profile의 read-only command grouping은 schema 표현이며 actuator 실행 가능성을 뜻하지 않는다. command를 활성화할 때는 해당 Protocol Adapter의 지원 범위, 인증, TTL, 중복 실행 방지, 실패 상태를 별도 검증하고 KubeEdge desired/twin이나 mapper topic으로 우회하지 않는다.

전달 범위와 migration gate

현재 etri-dev0003-raspi5의 sensehat-001은 direct admission을 검증하는 교체 가능한 fixture다. 승인된 Protocol Adapter가 http://127.0.0.1:18080/v1/events로 canonical Event를 전달하고 agent가 SQLite outbox와 HTTPS/mTLS replay를 담당한다. 이 경로에는 로컬 MQTT broker가 필요하지 않다.

현재 Jetson MQTT mode와 edge-local broker는 배포하지 않는다. 대신 etri-dev0001-jetorn에는 direct agent, 독립 SQLite PVC와 인증 heartbeat 기반만 둔다. 이 기반은 Arduino Serial 장치를 열거나 Device/Profile/Event를 등록하지 않으므로 Serial wave 완료 근거가 아니다. MQTT-only 장비 또는 로컬 pub/sub 요구가 확인되면 별도 adapter/profile과 실제 endpoint를 검증한 뒤에만 추가하며 전체 physical plane의 기본 경로로 설명하지 않는다.

Serial, Modbus, OPC-UA와 추가 I2C 장비는 target architecture의 protocol-adapter wave다. RTSP는 별도 media/workflow wave다. 각 wave는 다음 gate를 독립적으로 통과해야 delivered로 표시한다.

  • 해당 Protocol Adapter와 EdgeX Device Profile 선택/구현
  • 실제 장비 endpoint의 독점 연결
  • normalization 및 typed Reading 검증
  • Core Metadata inventory와 Core Data freshness 검증
  • 지원 command가 있을 때만 command와 실패 동작 검증
  • AI services/storage/dashboard consumer 검증
  • 실제 배포 환경 cutover 확인

한 protocol의 성공을 다른 protocol 완료 근거로 사용하지 않는다. virtual-device/ Serial JSON runtime은 보존되는 독립 프로토타입이며 EdgeX Serial wave 완료로 간주하거나 자동 결합하지 않는다.
