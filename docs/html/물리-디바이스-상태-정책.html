물리 디바이스 상태 정책

적용 범위

이 정책은 EdgeX Core Metadata에 등록된 physical Device에 적용한다. discovery candidate, virtual-device 설계 객체, Kubernetes node/workload는 별도 상태로 다룬다.

권위 필드

상태 필드 원본
등록 name, profileName, serviceName, protocols Core Metadata
관리 adminState Core Metadata
실행 operatingState Core Metadata/Device Service
연결 connection_state aggregator가 admin/operating으로 계산
수집기 device_service_available operatingState=UP
telemetry latest_event_timestamp, latest_readings Core Data Event/Reading
최신성 telemetry_freshness Event origin과 freshness window
종합 overall_status, reason aggregator 정책 결과

상태 전이

미등록
  → 승인된 Device/Profile
  → Device Service 준비
  → Metadata registered
  → 첫 Core Data Event
  → available/degraded/unavailable 관측

첫 Event가 없으면 Metadata 등록만으로 healthy가 되지 않는다. no_events는 degraded다.

상태 규칙

  1. adminState=LOCKED면 unavailable이다.
  2. operatingState=DOWN이면 unavailable이다.
  3. 상태가 UNKNOWN이거나 누락이면 degraded다.
  4. UP이고 최신 Event가 EDGEX_EVENT_FRESH_SECONDS 이내면 available이다.
  5. UP이어도 Event가 stale이면 degraded다.
  6. UP이어도 Event가 없으면 degraded다.

discovery와 등록의 분리

발견 후보는 “연결 흔적”이지 inventory가 아니다. 후보는 다음을 통과해야 Core Metadata에 등록한다.

  • stable identity 확인
  • Profile/Protocol Adapter 매칭
  • 허용된 image와 설정 확인
  • 운영자 승인
  • 첫 Event 확인

candidate가 사라져도 즉시 Device를 삭제하지 않는다. stale 유예와 운영자 확인을 거친 뒤 관리 정책에 따라 처리한다.

노드 상태와의 관계

Kubernetes/KubeEdge node가 Ready여도 물리 센서가 연결됐다는 뜻이 아니다. 반대로 node 진단이 일시적으로 실패해도 EdgeX Device와 Core Data Event가 fresh라면 physical status를 자동으로 unavailable로 내리지 않는다.

명령 정책

현재 command 실행은 disabled다. Device Profile의 read-only resource와 Core Command API가 존재한다는 사실만으로 actuator 제어가 활성화됐다고 쓰지 않는다. command를 활성화하려면 대상·권한·TTL·idempotency·실패복구·감사 로그를 별도 승인하고 검증한다.

이력과 감사

대시보드는 현재 snapshot과 latest Event를 표시한다. 장기 변경 이력은 Core Data/PostgreSQL 및 운영 로그의 timestamp·Event ID를 사용한다. raw telemetry를 dashboard 자체 저장소에 복제하지 않는다.
