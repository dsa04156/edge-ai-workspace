물리 디바이스 상태 정책

권위와 경계

물리 디바이스의 inventory, state, telemetry, command에 대한 권위는 EdgeX다.

physical MQTT / Serial / Modbus / OPC-UA / RTSP device
  -> protocol-specific EdgeX Device Service
  -> EdgeX Event / Reading -> Core Data
  -> AI services / storage / state-aggregator / dashboard

RTSP frame은 이 telemetry 경로에 넣지 않는다. Workflow Pod가 stream을 직접 구독하고 상태·결과 metadata만 Event로 전달한다. 중앙 EdgeX 내부 MessageBus는 EdgeX Core 런타임 구성이지 물리 protocol endpoint나 장애 버퍼가 아니다.

KubeEdge는 Kubernetes edge node와 workload에만 사용한다. KubeEdge Device, DeviceModel, DeviceStatus, MapperFramework와 mqttvirtual은 legacy physical integration 경로이며 current status/control plane, 병행 plane 또는 EdgeX 장애 시 fallback이 아니다. mapper direct-write도 legacy다.

Inventory와 state

Core Metadata Device가 물리 inventory의 원본이다. consumer는 다음 필드를 보존하고 노출한다.

  • name
  • profileName
  • serviceName
  • protocols
  • adminState
  • operatingState
  • tags와 properties의 선택적 node diagnostic/placement

EdgeX Device Service는 protocols의 endpoint를 연결하고 Device Profile에 맞는 Event/Reading을 만든다. Core Metadata의 serviceName은 실제 endpoint를 소유하는 Device Service여야 하며 별도 Agent를 논리 Device Service로 가장하지 않는다.

Kubernetes node placement는 display-only 진단 정보다. placement 누락, Kubernetes Node NotReady, mapper Pod 상태를 물리 디바이스 availability의 gate로 사용하지 않는다.

발견 후보와 inventory 경계

edge-device-discovery는 onboarding staging Agent다. 중앙에서 서명된 노드별 Discovery Plan을 조회한 뒤 USB Serial stable /dev/serial/by-id/* identity와 허용된 I2C bus/address/chip ID만 관측한다. Serial은 Plan이 허용할 때만 WHOAMI/Manifest를 시도하고, I2C 버스 파일의 존재만으로 센서 후보를 만들지 않는다. 네트워크 전체 대역과 I2C 전체 주소 범위 scan은 하지 않는다. report의 present/stale은 후보 evidence일 뿐 Core Metadata Device, operatingState, Device Service 통신이나 Core Data Event가 아니다.

후보, 상태 전이, 승인, 등록 Saga와 audit는 Adapter Controller SQLite Registry에 영속 저장하며 EdgeX inventory에 합치지 않는다. 기존 후보 ConfigMap은 최초 기동 시 migration 입력일 뿐이다. exact Catalog match가 있어도 운영자 승인과 외부 인증, 검증된 Device Service, Profile/Device Metadata readback, first Event를 모두 통과해야 current physical inventory/availability에 반영된다. KubeEdge Device CRD는 이 과정에 사용하지 않는다.

Telemetry와 timestamp

Core Data Event가 physical telemetry의 원본이다. event의 다음 값을 손실 없이 사용한다.

  • deviceName: Core Metadata Device와의 결합 key
  • sourceName: Device Profile resource/source
  • origin: nanoseconds 단위의 sample/event 시각
  • Readings: EdgeX valueType과 typed value

freshness는 최신 유효 Event의 nanosecond origin을 sample 시각으로 사용해 계산한다. 수집 API 호출 시각, 데이터베이스 query window, Kubernetes heartbeat 또는 legacy DeviceStatus timestamp로 대체하지 않는다. storage와 AI consumer는 Core Data 이후에 위치하며 mapper direct-write로 Core Data를 우회하지 않는다.

현재 Serial과 I2C 경로는 Device Service가 EdgeX SDK async Event를 중앙 MessageBus에 발행하고 Core Data가 PostgreSQL에 저장한 뒤 API에서 Event/Reading을 조회하는 구조다. MQTT broker ACK만으로 저장 성공을 주장하지 않고 Core Data readback을 확인한다. edge outbox가 없으므로 중앙 단절 중 유실 방지나 offline replay를 보장하지 않는다. 2026-07-22 MessageBus 0 replica 실측에서도 로컬 cache와 AI consumer는 계속 동작했지만 Core Data count는 고정됐고, 복구 후 미전송 구간을 건너뛴 새 Event부터 저장됐다.

Availability

physical device availability는 다음 우선순위로 계산한다.

  1. adminState=LOCKED이면 unavailable / disconnected.
  2. operatingState=DOWN이면 unavailable / disconnected.
  3. operatingState=UNKNOWN이면 degraded / unknown.
  4. operatingState=UP이고 최신 Core Data event가 freshness 기준 안이면 available.
  5. operatingState=UP이지만 event가 없거나 stale이면 degraded.

알 수 없는 enum이나 parse할 수 없는 origin은 정상으로 추정하지 않고 degraded와 명시적 reason으로 노출한다. node/workload 관찰 정보는 별도로 표시할 수 있지만 위 결과를 승격하거나 강등하지 않는다.

명령과 상태 변경

Serial 6개 Device의 temperature, light, magnetic, acceleration_x, acceleration_y, acceleration_z와 I2C 6개 Device의 temperature, humidity, pressure, compass, orientation, gyroscope는 각 Device Service recent cache의 최신값을 반환하는 read-only Core Command GET이다. cache는 Device/resource별 최근 10분·최대 10,000 sample을 메모리에 보관하며 Pod 재시작 시 초기화된다. Device Profile에는 writable resource가 없으며 actuator 실행 가능성을 뜻하지 않는다.

같은 edge node의 Workflow Pod는 다음 read-only Local Data API를 사용할 수 있다.

GET /api/v3/localdata/device/name/{device}/resource/name/{resource}/latest
GET /api/v3/localdata/device/name/{device}/resource/name/{resource}?from={origin_ns}&to={origin_ns}&limit={1..10000}

Local Data API의 origin은 중앙 Event와 같은 sample 시각이다. 이 API는 중앙 Core Data history로 fallback하지 않으며 dashboard freshness와 영구 이력의 권위도 바꾸지 않는다.

manifest의 edge-ai.io/local-data-client=true label은 의도된 client를 표시하지만 현재 Flannel CNI에서는 NetworkPolicy가 강제되지 않는다. 이 unauthenticated endpoint에 실제 접근 제어가 필요하면 정책 지원 CNI 또는 mTLS/애플리케이션 인증을 적용한다.

전달 범위와 migration gate

2026-07-21 기존 aggregate sensehat-001 bootstrap, direct Agent와 SQLite PVC는 퇴역했다. Jetson의 device-serial-jetson은 arduino-001, Raspberry Pi의 device-sensehat-raspi는 sensehat-001 물리 source를 각각 한 번 읽어 6개 가상 Device Event로 분리한다. edge-local broker와 별도 InfluxDB는 없다. MQTT-only 장비 또는 local pub/sub 요구가 확인되면 별도 Device Service/profile과 실제 endpoint를 검증한 뒤에만 broker를 추가한다.

Serial과 Sense HAT I2C 정상 경로는 delivered다. Modbus, OPC-UA와 다른 장비·주소의 추가 adapter는 target architecture의 독립 protocol wave다. RTSP는 별도 media/workflow 설계 wave이며 현재 구현 완료 범위가 아니다. 각 wave는 다음 gate를 독립적으로 통과해야 delivered로 표시한다.

  • 해당 Protocol Adapter와 EdgeX Device Profile 선택/구현
  • 실제 장비 endpoint의 독점 연결
  • normalization 및 typed Reading 검증
  • Core Metadata inventory와 Core Data freshness 검증
  • 지원 command가 있을 때만 command와 실패 동작 검증
  • AI services/storage/dashboard consumer 검증
  • 실제 배포 환경 cutover 확인

한 protocol의 성공을 다른 protocol 완료 근거로 사용하지 않는다. 현재 Serial/I2C 완료 범위에는 정상 수집과 driver/reader 수준의 DOWN → UP 복구가 포함된다. 실제 케이블·보드 손분리 현장 시연과 offline replay는 포함하지 않는다. virtual-device/ Serial JSON runtime은 보존되는 독립 프로토타입이며 현재 EdgeX Serial 경로와 자동 결합하지 않는다.
