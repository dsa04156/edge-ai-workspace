일일 기록

목적

이 문서는 KubeEdge 기반 혼합 디바이스 edge AI 운영 가시화 PoC의 일일 작업 기록을 남기기 위한 문서다.

일지는 매일의 작업 사실, 확인한 상태, 남은 이슈, 다음 작업을 짧게 기록하는 용도다. 현재 PoC는 서비스 데모 우선, 디바이스-서비스 연결 구조, 통합 운영 가시화, 현장 적용성, 생산성 향상 효과를 중심으로 설명한다.

작성 원칙

  • 실제로 확인한 내용과 계획을 구분한다.
  • dashboard에서 관찰한 상태는 telemetry freshness, DeviceStatus snapshot, mapper 상태, node 상태를 나눠 적는다.
  • status.state=online만으로 healthy라고 판단하지 않는다.
  • raw telemetry 값을 DeviceStatus에 올린 것처럼 쓰지 않는다.
  • workflow/offloading/agent-assisted planning은 현재 구현 완료 기능처럼 쓰지 않는다.
  • 이슈는 원인 확정 여부를 함께 적는다.

2026-07-21

오늘 목표

  • Jetson Serial Device Service에 로컬 최근 데이터 cache/API를 추가하고 6개 가상 Device의 중앙·로컬 경로를 같은 revision에서 검증한다.

진행 내용

  • Device/resource별 최근 10분·최대 10,000 sample의 동시성 안전 메모리 cache를 구현했다.
  • latest/recent Local Data API와 Core Command 최신값 조회를 같은 cache로 통합했다.
  • ARM64 image sha256:4c933c3d8827dec325055634ed196380690c4748362fecb3f9676b412e724b71을 배포했다.
  • Argo CD edgex-telemetry revision a5dc329b442d54c82ee222127783566f34b6e7d3에서 live readback을 수행했다.

이슈 / 리스크

  • 현재 Flannel CNI는 Kubernetes NetworkPolicy를 집행하지 않는다. label 없는 기존 Pod도 unauthenticated read-only Local Data API에 접근할 수 있음을 실측했다.
  • 실제 접근 제어가 필요하면 NetworkPolicy 지원 CNI 또는 mTLS/애플리케이션 인증이 필요하다.
  • 실제 Serial 케이블 분리·복구와 중앙 단절 중 데이터 보존은 검증 범위가 아니다.

결정 사항

  • Workflow client label은 현재 배치·정책 의도 표식으로만 사용하며 보안 경계로 설명하지 않는다.
  • cache는 로컬 저지연 조회, PostgreSQL은 영구 이력, 미구현 outbox는 장애 재전송 책임으로 계속 분리한다.

추가 이슈 / 다음 검증

  • Sense HAT 보드 분리·복구 현장 시연은 아직 남아 있다.
  • Modbus와 OPC-UA는 실제 endpoint가 없으므로 구현·실장 검증 완료로 표시하지 않는다.
  • EdgeX SDK의 중앙 internal MessageBus 연결은 유지하지만 물리 I2C 입력에 local MQTT broker나 Agent를 사용하지 않는다.

2026-07-22

오늘 목표

  • 실제 Jetson Arduino 가속도를 사용하는 첫 서비스 데모를 구현하고 디바이스-서비스-AI 연결을 대시보드에 표시한다.

진행 내용

  • sensor-anomaly-demo를 추가해 virtual-acceleration-{x,y,z}-001의 Local Data API를 500ms polling하고 같은 nanosecond origin을 한 frame으로 결합했다.
  • 30 sample warm-up, threshold 4.0, anomaly 2연속, clear 3연속인 online-gaussian-baseline-v1 변화 탐지기를 구현했다.
  • 최근 결과 최대 1,000건, pending frame 10초·1,000건, source별 cursor와 중복 제거를 bounded memory로 구현했다.
  • /healthz, /readyz, /api/v1/status, /api/v1/results read-only API와 Jetson Deployment/Service/NetworkPolicy/Argo CD Application을 추가했다.
  • state-aggregator에 failure-isolated /state/service-demo를 추가하고 dashboard에 physical source → Device Service → Device 3개 → AI consumer binding, raw X/Y/Z, magnitude, score, origin, 최근 input age와 상태를 표시했다.
  • 실제 센서 입력이 없던 edge-orch-factory-vision-inspection-ai manifest와 live Application, exact orphan workload를 제거했다.

이슈 / 리스크

  • 500ms REST polling은 push stream이 아니므로 고주기 진동·카메라 입력 경로로 일반화하지 않는다.
  • detector는 학습된 고장 분류기가 아니라 online 통계 baseline의 magnitude 변화 탐지다.
  • 실제 장치를 움직여 anomaly를 발생시키는 현장 시연 전에는 실제 고장 검출 실증으로 표현하지 않는다.
  • 현재 Flannel CNI에서는 NetworkPolicy label이 접근 제어 경계가 아니다.

결정 사항

  • EdgeX Core Metadata/Core Data/PostgreSQL은 raw inventory·telemetry 권위를 유지하고 AI result는 별도 derived service output으로 둔다.
  • 첫 데모는 동적 Workflow Builder가 아니라 명시적으로 배포하는 고정 Jetson workload로 제한한다.
  • 고정 ClusterIP/PodIP/node IP를 설정에 넣지 않고 Service FQDN만 사용한다.

다음 작업

  • 실제 장치를 움직여 anomaly 상태를 발생시키고 정상 복귀까지 현장 화면으로 시연한다.
  • Serial 케이블과 Sense HAT 보드 분리·복구를 별도 현장 gate로 검증한다.
  • 500ms polling보다 높은 주기가 필요한 입력은 push/stream 경로를 별도 설계한다.
