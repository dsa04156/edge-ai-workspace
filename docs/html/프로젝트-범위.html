프로젝트 범위

목적

이 문서는 저장소의 현재 구현, 후속 설계와 과거 실험을 구분하는 최상위 기준이다. 문서와 대시보드는 실제 endpoint·manifest·테스트 근거가 없는 기능을 완료로 표시하지 않는다.

현재 범위

물리 디바이스와 데이터

  • EdgeX Core Metadata의 Device/Profile/Device Service를 inventory와 schema 권위로 사용한다.
  • EdgeX Device Service가 Serial·I2C 등 승인된 endpoint를 직접 소유하고 값을 표준화한다.
  • EdgeX Core Data의 Event/Reading과 origin을 telemetry·freshness 권위로 사용한다.
  • 중앙 EdgeX Core와 PostgreSQL은 etri-ser0002-cgnmsb에 한 세트만 배치한다.
  • KubeEdge는 edge node와 workload 관리에만 사용한다.

현재 수직 슬라이스

물리 source 노드 수집 Runtime EdgeX Device
Arduino Uno etri-dev0001-jetorn device-serial-jetson 온도·조도·자기·가속도 X/Y/Z 6개
Sense HAT v1 etri-dev0003-raspi5 device-sensehat-raspi 환경·자세·자이로 6개

두 Runtime은 같은 물리 연결을 여러 기능별 Device로 fan-out한다. arduino-001과 sensehat-001은 물리 source ID이며 aggregate EdgeX Device가 아니다.

서비스와 운영 화면

  • sensor-anomaly-demo 고정 서비스와 application-owned SQLite 결과·알림 저장
  • HAMi GPU와 CUDA probe를 사용하는 Server1 observed-only 추론 후보. 2026-08-18 현재

기준선 후보는 부하 실험에서 성능 자격이 거부되어 요청을 전환하지 않는다.

  • Git ServiceDescriptor 기반 서비스 목록과 실행 DAG
  • EdgeX·Kubernetes·Prometheus를 결합하는 state-aggregator read model
  • 센서 freshness, 노드/workload와 서비스 입력·모델·결과의 가시화
  • 브라우저 안에서만 동작하는 workflow 설계·validation·execution plan preview

제한된 장비 관리

  • passive discovery candidate 조회·검토와 exact Catalog binding validation
  • 승인된 Profile/Device 등록 Saga와 first Event 확인
  • Controller가 소유한 Adapter Runtime만 제한적으로 restart·retire
  • 임의 image·hostPath·raw manifest·command 입력 없음
  • 사용자 인증·인가가 추가되기 전까지 테스트베드 접근 경계에서만 사용

승인과 검증이 필요한 범위

다음은 코드나 개발 fixture가 있어도 일반 운영 기능으로 보지 않는다.

항목 현재 지위 승격 조건
Server1 inference observed-only GPU endpoint, 현재 기준선 성능 자격 rejected 정확한 모델 버전의 부하 실험 통과 + 요청 전환 승인 주체·실패 대응 검증
MQTT·Modbus 검증된 개발 package/fixture 실제 broker·PLC 계약과 장애 시험
OPC-UA·RTSP 계약 또는 후보 경로 Profile·실장비·telemetry/result 증거
디바이스 discovery 제한된 passive Serial/I2C 관측 승인·Catalog binding·first Event
생산품질 판별 versioned 입력 schema PLC·MES mapping, label, 모델과 E2E

명시적으로 제외하는 것

  • EdgeX와 병행하는 KubeEdge Device/DeviceModel/DeviceStatus 물리 권위
  • MapperFramework, mapper direct-to-Influx와 legacy MQTT topic을 fallback으로 사용
  • 광역 네트워크 probe나 임의 hostPath/image/command 실행
  • dashboard의 Kubernetes apply/delete/restart 또는 EdgeX metadata mutation
  • 승인 없는 actuator command와 write command
  • 동적 workflow·migration·offloading 전체 구현 완료 주장

완료 증거

기능은 다음 증거를 모두 연결할 수 있을 때만 현재 범위로 승격한다.

  1. Git에서 검토한 계약과 immutable image
  2. root Kustomize 또는 승인된 선택 overlay
  3. 관련 자동 테스트와 manifest render
  4. Argo CD 또는 명시적 운영 소유권
  5. Pod/endpoint Ready와 실제 API readback
  6. 실패·stale·누락 상태가 정상처럼 보이지 않는 대시보드 표시

Server1 후보의 실험 설계, 합성 입력 90회 기준선, 실제 Arduino Reading 120개를 고정한 18회 비교 결과와 승격 gate는 AI 서비스 자원 증강 부하 실험을 따른다. CPU/GPU가 존재하거나 endpoint가 Ready라는 사실만으로 오프로딩 효과를 주장하지 않는다.

과거 workflow·placement·replanning 코드는 edge-orch/workflow_*, edge-orch/placement_engine/, workflow/, docs/archive/에 보존하며 현재 요구사항으로 해석하지 않는다.
