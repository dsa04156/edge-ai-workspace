edgex/device-serial/internal/driver/reader.go는 established stream의 Serial fast-retry와 오류 감지→port ready→first byte→첫 유효 sample 전송 재개 구간을 소유한다. hangup_linux.go는 기존 termios flag를 보존하면서 HUPCL을 해제해 Uno auto-reset을 억제한다. recovery.go는 400ms 개발 target, 재시도 설정 validation, EdgeX custom metric과 /api/v3/serial-recovery/stats read-only API를 소유한다. 이 process-local 계측은 Kubernetes node failover나 durable telemetry delivery를 대체하지 않는다.

배포 소유권

중앙 EdgeX·Device Service edgex-telemetry Application에 선언된 Git ref의 edgex/k8s

state-aggregator Deployment Controller가 생성하는 AI workload는 edge-ai-workloads namespace에만 존재한다. 이 동적 workload의 소유자는 Controller이며 Argo CD가 개별 Deployment manifest를 소유하지 않는다. Controller의 권한은 신규 create와 상태 read로 제한하고 기존 Deployment update·patch·delete, migration과 offloading은 지원하지 않는다. Controller 자체, 전용 namespace와 RBAC는 계속 edge-orch-state-aggregator Application이 GitOps로 소유한다.

Runtime Recommendation Engine은 Git Service Catalog에 선언된 workload만 읽고, Deployment/StatefulSet·Pod·Node·서비스 지표를 결합한다. 최신 상태, dwell/cooldown과 판단 이력은 state-aggregator PVC의 SQLite가 소유한다. 추천 결과는 Placement Engine 입력일 뿐 Controller 실행 요청으로 연결되지 않으며 자동 배포·traffic 전환·삭제를 수행하지 않는다. 같은 모듈의 Runtime Execution Plan은 최신 추천을 결정적인 단계 목록으로 projection하며, 별도 실행 상태를 저장하거나 Deployment Controller·Kubernetes·traffic plane을 호출하지 않는다. 대상 workload와 node, 선행조건, 실패조건, 조건부 rollback은 계획 설명에만 존재한다.

sensor-anomaly-demo/app/inference_executor.py는 local/remote/fallback 추론 실행 계약과 요청별 latency·authoritative-result metadata를 소유한다. remote_inference.py는 Git/Secret으로 승인된 Server1 endpoint 호출, 응답 identity/model/freshness 검증과 runtime mode 전환을 담당하고, inference_api.py는 같은 model adapter를 재사용하는 idempotent Server1 /infer endpoint를 제공한다. raw telemetry와 결과 저장은 계속 각각 EdgeX와 ACTIVE edge worker가 소유한다. state-aggregator의 Service Catalog offloading contract는 remote workload/API/architecture/ accelerator/network threshold를 고정하고 기존 placement.py의 Filter/Score를 재사용한다. 이는 legacy placement_engine/을 운영 경로로 되살리는 것이 아니다. 이 partial offloading 경로는 2026-08-28 현재 checkout의 로컬 검증 대상이며 Argo CD가 동기화한 07fc3b1 배포 기준선에는 포함되지 않는다.

Execution Controller는 별도 승인 API에서만 plan을 소비한다. app/config/candidate_workload_templates.json이 source 복제 대신 사용할 서비스별 승인 candidate 계약과 state policy를 소유한다. Controller는 source Deployment·Service·PVC/StorageClass와 target Node를 읽기 전용 preflight한 뒤 전용 namespace에 신규 Deployment만 생성하고 Ready를 관측한다. app/config/candidate_validation_contracts.json은 Ready 이후 Pod-IP read-only health/input/model/ inference/freshness/latency 검증과 dwell을 소유한다. planId별 실행 record와 단계 상태, candidate/PVC 식별자, validation check와 감사 event는 같은 PVC의 별도 SQLite 파일이 소유한다. app/config/traffic_routing_contracts.json은 Service/namespace/port/source와 post-switch·rollback 정책을 고정한다. Runtime Controller는 Service selector를 patch하지 않고 자신이 소유한 단일 EndpointSlice만 resourceVersion compare-and-swap으로 갱신하며, switch 전후 snapshot과 서비스별 lock을 SQLite에 보존한다. 현재 EdgeMesh의 EndpointSlice 소비가 입증되지 않아 sensor-anomaly-demo 계약은 blocked이고 실클러스터 traffic mutation은 수행하지 않는다. terminate_current, source/candidate 삭제와 promotion은 지원하지 않는다.

대시보드의 static/runtime-operations.js와 static/runtime-operations.css는 서비스 운영 read model의 화면 소유 경로다. Runtime Recommendation에 포함된 Placement 후보를 그대로 표시하고 화면 갱신 때 /api/placements/select를 호출하지 않는다. dashboard.js의 노드 상세는 이 모듈이 읽은 /api/resources snapshot을 사용해 Prometheus usage와 Kubernetes scheduling capacity를 분리한다. 화면에는 Execution Controller 승인·실행 동작을 연결하지 않는다.

live 리소스를 직접 수정해 Git과 충돌시키지 않는다. image를 바꾸면 tag가 아니라 registry에서 확인한 immutable digest와 실제 Pod imageID까지 검증한다.
