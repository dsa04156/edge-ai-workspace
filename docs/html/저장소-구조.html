저장소 구조

목적

이 문서는 레포 안의 디렉터리와 주요 파일을 현재 PoC 범위 기준으로 분류한다. 새 작업을 시작할 때 어떤 경로를 현재 구현 경로로 볼지, 어떤 경로를 보조/참조/보관 대상으로 볼지 판단하기 위한 기준 문서다.

현재 범위 판단은 docs/프로젝트-범위.md를 우선한다.

분류 기준

분류 의미
Current 현재 서비스 데모, 디바이스-서비스 연결 구조, 통합 운영 가시화에 직접 연결되는 경로
Current-supporting 설치, 배포, 운영, ingress, registry 등 현재 범위를 지원하는 경로
Legacy / Reference 현재 연구 방향에서 진행하지 않는 과거 physical-device mapper/KubeEdge Device plane, workflow/offloading/agent-planning 실험 또는 참조 구현
Archive 과거 통합 기록, 연구 초안, 논문/실험 자료. 현재 판단 기준이 아님
외부/참조 KubeEdge API, MapperFramework 등 외부 코드 또는 참고용 코드
Cleanup Review 운영 중 생성된 데이터, 캐시, runner 산출물 등 레포 관리 대상인지 검토가 필요한 경로

edgex/k8s/overlays/development/adapter-management/ 개발 testbed 인증 overlay fail-closed external base를 현재 testbed에서만 development-mock으로 명시적으로 변경
edgex/k8s/overlays/examples/discovery-agent-{jetson,raspi}/ 노드별 배치 예시 Jetson 또는 Raspberry Pi 한 노드만 선택하는 discovery DaemonSet render 예시. root 운영 render에는 직접 포함하지 않음
edgex/adapter-controller/ 검증 Adapter Runtime controller와 등록 control plane SQLite candidate/state/Plan/Saga/audit, Git Device Catalog exact match, 운영자·외부 인증, 실제 Runtime image digest, EdgeX Profile/Device readback과 first Event를 관리. legacy 후보 ConfigMap은 1회 import
edgex/adapter-controller/config/device_bindings.json Device/Profile Catalog stable hardware identity와 immutable image/parser/Profile allowlist를 연결. API에서 임의 image 추가 불가
edgex/k8s/base/modbus-simulator/, edgex/k8s/overlays/development/modbus-simulator/ 공식 Modbus Device Service 개발 검증 fixture root 운영 render 밖에서 read-only Modbus TCP endpoint를 제공. 수동 exact binding과 승인 Saga 자동 테스트용이며 실제 PLC 지원 근거가 아님
edgex/adapter-controller/config/discovery_plans.json 초기 node Discovery Plan DB에 Plan이 없는 node만 보수적 기본값으로 seed
edgex/k8s/crds/, base/adapter-controller/ Adapter Runtime 운영 API와 배포 edgex-edge에만 적용되는 CRD, 최소 RBAC, 내부 HMAC API와 state-aggregator 전용 ingress 정책
edgex/telemetry-plane/ 중앙 gateway 구현과 퇴역 Agent 코드 gateway는 유지하지만 edge Agent/outbox/Metadata bootstrap은 운영 render가 아니며 현재 Serial/I2C 경로에도 참여하지 않음
edge-orch/state-aggregator/ inventory/history API와 대시보드 관리 BFF 중앙 Core Metadata/Core Data를 authority로 소비한다. /state/*는 read-only이고 /management/*는 발견 후보 검색·검토, 연결 등록/장비 관측/통신/데이터 증거, runtime inventory/plan과 검증 connection saga, 기존 Device allowlist patch를 제공한다. Kubernetes 쓰기 권한은 갖지 않는다
edge-orch/sensor-anomaly-demo/ Jetson 실측 센서 서비스 데모 Arduino 가속도 3축 Local Data를 origin으로 결합하고 online Gaussian baseline 변화 탐지 결과를 read-only API로 제공
edge-orch/state-aggregator/app/static/ 운영 대시보드 EdgeX 상태/history와 서비스 데모를 표시한다. 디바이스 관리는 발견 후보 검색·수동 endpoint 선언·승인/무시와 KubeEdge 노드 범위 선택, 등록 물리 연결과 실제 장비 상태 구분, protocol package의 재사용/설치/차단 상태, runtime owner/phase/consumer, EdgeX Device, 통합 validation/apply/first-Event 상태를 관리한다

EdgeX Core Metadata의 Device/Device Profile은 KubeEdge Device/DeviceModel CRD와 다른 객체다. Discovery SQLite도 승인 전 후보와 등록 진행을 위한 control-plane 저장소일 뿐 물리 Device inventory가 아니다. 기존 telemetry Agent/SQLite outbox/HTTPS 수직 슬라이스와 aggregate sensehat-001 bootstrap은 퇴역했다. 현재 render에는 Jetson Arduino Serial과 Raspberry Pi Sense HAT I2C Device Service가 있고 MQTT 입력 workload는 없다. MQTT 자기등록은 schema parser까지만 있고 subscriber는 없다. Modbus는 자동 discovery 없이 수동 개발 simulator endpoint용 공식 Device Service 등록 경로만 구현됐고, OPC-UA·ONVIF discovery는 미구현이다. RTSP는 별도 media 경로다.

2차년도 설계 트랙 경로

다음 경로는 현재 서비스 데모 기능으로 주장하지 않고, 2차년도 협약 방향에 맞춘 설계/프로토타입 후보로 관리한다.

경로 역할 작업 원칙
docs/2차년도-가상디바이스-워크플로-설계.md 등록 Device/source, 디바이스트윈, AI 서비스 워크플로우 재설계 기준 별도 VirtualDevice registry는 현재 구현 완료 경로로 두지 않으며 physical-device authority는 EdgeX와 충돌시키지 않음
docs/(2차년도협약용) 연구개발계획서-엣지 컴퓨팅 시스템을 위한 대규모 혼합 디바이스 제어·관리 플랫폼 개발_0415.pdf 2차년도 협약 방향 원문 요구사항과 표현 근거로만 사용하고 PDF 원본은 수정하지 않음
virtual-device/ Serial JSON 물리 디바이스를 profile 기반 표준 MQTT 데이터로 변환하는 컨테이너형 Virtual Device Runtime 최소 프로토타입 AI/KubeEdge/EdgeX/registry/dashboard/자원 증강을 포함하지 않고 기존 sensor-collector/와 분리 유지
신규 workflow-* 경로 후보 AI 서비스 workflow builder/runtime/control plane 후보 legacy workflow 코드를 현행 기능으로 오해하지 않도록 새 설계 경계 명시
신규 resource-augmentation-scheduler 경로 후보 runtime pod/service 사용량과 AugmentationResource/DeviceAugmentation 상태를 결합해 자원증강 recommendation/status를 계산하는 v1 prototype 후보 dashboard 수동 실행이나 per-click Job 생성이 아니라 controller/scheduler 정책 경로로 다룸
