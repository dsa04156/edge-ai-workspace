현재 데모 경로

상태 요약

2026-07-21 현재 중앙 EdgeX는 etri-ser0002-cgnmsb에 유지되고, 기존 커스텀 edge Agent 두 개는 퇴역했다. 따라서 지금은 중앙 기반은 준비되어 있지만 실제 물리 센서 수집 Device Service는 아직 없는 전환 상태다.

[현재 배포]

etri-ser0002-cgnmsb
  └─ edgex-system
      ├─ Core Keeper
      ├─ Core Metadata
      ├─ Core Data
      ├─ Core Command
      ├─ internal MessageBus (ClusterIP)
      ├─ PostgreSQL
      └─ ingest gateway (유지, 현재 edge client 없음)

edgex-edge
  ├─ Namespace
  └─ default-deny NetworkPolicy

KubeEdge
  └─ node/workload 관리

삭제된 운영 리소스:

  • edgex-edge-agent-jetson
  • edgex-edge-agent-sensehat
  • 두 Agent의 2GiB SQLite outbox PVC
  • Agent contract ConfigMap과 전용 egress NetworkPolicy
  • edge-telemetry-agent, etri-sensehat, sensehat-001을 재등록하던 Metadata bootstrap manifest

Agent 이름이 붙은 기존 Secret과 중앙 gateway 인증 설정은 다음 Device Service의 인증 경로가 확정될 때까지 유지한다. 이 Secret이 남아 있다는 사실은 Agent가 배포되어 있다는 뜻이 아니다.

다음 서비스 데모 경로

첫 수직 슬라이스는 Jetson의 Arduino 센서 1종이다.

Arduino sensor
  -> Serial endpoint on etri-dev0001-jetorn
  -> custom EdgeX Serial Device Service
  -> EdgeX Event / Reading
  -> 중앙 Core Data / PostgreSQL
  -> state-aggregator / dashboard

역할은 다음처럼 분리한다.

구성 책임
EdgeX Device Service Serial 연결, 재연결, 값 표준화, 상태, 지원 command
Device Profile resource 이름, value type, 단위, read/write 계약
Device 실제 또는 가상화된 장비 identity와 protocol binding
Core Metadata Device Service/Profile/Device inventory와 관리 상태
Core Data Event/Reading 저장과 deviceName 기반 조회
Core Command 검증된 command를 담당 Device Service로 전달
KubeEdge Device Service와 AI workload 배치·상태 관리
dashboard Metadata 상태와 최신 Event freshness를 통합 표시

MQTT와 MessageBus 경계

  • 중앙 edgex-messagebus는 stock EdgeX Core 내부 통신용 ClusterIP Service다.
  • MQTT-only 센서가 아니면 Jetson에 Mosquitto를 기본 배치하지 않는다.
  • Serial/Modbus/OPC-UA/I2C는 해당 Device Service가 직접 endpoint를 연다.
  • 고정 ClusterIP, PodIP, node IP로 endpoint를 우회하지 않는다. 서비스 접근은 Kubernetes/EdgeMesh DNS와 정상 서비스 디스커버리를 사용한다.
  • EdgeMesh 설정과 리소스는 이번 전환에서 변경하지 않는다.

데이터 조회 기준

Device Service가 연결된 뒤 워크플로우와 대시보드는 동일한 EdgeX device identity를 사용한다.

최신/과거 Event:
GET /api/v3/event/device/name/{deviceName}?limit={n}

inventory/state:
GET /api/v3/device/name/{deviceName}
GET /api/v3/deviceservice/name/{serviceName}

고주기 실시간 데이터와 카메라 frame을 Core Data GET polling으로 소비하지 않는다. 실시간 AI 입력은 Device Service의 검증된 stream 경로나 RTSP 직접 구독을 별도 설계하고, EdgeX에는 inventory, 상태, command와 필요한 Event/Reading을 남긴다.

현재 완료와 미완료

항목 상태
중앙 EdgeX Core/MessageBus/PostgreSQL 배치 유지
기존 custom edge Agent/PVC 운영 배치 퇴역
Jetson Arduino Serial Device Service 다음 구현, 미배포
Device Profile/Device 등록 다음 구현, 미등록
Core Data 실제 sensor Event/Reading 전환 중, 현재 완료 주장 금지
dashboard device freshness Device Service 연결 후 종단간 재검증 필요
command/actuator 별도 승인과 안전 검증 전까지 비활성
동적 workflow/offloading 후속 고도화

완료 판정

다음 증거가 한 번에 확보되어야 첫 서비스 데모가 완료된다.

  1. Device Service Pod가 지정 edge node에서 Ready다.
  2. Core Metadata에 Device Service/Profile/Device가 의도한 이름과 protocol로 존재한다.
  3. 실제 Arduino sample이 typed Event/Reading으로 Core Data에 저장된다.
  4. 연결 단절·복구 시 Device Service 상태와 재연결 동작이 검증된다.
  5. dashboard가 같은 device identity, 상태와 최신 Event freshness를 표시한다.
  6. command가 범위에 포함되면 허용 목록과 실패 동작까지 별도로 검증한다.
