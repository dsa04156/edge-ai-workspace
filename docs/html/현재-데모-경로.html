현재 데모 경로

Core Data telemetry freshness는 latest Event의 nanosecond origin을 sample 시각으로 계산하며 API 조회 시각이나 Kubernetes 상태로 대체하지 않는다.

상태 요약

2026-07-22 현재 중앙 EdgeX는 etri-ser0002-cgnmsb에 유지되고, 기존 커스텀 edge Agent 두 개는 퇴역했다. Jetson의 device-serial-jetson과 Raspberry Pi의 device-sensehat-raspi는 정식 EdgeX Device SDK 기반이며, 실제 Serial/I2C source를 각각 한 번 읽고 기능별 가상 Device 6개씩으로 전달한다. 첫 AI consumer는 같은 Jetson에 고정 배치하는 sensor-anomaly-demo다.

[현재 배포]

etri-ser0002-cgnmsb
  └─ edgex-system
      ├─ Core Keeper
      ├─ Core Metadata
      ├─ Core Data
      ├─ Core Command
      ├─ internal MessageBus (ClusterIP)
      ├─ PostgreSQL
      └─ ingest gateway (유지, 현재 edge client 없음)

edgex-edge
  ├─ device-serial-jetson @ etri-dev0001-jetorn
      ├─ /dev/arduino-001 (exact CharDevice mount)
      ├─ 공유 Serial reader 1개
      ├─ 1-resource Device Profile 6개
      ├─ virtual-*-001 Device 6개
      ├─ 10분 / 10,000 sample memory recent cache
      ├─ latest / recent Local Data API
      └─ 최소 ingress/egress NetworkPolicy
  ├─ sensor-anomaly-demo @ etri-dev0001-jetorn
      ├─ acceleration X/Y/Z Local Data 500ms polling
      ├─ 같은 origin frame join
      ├─ online Gaussian baseline 변화 탐지
      └─ read-only status/results API
  └─ device-sensehat-raspi @ etri-dev0003-raspi5
      ├─ /dev/i2c-1 (exact CharDevice mount)
      ├─ RTIMULib reader process 1개
      ├─ temperature/humidity/pressure/compass/orientation/gyroscope Profile 6개
      ├─ env-sensehat-* / imu-sensehat-* Device 6개
      ├─ 10분 / 10,000 sample memory recent cache
      ├─ latest / recent Local Data API
      └─ 최소 ingress/egress NetworkPolicy

KubeEdge
  └─ node/workload 관리

삭제된 운영 리소스:

  • edgex-edge-agent-jetson
  • edgex-edge-agent-sensehat
  • 두 Agent의 2GiB SQLite outbox PVC
  • Agent contract ConfigMap과 전용 egress NetworkPolicy
  • edge-telemetry-agent, etri-sensehat, sensehat-001을 재등록하던 Metadata bootstrap manifest

Agent 이름이 붙은 기존 Secret과 중앙 gateway 인증 설정은 중앙 구성 호환을 위해 남아 있지만 현재 Serial/I2C 경로에는 참여하지 않는다. 이 Secret이 남아 있다는 사실은 Agent가 배포되어 있다는 뜻이 아니다.

현재 서비스 데모 경로

현재 수직 슬라이스는 Jetson Arduino Serial과 Raspberry Pi Sense HAT I2C 두 종류다. Jetson acceleration 세 Device에는 첫 고정 AI consumer가 연결된다. 이는 Argo CD가 관리하는 명시적 Deployment이며 Workflow Builder의 동적 실행을 뜻하지 않는다.

Arduino sensor
  -> /dev/serial/by-id/... on etri-dev0001-jetorn
  -> /dev/arduino-001 in device-serial-jetson
  -> resource route / 6 virtual Devices
     +-> acceleration X/Y/Z memory recent cache
     |   -> sensor-anomaly-demo @ same Jetson (500ms polling)
     |   -> origin join -> online baseline score
     |   -> state-aggregator / service demo dashboard
  -> Device별 EdgeX async Event / Reading
  -> 중앙 internal MessageBus
  -> Core Data / PostgreSQL
  -> state-aggregator / dashboard

Sense HAT v1
  -> /dev/i2c-1 on etri-dev0003-raspi5
  -> RTIMULib reader in device-sensehat-raspi
  -> resource group route / 6 virtual Devices
     +-> memory recent cache -> same-node consumer (read-only 계약, 현재 별도 consumer 없음)
  -> Device별 EdgeX async Event / Reading
  -> 중앙 internal MessageBus
  -> Core Data / PostgreSQL
  -> state-aggregator / dashboard

역할은 다음처럼 분리한다.

구성 책임
EdgeX Device Service Serial 또는 I2C endpoint 단독 소유, sample 검증, resource fan-out, reader 재시작/재연결, 상태, recent cache/Local Data API, read-only command
Device Profile resource 이름, value type, 단위, read/write 계약
Device Serial 6개와 Sense HAT environment/IMU 6개의 가상 identity와 물리 source binding
Core Metadata Device Service/Profile/Device inventory와 관리 상태
Core Data Event/Reading 저장과 deviceName 기반 조회
Core Command 총 12개 가상 Device의 read-only GET을 담당 Device Service로 전달
KubeEdge Device Service와 AI workload 배치·상태 관리
sensor-anomaly-demo 세 acceleration Device의 같은-origin raw frame을 로컬에서 읽고 변화 점수·상태를 read-only API로 제공
state-aggregator EdgeX raw authority의 inventory/latest/history와 service demo derived result를 서로 다른 endpoint에서 failure-isolated 조회
dashboard Metadata 상태, 최신 Event freshness, 선택 Device의 저장 이력, Jetson service demo binding/result를 구분해 표시

MQTT와 MessageBus 경계

  • 중앙 edgex-messagebus는 stock EdgeX Core 내부 통신용 ClusterIP Service이며 Device Service의 async Event를 Core Data로 전달한다.
  • MQTT-only 센서가 아니면 Jetson에 Mosquitto를 기본 배치하지 않는다.
  • Serial/Modbus/OPC-UA/I2C는 해당 Device Service가 직접 endpoint를 연다.
  • 고정 ClusterIP, PodIP, node IP로 endpoint를 우회하지 않는다. 서비스 접근은 Kubernetes/EdgeMesh DNS와 정상 서비스 디스커버리를 사용한다.
  • EdgeMesh 설정과 리소스는 이번 전환에서 변경하지 않는다.

데이터 조회 기준

Device Service가 연결된 뒤 워크플로우와 대시보드는 동일한 EdgeX device identity를 사용한다.

최신/과거 Event:
GET /api/v3/event/device/name/{deviceName}?limit={n}

dashboard용 저장 이력:
GET /state/devices/{deviceName}/telemetry?window=-30m&limit=1000

inventory/state:
GET /api/v3/device/name/{deviceName}
GET /api/v3/deviceservice/name/{serviceName}

현재값 command:
GET /api/v3/device/name/{deviceName}/{commandName}

edge node 로컬 최신값/최근 구간:
GET /api/v3/localdata/device/name/{deviceName}/resource/name/{resourceName}/latest
GET /api/v3/localdata/device/name/{deviceName}/resource/name/{resourceName}?from={origin_ns}&to={origin_ns}&limit={n}

Local Data API는 최근 10분·시계열별 최대 10,000 sample의 휘발성 cache만 조회하며 중앙 history로 fallback하지 않는다. 첫 서비스 데모는 이 API를 500ms polling해 실시간에 가까운 저주기 센서 입력을 소비한다. 이는 push stream이 아니며 고주기 진동 연속 stream과 카메라 frame을 같은 REST polling으로 소비하지 않는다. 그런 입력은 Device Service의 검증된 stream 경로나 RTSP 직접 구독을 별도 설계하고, EdgeX에는 inventory, 상태, command와 필요한 Event/Reading을 남긴다.

dashboard 저장 그래프는 이 로컬 cache가 아니라 state-aggregator가 중앙 Core Data API를 조회한 결과다. 기본 30분과 5분·1시간·24시간 범위를 제공하며, 최신 1,000 Event 상한 때문에 요청한 전체 범위를 모두 포함하지 않을 수 있다. 화면은 반환 Reading 수와 실제 첫/마지막 timestamp를 함께 표시하고 PostgreSQL에 직접 SQL을 실행하지 않는다.

Core Data의 device Event endpoint는 시간 query를 지원하지 않으므로 state-aggregator가 최신 1,000 Event를 offset/limit으로 읽고 Event origin 기준으로 선택 범위를 거른다. 따라서 5분 조회는 실제 5분 안의 Event만 반환하고, 24시간 조회는 최신 1,000 Event가 덮는 실제 구간까지만 표시한다.

Workflow client label을 선택하는 NetworkPolicy는 manifest에 있지만 현재 테스트베드의 Flannel CNI가 이를 집행하지 않는다. Local Data API는 unauthenticated read-only endpoint이며 label 없는 Pod의 live 접근도 확인됐다. 따라서 현재 label은 보안 경계가 아니고, 실제 차단에는 정책 지원 CNI 또는 mTLS/애플리케이션 인증이 필요하다.

완료 판정

정상 수집 경로는 다음 1, 2, 3, 5와 read-only command까지 같은 배포에서 확인했다. 완전한 장애·복구 데모를 PASS로 선언하려면 4를 실제 장치에서 추가 확인한다.

  1. Device Service Pod가 지정 edge node에서 Ready다.
  2. Core Metadata에 Device Service/Profile/Device가 의도한 이름과 protocol로 존재한다.
  3. 실제 Arduino와 Sense HAT sample이 typed Event/Reading으로 Core Data에 저장된다.
  4. 연결 단절·복구 시 Device Service 상태와 재연결 동작이 검증된다.
  5. dashboard가 같은 device identity, 상태와 최신 Event freshness를 표시한다.
  6. command가 범위에 포함되면 read-only와 write/actuator를 구분하고 허용 목록과 실패 동작까지 별도로 검증한다.
  7. sensor-anomaly-demo와 중앙 /state/service-demo가 같은 세 Device identity와 증가하는 실제 origin을 반환한다.
