현재 데모 경로

현재 checkout에서 재현 가능한 데이터 흐름을 설명한다. live cluster에서 보였던 별도 workload는 이 문서의 구현 증거로 자동 승격하지 않는다.

1. 한 줄 흐름

I2C/Serial fixture 또는 Protocol Adapter
  → telemetry_plane.edge.EdgeAgent
  → SQLite WAL outbox
  → HTTPS/mTLS edgex-ingest-gateway
  → EdgeX Core Data REST
  → PostgreSQL
  → state-aggregator
  → dashboard / AI consumer

2. 실제 코드와 배포 위치

단계 코드/manifest 확인할 것
중앙 배포 edgex/k8s/kustomization.yaml server2 중앙 stack과 edge overlay가 함께 render되는가
중앙 gateway edgex/k8s/base/server/gateway.yaml HTTPS 8443, Core Data URL, TLS Secret, NetworkPolicy
중앙 EdgeX edgex/k8s/base/server/core.yaml Keeper/Metadata/Data/Command/MessageBus/PostgreSQL
엣지 계약 edgex/k8s/base/edge-agent/common.yaml gateway URL, outbox path, source mode, command disabled
엣지 배치 edgex/k8s/overlays/testbed/sensor-gateways/*.yaml nodeSelector, PVC, mTLS Secret, direct adapter port
수집 agent edgex/telemetry-plane/src/telemetry_plane/edge.py source ACK 전에 SQLite enqueue, replay, health/metrics
outbox edgex/telemetry-plane/src/telemetry_plane/outbox.py WAL, FIFO stream, lease/token, persisted ACK 후 삭제
gateway edgex/telemetry-plane/src/telemetry_plane/gateway.py 인증, idempotency, Core Data response reconciliation
조회 API edge-orch/state-aggregator/app/main.py, app/edgex.py Metadata inventory와 Core Data event를 정규화

3. 중앙 EdgeX 서비스

중앙 namespace는 edgex-system이다.

서비스 역할 외부 소비
Core Keeper 공통 설정·서비스 registry 내부 bootstrap
Core Metadata Device/Profile/Device Service inventory state-aggregator
Core Data Event/Reading 저장·조회 gateway, state-aggregator, AI consumer
Core Command 명령 API 기반 현재 command 경로는 disabled
MessageBus EdgeX 내부 MQTT runtime 센서 northbound 전송 아님
PostgreSQL Core Data 영구 DB EdgeX 내부 storage
ingest gateway edge agent의 HTTPS 진입점 Core Data REST 저장 확인 후 ACK

4. Edge agent 수명주기

  1. Adapter 또는 direct source가 EdgeX v3 Event를 만든다.
  2. agent가 schema·type·timestamp·ID를 검증한다.
  3. enqueue_event()가 SQLite에 commit된 뒤 source callback이 성공한다.
  4. uplink가 gateway에 Event ID와 인증 정보를 보낸다.
  5. gateway가 (edge_id, event_id)를 inbox에서 예약하고 Core Data에 저장한다.
  6. Core Data가 신규 저장 또는 동일 payload를 확인하면 gateway가 persisted ACK를 반환한다.
  7. agent는 ACK 후에만 outbox row를 delivered 처리한다.
  8. 장애·timeout·충돌은 재시도 또는 명시적 rejected 상태로 남긴다.

5. 조회 API

curl http://state-aggregator:8000/state/devices
curl 'http://state-aggregator:8000/state/devices/sensehat-001/telemetry?window=-30m&limit=300'
curl http://state-aggregator:8000/state/dashboard
curl http://state-aggregator:8000/state/nodes
curl http://state-aggregator:8000/state/summary

/state/devices는 Core Metadata의 Device를 읽고 Core Data의 latest Event를 결합한다. deviceName, profileName, serviceName, protocols, adminState, operatingState는 EdgeX 원본을 보존한다. connection_state, device_service_available, telemetry_freshness, overall_status는 aggregator가 계산한 read model이다.

/state/devices/{device_id}/telemetry는 Core Data의 Event/Reading history를 반환한다. 입력 window는 -30m, -1h 같은 제한된 형식이며 임의 SQL이나 DB 직접 조회를 노출하지 않는다.

6. 현재 확인 가능한 fixture

edgex/k8s/base/server/config/metadata-contract.json에는 sensehat-001과 etri-sensehat profile이 정의되어 있다. 이 fixture는 platform contract 검증용이며 옥동의 최종 PLC/MES 장비 목록이 아니다.

실장비·서비스로 승격하려면 다음을 별도로 기록한다.

  • physical endpoint와 소유 노드
  • Device Profile과 resource schema
  • adapter 입력·출력과 sample 주기
  • Core Data Event의 첫 수신
  • 통신 단절·재연결·중복 replay 결과
  • AI 서비스가 읽는 입력 window와 결과 schema

7. 현재 제외되는 실행

  • dashboard에서 Kubernetes apply/delete/restart
  • dashboard에서 EdgeX Device/Profile 수정
  • workflow 화면에서 실제 container 실행
  • runtime migration/offloading
  • command/actuator mutation
  • RTSP frame을 agent 또는 Core Data로 전송

이 항목은 설계 문서에서만 다루며, 현재 데모의 성공 기준에는 포함하지 않는다.
