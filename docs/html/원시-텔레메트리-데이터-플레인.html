원시 텔레메트리 데이터 플레인

목적

이 문서는 센서·PLC·장비의 raw telemetry가 엣지에서 중앙 EdgeX/PostgreSQL까지 이동하는 실제 계약을 정의한다. AI 서비스와 dashboard는 이 경로의 consumer이며 별도 physical authority가 아니다.

권위와 책임

단계 권위/소유자 저장·전달
물리 입력 Protocol Adapter 장비 연결, framing, protocol error
표준 Event EdgeX v3 contract deviceName, profileName, sourceName, origin, typed readings
엣지 내구성 edge-telemetry-agent SQLite WAL, FIFO stream, retry lease
중앙 수신 edgex-ingest-gateway edge 인증, idempotency inbox, Core Data 저장 확인
장기 저장 EdgeX Core Data/PostgreSQL Event/Reading history
소비 read model state-aggregator inventory + latest event + freshness

Event 계약

최소 canonical Event는 다음 필드를 요구한다.

{
  "apiVersion": "v3",
  "id": "stable-event-id",
  "deviceName": "sensehat-001",
  "profileName": "etri-sensehat",
  "sourceName": "humidity",
  "origin": 1784016000000000000,
  "readings": [
    {
      "deviceName": "sensehat-001",
      "profileName": "etri-sensehat",
      "resourceName": "humidity",
      "valueType": "Float64",
      "value": 45.3,
      "origin": 1784016000000000000
    }
  ],
  "tags": {"node_id": "etri-dev0003-raspi5"}
}

Agent는 apiVersion=v3, non-empty identity, typed value, finite number, origin timestamp, unique Event ID를 검증한다. Core Data가 만든 created, modified, Reading ID는 canonical fingerprint에 넣지 않는다.

SQLite outbox 계약

EdgeOutbox는 다음을 보장한다.

  • SQLite WAL과 synchronous=FULL로 source ACK 전 commit
  • (stream_device, stream_source, stream_sequence) 기준 FIFO
  • 재시도 lease와 token fencing으로 오래된 worker의 ACK 차단
  • 동일 Event ID·동일 payload는 idempotent
  • 동일 Event ID·다른 payload는 conflict
  • 용량 초과는 silently drop하지 않고 OutboxCapacityExceeded로 기록
  • 중앙 persisted ACK 전에는 row를 제거하지 않음

outbox는 최근 cache나 장기 분석 DB가 아니다. 중앙 연결 실패를 견디는 전달 버퍼다. 오래된 telemetry를 장기 조회하려면 Core Data/PostgreSQL API를 사용한다.

HTTPS gateway 계약

gateway는 edgex-system namespace에서 8443/TLS로 동작한다.

  1. edge ID와 HMAC/mTLS credential을 검증한다.
  2. Event를 canonicalize하고 inbox에 예약한다.
  3. 같은 (edge_id,event_id) payload면 기존 처리 상태를 재사용한다.
  4. Core Data v3 AddEvent를 호출한다.
  5. Core Data가 201 또는 동일 Event readback을 반환한 경우만 persisted로 표시한다.
  6. conflict·invalid schema·Core Data 장애를 구분해 응답한다.

gateway가 HTTP 200을 반환했다는 사실만으로 DB 영구 저장을 가정하지 않는다. agent가 삭제할 수 있는 ACK는 Core Data reconciliation이 끝난 persisted ACK뿐이다.

장애 흐름

장애 엣지 동작 중앙 동작 운영 판정
장비 read timeout Adapter error, 다음 sample 재시도 Event 없음 source/adapter 점검
중앙 DNS/TLS 실패 outbox pending 유지 gateway 접근 로그 없음 outbox oldest age 확인
gateway 5xx lease 만료 후 재시도 inbox posting/recover Core Data·gateway 점검
Event schema 오류 rejected row와 reason 보존 저장하지 않음 profile/adapter 계약 수정
동일 ID 다른 payload conflict 기존 Event 보호 producer ID 생성 점검
PostgreSQL 장애 agent는 pending 유지 Core Data 저장 실패 중앙 DB 복구 후 replay

중앙 EdgeX MessageBus와 MQTT

중앙 MessageBus는 Core Keeper/Metadata/Data/Command가 사용하는 EdgeX 내부 runtime이다. agent의 northbound HTTPS와 SQLite outbox를 대체하지 않는다.

MQTT는 다음 경우에만 선택한다.

  • 장비가 MQTT만 제공한다.
  • 노드 내부 여러 consumer가 명시적으로 pub/sub를 요구한다.

Modbus, OPC-UA, Serial, I2C 직접 입력과 HTTPS northbound에는 MQTT broker가 필수가 아니다.

데이터 보존 경계

Recent memory/cache     → 로컬 추론용, 별도 구현
SQLite outbox            → 중앙 미전송 Event, 장애 기간 보존
Core Data/PostgreSQL     → 장기 Event/Reading 이력
AI result store          → 모델 결과·알림·KPI

한 DB에 raw telemetry와 workflow 상태를 모두 넣지 않는다. state-aggregator는 Core Data를 직접 권위로 읽고, optional InfluxDB resource-profile recording은 physical telemetry 저장소가 아니다. InfluxDB latest 설명에서는 _start/_stop은 Flux query window, _time은 실제 sample timestamp, 최신성은 device-level latest sample 기준이며 property별 freshness를 보장하지 않는다고 명시한다.
