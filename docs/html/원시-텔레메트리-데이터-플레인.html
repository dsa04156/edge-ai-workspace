HTTPS 기반 원시 텔레메트리 데이터 플레인

목적

이 문서는 물리 노드의 Protocol Adapter가 만든 canonical EdgeX Event를 SQLite에 먼저 보존하고, HTTPS/mTLS로 중앙 EdgeX Core Data와 PostgreSQL까지 전달하는 현재 권위 경로를 고정한다.

핵심 원칙은 다음과 같다.

  • 센서 전송에 MQTT를 기본 요구하지 않는다.
  • 중앙 연결 실패가 물리 수집을 중단시키지 않도록 edge outbox에 먼저 기록한다.
  • gateway 수신이 아니라 Core Data의 PostgreSQL 저장 결과를 outbox 삭제 기준으로 사용한다.
  • EdgeX Core Metadata와 Core Data를 inventory/schema와 telemetry의 중앙 authority로 유지한다.
  • RTSP frame은 telemetry plane에 넣지 않는다.

현재 권위 경로

[물리 노드 / EdgeCore]

센서 / PLC / 장비
  -> Protocol Adapter
     - Modbus / OPC-UA / Serial / I2C 직접 수집
     - 또는 MQTT-only 장비용 optional MQTT adapter
  -> canonical EdgeX v3 Event
  -> edge-telemetry-agent
  -> SQLite outbox
       |
       | HTTPS + mTLS + HMAC
       v

[Edge AI 서버: etri-ser0002-cgnmsb]

edgex-ingest-gateway
  -> EdgeX Core Data REST
  -> PostgreSQL
  -> 중앙 Application Service / AI consumer / dashboard

카메라의 RTSP frame은 요청 시 Workflow Pod가 직접 구독한다. 카메라 연결 상태, 추론 결과와 운영 metadata만 필요할 때 canonical Event로 이 경로에 넣는다.

MessageBus와 MQTT의 위치

구분 현재 역할 필수 여부
물리 노드 local MQTT broker MQTT-only 장비 또는 local pub/sub compatibility 입력 조건부
agent northbound HTTPS/mTLS로 gateway에 Event 전송 필수
중앙 EdgeX internal MessageBus stock EdgeX Core의 중앙 런타임과 후속 consumer 통합 현재 중앙 배포에 필요
SQLite outbox 중앙 장애 중 Event 보존과 복구 후 replay 필수

중앙 edgex-messagebus는 센서가 서버로 데이터를 보내는 경로가 아니다. 물리 노드에는 기본 broker를 배치하지 않는다. 현재 root render에는 MQTT-mode agent, device-mqtt, edge-local broker가 없으며 모든 edge northbound는 HTTPS다.

EdgeX 내부 MessageBus provider를 다른 구현으로 교체하는 것은 별도 중앙 런타임 변경이다. 이 선택과 엣지 northbound가 HTTPS인 것은 서로 독립이다.

현재 배포된 검증 fixture

Sense HAT (I2C)
  -> edge-device/publishers/sensehat_publisher.py
  -> http://127.0.0.1:18080/v1/events
  -> edge-telemetry-agent
  -> /var/lib/edgex/outbox/outbox.db
  -> https://edgex-ingest-gateway.edgex-system.svc.cluster.local:8443
  -> Core Data / PostgreSQL
  • 배치 노드: etri-dev0003-raspi5
  • EdgeX Device: sensehat-001
  • Device Profile: etri-sensehat
  • source: temperature, humidity, pressure, compass, orientation, gyroscope
  • local ingress: host-network namespace의 loopback에만 bind
  • local MQTT broker: 사용하지 않음

이 Sense HAT identity와 publisher는 현재 연결 검증에 사용한 fixture다. 사용자가 교체할 수 있으며 시스템의 고정 입력, MQTT 정책 또는 완료 기준으로 다루지 않는다. 장비가 Serial/Modbus/OPC-UA/I2C로 직접 연결되면 adapter가 Event를 만들어 loopback agent API로 전달한다. MQTT-only 장비는 별도 adapter와 broker 필요성을 검증한 뒤 같은 loopback 계약에 연결한다.

Event와 저장 계약

Protocol Adapter는 최소한 다음 필드를 가진 Event를 만든다.

{
  "apiVersion": "v3",
  "id": "4b722578-d997-47f2-8685-88cc7161e80d",
  "deviceName": "sensehat-001",
  "profileName": "etri-sensehat",
  "sourceName": "humidity",
  "origin": 1784516400000000000,
  "tags": {
    "edge_node_id": "etri-dev0003-raspi5",
    "source_adapter": "i2c"
  },
  "readings": [
    {
      "deviceName": "sensehat-001",
      "profileName": "etri-sensehat",
      "resourceName": "humidity",
      "valueType": "Float64",
      "value": 45.3,
      "origin": 1784516400000000000
    }
  ]
}

agent는 Event 전체를 엄격히 검증한다. 같은 Event ID와 같은 canonical payload는 idempotent duplicate로 ACK하고, 같은 ID의 다른 payload는 409 event_id_conflict로 거절한다. outbox 용량을 넘으면 507 outbox_full을 반환하므로 adapter가 sample을 저장됐다고 오인하지 않는다.

전달과 장애 동작

  1. adapter가 agent의 loopback POST /v1/events를 호출한다.
  2. agent가 Event를 SQLite WAL outbox에 transaction commit한다.
  3. commit 성공 뒤 202 queued와 정확한 event_id를 반환한다.
  4. uploader가 device/source stream별 FIFO로 gateway에 재전송한다.
  5. gateway가 mTLS client identity와 edge별 HMAC을 검증한다.
  6. gateway가 Core Data POST /api/v3/event/{service}/{profile}/{device}/{source}를 호출한다.
  7. Core Data가 PostgreSQL 저장 뒤 반환한 ID를 gateway가 확인한다.
  8. gateway가 정확한 persisted ACK를 반환한 뒤에만 agent가 outbox row를 삭제한다.

응답이 유실되어 같은 ID가 재전송되면 gateway는 Core Data의 기존 Event를 다시 읽고 canonical fingerprint가 같은 경우만 저장 완료로 조정한다. ID만 같고 내용이 다르면 quarantine 대상 충돌로 처리한다.

중앙 gateway, Core Data 또는 네트워크가 중단되면 outbox row를 유지하고 exponential backoff로 재시도한다. 노드별 PVC는 2GiB이고 논리 admission 한도는 기본 1GiB다. 이 버퍼는 영구 archive가 아니며 장기간 장애와 노드 디스크 손실을 보호하는 백업도 아니다.

Metadata와 상태 권위

edgex-metadata-bootstrap Job이 다음 순서로 이름 기반 idempotent 등록을 수행한다.

  1. 논리 Device Service edge-telemetry-agent
  2. Device Profile
  3. Device

현재 live contract는 임시 검증 fixture인 sensehat-001 / etri-sensehat 1개만 포함한다. arduino-001, etri-uno-mqtt와 Jetson MQTT device는 제거되었다. inventory와 schema는 Core Metadata, telemetry와 freshness는 Core Data Event/Reading이 권위다. Kubernetes node placement는 display-only 진단이다.

현재 command 실행은 COMMAND_ENABLED=false다. Metadata의 read-only command grouping을 actuator 제어 완료로 해석하지 않는다.

Trust boundary와 secret

경계 보호 수단 실패 동작
host adapter -> agent host-network loopback 127.0.0.1:18080, 엄격한 Event schema, 1MiB 제한 외부 인터페이스에는 bind하지 않음
edge agent -> gateway TLS server verification, mTLS client cert, edge별 HMAC ACK하지 않고 outbox 보존
gateway -> Core Data cluster DNS/ClusterIP, 제한된 REST path retryable failure로 agent에 전달
Core Data -> PostgreSQL 중앙 namespace 내부 service와 Secret 기반 DB 설정 Core Data 성공 전 persisted ACK 금지

필요한 Secret:

  • edgex-ingest-gateway-tls
  • edgex-telemetry-plane-credentials
  • edgex-telemetry-edge-auth
  • edge별 *-credentials
  • edge별 *-gateway-mtls
  • edgex-postgres-credentials

private key, HMAC secret, DB URL은 ConfigMap이나 image에 넣지 않는다. 운영 적용 전 edgex/k8s/scripts/preflight-runtime-secrets.sh로 key와 namespace를 점검한다.

검증 기준

현재 자동 검증:

  • telemetry-plane unit/integration test: source mode, outbox, exact ACK, retry, gateway idempotency, Metadata bootstrap
  • Kustomize manifest test: 중앙/edge placement, direct-only edge render, loopback host network, Secret 참조, immutable image, NetworkPolicy
  • adapter fixture test: canonical Event mapping과 local durable queue ACK 검증
  • root Kustomize render: device-mqtt workload 부재

live 완료 판정에는 다음 증거가 추가로 필요하다.

  • 새 agent/gateway image digest 배포
  • 실제 또는 승인된 adapter sample의 202 queued
  • Core Data의 동일 Event ID readback
  • gateway 중단 중 outbox 증가와 복구 후 drain
  • Core Metadata의 Device/Profile과 dashboard freshness 표시

Sense HAT publisher의 교체 여부는 telemetry plane 자체의 완료 판정과 분리한다.
