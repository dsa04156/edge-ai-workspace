프로젝트 배경

한 줄 정의

이 저장소는 옥동 현장의 PLC·MES·센서 데이터를 EdgeX 기반 데이터 플레인과 KubeEdge 기반 엣지 노드 운영에 연결하고, 생산품질 판별·유압펌프/모터 이상감지 PoC를 운영 화면에서 확인하기 위한 혼합 디바이스 엣지 AI 플랫폼이다.

현재 우선순위는 전체 동적 오케스트레이션을 한 번에 완성하는 것이 아니라, 수집→저장→상태 해석→서비스 데모라는 수직 슬라이스를 실제 근거와 함께 안정화하는 것이다.

대상 환경

구분 예시 역할
중앙 엣지 AI 서버 EdgeX Core, PostgreSQL, ingest gateway, state-aggregator, AI consumer
Jetson 노드 현장 adapter와 엣지 workload 대상
Raspberry Pi 5 I2C 센서와 경량 workload 대상

가상 장비 simulator/replay와 후속 virtual-device abstraction

2026년도 2차년도 목표

옥동 PoC의 우선 서비스는 다음 두 가지다.

  1. PLC·MES·센서 데이터를 이용한 생산품질 양품·불량 판별
  2. 메인·보조 유압펌프 및 모터의 이상 감지

ETRI가 책임지는 플랫폼 증거는 실시간 수집, 표준 Event, 장애 버퍼·재전송, AI 서비스 입력 계약, 엣지·서버 배치 검토, 통합 상태·알림 화면, 단위·통합 시험이다. 목표·월별 산출물·완료 gate는 2026년도 2차년도 ETRI 실행계획을 기준으로 한다.

현재 권위 데이터 경로

물리 센서·PLC·장비
  -> Protocol Adapter
  -> canonical EdgeX v3 Event
  -> edge-telemetry-agent / SQLite WAL outbox
  -> HTTPS/mTLS ingest gateway
  -> EdgeX Core Data / PostgreSQL
  -> state-aggregator / dashboard / AI consumer

Kubernetes/KubeEdge
  -> 엣지 노드·워크로드 배치와 자원 진단
  • Device/Profile, adminState, operatingState의 권위는 중앙 EdgeX Core Metadata다.
  • Event/Reading과 freshness의 권위는 중앙 EdgeX Core Data와 PostgreSQL이다.
  • edge agent의 SQLite는 중앙 영구 저장 전 장애 버퍼다. 장기 telemetry 저장소나 inventory registry가 아니다.
  • 중앙 MessageBus는 EdgeX Core 내부 runtime이다. 센서에서 서버로 보내는 northbound 경로나 edge 장애 버퍼가 아니다.
  • MQTT broker는 MQTT-only 장비 또는 명시적 local pub/sub가 필요할 때만 별도 검증 후 추가한다.
  • KubeEdge Device/DeviceModel/DeviceStatus와 MapperFramework는 legacy/reference이며 EdgeX와 병행 authority나 fallback이 아니다.

현재 checkout에서 확인되는 범위

  • root 배포 진입점은 edgex/k8s/kustomization.yaml이다.
  • 중앙 서버 manifest는 Core Keeper/Metadata/Data/Command, 내부 MessageBus, PostgreSQL, ingest gateway를 묶는다.
  • edge overlay는 direct-mode agent, SQLite outbox PVC, mTLS/edge-auth Secret과 노드 배치를 정의한다.
  • metadata-contract.json의 대표 fixture는 sensehat-001/etri-sensehat이다.
  • state-aggregator는 Core Metadata inventory와 Core Data latest Event를 결합해 /state/devices, /state/dashboard, /state/summary를 제공한다.
  • dashboard workflow는 stage/binding validation과 execution-plan preview를 브라우저 안에서만 수행한다.

이 범위는 “모든 프로토콜, AI 모델, 자동 등록, runtime migration이 완료됐다”는 뜻이 아니다. 실제 endpoint, profile, typed Event, 장애 시험과 live 증거가 없는 항목은 후속 범위로 표시한다.

등록·상태 판정 원칙

물리 장비는 임의 포트나 topic만으로 Core Metadata에 자동 생성하지 않는다. Device Profile과 Protocol Adapter 계약을 확인하고 등록한다. availability는 다음 순서로 계산한다.

  1. adminState=LOCKED 또는 operatingState=DOWN이면 unavailable.
  2. 운영 상태가 UNKNOWN이면 degraded.
  3. UP이어도 최신 Core Data Event가 없거나 stale이면 degraded.
  4. 잠기지 않았고 UP이며 최신 Event가 fresh일 때만 available.

상세 규칙은 물리 디바이스 상태 정책과 대시보드 판단 정책을 따른다.

후속 범위와 제외

후속 단계에서 Serial·I2C 외 Modbus·OPC-UA·MQTT·ONVIF/RTSP를 각각 adapter/profile/실제 endpoint/typed telemetry/consumer 증거로 승격한다. RTSP 원본 frame은 Core Data에 저장하지 않고 요청 시 Workflow Pod가 직접 구독한다.

다음은 현재 완료로 표현하지 않는다.

  • 운영자 승인 없는 자동 등록
  • 임의 container image 실행
  • 네트워크 전체 자동 스캔
  • dashboard에서 Kubernetes/EdgeX mutation 또는 actuator command
  • dynamic workflow execution, offloading, runtime migration, LLM 전역 제어

과거 구현과 연구 자료는 docs/superpowers/와 docs/archive/에 보존하며, 현재 기능의 근거로 승격하지 않는다.
