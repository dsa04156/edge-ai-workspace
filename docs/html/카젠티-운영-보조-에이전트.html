카젠티 운영 보조 에이전트 PoC

현재 상태: 2026-07-21 custom edge Agent와 aggregate sensehat-001 bootstrap은 퇴역했다. device-serial-jetson과 device-sensehat-raspi는 physical arduino-001, sensehat-001을 기능별 가상 Device 6개씩으로 분리한다. Assistant는 live API를 다시 조회해 상태를 요약하며 문서 예시값을 현재값으로 사용하지 않는다.

목적

Kagenti operator assistant는 EdgeX-backed state-aggregator API를 read-only로 조회해 한국어 운영 요약과 점검 순서를 제안한다. 자율 제어, 자동 복구 또는 배치 계층이 아니다.

EdgeX state -> state-aggregator -> read-only operator summary -> human operator

물리 디바이스 정보의 권위는 EdgeX Core Metadata와 Core Data다.

Core Data telemetry freshness는 latest Event의 nanosecond origin을 sample 시각으로 계산한다. Assistant는 API 조회 시각이나 Kubernetes 상태로 이 값을 보정하지 않는다.

현재 endpoint

GET /state/operator-assistant

참조 API:

/state/dashboard
/state/devices
/state/nodes
/state/summary
/state/virtual-resources

/state/nodes와 resource 정보는 workload 진단용이다. 물리 device availability 판단에는 사용하지 않는다.

응답 구조

field 의미
generated_at 요약 생성 시각
assistant_name PoC assistant 이름
mode read_only
summary_ko Core Metadata 등록·available 수와 Core Data freshness 요약
focus_devices[] degraded/unavailable device 중 우선 확인 대상
recommended_actions[] 사람이 수행할 점검 순서 제안
guardrails[] mutation 금지 경계
source_endpoints[] 요약에 사용한 read-only API

/state/devices에서 읽는 계약

Assistant와 dashboard는 다음 EdgeX-backed 필드를 사용한다.

name
source
profile_name
device_service_name
protocol_names
admin_state
operating_state
connection_state
device_service_available
latest_event_timestamp
latest_readings[]

source=edgex이며, profile/논리 수집 서비스/protocol/admin/operating 정보는 Core Metadata에서 온다. Event timestamp, source_name, resource_name, value는 Core Data에서 온다. node_name은 선택적 진단 정보다.

운영자 요약 예시

EdgeX 기반 read-only 운영 보조 요약입니다.
Core Metadata 등록 device 12개 중 available device 12개,
우선 점검 대상 0개입니다.
Core Data event freshness 비율은 1.0입니다.

수치 예시는 payload 형식 설명용이며 live 환경의 현재 수치를 주장하지 않는다.

Focus device 예시

{
  "name": "virtual-temperature-001",
  "node_name": "etri-dev0001-jetorn",
  "status": "degraded",
  "reason": "EdgeX device service is UP but latest Core Data event is stale",
  "admin_state": "UNLOCKED",
  "operating_state": "UP",
  "device_service_available": true,
  "telemetry_freshness": "stale"
}

Focus payload는 /state/devices 계약의 운영 판단 필드만 요약한다. 상세 조사에서는 원본 항목의 source, profile, 논리 수집 서비스, protocol, latest_event_timestamp, latest_readings를 함께 확인한다.

Recommended action 예시

virtual-temperature-001: 공유 Serial endpoint, device-serial-jetson, 중앙 MessageBus와 Core Data 최신 event를 순서대로 확인한다.

추천 규칙:

  • admin_state=LOCKED: Core Metadata admin 정책을 확인한다.
  • operating_state가 UP이 아니거나 device_service_available=false: Device Service 등록, Pod health와 physical Serial/I2C connection을 확인한다.
  • telemetry_freshness가 fresh가 아님: Core Data 최신 event, profile resource, event source를 확인한다.
  • 필요할 때에만 node/workload placement를 별도 진단한다.

Agent는 점검 순서를 제안할 뿐 명령을 실행하지 않는다.

서비스 영향 설명

Assistant가 설명하는 binding은 다음 흐름이다.

EdgeX Device
  -> protocol-specific EdgeX Device Service
  -> central internal MessageBus -> Core Data / PostgreSQL
  -> AI service / storage / dashboard

운영자는 profile, protocol, Device Service 상태와 Core Data source/resource를 통해 어느 consumer가 영향을 받는지 확인한다. 이 관계는 workflow orchestration이나 자동 placement가 아니다.

Guardrail

금지 범위:

  • EdgeX Core Metadata device/profile 수정
  • Protocol Adapter 또는 telemetry agent 재시작·재배포
  • MQTT 또는 다른 protocol command 발행
  • Kubernetes 리소스 생성·수정·삭제
  • actuator 직접 제어
  • 자동 placement/offloading/workflow 실행
  • LLM 기반 전역 제어

허용 범위:

  • state-aggregator read-only API 조회
  • EdgeX KPI와 device 상태 요약
  • degraded/unavailable device 목록화
  • Core Data event freshness와 latest readings 설명
  • runbook 기반 점검 순서 제안
  • AI/storage/dashboard consumer 영향 범위 설명

Workflow designer와 assistant preview는 dry-run/no-mutation 경계를 유지한다.

현재 physical 범위

2026-07-21 현재 기존 loopback Agent/SQLite/HTTPS edge 경로와 aggregate sensehat-001 bootstrap은 퇴역했다. physical arduino-001, sensehat-001은 protocol/tag source ID이며, Assistant는 Serial 6개와 직접 I2C 6개, 총 12개 Device의 Metadata, Core Data와 dashboard readback이 일치할 때만 활성 상태로 요약한다. 실제 물리 분리·복구와 이후 MQTT-only·Modbus·OPC-UA·다른 I2C 장비/RTSP wave는 각각 실제 endpoint와 consumer 처리를 검증한 뒤에만 완료로 보고한다.

생산성 표현

Kagenti operator assistant는 EdgeX 기반 device identity, 논리 수집 서비스 상태와 Core Data event freshness를 read-only로 요약한다. 운영자는 전체 장치를 개별 명령으로 확인하기 전에 focus list와 추천 점검 순서로 문제 범위를 좁히고, source/resource별 최신 reading과 AI·저장소·dashboard 영향 범위를 확인할 수 있다.

이는 운영 점검 경로를 단순화하는 PoC 언어다. 자동 복구, live deployment 완료, 정량적 인력 절감 또는 미구현 protocol 지원을 주장하지 않는다.
