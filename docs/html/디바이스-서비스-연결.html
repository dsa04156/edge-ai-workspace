디바이스-서비스 연결

목적

물리 Device와 AI 서비스의 관계를 한 화면에서 추적하되, EdgeX inventory와 서비스 binding을 같은 객체로 섞지 않는다.

연결 모델

Physical source
  → EdgeX Device / Device Profile
  → Device Service 또는 edge Protocol Adapter
  → Core Data Event/Reading
  → Service input binding
  → preprocess → inference → result/alert
객체 식별자 권위
Physical Device deviceName EdgeX Core Metadata
Schema profileName EdgeX Device Profile
수집 Runtime serviceName EdgeX Core Metadata와 배포 manifest
Telemetry sourceName, resourceName, origin EdgeX Core Data
AI 서비스 service_id, model_version 서비스 registry/manifest
연결 binding_id, input window, freshness gate 서비스 계약

현재 fixture

현재 checkout의 중앙 metadata contract는 다음 논리 Device를 기준으로 한다.

Device Profile Service Protocol 입력
sensehat-001 etri-sensehat edge-telemetry-agent I2C temp, humidity, pressure, compass, orientation, gyro

Sense HAT의 여러 resource를 여러 physical sensor처럼 다시 등록하지 않는다. 장비 하나는 하나의 EdgeX Device로 두고 resource/command로 표현한다.

2차년도 서비스 binding

생산품질 양품·불량 판별

binding_id: quality-classifier-sensor-mes-v1
service_id: quality-classifier
inputs:
  - source: mes.production_order
  - source: edgex.<deviceName>.<resourceName>
    window: production_cycle
join_key: production_order_id
output:
  result: good|defect|unknown
  confidence: float
  model_version: string

MES 생산 건과 센서 window가 같은 production_order_id와 공통 timestamp를 가져야 판정한다. 입력이 누락되면 양품/불량을 임의로 결정하지 않고 unknown 또는 검토 대상으로 둔다.

펌프·모터 이상 감지

binding_id: pump-motor-anomaly-v1
service_id: pump-motor-anomaly
inputs:
  - source: edgex.<deviceName>.vibration_x
  - source: edgex.<deviceName>.vibration_y
  - source: edgex.<deviceName>.vibration_z
  - source: edgex.<deviceName>.current
  - source: edgex.<deviceName>.temperature
window: 10s
output:
  anomaly_score: float
  severity: normal|warning|critical
  reason_codes: []

3축만 쓰는 서비스와 전류·온도까지 쓰는 서비스를 같은 모델로 표현하지 않는다. binding에 입력 resource, window, 결측 처리, 모델 버전을 명시한다.

연결 상태 판정

서비스 binding은 다음 gate를 모두 통과해야 ready다.

  1. EdgeX Device와 Profile이 존재한다.
  2. Device Service가 정상이고 adminState=UNLOCKED다.
  3. Core Data 최신 Event가 입력 window 안에 있다.
  4. 필요한 resource가 모두 존재하고 type이 schema와 같다.
  5. AI 서비스 endpoint가 health/readiness를 통과한다.
  6. 결과 저장소와 알림 sink가 준비돼 있다.

하나라도 실패하면 blocked 또는 degraded로 표시하고 자동 실행하지 않는다.

protocol별 서비스 연결

입력 Adapter 위치 현재 지위
I2C Raspberry Pi node local Sense HAT fixture 검증
Serial Jetson/Raspberry Pi node local pseudo terminal·실장비 wave 필요
Modbus RTU/TCP 지정 node local endpoint/unit/register allowlist 필요
OPC-UA 지정 node local endpoint/application URI 검증 필요
MQTT 명시적 broker/adapter MQTT-only 장비에서만 추가
RTSP Workflow Pod 직접 구독 영상 frame은 EdgeX로 보내지 않음

UI에 보여줄 정보

서비스 목록은 다음 6개만 먼저 보여준다.

  • 서비스 이름과 버전
  • 입력 Device/Profile/resource
  • 입력 window와 freshness
  • 배치 후보 노드
  • 현재 binding 상태
  • 결과 저장·알림 상태

상세 화면에서는 EdgeX 원본 값과 서비스 계산값을 분리한다. UI에서 binding 저장, Device 생성, Pod 배포를 직접 실행하지 않는다.
