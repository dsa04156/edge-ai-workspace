EdgeX Core Data 1,000 디바이스 부하검증 Implementation Plan

For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

Goal: 현재 EdgeX Core Data의 Event 단위 PostgreSQL 저장 경로를 1,000개 합성 device와 지정 입력률로 재현하고 자동 판정하는 일회성 부하검증 도구를 만든다.

Architecture: Go 표준 라이브러리 CLI가 rate-limited Core Data REST Event를 보내고 HTTP commit 응답, latency, device별 readback과 cleanup을 측정한다. shell runner가 amd64 정적 바이너리를 빌드해 server2 고정 일회성 Kubernetes Pod에서 실행하며 운영 Kustomization과 EdgeMesh는 변경하지 않는다.

Tech Stack: Go 1.22 standard library, EdgeX Core Data v3 REST API, Bash, Kubernetes Pod, pytest runner contract tests

Implementation Status (2026-07-22): 완료. 최종 운영 기준과 실측 PASS/FAIL은 docs/ops/엣지엑스-코어데이터-1000-디바이스-부하검증.md를 따른다. 초기 계획의 1Hz 기본값은 live OOM 결과에 따라 1/60Hz 안전 기본값과 별도 1Hz 스트레스 profile로 변경했다.

Global Constraints

  • 물리 inventory/state/telemetry/command의 권위는 EdgeX다.
  • 합성 Device를 Core Metadata에 등록하지 않는다.
  • 고정 ClusterIP, PodIP 또는 node IP를 사용하지 않고 Service FQDN을 사용한다.
  • EdgeMesh와 Argo CD Application을 변경하지 않는다.
  • root edgex/k8s/kustomization.yaml에 부하 Pod를 추가하지 않는다.
  • 합성 Event cleanup은 실행별 정확한 device 이름에만 수행한다.
  • 기본 EdgeX Core Data 저장 구현은 변경하지 않는다.
