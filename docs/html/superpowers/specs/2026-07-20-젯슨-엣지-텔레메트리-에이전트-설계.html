Jetson 엣지 텔레메트리 에이전트 설계

상태와 목적

상태: 승인된 1차 배포 설계. 실제 완료 여부는 manifest, 테스트와 live 검증 결과로 판단한다.

etri-dev0001-jetorn에 Arduino 센서가 연결된 상황에서, 실제 Serial 수집기를 교체하기 전에 broker-free edge-telemetry-agent 기반을 먼저 배치한다. 이번 단계는 Jetson의 독립 identity, SQLite outbox와 중앙 HTTPS 인증 경로를 검증한다.

범위

포함한다.

  • Jetson 전용 edge-telemetry-agent Deployment와 2GiB outbox PVC
  • EDGE_ID=etri-dev0001-jetorn, direct-mode loopback admission
  • Jetson 전용 HMAC Secret과 mTLS client certificate
  • 중앙 gateway edge-auth 목록 확장
  • 중앙 DB credential을 건드리지 않는 telemetry-only Secret 교체 경로
  • manifest, Secret preflight, 문서와 live heartbeat 검증

포함하지 않는다.

  • Arduino Serial 장치 open 또는 /dev/ttyACM* mount
  • Arduino Event 변환, Device Profile과 Device 등록
  • 기존 Arduino MQTT publisher/reader 제거 또는 변경
  • edge-local MQTT broker 추가
  • EdgeMesh 설정 변경, 고정 ClusterIP/PodIP 사용
  • command, actuator, workflow 또는 offloading 실행

접근 방식 비교

선택: 노드별 Deployment와 telemetry-only 인증 교체

현재 Sense HAT agent와 같은 패턴으로 Jetson용 Deployment/PVC를 별도로 둔다. 노드별 identity와 outbox 수명주기가 명확하고, 현재 testbed 규모에서 가장 단순하다. 기존 CA private key가 보관되지 않았으므로 중앙 DB Secret은 유지하고 telemetry HMAC·PKI만 명시적으로 교체한다.

제외: DaemonSet

edge node 전체 자동 배치는 쉽지만 Raspberry Pi AI HAT 후보까지 불필요하게 배포될 수 있고, 노드별 Secret과 RWO PVC 관리가 복잡해진다.

제외: 기존 Sense HAT identity 재사용

인증 준비는 줄지만 두 물리 노드의 감사·진단 identity가 합쳐지고 credential 격리가 깨지므로 허용하지 않는다.

배포 구조

edgex/k8s/overlays/testbed/sensor-gateways/에 Jetson 전용 manifest를 추가하고 root Kustomize 진입점은 유지한다.

etri-dev0001-jetorn
  edgex-edge-agent-jetson
    127.0.0.1:18080  direct adapter ingress
    SQLite WAL       /var/lib/edgex/outbox/outbox.db
    HTTPS/mTLS/HMAC  중앙 gateway DNS

etri-ser0002-cgnmsb
  edgex-ingest-gateway
    edge identities:
      etri-dev0003-raspi5
      etri-dev0001-jetorn

Jetson agent는 기존 arm64 immutable image와 공통 edgex-edge-agent-contract ConfigMap을 재사용한다. hostNetwork=true와 ClusterFirstWithHostNet을 유지해 adapter ingress는 node loopback에만 열고, gateway 주소는 edgex-ingest-gateway.edgex-system.svc.cluster.local DNS를 사용한다.

데이터 흐름과 상태

이번 단계에는 Arduino adapter가 없으므로 Event는 들어오지 않는다. agent는 시작 후 인증된 heartbeat를 gateway로 보내며 중앙 diagnostics에는 Jetson identity가 나타난다. source_seen=false와 unhealthy 진단은 이 단계의 예상 상태이며 Pod 장애를 뜻하지 않는다.

다음 Serial 단계에서 adapter가 canonical EdgeX v3 Event를 127.0.0.1:18080/v1/events로 넣으면 같은 agent가 SQLite commit, 재시도와 중앙 persisted ACK를 담당한다.

Secret과 장애 처리

기존 provision-runtime-secrets.sh --replace는 DB credential까지 회전시킬 수 있으므로 live Jetson 추가에 사용하지 않는다. provisioning에 telemetry-only 교체 모드를 추가해 다음 Secret만 갱신한다.

  • edgex-telemetry-edge-auth
  • edgex-ingest-gateway-tls
  • Sense HAT와 Jetson의 edge-auth credential
  • Sense HAT와 Jetson의 gateway mTLS credential

telemetry PKI 교체 직후 gateway와 기존 Sense HAT agent가 서로 다른 인증서를 잠깐 읽을 수 있다. 점검 창에서 Secret 적용 후 해당 Pod를 재생성하고 readiness와 heartbeat가 모두 복구됐는지 확인한다. PostgreSQL credential과 PVC 데이터는 유지한다.

Jetson에서 gateway 접근이 실패해도 agent는 계속 실행하며 heartbeat 실패를 기록한다. 향후 Event가 들어온 상태라면 outbox row는 persisted ACK 전까지 삭제하지 않는다.

문서 갱신

현재 기준 문서에서 “Jetson agent가 없다”는 문장을 제거하고 다음 상태를 구분한다.

  • Raspberry Pi Sense HAT: direct Event까지 연결된 교체 가능한 fixture
  • Jetson: direct agent, SQLite와 인증 heartbeat만 배포됨
  • Arduino Serial: 아직 연결·등록되지 않은 다음 protocol migration wave
  • 기존 Jetson MQTT workload: current EdgeX plane이 아닌 legacy 경로

운영 문서에는 두 edge agent/PVC, Secret preflight, heartbeat 진단과 source_seen=false 예상 상태를 추가한다. 생성 HTML은 generator로 재생성하고 직접 편집하지 않는다.

검증과 완료 조건

  1. root Kustomize render에 두 direct-mode agent와 서로 다른 PVC/Secret/identity가 존재한다.
  2. Jetson agent는 etri-dev0001-jetorn에만 배치되고 MQTT env나 broker dependency가 없다.
  3. Secret preflight가 중앙과 두 agent credential을 모두 확인한다.
  4. telemetry-plane, manifest와 Secret provisioning 집중 테스트가 통과한다.
  5. 문서 링크 검사, HTML 생성 테스트와 git diff --check가 통과한다.
  6. Argo CD Application이 새 Git revision으로 Synced/Healthy가 된다.
  7. Jetson agent와 PVC가 각각 Ready, Bound다.
  8. gateway가 Jetson heartbeat를 인증하고 diagnostics에 etri-dev0001-jetorn을 표시한다.
  9. 기존 Sense HAT agent와 중앙 Core/PostgreSQL이 인증 교체 후 정상 복구된다.

Arduino telemetry Event, Metadata 등록과 dashboard freshness는 이번 단계의 완료 조건이 아니다.
