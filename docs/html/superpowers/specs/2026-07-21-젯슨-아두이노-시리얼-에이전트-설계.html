젯슨 아두이노 시리얼 내장 에이전트 설계

상태: 폐기됨(Superseded). 이 문서는 단방향 Agent 중심 설계이며 해당 Agent Deployment/PVC는 2026-07-21 운영 경로에서 제거했다. 현재 기준은 @@INLINE0@@이며 다음 구현은 공식 EdgeX Device SDK 기반 Serial Device Service 수직 슬라이스다.

분류: 설계 이력. 현재 운영 기능의 완료 근거가 아니다.

과거 설계 내용

아래 내용은 설계 변경 이력을 보존하기 위한 것이며 현재 구현 기준이 아니다.

이번 변경은 etri-dev0001-jetorn에 연결된 Arduino를 현재 edge-telemetry-agent가 직접 읽게 만든다. 별도 Serial sidecar, EdgeX Device SDK 서비스, 로컬 MQTT broker 또는 Workflow Runtime을 추가하지 않는다.

목표 데이터 경로는 다음 하나다.

Arduino
  -> USB CDC Serial
  -> edge-telemetry-agent의 내장 Serial source
  -> 기존 SQLite outbox
  -> 기존 HTTPS/mTLS/HMAC ingest gateway
  -> EdgeX Core Data
  -> PostgreSQL과 중앙 EdgeX consumer

이 설계는 1차 서비스 데모를 실제 물리 센서 연결과 중앙 운영 가시화까지로 제한한다. Jetson에서 실행되는 Workflow Pod의 로컬 실시간 입력은 후속 독립 범위이며 이번 구현에서 미리 만들지 않는다.

확인된 물리 계약

2026-07-21 live 진단에서 다음을 확인했다.

  • node: etri-dev0001-jetorn
  • USB 장치: Arduino USB CDC ACM
  • 현재 장치 파일: /dev/ttyACM0
  • 안정 식별 경로:

/dev/serial/by-id/usb-Arduino__www.arduino.cc__0043_75035303230351E0D171-if00

  • vendor/product: 2341:0043
  • baud rate: 115200
  • framing: UTF-8 JSON object 한 개와 CRLF 한 줄
  • 현재 Serial 장치를 점유한 수집 프로세스: 없음

실측 payload 계약은 다음 네 종류다.

{"device_id":"arduino-001","sensor":"temperature","raw":278}
{"device_id":"arduino-001","sensor":"light","value":284}
{"device_id":"arduino-001","sensor":"magnetic","value":0}
{"device_id":"arduino-001","sensor":"acceleration","x":284,"y":240,"z":258}

장치를 여는 첫 시점에는 한 줄 중간부터 읽은 부분 payload가 나타날 수 있다. 파서는 첫 CRLF까지의 잘린 값과 잘못된 JSON을 버리고 다음 완전한 줄부터 복구해야 한다.

Agent 내부 구조

edge-telemetry-agent는 기존 outbox, gateway client, heartbeat와 health endpoint를 그대로 유지한다. Jetson 구성에만 serial source를 추가한다.

SerialEventSource
  -> parse_serial_line()
  -> build_edgex_event()
  -> EdgeAgent.enqueue_event()
  -> EdgeOutbox

EdgeAgent.run()
  -> 기존 gateway flush/retry
  -> 기존 heartbeat

SerialEventSource는 Serial 연결과 입력 반복만 소유한다. JSON validation과 Event mapping은 순수 함수로 분리해 실제 하드웨어 없이 단위 테스트할 수 있게 한다. Agent는 source가 만든 Event도 direct/MQTT source와 동일한 enqueue_event() 경계에서 검증하고 저장한다.

Jetson의 serial 모드에서는 loopback direct-adapter HTTP server를 열지 않는다. Sense HAT은 기존 direct 모드를 유지하므로 127.0.0.1:18080/v1/events 계약을 변경하지 않는다.

Event mapping

EdgeX identity는 다음으로 고정한다.

항목 값
Device Service edge-telemetry-agent
Device Profile etri-arduino-serial
Device arduino-001
protocol serial
edge node tag etri-dev0001-jetorn

sensor별 Event/Reading mapping은 다음과 같다.

sensor sourceName Reading valueType
temperature temperature temperature_raw Int32
light light light_raw Int32
magnetic magnetic magnetic_raw Int32
acceleration acceleration acceleration_x_raw, acceleration_y_raw, acceleration_z_raw Int32

Profile은 위 여섯 resource와 temperature, light, magnetic, acceleration read-only Device Command를 같은 grouping으로 정의한다. 쓰기 가능한 resource나 actuator command는 추가하지 않는다.

Firmware가 단위와 source timestamp를 제공하지 않으므로 값을 임의로 섭씨, lux, tesla 또는 g로 변환하지 않는다. Event와 Reading origin은 Agent가 완전한 Serial line을 받은 시각의 Unix nanoseconds다. 같은 값이 연속으로 들어와도 장비 sequence나 source timestamp가 없으므로 중복으로 추정해 제거하지 않는다. 각 완전한 line은 새 UUID Event가 된다.

다음 입력은 outbox에 넣지 않고 명시적 invalid-sample 진단으로 계산한다.

  • UTF-8 또는 JSON으로 해석할 수 없는 line
  • JSON object가 아닌 값
  • device_id != "arduino-001"
  • 지원하지 않는 sensor
  • 필수 resource 누락
  • boolean, 문자열, 실수 또는 Int32 범위 밖의 raw 값
  • 구성된 최대 line 크기를 넘는 값

설정과 배포

Jetson Deployment는 기존 단일 container와 PVC/Secret/identity를 유지한다. 추가 구성은 Serial source에 필요한 값으로 제한한다.

TELEMETRY_SOURCE_MODE=serial
SERIAL_DEVICE_PATH=/dev/arduino-001
SERIAL_BAUD_RATE=115200
SERIAL_TIMEOUT_SECONDS=1
SERIAL_RECONNECT_BACKOFF_SECONDS=1
SERIAL_RECONNECT_BACKOFF_MAX_SECONDS=30
SERIAL_DEVICE_NAME=arduino-001
SERIAL_PROFILE_NAME=etri-arduino-serial

Kubernetes hostPath는 확인된 by-id 장치를 container의 /dev/arduino-001에 mount한다. Pod에는 Jetson의 dialout group ID 20을 supplemental group으로 추가한다. Agent는 non-root, capability drop, read-only root filesystem을 유지하고 privileged를 사용하지 않는다. KubeEdge/containerd가 이 최소 권한 device mount를 허용하지 않으면 privileged로 자동 전환하지 않고 배포를 중단해 별도 승인 대상으로 보고한다.

Jetson은 기존 gateway DNS edgex-ingest-gateway.edgex-system.svc.cluster.local:8443를 계속 사용한다. EdgeMesh 설정과 Service label을 변경하지 않으며 ClusterIP나 PodIP를 구성에 넣지 않는다.

수명주기와 장애 동작

Agent 시작 시 outbox와 HTTPS health endpoint를 먼저 초기화하고 Serial source를 시작한다. Serial open이 실패해도 미전송 outbox flush와 heartbeat는 계속 동작한다. source는 1초부터 최대 30초까지 bounded exponential backoff로 재연결한다.

정상 line은 EdgeX Event 생성 후 EdgeOutbox.enqueue()가 성공한 경우에만 수신된 source로 계산한다. 중앙 연결 실패 시 기존 outbox가 Event를 보존하고 persisted ACK 후 삭제한다.

Outbox가 가득 차면 기존 Event를 삭제하지 않는다. Serial source는 새 Event를 조용히 유실시키지 않고 capacity rejection metric과 마지막 오류를 남긴다. 스트리밍 장치에는 source-side ACK가 없으므로 이 상태에서 새 sample 보존을 보장한다고 표현하지 않는다.

Serial open/read 실패는 source diagnostics와 metric에 마지막 오류를 남기고 같은 reader task가 bounded backoff로 재시도한다. reader task가 재시도 경계 밖의 예기치 않은 예외로 종료되면 Agent process도 실패해 Kubernetes가 Pod를 재시작한다. 종료 시 reader를 먼저 멈추고 장치 handle을 닫은 뒤 outbox와 gateway client를 닫는다.

중앙 EdgeX와 운영 가시화

Metadata bootstrap은 기존 논리 Device Service edge-telemetry-agent 아래에 etri-arduino-serial Profile과 arduino-001 Device를 멱등 등록한다. Device protocol properties에는 Serial device identity, baud rate, encoding과 node tag를 기록한다.

Gateway는 기존 HTTPS admission과 Core Data persisted-ACK 계약을 사용한다. 중앙 edgex-messagebus는 EdgeX 내부 통신으로 유지하지만 Arduino의 southbound transport나 Jetson 장애 버퍼가 아니다.

Dashboard availability는 기존 정책대로 Metadata의 adminState/operatingState와 Core Data latest Event freshness를 사용한다. Agent Pod Running 또는 heartbeat만으로 arduino-001을 available로 표시하지 않는다.

현재 저장소 규칙의 “프로토콜별 EdgeX Device Service가 물리 endpoint를 독점한다”는 문구는 이번에 승인된 Phase 1 결정과 맞지 않는다. 구현 변경에는 활성 범위 문서와 root AGENTS.md를 함께 갱신해 다음 책임을 명시한다.

  • Phase 1에서 edge-telemetry-agent는 Core Metadata에 등록된 논리 Device Service다.
  • Jetson Agent의 내장 Serial source만 Arduino endpoint를 독점한다.
  • EdgeX Device SDK 기반 프로토콜별 서비스는 현재 배포 경로가 아니다.
  • EdgeX Core Metadata/Core Data는 inventory/schema와 중앙 telemetry의 권위를 유지한다.

검증 기준

자동 검증

  • Serial 구성은 장치 경로, baud, timeout, backoff와 identity를 엄격히 검증한다.
  • 실측 네 sensor payload가 정확한 typed EdgeX Event로 변환된다.
  • partial line, invalid JSON, 잘못된 device/sensor/type/range가 outbox에 들어가지 않는다.
  • 동일 값의 연속 유효 line은 서로 다른 Event로 보존된다.
  • fake serial disconnect/reconnect 뒤 수집이 재개된다.
  • outbox commit 실패 시 source freshness가 성공으로 갱신되지 않는다.
  • Agent shutdown이 reader와 Serial handle을 닫는다.
  • Jetson manifest는 단일 Agent container, exact nodeSelector, stable device mount,

supplemental group과 serial mode를 가진다.

  • Jetson manifest와 runtime에는 local MQTT dependency가 없다.
  • Sense HAT direct mode와 기존 telemetry-plane/k8s 테스트가 회귀하지 않는다.
  • Metadata contract에는 etri-arduino-serial/arduino-001이 정확히 한 번 존재한다.
  • Kustomize render, 문서 링크/HTML/search-index와 whitespace 검사가 통과한다.

live 검증

  • 새 ARM64 immutable image가 내부 registry에 존재한다.
  • Argo CD edgex-telemetry가 목표 Git revision으로 Synced/Healthy다.
  • Jetson Agent Pod가 etri-dev0001-jetorn에서 non-privileged로 Ready다.
  • Agent diagnostics에서 source_seen=true이고 freshness가 계속 갱신된다.
  • Core Metadata에서 Profile/Device/Service binding을 읽을 수 있다.
  • Core Data에서 네 sourceName과 여섯 raw Reading을 실제 값으로 확인한다.
  • PostgreSQL persisted ACK 뒤 outbox backlog가 정상 범위로 내려간다.
  • state-aggregator/dashboard가 arduino-001을 EdgeX source와 fresh telemetry로 표시한다.
  • 기존 Sense HAT, 중앙 Core/PostgreSQL, EdgeMesh Pod가 변경 없이 정상이다.

완료 경계

완료 보고는 Arduino Serial Event의 live Core Data 저장과 dashboard freshness까지 증거가 있을 때만 한다. Agent 배포, /dev/ttyACM0 존재, heartbeat 또는 unit test만으로 물리 연동 완료를 주장하지 않는다.

이번 완료는 Workflow 실행, 로컬 추론 입력, Modbus/OPC-UA 지원 또는 범용 멀티프로토콜 middleware 완료를 의미하지 않는다. 향후 Jetson Workflow가 로컬 입력을 요구하면 이번 Serial 수집 계약을 유지한 채 별도 설계에서 로컬 소비 API와 retention을 정의한다.
