Local Data Cache v2 설계

1. 목적

Jetson Arduino Serial과 Raspberry Pi Sense HAT I2C Device Service의 로컬 최근 데이터 캐시를 고정 상한이 있는 공통 Go 링버퍼로 교체한다. 디바이스와 resource 수가 증가해도 캐시 슬롯 메모리가 Device Service별 64MiB를 넘지 않게 하고, 기존 Local Data API와 중앙 EdgeX Event 경로를 유지한다.

이번 변경은 실시간 recent cache만 다룬다. SQLite Outbox, 중앙 장애 중 Event 재전송, Redis, 장기 로컬 이력과 workflow orchestration은 범위에 포함하지 않는다.

2. 현재 문제

현재 두 Device Service는 (deviceName, resourceName)별 []cachedSample을 사용한다. 이 구현은 기능적으로 정렬·시간 보존·개수 제한을 만족하지만 다음 한계가 있다.

  • resource가 늘어날수록 서비스 전체 메모리 상한이 없다.
  • 최대 개수 도달 후에도 slice 삽입·복사가 발생할 수 있다.
  • Serial과 Sense HAT가 같은 캐시 규칙을 각각 구현해 계약이 분기될 수 있다.
  • 운영자가 현재 series, sample, 할당 슬롯과 eviction을 직접 조회할 수 없다.

3. 결정

3.1 공통 모듈

edgex/local-data-cache를 독립 Go module로 만든다. 두 Device Service는 이 모듈의 제네릭 Cache[T]를 사용한다.

  • Serial 값 타입: int32
  • Sense HAT 값 타입: float64
  • 공통 sample 필드: origin, valueType, value
  • 공통 cache key: (deviceName, resourceName)

공통 모듈은 EdgeX SDK에 의존하지 않는다. Device Service가 메트릭 등록과 HTTP 응답 변환을 담당한다.

3.2 링버퍼

각 series는 head, size, []Sample[T]을 가진 원형 버퍼다.

  • 정상적인 단조 증가 origin append는 O(1)이다.
  • 버퍼가 series quota에 도달하면 가장 오래된 sample을 덮어쓴다.
  • 시간 보존 범위를 벗어난 sample은 append 시 제거한다.
  • 드물게 늦게 도착한 out-of-order sample은 slow path에서 안정 정렬하고 최신 quota만 유지한다.
  • query는 요청 window와 limit을 적용한 뒤 origin 오름차순 복사본을 반환한다.

3.3 이중 상한

기본값은 다음과 같다.

항목 값
MaxAge 10m
MaxSamplesPerSeries 10000
MaxBytes 67108864 (64MiB)
recent 기본 응답 limit 1000

MaxBytes는 Go heap 전체가 아니라 링버퍼 sample 슬롯의 할당 예산이다. unsafe.Sizeof(Sample[T]{})로 슬롯 크기를 계산하고 모든 series의 slice capacity 합이 MaxBytes / slotSize를 넘지 않게 한다. map key, string backing data, mutex와 Go runtime overhead는 이 값에 포함되지 않으며 Kubernetes container memory limit이 프로세스 전체 hard limit이다.

새 series가 생기면 전체 slot budget을 활성 series 수로 나눈 공정 quota를 다시 계산한다.

seriesQuota = min(MaxSamplesPerSeries, totalSlotBudget / activeSeries)

기존 series capacity가 새 quota보다 크면 최신 sample만 남기고 축소한다. series가 삭제되어 quota가 커지는 경우에는 즉시 전체를 확장하지 않고 이후 append 시 필요한 series만 점진적으로 확장한다.

3.4 설정

두 Device Service의 configuration.yaml에 동일한 Driver 설정을 둔다.

Driver:
  LocalDataCacheMaxAge: 10m
  LocalDataCacheMaxSamplesPerSeries: "10000"
  LocalDataCacheMaxBytes: "67108864"

누락 시 위 기본값을 사용한다. 0, 음수, 파싱 불가능 값이나 sample 한 개도 담지 못하는 byte 값은 startup error로 처리한다.

3.5 관측성

Device Service는 EdgeX SDK MetricsManager에 다음 custom metric을 등록한다.

  • LocalDataCacheSamples: 현재 보존 sample 수 gauge
  • LocalDataCacheSeries: 현재 series 수 gauge
  • LocalDataCacheAllocatedBytes: 할당된 링버퍼 슬롯 byte gauge
  • LocalDataCacheEvictions: 누적 eviction counter

각 metric은 Writable.Telemetry.Metrics에서 활성화한다. MetricsManager가 없는 단위 테스트 환경에서는 캐시 동작을 계속하지만, 실제 SDK 환경에서는 등록 실패를 startup error로 처리한다.

각 Device Service는 같은 포트에 다음 read-only endpoint를 추가한다.

GET /api/v3/localdata/stats

응답은 retention 설정, slot 크기, 현재 series/sample/allocated bytes와 age/per-series/global-rebalance eviction 누계를 포함한다. endpoint에는 고정 IP를 사용하지 않으며 기존 Local Data API와 같은 Service FQDN·NetworkPolicy 경계를 사용한다.

3.6 기존 API 호환성

다음 endpoint와 의미는 유지한다.

GET /api/v3/localdata/device/name/{device}/resource/name/{resource}/latest
GET /api/v3/localdata/device/name/{device}/resource/name/{resource}?from={ns}&to={ns}&limit={1..10000}
  • latest sample 없음: 404
  • 알려진 source의 빈 recent window: 200, samples=[]
  • recent 결과: 최신 limit개를 origin 오름차순 반환
  • retention 응답: maxAge, maxSamples, maxBytes 포함
  • Device 삭제: 해당 Device의 모든 series 제거
  • Pod 재시작: 캐시 초기화

4. 데이터 흐름

Serial/I2C sample
  -> Device Service parser
      -> Cache[T].Append
          -> series ring append / eviction / metric snapshot
      -> EdgeX AsyncValues
          -> 중앙 MessageBus -> Core Data -> PostgreSQL

same-node Workflow Pod
  -> Service FQDN
      -> latest/recent/stats Local Data API
          -> Cache[T]

로컬 캐시 write와 중앙 async publish는 같은 sample handler에서 연속 수행하지만, 캐시는 중앙 미전송 queue가 아니다.

5. 오류와 경계

  • 알려지지 않은 Device/resource는 기존처럼 404다.
  • out-of-order sample은 버리지 않고 정렬 slow path로 보존한다.
  • 동일 origin은 수신 순서를 유지한다.
  • 전역 quota 축소로 제거된 sample은 globalRebalance eviction으로 기록한다.
  • series 자체 quota 초과는 seriesLimit, 시간 초과는 age로 기록한다.
  • MaxBytes가 활성 series 수보다 작은 slot 수만 허용하는 경우 새 series append를 명시적 error로 거부한다. 기본 64MiB에서는 현재 및 목표 규모에 해당하지 않는다.
  • 카메라 frame은 이 캐시에 넣지 않는다.

6. 검증

자동 검증은 다음을 포함한다.

  1. 정상 append의 원형 overwrite와 오름차순 query
  2. age, per-series, global byte quota eviction
  3. series 증가 시 공정 quota 재조정
  4. out-of-order와 동일 origin 안정 정렬
  5. concurrent read/write race test
  6. Serial int32, Sense HAT float64 adapter 호환
  7. latest/recent/stats HTTP 계약
  8. Driver 설정 validation과 EdgeX metric 등록
  9. Kustomize render와 동일 설정 반영
  10. ARM64 image build, immutable digest pin, Argo CD sync
  11. Jetson/Sense HAT live latest·recent·stats와 AI demo origin 증가

7. 완료 기준

  • 두 Device Service가 공통 cache module을 사용한다.
  • 기존 Local Data API 단위·race·manifest 테스트가 통과한다.
  • stats가 64MiB budget 이하의 할당 byte와 실제 series/sample을 반환한다.
  • 두 ARM64 Pod가 새 digest로 Ready이고 restart가 증가하지 않는다.
  • Jetson Serial과 Sense HAT I2C의 origin이 증가한다.
  • sensor-anomaly-demo가 mode=live, inputState=fresh를 유지한다.
  • 중앙 Core Data/PostgreSQL Event 증가와 기존 dashboard 조회가 유지된다.
  • 문서는 SQLite Outbox가 아직 없다는 경계를 계속 명시한다.
