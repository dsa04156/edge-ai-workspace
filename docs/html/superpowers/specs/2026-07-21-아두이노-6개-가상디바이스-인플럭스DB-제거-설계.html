아두이노 6개 가상 디바이스와 InfluxDB 제거 설계

상태

  • 승인일: 2026-07-21
  • 구현 대상: 현재 Jetson Arduino Serial 수직 슬라이스와 state-aggregator
  • 배포 경로: Argo CD Application edgex-telemetry가 동기화하는 edgex/k8s

목표

Jetson에 연결된 Arduino Uno의 시리얼 포트는 한 번만 열되, 수집되는 여섯 Reading을 EdgeX Core Metadata에서 서로 독립적인 가상 디바이스 여섯 개로 등록하고 Core Data Event도 각 deviceName으로 분리한다. 현재 운영 경로에 남은 InfluxDB manifest, client, recorder, API 계약과 UI 문구는 제거하고 영구 저장 권위는 EdgeX Core Data와 PostgreSQL로 단일화한다.

범위

포함

  • device-serial-jetson의 공유 시리얼 연결과 resource별 fan-out
  • 가상 디바이스 여섯 개와 1-resource Device Profile 여섯 개
  • 기존 arduino-001 Device, aggregate Profile과 과거 Event 정리
  • InfluxDB 배포 manifest와 state-aggregator의 InfluxDB 코드·설정·기록 API 제거
  • 관련 단위 테스트, manifest 테스트, 활성 문서와 생성 HTML 최신화
  • 이미지 build/push, Git push, Argo CD 동기화와 live readback 검증

제외

  • EdgeMesh 구성 변경
  • EdgeX 중앙 Core Service, MessageBus 또는 PostgreSQL 제거
  • MQTT broker나 edge agent 재도입
  • SQLite outbox 또는 로컬 최근 데이터 API 구현
  • Modbus, OPC-UA, I2C, RTSP adapter 구현
  • legacy workflow/offloading 경로의 현재 기능 승격

선택한 구조

Arduino Uno (`device_id=arduino-001`)
  -> /dev/arduino-001 (115200, 단일 open)
  -> device-serial-jetson
     -> temperature_raw    -> virtual-temperature-001
     -> light_raw          -> virtual-light-001
     -> magnetic_raw       -> virtual-magnetic-001
     -> acceleration_x_raw -> virtual-acceleration-x-001
     -> acceleration_y_raw -> virtual-acceleration-y-001
     -> acceleration_z_raw -> virtual-acceleration-z-001
  -> EdgeX internal MessageBus service FQDN
  -> Core Data
  -> PostgreSQL
  -> state-aggregator / dashboard / AI consumer

숨겨진 부모 EdgeX Device는 두지 않는다. arduino-001은 wire payload 검증과 protocol/tag metadata에만 남는 물리 source 식별자다. 여섯 EdgeX Device가 inventory, 상태, telemetry 조회의 독립 단위다.

EdgeX Metadata 계약

Device name Profile name Resource Event sourceName
virtual-temperature-001 etri-arduino-temperature temperature_raw temperature
virtual-light-001 etri-arduino-light light_raw light
virtual-magnetic-001 etri-arduino-magnetic magnetic_raw magnetic
virtual-acceleration-x-001 etri-arduino-acceleration-x acceleration_x_raw acceleration_x
virtual-acceleration-y-001 etri-arduino-acceleration-y acceleration_y_raw acceleration_y
virtual-acceleration-z-001 etri-arduino-acceleration-z acceleration_z_raw acceleration_z

각 Device는 다음 protocol property를 가진다.

protocols:
  serial:
    Port: /dev/arduino-001
    BaudRate: "115200"
    DeviceID: arduino-001
    ResourceName: temperature_raw
  • DeviceID는 EdgeX Device 이름이 아니라 wire payload의 물리 source ID다.
  • ResourceName은 해당 가상 디바이스로 보낼 유일한 Reading이다.
  • 같은 물리 연결 안에서 한 resource를 둘 이상의 Device에 중복 binding하지 않는다.
  • Device tag에는 physicalDeviceId=arduino-001과 nodeName=etri-dev0001-jetorn을 기록한다.

Device Service 런타임

Driver는 Device별 reader 대신 (Port, BaudRate, DeviceID)로 식별하는 공유 connection을 관리한다. connection은 resource-to-device route를 보유한다.

  • 첫 번째 UNLOCKED Device가 등록되면 reader를 하나 시작한다.
  • 같은 connection의 나머지 Device는 기존 reader에 route만 추가한다.
  • Device update가 동일한 binding이면 reader를 재시작하지 않는다.
  • Device를 LOCKED 또는 제거하면 그 route와 latest value만 지운다.
  • 마지막 route가 제거될 때만 시리얼 포트를 닫는다.
  • 물리 연결의 UP/DOWN 상태는 연결에 속한 모든 UNLOCKED 가상 Device에 fan-out한다.
  • 이미 상태가 결정된 connection에 새 Device가 붙으면 저장된 현재 상태를 즉시 반영한다.

시리얼 parser는 현재 strict JSON 계약을 유지한다. temperature, light, magnetic sample은 한 Event로, acceleration sample은 X/Y/Z 세 Event로 나눈다. 각 Event에는 하나의 typed Int32 Reading만 들어간다. route가 없는 resource는 발행하지 않으며 malformed line과 다른 물리 device_id는 폐기한다.

Core Command GET은 각 가상 Device의 최근 단일 Reading을 반환한다. write command와 discovery는 계속 지원하지 않는다.

InfluxDB 제거 계약

현재 live cluster에는 InfluxDB workload가 없지만 저장소에는 선택적 구현이 남아 있다. 다음을 제거한다.

  • root influxdb/의 StatefulSet/Service/PVC/Secret 및 connectivity test manifest
  • state-aggregator/app/influx.py
  • state-aggregator/app/placement_recorder.py
  • INFLUXDB_*, RESOURCE_PROFILE_RECORDING_MODE, 기록 interval/window 설정
  • scheduled/poll recorder task와 /state/service-resource-profiles/record
  • API의 recording_backend, recording_mode, recording_interval_seconds, recorded_at, last_record_result
  • UI의 InfluxDB + result cache 기본 sink 문구

Prometheus 기반 현재 service resource observation과 /state/resource-profiles, /state/service-resource-profiles 조회 API는 유지한다. 반환값은 관찰 시각, scope, summary와 profile 목록만 포함한다. 물리 telemetry history는 계속 EdgeX Core Data API에서 조회한다.

설계 이력과 보관 문서의 과거 InfluxDB 언급은 역사적 사실로 유지할 수 있다. 활성 문서는 InfluxDB가 현재 코드·manifest·배포에 없고 Core Data/PostgreSQL이 저장 권위임을 명시한다.

전환 순서

  1. Driver의 공유 connection/fan-out 테스트를 실패 상태로 추가한다.
  2. 최소 구현으로 테스트를 통과시킨다.
  3. 여섯 Profile/Device와 Kustomize mount 계약 테스트를 추가하고 manifest를 교체한다.
  4. InfluxDB 제거 계약 테스트를 먼저 갱신한 뒤 코드·manifest를 삭제한다.
  5. 전체 Go/Python/manifest/docs 검증을 수행한다.
  6. 새 Device Service 이미지를 build/push하고 digest로 manifest를 고정한다.
  7. 변경을 push하여 Argo CD가 배포하도록 한다.
  8. 여섯 Device와 최신 Event를 확인한 뒤 기존 arduino-001, etri-arduino-serial과 arduino-001 과거 Event를 정확한 이름으로 삭제한다.
  9. 여섯 Device의 Metadata, Core Data Event/Reading, Core Command GET, dashboard availability를 readback한다.

실패와 복구

  • 이미지 또는 manifest 검증 실패 시 push하지 않는다.
  • Argo sync 또는 새 Device 수집 실패 시 기존 중앙 Core와 EdgeMesh는 건드리지 않고 Device Service 로그·Metadata·Event 경로만 진단한다.
  • 시리얼 연결 실패는 여섯 Device를 DOWN으로 반영한다.
  • 일부 route 구성 오류는 Device Service 시작을 실패시켜 잘못된 중복/누락 inventory를 정상 상태로 노출하지 않는다.
  • 기존 Device 삭제는 새 여섯 Device의 정상 Event readback 이후에 수행한다.

완료 기준

  • reader factory/open 횟수가 여섯 Device에 대해 1회다.
  • Metadata inventory에 위 여섯 Device가 있고 arduino-001은 없다.
  • 각 Device의 latest Event에는 해당 resource 하나만 있다.
  • acceleration 한 wire sample이 X/Y/Z Device Event 세 개로 분리된다.
  • 각 Device의 Core Command GET이 최근값을 반환한다.
  • dashboard가 여섯 Device를 독립 행으로 표시하고 fresh/available을 계산한다.
  • live cluster와 active root render에 InfluxDB workload가 없다.
  • active state-aggregator 코드와 API/UI에 InfluxDB recorder 계약이 없다.
  • EdgeMesh generation과 workload는 변경하지 않는다.
  • 전체 테스트, Kustomize render, 문서 생성·링크 검사와 git diff --check가 통과한다.
