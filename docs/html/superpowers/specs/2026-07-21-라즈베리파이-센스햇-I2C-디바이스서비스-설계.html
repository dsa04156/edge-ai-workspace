라즈베리파이 Sense HAT I2C Device Service 설계

상태

  • 승인일: 2026-07-21
  • 대상 node: etri-dev0003-raspi5
  • 물리 장치: Raspberry Pi Sense HAT v1, /dev/i2c-1
  • 운영 배포 진입점: Argo CD Application edgex-telemetry가 동기화하는 edgex/k8s

목표

Raspberry Pi 5에 연결된 Sense HAT를 MQTT publisher나 KubeEdge MapperFramework가 아니라 정식 EdgeX Device SDK 기반 device-sensehat-raspi가 직접 수집한다. 한 물리 I2C source를 한 번 읽고 환경·IMU 기능별 6개 가상 Device로 fan-out한다. 각 가상 Device는 독립 Profile, Event/Reading, read-only Command와 로컬 recent cache identity를 가진다.

Jetson Serial Device Service는 그대로 유지한다. 이 추가로 실제 검증 가능한 protocol adapter가 Serial과 I2C 두 종류가 되며, Modbus와 OPC-UA는 실제 endpoint가 없으므로 지원 완료로 주장하지 않는다.

실측 기반

2026-07-21 임시 read-only 진단 Pod에서 다음을 확인했다.

  • node etri-dev0003-raspi5: Ready, linux/arm64
  • HAT EEPROM: Sense HAT, product 0x0001, version 0x0001
  • I2C bus: /dev/i2c-1
  • LSM9DS1 magnetometer 0x1c, accelerometer/gyroscope 0x6a
  • LPS25H pressure sensor 0x5c
  • RTIMULib를 통한 온도·습도·압력·orientation·gyroscope·acceleration·compass 실측 성공

기존 edge-device/publishers/sensehat_publisher.py와 mqttvirtual manifest는 legacy 경로다. 새 Device Service의 실행 의존성이나 fallback으로 사용하지 않는다.

선택한 구조

Sense HAT v1 (/dev/i2c-1)
  -> 같은 container의 RTIMULib Python protocol reader
  -> newline JSON sample
  -> Go EdgeX Device SDK driver
     ├─ 6개 가상 Device route
     ├─ Device/resource별 10분·10,000 sample memory cache
     ├─ Core Command latest GET
     ├─ Local Data API latest/recent
     └─ EdgeX AsyncValues
  -> 중앙 EdgeX MessageBus
  -> Core Data / PostgreSQL
  -> state-aggregator / dashboard

Python reader는 별도 Agent나 sidecar가 아니다. device-sensehat-raspi image 내부의 I2C protocol module이며 Go Device Service가 process lifecycle, 재시작 backoff, state와 Event 발행을 소유한다. Python module은 MQTT, HTTP 또는 중앙 저장소에 연결하지 않는다.

RTIMULib를 택한 이유는 실제 Sense HAT v1에서 이미 검증된 sensor calibration과 fusion을 재사용하기 위해서다. 직접 register 계산을 새로 구현하는 것보다 실측 장치의 기존 driver 계약을 좁게 감싸는 편이 현재 PoC의 오류 위험이 낮다.

가상 Device 계약

Device Profile resources command
env-sensehat-temperature-01 etri-sensehat-temperature temp_humidity, temp_pressure temperature
env-sensehat-humidity-01 etri-sensehat-humidity humidity humidity
env-sensehat-pressure-01 etri-sensehat-pressure pressure pressure
imu-sensehat-compass-01 etri-sensehat-compass compass compass
imu-sensehat-orientation-01 etri-sensehat-orientation pitch, roll, yaw orientation
imu-sensehat-gyroscope-01 etri-sensehat-gyroscope gyro_x, gyro_y, gyro_z gyroscope

모든 resource는 Float64, read-only다. 단위는 온도 C, 습도 %RH, 압력 hPa, 방향 deg, gyroscope rad/s다. 한 sample의 여러 resource는 같은 nanosecond origin을 사용한다.

Device protocol은 다음 공통 물리 binding과 고유 group을 가진다.

protocols:
  i2c:
    Bus: /dev/i2c-1
    DeviceID: sensehat-001
    ResourceGroup: orientation
tags:
  physicalDeviceId: sensehat-001
  nodeName: etri-dev0003-raspi5

sensehat-001은 물리 source/tag이며 aggregate EdgeX Device로 등록하지 않는다.

reader와 오류 동작

  • reader는 /usr/bin/python3 /opt/device-sensehat/read_sensehat.py --interval 1s를 shell

없이 실행한다.

  • RTIMULib 설정은 image의 /etc/RTIMULib.ini를 writable /tmp로 복사해 사용한다.
  • pressure, humidity, temperature와 IMU validity flag를 확인한 sample만 출력한다.
  • NaN/Inf, field 누락, JSON 오류와 다른 device_id는 Event/cache에 넣지 않는다.
  • reader process 시작 또는 I2C read가 실패하면 1·2·4·8·16·30초 backoff로 재시작하고

6개 Device operating state를 DOWN으로 갱신한다.

  • 첫 유효 sample 이후 UP으로 갱신한다.
  • 동일 Metadata update는 reader를 재시작하거나 cache를 지우지 않는다.
  • 마지막 binding이 제거되거나 Device가 LOCKED되면 reader를 닫고 해당 cache를 지운다.

cache와 Local Data API

Jetson Serial과 같은 계약을 사용한다.

  • key: (deviceName, resourceName)
  • retention: 최근 10분, 시계열별 최대 10,000 sample
  • Pod 재시작 시 초기화
  • SQLite/PVC와 중앙 history fallback 없음
  • 최신값:

GET /api/v3/localdata/device/name/{device}/resource/name/{resource}/latest

  • 최근 구간:

GET /api/v3/localdata/device/name/{device}/resource/name/{resource}?from={origin_ns}&to={origin_ns}&limit={1..10000}

서비스 FQDN은 device-sensehat-raspi.edgex-edge.svc.cluster.local:59911이다. 고정 ClusterIP, PodIP, node IP를 consumer 설정에 기록하지 않는다.

image와 배포

  • ARM64 runtime base는 Debian trixie와 Raspberry Pi archive의

python3-rtimulib=7.2.1-7, librtimulib7=7.2.1-7만 포함한다.

  • EdgeX Go binary와 Python reader를 한 image에 넣고 최종 workload는 immutable digest로

고정한다.

  • Recreate, replica 1, exact node selector를 사용해 물리 endpoint 소유자를 하나로 둔다.
  • host의 /dev/i2c-1 CharDevice 하나만 같은 path로 mount한다.
  • hostNetwork, PVC, SQLite, local application MQTT broker를 사용하지 않는다.
  • read-only root filesystem과 /tmp emptyDir를 사용한다.
  • 현재 PoC의 device cgroup 제약 때문에 root/privileged 예외를 사용하되 exact

CharDevice와 단일 Pod로 범위를 제한한다.

네트워크 경계

  • 중앙 Keeper/Metadata/MessageBus와 DNS는 .svc.cluster.local FQDN으로 접근한다.
  • Local Data API ingress manifest는 edge-ai.io/local-data-client=true를 의도된 client로

선언한다.

  • 현재 Flannel CNI는 NetworkPolicy를 집행하지 않으므로 label은 보안 경계가 아니다.
  • Local Data API는 unauthenticated read-only다. 실제 차단이 필요하면 정책 지원 CNI나

mTLS/애플리케이션 인증을 별도 적용한다.

  • EdgeMesh 리소스와 설정은 변경하지 않는다.

다중 protocol 판정

이번 작업의 live 완료 판정은 다음으로 제한한다.

protocol 판정
Serial Jetson Arduino 실제 endpoint, 6개 가상 Device와 중앙/로컬 readback 유지
I2C Raspberry Pi Sense HAT 실제 endpoint, 6개 가상 Device와 중앙/로컬 readback 신규 확인
MQTT 새 두 Device Service의 물리 입력에는 사용하지 않음; 중앙 EdgeX 내부 MessageBus 구현과 구분
Modbus 실제 endpoint 없음, 미배포/미검증
OPC-UA 실제 endpoint 없음, 미배포/미검증
RTSP 카메라 Workflow의 별도 media 경로, 이번 범위 아님

한 protocol의 성공을 다른 protocol 완료 근거로 사용하지 않는다.

완료 기준

  • device-sensehat-raspi가 Raspberry Pi에서 기대 ARM64 digest로 Ready이고 restart가

증가하지 않는다.

  • 6개 Profile/Device가 Core Metadata에서 UNLOCKED, UP, i2c binding으로 존재한다.
  • 실제 Sense HAT sample이 각 Device의 typed Float64 Event/Reading으로 저장된다.
  • 6개 read-only Core Command와 대표/전체 Local Data API가 cache 최신값을 반환한다.
  • dashboard가 Jetson Serial 6개와 Sense HAT I2C 6개를 독립 inventory/freshness로 표시한다.
  • root render에 Agent, Sense HAT MQTT publisher workload, device-mqtt, edge-local application

broker, InfluxDB, SQLite/PVC 또는 고정 IP가 없다.

  • Serial과 I2C가 동시에 정상이고 중앙 EdgeX 회귀가 없다.
  • EdgeMesh generation/image/readiness가 작업 전과 같다.
  • 단위·race·vet·manifest·문서 테스트와 Kustomize render가 통과한다.

실제 I2C 분리·복구, 장기 안정성, NetworkPolicy 차단과 Modbus/OPC-UA는 별도 gate다.
