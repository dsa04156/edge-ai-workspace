EdgeX 중앙 Core와 HTTPS edge buffer 설계

상태: 설계 이력. 현재 운영 기능의 완료 근거가 아니며 승인 설계의 이력으로 보존한다.

상태

현재 승인 설계다. 초기 문서의 “모든 edge source가 local Mosquitto를 사용한다”는 가정은 폐기했다.

문제

물리 센서가 Jetson/Raspberry Pi에 연결돼 있고 원시 telemetry는 중앙 Edge AI 서버에 저장해야 한다. 중앙 네트워크나 Core Data가 잠시 중단돼도 edge 수집은 계속돼야 하며, MQTT를 지원하지 않는 Modbus/OPC-UA/Serial/I2C 장비에 broker를 강제하면 불필요한 운영 계층이 생긴다.

결정

[physical / EdgeCore]
Protocol Adapter
  -> canonical EdgeX Event
  -> edge-telemetry-agent
  -> SQLite outbox
       |
       | HTTPS + mTLS + HMAC
       v

[Edge AI server]
edgex-ingest-gateway
  -> EdgeX Core Data REST
  -> PostgreSQL
  -> central consumers / dashboard

EdgeX Core Metadata는 Device/Profile inventory와 schema를 유지한다. 중앙 internal MessageBus는 stock EdgeX Core와 후속 consumer용이며 physical northbound가 아니다.

Source adapter 모드

direct

  • 기본 모드
  • TELEMETRY_SOURCE_MODE=direct
  • host adapter가 http://127.0.0.1:18080/v1/events로 Event를 전달
  • Modbus, OPC-UA, Serial, I2C adapter가 공통 outbox/uploader를 재사용
  • local broker 불필요

loopback endpoint는 host에서 실행하는 adapter와 host-network agent 사이에서만 사용한다. 외부 interface bind는 설정 단계에서 거부한다.

mqtt

  • optional compatibility 모드
  • TELEMETRY_SOURCE_MODE=mqtt
  • MQTT-only 장비 또는 local pub/sub 요구가 있을 때만 사용
  • payload는 raw JSON이 아니라 canonical EdgeX v3 Event
  • QoS 1 ACK는 Event가 SQLite에 commit된 뒤에만 수행

현재 Sense HAT는 direct, Jetson canary는 mqtt mode다.

Sense HAT vertical slice

  • node: etri-dev0003-raspi5
  • adapter: edge-device/publishers/sensehat_publisher.py
  • protocol: I2C
  • Device: sensehat-001
  • Profile: etri-sensehat
  • source: temperature, humidity, pressure, compass, orientation, gyroscope
  • MQTT broker: 없음

publisher는 한 sample의 source별 Event ID를 만들고 local durable ACK가 모호하면 같은 Event를 재시도한다.

Outbox

SQLite는 WAL, synchronous=FULL과 transaction commit을 사용한다.

  • Event ID primary key
  • 같은 ID/같은 canonical payload: deduplicated
  • 같은 ID/다른 payload: conflict
  • device/source stream별 FIFO
  • inflight lease와 token fencing
  • retryable failure: exponential backoff
  • terminal Core validation/conflict: rejected/quarantine
  • persisted ACK: row 삭제
  • 기본 logical maximum: 1GiB
  • PVC: agent별 2GiB

용량을 넘을 때 오래된 Event를 자동 삭제하지 않는다. adapter에 507 outbox_full을 반환해 저장되지 않은 sample을 성공으로 오인하지 않게 한다.

Gateway와 persisted ACK

gateway는 다음을 확인한다.

  1. request body 상한
  2. mTLS client identity
  3. edge ID별 HMAC과 timestamp
  4. strict EdgeX Event schema
  5. Core Data REST response와 Event ID

Core Data add path:

POST /api/v3/event/edgex-ingest-gateway/{profile}/{device}/{source}

Core Data 201의 ID가 요청 Event ID와 같은 경우만 persisted ACK를 반환한다. 응답 유실 뒤 Core Data가 409를 반환하면 GET /api/v3/event/id/{id}로 읽고 server-generated field를 제외한 canonical fingerprint를 비교한다.

  • 같은 payload: persisted/deduplicated ACK
  • 다른 payload: 409 id_collision
  • Core Data timeout/5xx: retryable failure

전체 downstream exactly-once는 주장하지 않는다. edge-to-Core Data storage는 at-least-once retry와 Event ID idempotency를 제공한다.

Metadata

edgex-metadata-bootstrap은 GET-before-POST 방식으로 다음을 등록한다.

  1. Device Service edge-telemetry-agent
  2. Device Profile
  3. Device

현재 service는 physical protocol process가 아니라 HTTPS telemetry plane을 나타내는 논리 Device Service다. command는 비활성이고 dashboard availability는 Metadata 관리 상태와 Core Data Event freshness를 함께 사용한다.

배치

server2 / edgex-system

  • ingest gateway
  • Core Keeper
  • Core Metadata
  • Core Data
  • Core Command
  • internal MessageBus
  • PostgreSQL
  • Metadata bootstrap

edge / edgex-edge

  • Jetson edge agent
  • Sense HAT edge agent
  • agent별 SQLite PVC

edge node에는 Core, internal MessageBus나 PostgreSQL을 배치하지 않는다.

RTSP와 Workflow Pod

RTSP frame은 Event/Reading과 SQLite outbox에 넣지 않는다.

camera -> RTSP -> on-demand Workflow Pod
                     -> AI result/status Event (optional)

Workflow Pod 생성·종료, GPU 배치와 offloading은 현재 telemetry plane의 범위 밖이다.

Trust boundary

crossing guard
adapter -> agent loopback bind, strict schema, body size, durable ACK
agent -> gateway TLS verification, client cert, HMAC
gateway -> Core Data cluster-only URL과 제한된 REST path
Core Data -> PostgreSQL Secret 기반 DB config와 Core Data 성공 응답

Known risks

  • Sense HAT agent의 hostNetwork는 host publisher가 loopback에 접근하기 위한 선택이다. 8443는 mTLS이고 18080은 loopback-only지만 host port 충돌을 live preflight에서 확인해야 한다.
  • Metadata bootstrap은 기존 이름을 skip한다. contract drift update/delete는 별도 운영 절차가 필요하다.
  • PostgreSQL과 outbox PVC는 단일 node local storage라 disk failure backup이 아니다.
  • Jetson MQTT compatibility mode는 broker와 canonical Event publisher가 실제로 필요한지 확인 후 유지해야 한다.
  • 중앙 internal MessageBus를 MQTT가 아닌 provider로 바꾸는 작업은 별도 EdgeX runtime migration이다.

수용 기준

  • direct mode가 MQTT 설정 없이 시작된다.
  • mqtt mode만 broker host/topic/session을 요구한다.
  • Sense HAT Event가 local queue ACK 뒤 Core Data에서 같은 ID로 조회된다.
  • gateway 중단 중 outbox가 유지되고 복구 뒤 drain된다.
  • 같은 Event retry는 중복 row를 만들지 않는다.
  • root Kustomize에 device-mqtt workload가 없다.
  • central Core/DB는 server2, agents는 지정 edge node에만 배치된다.
  • dashboard가 sensehat-001 / etri-sensehat / edge-telemetry-agent와 latest Event freshness를 표시한다.
