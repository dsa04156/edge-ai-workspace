센서 이력 그래프 연결 설계

목적

대시보드에서 EdgeX Device를 선택했을 때 최신 Event의 Reading 몇 개가 아니라 중앙 EdgeX Core Data에 저장된 해당 Device의 실제 시계열 이력을 조회해 그래프로 표시한다. 대상은 Jetson Serial 가상 Device 6개와 Raspberry Pi Sense HAT 가상 Device 6개, 총 12개다.

현재 문제

state-aggregator에는 이미 다음 이력 API가 있다.

GET /state/devices/{deviceName}/telemetry?window=-30m&limit=1000

이 API는 EdgeX Core Data의 Device Event API를 호출하며 Core Data의 영속 저장소는 PostgreSQL이다. 그러나 현재 Device 선택 패널은 /state/dashboard에 포함된 latest_readings만 renderTelemetryChart()에 넘긴다. 따라서 여러 시각의 값을 잇는 시계열 그래프가 아니라 최신 Event의 resource들을 한 화면에 배치하는 수준이다.

선택한 접근

브라우저는 Device 선택 시 기존 state-aggregator 이력 API를 호출한다.

Device 선택
  → state-aggregator /state/devices/{name}/telemetry
  → EdgeX Core Data /api/v3/event/device/name/{name}
  → PostgreSQL
  → TelemetryPoint[]
  → resource별 시계열 그래프

브라우저와 state-aggregator는 PostgreSQL에 직접 SQL 연결하지 않는다. EdgeX Device 이름, Event/Reading schema, timestamp와 데이터 권위를 Core Data API 경계에서 유지한다.

검토한 다른 접근은 사용하지 않는다.

  • 브라우저의 PostgreSQL 직접 연결: 자격증명 노출과 EdgeX 데이터 계약 우회 때문에 제외한다.
  • 12개 Device 이력 전체 선로딩: 초기 부하와 불필요한 Core Data 조회 때문에 제외한다.

사용자 동작

  1. 운영자가 Device 목록에서 하나를 선택한다.
  2. 설명 패널은 즉시 Device metadata와 이력 로딩 상태를 표시한다.
  3. 기본 범위 30분, 최대 1000 EdgeX Event를 조회한다.
  4. 응답 Reading을 source_name.resource_name series로 그룹화하고 timestamp 오름차순으로

그래프에 표시한다.

  1. 운영자는 5분, 30분, 1시간, 24시간 범위를 선택하거나 같은 범위를 새로고침한다.
  2. 선택 또는 범위가 바뀌면 새 요청을 시작하며, 늦게 도착한 이전 요청은 현재 패널을

덮어쓰지 않는다.

범위는 Core Data 조회의 start 경계다. limit=1000은 반환 Event 상한이므로 고주기 Device의 긴 범위가 모든 Event를 보장한다는 표현은 하지 않는다. UI에는 요청 범위, 반환 Reading 수와 실제 첫/마지막 timestamp를 함께 표시한다.

상태와 오류 처리

  • loading: 선택한 Device와 범위를 유지한 채 이력 조회 중임을 표시한다.
  • ready: 숫자 Reading을 resource별 series로 그린다.
  • empty: Core Data가 빈 배열을 반환했음을 명시한다. 최신값을 과거 이력처럼 대체하지 않는다.
  • error: HTTP 실패나 비배열 응답을 표시하고 새로고침 동작을 제공한다.
  • stale response: request sequence가 현재 선택과 다르면 결과와 오류를 모두 폐기한다.

AI 서비스 장애나 특정 Device 이력 조회 실패는 /state/dashboard, 다른 Device 목록과 기존 서비스 데모 패널을 실패시키지 않는다.

경합 방지, 범위 동작과 history chart 렌더링

  • edge-orch/state-aggregator/app/static/dashboard-refactor.css: 범위 control과 상태 UI

  • 기존 Python dashboard 정적 회귀 테스트와 운영 문서

기존 backend 이력 endpoint와 EdgeX client는 이미 live 데이터로 동작하므로 schema 변경이나 직접 DB client를 추가하지 않는다.

테스트와 완료 기준

  • URL은 Device 이름과 window를 안전하게 encode하고 limit=1000을 사용한다.
  • 정상 응답, 빈 배열, HTTP 오류, 잘못된 payload를 구분한다.
  • 빠른 Device 전환에서 이전 응답이 새 선택을 덮어쓰지 않는다.
  • 선택 패널은 latest_readings가 아니라 history state로 그래프를 그린다.
  • 네 범위와 새로고침 control이 키보드 접근 가능한 button으로 제공된다.
  • Serial 단일-resource Device와 Sense HAT 다중-resource Device 모두 live Core Data

이력을 표시한다.

  • 기존 Python, JavaScript, EdgeX manifest, docs 테스트가 모두 통과한다.
  • 새 state-aggregator image를 immutable digest로 배포하고 Argo CD가 exact Git SHA에서

Synced/Healthy다.

  • 실제 Firefox desktop/mobile에서 이력 그래프, 범위 전환, 빈 공간/겹침과 console 오류를

확인한다.
