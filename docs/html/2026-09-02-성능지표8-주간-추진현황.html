2026-09-02 성능지표 8 주간 추진현황

용도: 성능지표 8 관련 주간보고 작성용 요약이다. 정확한 시험 경계와 전체 근거는 가상화 노드 오류 복구시간을 따른다.

한 줄 요약

EdgeX 기반 디바이스 연결 장애 복구 기능을 개선해 2차년도 400 ms 내부 개발 기준을 30회 반복시험에서 충족하고, 별도 장애였던 Core Data 503을 해소해 복구 데이터의 중앙 저장 재개까지 확인했다.

다섯 살에게 설명하면

평소 센서가 너무 자주 말하게 하지 않고 1초마다 말하게 뒀다. 선이 실제로 끊겼다가 다시 연결된 순간에만 컴퓨터가 “지금 값 알려 줘”라고 최대 네 번 짧게 요청한다. 그래서 평소 통신량은 늘리지 않으면서 끊긴 뒤에는 400 ms 안에 다시 데이터를 받을 수 있었다.

중앙 저장소도 오래된 데이터를 찾다가 멈추는 문제가 있었다. 센서별 서랍에서 먼저 찾고, 한 작업을 끝낸 뒤 다음 서랍을 열도록 바꿔 새 데이터가 중앙까지 다시 들어오게 했다.

지난주 추진실적

  1. 성능지표 8의 측정 범위를 오류 감지 → 첫 유효 데이터의 EdgeX SDK 전송 재개로 고정하고 Kubernetes node·Pod 전체 failover와 구분했다.
  2. Arduino Serial 정상 전송 주기는 1,000 ms로 유지하고, 실제 연결 오류 뒤에만 고정 READ_NOW를 25 ms 간격으로 최대 네 번 보내는 on-demand 복구 방식을 적용했다.
  3. USB 재열거 때 ttyACM 번호가 바뀌어도 USB serial identity와 동적 endpoint로 같은 장비를 따라가도록 연결 경로를 안정화했다.
  4. 실제 cdc_acm 인터페이스를 50 ms 단절·복원하는 정식 30회 시험에서 30/30회 400 ms 이내 복구를 확인했다.
  5. Core Data Event/Reading 503의 원인을 대용량 최신순 조회와 DB connection pool 교착으로 확인하고, device-first index 조회와 connection 선반납 방식으로 수정·배포했다.
  6. 수정 후 추가 canary에서 205.724 ms 복구와 전송 재개 4.130 ms 뒤 첫 Core Data Event 저장·조회까지 확인했다.

주간보고 붙여넣기용 문장

EdgeX 기반 디바이스 연결 장애 복구 기능을 개선하고 실장비 반복시험을 수행하였다. 정상 센서 전송은 1초 주기로 유지하되, 연결 단절이 검출된 경우에만 제한된 현재값 요청을 수행하도록 구성하였다. 실제 Serial 연결의 50 ms 단절·복원 30회 시험 결과 30회 모두 400 ms 이내에 데이터 전송이 재개됐으며, p50 196.619 ms, p95 304.244 ms, 최대 309.848 ms로 확인됐다. 또한 Core Data의 대용량 디바이스 조회 및 DB connection pool 교착 문제를 개선해 Event/Reading 503을 해소했으며, 후속 E2E canary에서 205.724 ms 복구와 전송 재개 후 4.130 ms 이내 중앙 Event 저장을 확인하였다.

다음 주 추진계획

  1. 공식 시험 record 형식에 맞춰 각 장애 회차의 process metric과 첫 후속 Core Data Event ID를 한 묶음으로 자동 수집한다.
  2. 현재 p95 304.244 ms, max 309.848 ms와 최종 250 ms 목표 사이의 초과 구간을 port-ready·first-byte·validation 단계별로 분석한다.
  3. Serial 구현에서 확인한 on-demand-read, resubscribe, passive-first-data 전략을 MQTT·Modbus·OPC-UA·RTSP Device Service 계약에 적용할 시험 항목으로 구체화한다.
  4. NotReady 상태인 Sense HAT 노드의 현장 연결을 복구한 뒤 같은 중앙 Event readback 절차를 적용한다.

해석 경계

  • 이번 결과는 2차년도 400 ms 내부 개발 gate와 중앙 저장 E2E canary 근거다.
  • 과제 최종 250 ms 목표, TTA 공식 성적과 Kubernetes/KubeEdge node·Pod 전체 failover

완료를 뜻하지 않는다.

  • 단절 중 생성된 데이터의 durable 저장·재전송은 별도 개발·시험 범위다.
