서비스 데모 시나리오

현재 상태

기존 Sense HAT Agent 데모는 2026-07-21 퇴역했다. 현재는 중앙 EdgeX만 유지되고 실제 edge Device Service가 없는 전환 상태이므로 서비스 데모를 PASS로 시연하지 않는다.

다음 대표 시나리오는 Jetson에 연결된 Arduino 센서 1종을 정식 EdgeX Serial Device Service로 연결하고 대시보드에서 디바이스-서비스 관계와 최신 telemetry를 확인하는 것이다.

Arduino sensor
  -> Serial endpoint on etri-dev0001-jetorn
  -> custom EdgeX Serial Device Service
  -> Device Profile / Device
  -> Core Data Event / Reading
  -> PostgreSQL / state-aggregator / dashboard

데모가 증명해야 하는 것

  • Core Metadata Device가 physical inventory와 관리 상태의 권위다.
  • Device Service가 실제 Serial endpoint, 재연결, 값 표준화와 상태를 관리한다.
  • Device Profile이 resource 이름, value type, 단위와 read/write 계약을 정의한다.
  • Core Data 최신 Event/Reading이 telemetry와 freshness의 권위다.
  • KubeEdge는 Device Service와 AI workload의 배치·상태만 관리한다.
  • dashboard가 device, profile, Device Service, protocol, 상태, 최신 reading과 consumer 연결을 한 흐름으로 보여준다.

사전 조건

  1. Jetson에서 Arduino 장치 파일, 권한과 baud rate를 read-only로 확인했다.
  2. 실제 line protocol과 sample field/value type을 기록했다.
  3. Device Service/Profile/Device 이름을 승인했다.
  4. Device Service image가 immutable digest로 배포된다.
  5. 중앙 EdgeX Core 서비스와 PostgreSQL이 Ready다.
  6. edgex-edge NetworkPolicy에 Device Service가 필요한 최소 통신만 허용된다.

MQTT broker는 Arduino가 MQTT-only 장비가 아닌 이상 사전 조건이 아니다.

시연 순서

1. Device Service workload 확인

Jetson에 Device Service Pod가 배치되고 Ready인지 확인한다. KubeEdge node 상태는 workload 진단 정보이며 physical device availability를 단독 결정하지 않는다.

2. Metadata binding 확인

Core Metadata에서 다음 관계를 확인한다.

Device Service
  -> Device Profile
  -> Device
  -> serial protocol binding

adminState, operatingState와 endpoint 연결 상태가 실제 Device Service 보고와 일치해야 한다.

3. 실제 telemetry 확인

Arduino의 실제 sample을 발생시키고 Core Data에서 같은 deviceName의 Event/Reading을 조회한다. resource 이름과 valueType, 단위, timestamp가 profile과 일치해야 한다.

4. 장애와 복구 확인

장치 분리 또는 통신 오류 시 Device Service가 DOWN/degraded 상태와 원인을 보고하고, 장치 복구 뒤 재연결해 새 Event를 발행하는지 확인한다. 재시도나 outbox가 범위에 포함되면 별도 실패 테스트와 데이터 보존 증거를 요구한다.

5. dashboard 확인

dashboard에서 다음을 한 화면으로 확인한다.

  • Device/Profile/Device Service/protocol
  • admin_state, operating_state, connection_state
  • 최신 Event 시각과 telemetry_freshness
  • typed latest_readings
  • 관련 AI service/storage/dashboard consumer
  • 선택적 node/workload 진단 정보

상태 판정

조건 dashboard 상태 의미
UNLOCKED + UP + connected + fresh Event available 수집과 저장 경로가 실제로 관측됨
Device Service UP이지만 stale/no events degraded 등록은 되었지만 데이터 경로 점검 필요
LOCKED/DOWN/disconnected unavailable 관리 상태 또는 endpoint 연결 점검 필요
Device Service 미배포 not_deployed 또는 등록 없음 현재 전환 상태, 완료 아님

PASS 기준

  1. 실제 Jetson endpoint와 Device Service 연결 증거가 있다.
  2. Device Service/Profile/Device가 정확한 관계로 등록된다.
  3. 실제 sample의 typed Event/Reading이 Core Data에서 조회된다.
  4. 장애·복구 시 상태와 새로운 Event가 기대대로 변한다.
  5. dashboard가 같은 EdgeX device identity와 freshness를 표시한다.
  6. 문서, manifest, 테스트와 live 상태가 같은 구조를 설명한다.

command/actuator, 동적 workflow 실행, runtime migration/offloading은 이 데모의 PASS 범위가 아니다.
