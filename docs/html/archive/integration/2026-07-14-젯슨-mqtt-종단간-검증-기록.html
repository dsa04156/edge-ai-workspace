2026-07-14 젯슨 MQTT 종단간 검증 기록

상태: 중앙 MessageBus 분리 배치 이전의 Jetson-local canary 검증 기록. 현재 운영 절차가 아니다.

목적과 현재 판정

이 문서는 현재 운영 배포인 Argo CD Application edgex-telemetry와 Kustomize 진입점 edgex/k8s의 MQTT canary 경로를 읽기 중심으로 검증한다. namespace는 telemetry, 배치 node는 etri-dev0001-jetorn다.

Jetson local Mosquitto 127.0.0.1:1883
  factory/devices/vib-arduino-acceleration-01/telemetry
  -> hostNetwork mqtt-edge-bridge
  -> Jetson local Mosquitto
     incoming/data/vib-arduino-acceleration-01/telemetry
  -> hostNetwork edgex-device-mqtt
  -> ClusterIP edgex-messagebus:1883
  -> edgex-core-data:59880
  -> PostgreSQL StatefulSet / local-path PVC
  -> state-aggregator(default namespace)
  -> dashboard

EdgeX가 물리 device inventory, state, telemetry의 권위다. KubeEdge는 이 경로의 workload를 Jetson에 배치하고 관측할 뿐이다. 현재 검증 범위는 EdgeX 4.0.2 ARM64 기반 MQTT canary 한 대다. Serial, Modbus, OPC-UA, RTSP는 실장비 E2E 검증 전이므로 이 문서의 PASS 범위가 아니다.

2026-07-14 live 판정:

  • Jetson local MQTT부터 EdgeX Core Data/PostgreSQL까지의 live ingestion은 edgex/scripts/smoke_test.py로 PASS했다.
  • state-aggregator image digest sha256:e13c8de7e8571ddd52821dc585fc7497eef3cfc880f9dc0654863dd26280d43a의 live API와 browser UI에서 arduino-001의 네 source를 확인했다.
  • 따라서 현재 전체 판정은 MQTT ingestion PASS, dashboard live cutover PASS, EdgeX Argo CD adoption pending이다.

검증 안전 경계

일반 검증에서는 workload/PVC를 삭제하거나 재시작하지 않고, manifest를 실제 apply하지 않으며, EdgeX metadata/state를 변경하거나 command/actuator 메시지를 발행하지 않는다. PVC 지속성을 확인하려고 PostgreSQL 또는 Core Data를 재시작하지 않는다. 이 문서의 유일한 live write gate는 아래 smoke script가 만드는 실행별 합성 telemetry sample이다. 스크립트가 임시 publisher Pod lifecycle과 정리를 자체 관리한다.

Core Metadata와 Core Data에는 NodePort, Ingress, LoadBalancer 또는 외부 API endpoint를 만들지 않는다. 조회는 Kubernetes API의 Service proxy만 사용한다.

1. 정적 렌더와 server dry-run

저장소 root에서 유일한 배포 진입점인 edgex/k8s를 확인한다.

rtk kubectl kustomize edgex/k8s >/tmp/edgex-k8s-rendered.yaml
rtk kubectl apply --dry-run=server -k edgex/k8s

--dry-run=server는 API validation만 수행하며 리소스를 저장하지 않는다. 렌더 결과와 server 응답은 다음 계약을 만족해야 한다.

  • namespace는 telemetry다.
  • 모든 workload의 node selector는 etri-dev0001-jetorn다.
  • EdgeX image는 ARM64 4.0.2 계열이다.
  • mqtt-edge-bridge와 edgex-device-mqtt만 hostNetwork: true다.
  • 모든 Service는 ClusterIP이며 Core API의 외부 노출 리소스가 없다.
  • edgex-messagebus Service port는 1883이다.
  • PostgreSQL volumeClaimTemplate은 local-path, 5Gi다.
  • Argo CD Application은 edgex-telemetry, source path는 edgex/k8s, destination namespace는 telemetry다.

Argo 선언과 live 동기화 상태를 읽는다.

rtk kubectl -n argocd get application edgex-telemetry \
  -o custom-columns='NAME:.metadata.name,PATH:.spec.source.path,NAMESPACE:.spec.destination.namespace,SYNC:.status.sync.status,HEALTH:.status.health.status'

정상 기준은 edgex-telemetry, edgex/k8s, telemetry, Synced, Healthy다. Application이 없으면 live MQTT ingestion 성공과 별개로 GitOps adoption은 pending이다.

2. node, workload, Service, PVC readiness

rtk kubectl get node etri-dev0001-jetorn \
  -o jsonpath='{.metadata.name}{" "}{.status.nodeInfo.architecture}{" "}{range .status.conditions[?(@.type=="Ready")]}Ready={.status}{"\n"}{end}'
rtk kubectl -n telemetry get pod \
  -l app.kubernetes.io/part-of=edgex-telemetry -o wide
rtk kubectl -n telemetry get deployment,statefulset
rtk kubectl -n telemetry get service \
  -o custom-columns='NAME:.metadata.name,TYPE:.spec.type,CLUSTER-IP:.spec.clusterIP,PORTS:.spec.ports[*].port'
rtk kubectl -n telemetry get pvc \
  -o custom-columns='NAME:.metadata.name,STATUS:.status.phase,CLASS:.spec.storageClassName,CAPACITY:.status.capacity.storage'

정상 기준:

  • etri-dev0001-jetorn는 Ready=True, arm64다.
  • edgex-postgres-0과 모든 app.kubernetes.io/part-of=edgex-telemetry Pod가 Running이며 container가 Ready다.
  • edgex-messagebus, edgex-core-keeper, edgex-core-data, edgex-core-metadata, edgex-device-mqtt, mqtt-edge-bridge의 desired/ready replica가 일치한다.
  • 모든 Pod의 NODE는 etri-dev0001-jetorn다.
  • PostgreSQL PVC는 Bound, StorageClass local-path, capacity 5Gi다.
  • 모든 Service의 type은 ClusterIP다.
  • edgex-messagebus는 port 1883, edgex-core-data는 59880, edgex-core-metadata는 59881을 제공한다.

host network 예외와 내부 bus 설정을 읽는다.

rtk kubectl -n telemetry get deployment mqtt-edge-bridge edgex-device-mqtt \
  -o custom-columns='NAME:.metadata.name,HOSTNETWORK:.spec.template.spec.hostNetwork,NODE:.spec.template.spec.nodeSelector.kubernetes\.io/hostname'
rtk kubectl -n telemetry get deployment edgex-messagebus \
  -o custom-columns='NAME:.metadata.name,READY:.status.readyReplicas'

두 host-network workload만 HOSTNETWORK=true이고 node가 etri-dev0001-jetorn이어야 한다. Southbound broker는 두 workload 관점에서 Jetson의 127.0.0.1:1883이며, edgex-messagebus:1883은 별도의 EdgeX 내부 bus다.

3. Core Metadata profile/device

Core Metadata edgex-core-metadata:59881은 외부에 노출하지 않고 Kubernetes API Service proxy로 조회한다.

rtk kubectl get --raw \
  '/api/v1/namespaces/telemetry/services/http:edgex-core-metadata:59881/proxy/api/v3/deviceprofile/name/etri-vibration-mqtt'
rtk kubectl get --raw \
  '/api/v1/namespaces/telemetry/services/http:edgex-core-metadata:59881/proxy/api/v3/device/name/vib-arduino-acceleration-01'

profile 정상 기준:

  • name=etri-vibration-mqtt
  • resource가 정확히 acceleration_x, acceleration_y, acceleration_z, source_timestamp를 포함한다.
  • acceleration resource는 Float64, source_timestamp는 Int64다.
  • telemetry device command가 네 resource를 묶는다.

device 정상 기준:

  • name=vib-arduino-acceleration-01
  • profileName=etri-vibration-mqtt
  • serviceName=device-mqtt
  • protocol에 mqtt가 있다.
  • properties.nodeName=etri-dev0001-jetorn은 선택적 placement 진단값이다. 기존 등록 Device에 아직 비어 있어도 inventory/availability 실패로 판정하지 않으며, 향후 재등록 또는 명시적 metadata migration으로 보강한다.
  • adminState와 operatingState가 응답에 존재하며 운영 허용/UP 상태다.

등록 정보가 없거나 다르면 다른 inventory source로 보완하지 않고 Core Metadata/bootstrap 문제로 판정한다.

4. Kubernetes live smoke gate

다음 기존 script가 live gate다.

rtk edgex/mqtt-bridge/.venv/bin/python edgex/scripts/k8s_smoke_test.py

이 script는 다음을 한 번에 검증한다.

  1. Kubernetes API Service proxy로 Metadata profile/device를 조회한다.
  2. etri-dev0001-jetorn에 host-network 임시 publisher Pod를 배치한다.
  3. Jetson 127.0.0.1:1883의 factory/devices/vib-arduino-acceleration-01/telemetry에 실행별 합성 source_timestamp를 가진 QoS 1 sample을 발행한다.
  4. Core Data Event origin의 발행 전후 범위를 페이지 단위로 조회한다.
  5. 같은 실행의 device, source, 네 Reading과 값을 식별한다.
  6. 성공과 실패 모두 임시 publisher를 정리한다.

성공 stdout은 정확히 다음 한 줄이어야 한다.

PASS device=vib-arduino-acceleration-01 source=telemetry readings=4

다른 PASS 문구, 과거 Event의 단순 존재, publisher 성공만으로 이 gate를 대체하지 않는다.

5. Core Data Event/Reading과 PostgreSQL 저장 결과

Core Data edgex-core-data:59880도 Kubernetes API Service proxy로만 조회한다.

rtk kubectl get --raw \
  '/api/v1/namespaces/telemetry/services/http:edgex-core-data:59880/proxy/api/v3/event/device/name/vib-arduino-acceleration-01?limit=1'

최신 smoke 실행을 판정할 때는 script의 correlation 검증 결과를 기준으로 하고, 위 latest 조회는 저장 결과를 사람이 확인하는 보조 조회로 사용한다. 응답 정상 기준:

  • events[0].id가 비어 있지 않다.
  • events[0].deviceName=vib-arduino-acceleration-01
  • events[0].sourceName=telemetry
  • events[0].origin이 유효한 정수 timestamp다.
  • Reading 이름 집합은 정확히 acceleration_x, acceleration_y, acceleration_z, source_timestamp다.
  • smoke sample에서 acceleration 값은 각각 0.12, 0.08, 0.91이고 source_timestamp는 해당 실행이 만든 correlation 값과 일치한다.
  • 각 Reading에 resourceName, valueType, value, origin이 존재한다.
  • Event가 Core Data 재조회에서 반환되고 PostgreSQL PVC가 Bound인 것이 현재 비파괴 저장 확인 범위다. 재시작을 통한 persistence 시험은 일반 E2E 검증에 포함하지 않는다.

Event가 없으면 순서대로 Jetson local Mosquitto, mqtt-edge-bridge, 변환 topic, edgex-device-mqtt, edgex-messagebus:1883, Core Data, PostgreSQL을 확인한다.

rtk kubectl -n telemetry logs deployment/mqtt-edge-bridge --tail=100
rtk kubectl -n telemetry logs deployment/edgex-device-mqtt --tail=100
rtk kubectl -n telemetry logs deployment/edgex-core-data --tail=100
rtk kubectl -n telemetry get pod,pvc -o wide

6. state-aggregator API

state-aggregator는 default namespace에서 동작한다. EdgeX Core URL은 namespace를 생략한 짧은 이름이 아니라 다음 cluster FQDN이어야 한다.

EDGEX_CORE_METADATA_URL=http://edgex-core-metadata.telemetry.svc.cluster.local:59881
EDGEX_CORE_DATA_URL=http://edgex-core-data.telemetry.svc.cluster.local:59880

배포 image와 환경을 읽는다.

rtk kubectl -n default get deployment state-aggregator \
  -o custom-columns='IMAGE:.spec.template.spec.containers[0].image,READY:.status.readyReplicas'
rtk kubectl -n default get pod -l app=state-aggregator \
  -o custom-columns='POD:.metadata.name,IMAGE-ID:.status.containerStatuses[0].imageID,READY:.status.containerStatuses[0].ready'
rtk kubectl -n default get deployment state-aggregator \
  -o jsonpath='{range .spec.template.spec.containers[0].env[*]}{.name}={.value}{"\n"}{end}'

API는 Kubernetes API Service proxy로 조회한다.

rtk kubectl get --raw \
  '/api/v1/namespaces/default/services/http:state-aggregator:8000/proxy/state/devices'
rtk kubectl get --raw \
  '/api/v1/namespaces/default/services/http:state-aggregator:8000/proxy/state/dashboard'
rtk kubectl get --raw \
  '/api/v1/namespaces/default/services/http:state-aggregator:8000/proxy/state/summary'

MQTT canary device의 필수 EdgeX 필드:

name
source
profile_name
device_service_name
protocol_names
admin_state
operating_state
connection_state
device_service_available
latest_event_timestamp
latest_readings[]
telemetry_freshness
node_name
overall_status
reason

정상 기준:

  • source=edgex
  • profile_name=etri-vibration-mqtt
  • device_service_name=device-mqtt
  • protocol_names에 mqtt가 있다.
  • admin_state가 잠금 상태가 아니고 operating_state=UP다.
  • connection_state=connected, device_service_available=true다.
  • latest_event_timestamp가 존재하고 telemetry_freshness=fresh다.
  • latest_readings가 Core Data 최신 Event의 source_name=telemetry와 네 resource_name을 보여준다.
  • node_name=etri-dev0001-jetorn는 placement 진단값이며 물리 availability의 권위나 선행 gate가 아니다.
  • Core Metadata/Core Data 조회 실패는 명시적 error/unobserved 상태로 드러나며 다른 source로 fallback하지 않는다.

availability 판정은 EdgeX 기준이다. 잠금 또는 DOWN은 unavailable, Device Service가 연결되고 최신 Event가 fresh하면 available, 상태가 불명확하거나 Event가 stale/no-events이면 degraded다.

7. dashboard live cutover

브라우저는 현재 외부 경로 http://192.168.0.56/aggregator#inventory에서 직접 확인한다. Kubernetes API Service proxy는 API 격리 확인이 필요할 때 사용한다.

rtk kubectl proxy --port=8001
http://192.168.0.56/aggregator#inventory

확인 항목:

  • MQTT canary arduino-001 card/row의 inventory source가 EdgeX로 표시된다.
  • profile etri-uno-mqtt, Device Service device-mqtt, protocol mqtt가 표시된다.
  • admin_state, operating_state, connection_state, Device Service availability가 API와 일치한다.
  • latest Event 시각과 freshness가 표시된다.
  • latest readings에 acceleration.x/y/z, magnetic.value, temperature.raw, light.value의 source/resource/value/type/origin 정보가 표시된다.
  • unavailable/degraded reason은 EdgeX state 또는 Core Data freshness로 설명된다.
  • optional node placement가 없어도 물리 availability가 강등되지 않는다.
  • 화면이 MQTT canary만 완료로 표시하고 Serial/Modbus/OPC-UA/RTSP를 live 완료로 표현하지 않는다.

  2. 그 image가 EdgeX 필드를 반환하는 /state/devices 또는 /state/dashboard 응답
  3. 같은 시점 dashboard 화면에서 위 필드를 렌더링한 캡처
  4. smoke script의 정확한 PASS line과 최신 Event identity

2026-07-14에는 runtime image digest, live API, browser Assets/Explain Panel과 output/edgex-dashboard-live-20260714.png를 함께 확인했으므로 dashboard live cutover는 PASS다.

8. post-cutover legacy mapper 부재 assertion

cutover 뒤에는 Argo CD Application 목록과 default namespace DaemonSet 목록을 읽는다.

rtk kubectl -n argocd get applications.argoproj.io \
  -o custom-columns='NAME:.metadata.name,SOURCE:.spec.source.path'
rtk kubectl -n default get daemonsets.apps \
  -o custom-columns='NAME:.metadata.name,DESIRED:.status.desiredNumberScheduled,READY:.status.numberReady'

정상 기준:

  • Application source에 mappers/mqttvirtual/resource가 없고 legacy mapper Application이 없다.
  • default namespace에 mqttvirtual-mapper DaemonSet이 없다.
  • current ingestion Application은 edgex-telemetry 하나이며 source는 edgex/k8s다.

legacy mapper가 남아 있으면 post-cutover FAIL이다. 일반 검증 중 이를 삭제하지 말고 Argo/GitOps cutover drift로 기록한다.
