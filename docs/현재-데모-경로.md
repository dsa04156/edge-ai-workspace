# 현재 데모 경로

## 정상 흐름

```text
Arduino / Sense HAT
  → node-local EdgeX Device Service
  → 중앙 EdgeX MessageBus
  → Core Data / PostgreSQL
  → state-aggregator
  → dashboard

Arduino 가속도·온도 Local Data
  → sensor-anomaly-demo
  → 결과·알림 SQLite
  → state-aggregator
  → 서비스 DAG·결과·알림 화면
```

## 실행 구성

| 단계 | workload | 배치 |
|---|---|---|
| Serial 수집 | `device-serial-jetson` | `etri-dev0001-jetorn` |
| I2C 수집 | `device-sensehat-raspi` | `etri-dev0003-raspi5` |
| 중앙 저장 | EdgeX Core Data + PostgreSQL | `etri-ser0002-cgnmsb` |
| edge inference | `sensor-anomaly-demo` | `etri-dev0001-jetorn` |
| 운영 read model | `state-aggregator` | Kubernetes server node |

## 확인 순서

telemetry freshness는 EdgeX Core Data latest Event의 nanosecond `origin`을 sample 시각으로
사용하며 API 조회 시각이나 Kubernetes 상태로 대체하지 않는다.

1. Kubernetes node와 workload가 Ready인지 본다.
2. Core Metadata에서 Device Service, Device와 Profile binding을 읽는다.
3. Core Data latest Event의 `origin`이 freshness window 안인지 확인한다.
4. AI 서비스의 input/model/result 상태를 확인한다.
5. `/state/services`와 대시보드의 서비스 이름·DAG·실행 target을 확인한다.

## 현재 사용하지 않는 경로

- `edgex-edge-agent-*`와 outbox PVC
- mapper direct-to-Influx
- legacy `command`/`heartbeat` MQTT topic
- KubeEdge DeviceStatus 기반 센서 상태
- RTSP frame의 Core Data 전송
- dashboard에서의 Kubernetes·EdgeX mutation

운영 명령은 [현재 서비스 데모 운영 절차](ops/현재-데모-운영-절차.md)를 따른다.
