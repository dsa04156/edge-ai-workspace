# 현재 데모 경로

## 목적

현재 PoC는 물리 디바이스를 실제로 중앙 EdgeX와 연결하고, 디바이스-서비스 연결 구조와 상태를 대시보드에서 운영 관점으로 보이는 데 집중한다. 동적 workflow 실행과 offloading 완성이 목표가 아니다.

물리 inventory와 schema는 EdgeX Core Metadata, telemetry와 freshness는 EdgeX Core Data가 권위다. KubeEdge는 edge node와 workload 관리에만 사용한다.

## 한 줄 경로

```text
센서 / PLC / 장비
  -> Protocol Adapter
  -> edge-telemetry-agent + SQLite outbox
  -> HTTPS/mTLS ingest gateway
  -> EdgeX Core Data / PostgreSQL
  -> state-aggregator / dashboard
```

카메라 frame은 요청 시 Workflow Pod가 RTSP를 직접 구독한다. telemetry agent는 frame transport가 아니라 상태와 결과 metadata 전달에만 사용할 수 있다.

## 책임 분리

| 영역 | 책임 컴포넌트 | 현재 계약 |
|---|---|---|
| protocol 연결 | 물리 노드의 Protocol Adapter | Modbus/OPC-UA/Serial/I2C 직접 수집 또는 조건부 MQTT 입력 |
| 로컬 장애 보존 | `edge-telemetry-agent` | canonical Event 검증, SQLite commit, retry/replay |
| 중앙 ingest | `edgex-ingest-gateway` | mTLS/HMAC 검증, Core Data REST 저장 확인 |
| inventory/schema | EdgeX Core Metadata | Device Service, Device Profile, Device |
| telemetry/freshness | EdgeX Core Data | Event `deviceName`, `sourceName`, `origin`, typed Reading |
| 영구 저장 | PostgreSQL | Core Data Event/Reading |
| node/workload | Kubernetes/KubeEdge/Prometheus | 배치와 readiness의 display-only 진단 |
| 운영 화면 | state-aggregator/dashboard | 중앙 Metadata/Data 조회와 설명 |

MapperFramework, `mqttvirtual`, KubeEdge `DeviceStatus`와 mapper direct-to-Influx는 current physical plane이나 fallback이 아니다.

## 현재 live 검증 fixture: Sense HAT I2C

```text
Sense HAT
  -> /home/etri/sensehat_publisher.py
  -> http://127.0.0.1:18080/v1/events
  -> edgex-edge-agent-sensehat
  -> /var/lib/edgex/outbox/outbox.db
  -> https://edgex-ingest-gateway.edgex-system.svc.cluster.local:8443
  -> Core Data / PostgreSQL
```

| 항목 | 값 |
|---|---|
| 물리 노드 | `etri-dev0003-raspi5` |
| EdgeX Device | `sensehat-001` |
| Device Profile | `etri-sensehat` |
| 논리 Device Service | `edge-telemetry-agent` |
| adapter | I2C Sense HAT publisher |
| local ingress | loopback HTTP `127.0.0.1:18080` |
| local buffer | SQLite WAL, logical maximum 1GiB, PVC 2GiB |
| northbound | HTTPS/mTLS + edge별 HMAC |
| local MQTT broker | 없음 |

이 디바이스명과 publisher는 현재 E2E 검증에 사용한 교체 가능한 fixture다. 향후 센서 교체를 막는 아키텍처 계약이나 전체 완료 기준으로 사용하지 않는다.

publisher는 여섯 source의 canonical EdgeX v3 Event를 만든다.

- `temperature`: `temp_humidity`, `temp_pressure`
- `humidity`: `humidity`
- `pressure`: `pressure`
- `compass`: `compass`
- `orientation`: `pitch`, `roll`, `yaw`
- `gyroscope`: `gyro_x`, `gyro_y`, `gyro_z`

agent는 SQLite commit 뒤에만 `202 queued`를 반환한다. 응답이 유실되면 publisher는 같은 Event ID를 재시도하고 outbox가 동일 payload를 deduplicate한다.

## MQTT 적용 조건

MQTT는 EdgeX나 agent의 전제조건이 아니다.

- MQTT-only 장비가 canonical Event를 발행할 때
- 한 노드의 여러 로컬 consumer가 pub/sub를 실제로 필요로 할 때

위 조건이 실제 장비에서 확인된 경우에만 local broker와 별도 MQTT Protocol Adapter를 추가한다. 현재 root render에는 MQTT-mode agent, `edgex-device-mqtt`, Jetson telemetry agent나 edge-local broker가 없다. MQTT-only adapter도 canonical EdgeX Event를 만들어 loopback agent API에 전달하는 동일한 durable 계약을 따라야 한다.

중앙 `edgex-messagebus`는 stock EdgeX Core와 중앙 consumer용 ClusterIP다. 물리 노드의 MQTT broker나 agent northbound와 다른 계층이다.

## 배포

단일 운영 진입점:

```bash
kubectl kustomize edgex/k8s
```

root Kustomize는 다음 두 overlay를 렌더링한다.

| overlay | namespace | 노드 | workload |
|---|---|---|---|
| `overlays/testbed/server2` | `edgex-system` | `etri-ser0002-cgnmsb` | gateway, Core Keeper/Metadata/Data/Command, internal MessageBus, PostgreSQL, Metadata bootstrap |
| `overlays/testbed/sensor-gateways` | `edgex-edge` | Raspberry Pi 검증 노드 | direct edge telemetry agent와 node-local outbox PVC |

root render에는 `edgex-device-mqtt` workload가 없다. 중앙 MessageBus는 server2에만 있고 edge node에는 Core, MessageBus, PostgreSQL을 배치하지 않는다.

## Metadata 등록

`edgex-metadata-bootstrap` Job은 이름으로 존재 여부를 확인한 뒤 다음 순서로 누락 객체만 만든다.

1. `edge-telemetry-agent` Device Service
2. 현재 contract의 `etri-sensehat` Device Profile
3. 현재 contract의 `sensehat-001` Device

등록 contract는 `edgex/k8s/base/server/config/metadata-contract.json`이다. Secret이나 런타임 endpoint credential은 이 파일에 넣지 않는다.

## 대시보드 조회

현재 핵심 API:

```text
GET /state/devices
GET /state/devices/{device_id}
GET /state/devices/{device_id}/telemetry
GET /state/dashboard
```

`/state/devices`의 최소 정보:

- Core Metadata `name`, `profileName`, `serviceName`
- `adminState`, `operatingState`
- protocol summary와 masked properties
- latest Core Data Event `sourceName`, `origin`, typed Readings
- freshness와 availability reason
- 선택적 Kubernetes node diagnostic

availability 순서는 `docs/대시보드-판단-정책.md`를 따른다. node placement와 workload readiness는 physical availability를 대체하지 않는다.

## 장애 시 동작

| 장애 | 동작 | 성공 기준 |
|---|---|---|
| gateway/네트워크 중단 | Event를 SQLite에 유지하고 backoff | pending 증가, ACK 후에만 감소 |
| gateway 응답 유실 | 같은 Event ID 재전송 | Core Data 기존 Event fingerprint가 같을 때 dedupe |
| ID 재사용/내용 충돌 | terminal conflict | 해당 Event를 자동 성공 처리하지 않음 |
| outbox 용량 초과 | adapter에 `507 outbox_full` | 저장되지 않은 sample을 ACK하지 않음 |
| Core Data 실패 | gateway가 retryable failure 반환 | outbox row 유지 |
| Metadata 객체 기존 존재 | bootstrap skip | 중복 객체 없음 |

SQLite outbox는 영구 backup이 아니다. node disk 손실과 장기간 용량 초과를 보호하려면 별도 보존 정책이 필요하다.

## 향후 프로토콜 확장 후보 gate

Serial, Modbus, OPC-UA와 추가 I2C 장비는 다음을 각각 검증한 뒤 현재 지원으로 승격한다.

1. 실제 endpoint reconnect와 connection owner
2. Device Profile과 canonical typed Event mapping
3. loopback agent admission과 SQLite 장애 보존
4. 중앙 persisted ACK와 Core Data readback
5. Core Metadata inventory와 dashboard freshness
6. command가 있을 때만 인증, TTL, dedupe와 실패 동작

RTSP는 별도 gate를 쓴다.

1. Workflow Pod의 직접 RTSP 구독
2. frame을 Core Data에 넣지 않는 media boundary
3. 상태·결과 metadata의 Device/Profile 계약
4. 요청/종료와 실패 관찰

## Workflow Builder Prototype 경계

dashboard의 workflow stage, binding, validation과 execution plan은 브라우저 안 dry-run이다.

- Metadata Device 목록과 Core Data freshness 조회
- stage와 device/resource bind/release
- validation과 execution plan preview

Kubernetes apply/delete/restart, command publish, actuator mutation, runtime migration/offloading은 실행하지 않는다. 운영 기능으로 승격하려면 먼저 범위, 검증 기준과 운영 책임을 문서에 추가한다.

## 완료 판정

저장소의 코드와 manifest만으로 live cutover 완료를 주장하지 않는다. 다음을 같은 실행에서 확인한다.

- 새 image digest가 gateway와 agent에 배포됨
- 승인된 adapter sample이 local `202 queued`를 받음
- 같은 Event ID가 중앙 Core Data에서 조회됨
- gateway 중단 동안 outbox가 보존되고 복구 후 drain됨
- Core Metadata inventory와 dashboard freshness가 일치함

현재 검증 fixture인 Sense HAT publisher의 교체는 이 데이터 플레인 완료 판정과 별도로 관리한다.

## 현재 제외

- MQTT가 필요하지 않은 노드의 상시 local broker
- mapper/KubeEdge DeviceStatus fallback
- command/actuator 실행
- RTSP frame의 Event/DB 저장
- Workflow Pod mutation
- runtime migration, dynamic offloading, agent-assisted planning
