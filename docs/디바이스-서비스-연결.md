# 디바이스 연결 가이드

## 목표

새 물리 장비를 EdgeX Device로 등록하고 첫 Event가 Core Data에 저장될 때까지의 기준을
설명한다. Kubernetes Pod를 띄운 것만으로 연결 완료로 판단하지 않는다.

## 연결에 필요한 네 가지

| 항목 | 설명 | 권위 |
|---|---|---|
| Device Profile | resource 이름, type, units, command | Git + EdgeX Core Metadata |
| Device | 장비 identity와 protocol binding | EdgeX Core Metadata |
| Device Service | endpoint 연결과 값 표준화 | EdgeX SDK workload |
| 첫 Event | 실제 수집·저장 증거 | EdgeX Core Data |

## 연결 절차

### 1. 장비 계약을 확정한다

- 물리 장비와 소유 node
- protocol과 exact endpoint
- resource 이름, 자료형, 단위와 수집 주기
- read-only/write command 경계
- 분리·재연결과 오류 처리 기준

비밀번호, token, URL userinfo, 임의 image·command·hostPath를 descriptor나 후보 정보에 넣지
않는다.

### 2. 검증된 Adapter Catalog binding을 선택한다

Serial은 `/dev/serial/by-id/*`, I2C는 allowlist bus/address와 read-only identity를 사용한다.
네트워크 endpoint는 광역 scan하지 않고 운영자가 직접 선언한다.

발견 후보의 `accepted`는 검토 상태일 뿐 자동 등록이나 workload 배포가 아니다. exact
node/protocol/path가 Git Catalog와 일치해야 등록 Saga로 넘길 수 있다.

### 3. Runtime을 준비한다

기존 Runtime이 같은 protocol binding을 이미 소유하면 재사용한다. 없으면 Adapter
Controller가 검증 template만 배포한다.

- 고정 Serial/I2C Runtime은 Argo CD 소유다.
- Controller가 만든 `AdapterRuntime`만 Controller가 재시작·퇴역할 수 있다.
- raw hostPath, 임의 image와 privileged 설정은 UI 입력으로 받지 않는다.

### 4. Profile과 Device를 등록한다

등록은 idempotent해야 한다. 같은 identity·같은 계약은 재사용하고, 같은 이름의 다른
계약은 conflict로 차단한다. 최종 Device/Profile/state 권위는 계속 EdgeX다.

### 5. 첫 Event를 확인한다

연결 완료에는 다음 증거가 모두 필요하다.

telemetry freshness는 EdgeX Core Data latest Event의 nanosecond `origin`을 sample 시각으로
사용하며 API 조회 시각이나 Kubernetes 상태로 대체하지 않는다.

1. Device Service workload와 endpoint Ready
2. Core Metadata의 Device Service/Profile/Device readback
3. Device `adminState=UNLOCKED`, `operatingState=UP`
4. Core Data의 계약된 resource와 type
5. latest Event `origin`이 freshness window 이내

## 현재 protocol 상태

| protocol | 현재 수준 | 주의점 |
|---|---|---|
| Serial | Arduino 운영 경로 검증 | exact CharDevice와 단독 reader 필요 |
| I2C | Sense HAT 운영 경로 검증 | allowlist bus/address와 장치 권한 필요 |
| MQTT | 개발 package와 canary | 운영 TLS/auth broker 계약 미완료 |
| Modbus TCP | 개발 simulator 수직 경로 검증 | 실제 PLC register map 미완료 |
| OPC-UA | 미검증 | Profile·실장비·telemetry 필요 |
| RTSP | 직접 구독 원칙 | frame을 Core Data에 넣지 않음 |

## 서비스에 입력으로 연결한다

Device 연결과 AI 서비스 연결은 별도 계약이다. 서비스 descriptor에 필요한
`device_name`, `resource_name`, schema, window와 freshness를 선언한다. 다음 gate가 모두
통과해야 서비스 입력을 `ready`로 표시한다.

- Device/Profile/Device Service identity 존재
- 필수 resource와 type 일치
- 최신 Event 또는 Local Data가 fresh
- window 표본과 다중 입력 시각 정렬 충족
- AI model과 결과 sink 준비

새 AI 서비스 등록은 [AI 서비스 등록 가이드](AI-서비스-등록-가이드.md)를 따른다.
