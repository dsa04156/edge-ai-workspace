# 현재 데모 흐름

## 실제 구현 경로

```text
센서·PLC·장비
  -> 노드 로컬 EdgeX Device Service
       1) endpoint 연결·값 표준화
       2) canonical EdgeX Event 발행
  -> Core Data / PostgreSQL
  -> Local Data API / edge AI consumer
  -> state-aggregator API
  -> dashboard
```

이 경로는 [원시 텔레메트리 데이터 플레인](../원시-텔레메트리-데이터-플레인.md),
`edgex/device-serial/`, `edgex/device-sensehat/`과 `edgex/k8s/`에서 구현한다.

## 현재 배포 단위

| 위치 | 배포 | 역할 |
|---|---|---|
| 중앙 `edgex-system` | Core Keeper/Metadata/Data/Command, MessageBus, PostgreSQL, ingest gateway | 등록·저장; gateway는 현재 Serial/I2C 정상 경로 밖에 유지 |
| `etri-dev0001-jetorn` | `device-serial-jetson` | Arduino Serial 직접 수집 |
| `etri-dev0003-raspi5` | `device-sensehat-raspi` | Sense HAT I2C 직접 수집 |
| `default` | `state-aggregator` | EdgeX 조회·상태 계산·dashboard API |

운영 배포는 root `edgex/k8s/kustomization.yaml`에서 재현한다. MQTT broker, `device-mqtt`, MQTT-mode agent는 현재 root 배포에 없다.

## 장애별 관찰 지점

| 증상 | 먼저 볼 곳 | 해석 |
|---|---|---|
| endpoint open 실패 | Device Service 로그와 char device | 장치·권한·binding 문제 |
| Local Data stale | Device Service recent API | 수집 중단 또는 cache 초기화 |
| Core Data 미저장 | Device Service와 Core Data API | 중앙 경로·MessageBus·저장 문제 |
| dashboard degraded | Metadata state + 최신 Event timestamp | node Ready만으로 복구 판정 금지 |

## 현재 fixture와 후속 승격

현재 Arduino Serial과 Sense HAT I2C는 각각 공식 SDK 기반 Device Service가 typed telemetry를
만든다. Modbus, OPC-UA, MQTT-only 장비를 “지원 완료”로 표시하려면 해당 Device Service,
Profile/Device contract, 실제 endpoint Event, 재연결과 장애 테스트가 모두 있어야 한다.

RTSP 영상은 Core Data로 보내지 않고 요청 시 Workflow Pod가 직접 구독한다. Core Data에는 상태·endpoint metadata·분석 결과만 남긴다.

## 실행 경계

dashboard의 서비스 설계 stage 구성, source bind, validation, execution plan preview는 브라우저
안 dry-run이다. Kubernetes apply/delete/restart, EdgeX mutation과 command publish는 이 화면에서
수행하지 않는다. 별도 Runtime 경로의 candidate·Lease 격리 검증과 로컬 partial offloading
구현은 [현재 구현 상태](../현재-구현-상태.md)에서 구분하며, 현재 정상 production 흐름은
Jetson edge-local 처리다.
