# 현재 데모 흐름

## 한 줄 요약

중앙 EdgeX는 유지되고 기존 custom edge Agent는 퇴역했다. 현재 Jetson Arduino를 정식 EdgeX Serial Device Service로 연결한 첫 수직 슬라이스가 정상 수집·저장·대시보드까지 동작한다.

## 현재 배포

```text
etri-ser0002-cgnmsb
  -> EdgeX Core Keeper / Metadata / Data / Command
  -> internal MessageBus (ClusterIP)
  -> PostgreSQL
  -> ingest gateway (현재 edge client 없음)

edgex-edge
  -> device-serial-jetson @ etri-dev0001-jetorn
  -> /dev/arduino-001, 공유 reader 1개, virtual-*-001 Device 6개
  -> default-deny + 최소 허용 NetworkPolicy
```

KubeEdge는 node와 workload 관리만 담당한다. EdgeX Core Metadata와 Core Data가 물리 디바이스 inventory/state와 telemetry의 권위다.

## 현재 흐름

```text
Arduino sensor
  -> Jetson Serial endpoint
  -> custom EdgeX Device Service
  -> Device Profile / Device
  -> EdgeX Event / Reading
  -> central internal MessageBus
  -> Core Data / PostgreSQL
  -> state-aggregator / dashboard
```

Device Service가 실제 endpoint 연결, 표준화, 상태와 read-only command를 관리한다. MQTT-only 장비가 아니므로 edge-local broker를 배치하지 않았다. 카메라 frame은 후속 Workflow Pod가 RTSP를 직접 구독한다.

## 권위와 상태 판단

| 영역 | authority | 판단 근거 |
|---|---|---|
| inventory / 관리 상태 | EdgeX Core Metadata | Device Service/Profile/Device, admin/operating state |
| telemetry / freshness | EdgeX Core Data | latest Event/Reading timestamp |
| node / workload | Kubernetes/KubeEdge | placement와 workload 상태 진단 |

Device Service가 UP이어도 Event가 없거나 stale이면 device는 degraded다. node placement는 진단 정보이며 physical availability gate가 아니다.

## 퇴역 경로

다음 항목은 현재 배포나 fallback이 아니다.

- `edgex-edge-agent-jetson`, `edgex-edge-agent-sensehat`
- Agent SQLite outbox와 HTTPS persisted-ACK edge 경로
- `edge-telemetry-agent`라는 논리 Device Service와 `sensehat-001` bootstrap
- KubeEdge Device/DeviceModel/DeviceStatus와 MapperFramework
- `mqttvirtual`, mapper direct-write, legacy command/heartbeat topic

## workflow 경계

Workflow Builder는 현재 browser 상태 안에서 stage 구성, device/resource bind/release dry-run, validation과 execution-plan preview만 제공한다. Kubernetes apply/delete/restart, EdgeX mutation, command publish, actuator 제어와 runtime offloading은 수행하지 않는다.
