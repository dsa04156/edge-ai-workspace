# 2차년도 설계 트랙

## 목표

2026년도 2차년도는 옥동의 PLC·MES·센서 데이터를 활용해 생산품질 판별과 메인·보조 유압펌프·모터 이상감지 PoC를 완성하는 단계다. [ETRI 실행계획](../2차년도-ETRI-실행계획.md)이 목표·역할·월별 산출물·완료 gate의 단일 진입점이다.

## 단계

| 시기 | 트랙 | 판단 기준 |
|---|---|---|
| 8월 | 현장 범위·Device·데이터 명세 | 입력 장비, 주기, 생산 건 식별자 확정 |
| 9월 | 수집·통합 | common timestamp, source/device contract, 장애 버퍼 |
| 10월 | AI 서비스·workflow | 컨테이너 API와 수집→전처리→추론→저장→알림 연결 |
| 11월 | 엣지·서버 분산·복구 | 배치 검토, 재실행, 데이터 source 계약 시험 |
| 12월 | 통합 PoC | dashboard·결과·장애 시나리오 시험결과서 |

## Device source와 workflow의 위치

현재 물리 디바이스 inventory와 telemetry의 권위는 EdgeX Device/Profile/Event다. 시뮬레이터와 replay 데이터는 물리 디바이스로 합치지 않고, 도입 시 별도의 데이터 source 계약과 운영 책임을 먼저 정의한다.

현재 서비스 설계 화면에서 허용하는 것은 stage 구성, Device/resource binding, validation,
execution-plan preview다. 별도 Runtime 경로에서는 승인 candidate 생성, SHADOW validation과
Lease handoff/rollback을 격리 환경에서 검증했지만 production traffic 전환은 차단 상태다.
부분 inference offloading도 로컬 구현·격리 protocol 시험 단계이며 운영 배포가 아니다.
다음은 후속 승격 gate가 필요하다.

- 옥동 실제 AI 컨테이너와 학습 모델의 결과 검증
- production traffic routing과 candidate promotion·정리 정책
- 범용 runtime migration/offloading과 자동 장애복구
- command/actuator mutation
- 운영자 승인·감사·rollback

따라서 `edge-orch/workflow_executor/`, `placement_engine/`, `workflow/`와 archive의 selective replanning 자료를 현재 운영 기능으로 설명하지 않는다.

## 보고서 표현

“완전 자율형 오케스트레이션” 대신 “서비스 데모 우선, 디바이스-서비스 연결과 통합 운영 가시화, 단계적 확장”으로 쓴다. 완료를 주장할 때는 해당 단계의 코드, manifest, 테스트와 live evidence를 함께 제시한다.
