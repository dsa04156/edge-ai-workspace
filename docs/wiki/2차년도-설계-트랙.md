# 2차년도 설계 트랙

## 한 줄 요약

2차년도는 옥동 PLC·MES·센서 데이터를 활용한 생산품질 판별과 유압펌프·모터 이상감지
서비스 2종을 중심으로 데이터 수집, AI 서비스 배포, 작업 분산, 장애복구와 통합
모니터링을 연결하는 PoC 프로토타입 구축 단계다. 이는 추진 목표이며 현재
workflow/offloading 구현 완료 주장이 아니다.

## 공식 추진 기준

보고서 본문은 [2026년도 2차년도 옥동 PoC 추진계획](../단계별-추진계획.md)을 따른다.

- 8월: 서비스 범위, 디바이스 구성과 데이터 접근방식 확정
- 9월: PLC·MES·센서 데이터 수집과 직접 전송 검증
- 10월: AI 서비스 2종 컨테이너화와 워크플로우 연동
- 11월: 엣지·서버 배치, 장애복구와 가상 디바이스 시험
- 12월: 데이터 수집부터 화면 표시까지 통합 PoC 검증

세부 데이터 필드, 장애별 처리와 화면 목록은 본문에 반복하지 않고 연결된 기술·운영
문서에서 관리한다.

## 현재 기준

현재 PoC는 아래 운영 기반을 만든다.

- 등록된 device
- node assignment
- telemetry/status 분리
- 상태 통합
- dashboard 가시화
- service-demo binding

2026-07-31 `서비스 설계` 캔버스는 이 트랙의 첫 browser-local 프로토타입이다. 실제
EdgeX Device/Profile resource 선택, 단계 연결, 타입·배치 validation과 dry-run 계획만
제공하며 서버 workflow registry나 runtime execution은 없다.

2026-08-03에는 [옥동 AI 서비스 데이터 계약](../옥동-데이터-계약.md)의 첫 코드 기준선을
추가했다. 서비스 2종의 versioned schema, 펌프 simulator/replay, model adapter와
SQLite/PVC 결과·알림 저장이 범위다. 이는 실제 옥동 field mapping, 생산품질 모델,
중앙 HA 저장 또는 workflow 실행 완료를 뜻하지 않는다.

2차년도 트랙은 이 기반 위에서 우선 서비스 2종을 실행하기 위한 아래 요소를 설계한다.

- PLC·MES·센서·품질 데이터의 공통 타임스탬프와 생산 건 연결
- 생산품질 판별 및 펌프·모터 이상감지 서비스 컨테이너
- 물리 on-device 기능, 상태, 자원, I/O를 표현하는 가상디바이스
- capability, resource, I/O, state, workflow binding snapshot을 관리하는 디바이스트윈
- 수집 → 전처리 → 추론 → 저장 → 알림의 stage 기반 AI service workflow
- validation과 execution-plan UI
- 엣지·서버 작업 분산과 장애 저장·재전송·복구 정책

## 경계

2차년도 가상디바이스는 legacy `test_device.py` fake MQTT publisher 의미와 다르다.
아래 legacy 경로를 현재 기능으로 조용히 승격하지 않는다.

- `edge-orch/workflow_executor/`
- `edge-orch/workflow_reporter/`
- `edge-orch/placement_engine/`
- `workflow/`
- selective replanning 또는 offloading archive 자료

legacy 구현을 재사용하려면 먼저 `docs/프로젝트-범위.md`와 `docs/저장소-구조.md`에 승격 근거를 남긴다.

## 운영상 의미

제안서나 보고서에서는 아래처럼 쓴다.

- 2차년도 작업은 단계적 설계/prototype 트랙으로 설명한다.
- 우선 서비스는 생산품질 판별과 유압펌프·모터 이상감지 2종으로 명시한다.
- 현재 dashboard 주장은 service demo visibility에 묶어 둔다.
- LLM이나 agent가 전체 플랫폼을 제어한다고 쓰지 않는다.
- workflow design/dry-run planning과 실제 runtime execution을 구분한다.
