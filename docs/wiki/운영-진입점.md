# 운영 진입점

## 5분 점검 순서

1. [현재 데모 운영 절차](../ops/현재-데모-운영-절차.md)로 중앙·edge Pod와 TLS endpoint를 확인한다.
2. Core Metadata에서 Device/Profile과 `adminState`·`operatingState`를 확인한다.
3. Core Data에서 최신 Event/Reading의 `origin`, `sourceName`, typed value를 확인한다.
4. `state-aggregator`의 `/state/devices`, `/state/dashboard`, `/state/summary`와 dashboard를 확인한다.
5. outbox depth와 gateway persisted ACK를 확인한다.
6. 마지막으로 Kubernetes/KubeEdge Node/Pod 배치를 진단 정보로 본다.

## 완료로 볼 수 없는 것

과거 canary 날짜나 문서의 “성공” 문구만으로 현재 live 상태를 판정하지 않는다. 현재 image digest, manifest, Core Metadata 응답, Core Data 최신 Event, dashboard 응답을 같은 실행에서 확인해야 한다.

또한 node Ready와 physical availability를 동일시하지 않는다. physical 상태는 [물리 디바이스 상태 정책](../물리-디바이스-상태-정책.md)의 EdgeX 관리 상태와 Core Data freshness를 따른다.

## 변경 주의

중앙 MessageBus 전체 재구축 문서는 파괴적 작업 전 승인 없이 실행하지 않는다. command 실행, 장비 제어, workload migration은 현재 비활성/설계 범위다.
