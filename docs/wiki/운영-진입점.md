# 운영 진입점

## 한 줄 요약

운영자는 Agent 퇴역 후 중앙 EdgeX와 빈 `edgex-edge` 상태를 확인하는 현재 운영 절차에서 시작한다. 과거 Agent 또는 중앙 MessageBus 직접 수집 재구축 문서는 실행하지 않는다.

## 현재 기준

운영 문서는 개념 문서와 분리한다. 실행, 검증, 장애 원인 좁히기 질문은 Ops 문서에서 시작한다.

| 상황 | 시작 문서 |
|---|---|
| 중앙 EdgeX와 Agent 퇴역 상태 점검 | [현재 서비스 데모 운영 Runbook](../ops/현재-데모-운영-절차.md) |
| EdgeX state-aggregator dashboard API/UI 확인 | [Dashboard 검증](../ops/대시보드-검증.md) |
| pod 또는 network 경로 점검 | [네트워크 트러블슈팅](../ops/네트워크-문제해결.md), [파드 통신 점검](../ops/파드-연결성-점검.md) |
| edge node join 확인 | [Edge 노드 조인 점검](../ops/엣지-노드-조인-점검.md) |
| GPU runtime 맥락 확인 | [HAMi GPU runtime](../ops/gpu-hami-런타임-운영.md) |

현재 중앙 EdgeX runtime은 `edgex-system`, 비어 있는 Device Service namespace는 `edgex-edge`, state-aggregator는 `default` namespace에 있다. 물리 inventory, 관리 상태, telemetry는 EdgeX가 authority이며 KubeEdge node/workload 정보는 별도 진단이다.

## 운영자 읽기 순서

라이브 데모에서는 다음 순서로 본다.

1. [현재 서비스 데모 운영 Runbook](../ops/현재-데모-운영-절차.md)에서 중앙 EdgeX와 Agent/PVC/Metadata bootstrap 퇴역 상태를 확인한다.
2. EdgeX Core Metadata에 퇴역 fixture가 남아 있지 않은지 확인한다.
3. EdgeX Core Data의 최신 Event/Reading `origin`, `sourceName`, typed value와 freshness를 확인한다.
4. namespace `default`의 state-aggregator API에서 `source=edgex`, `connection_state`, `device_service_available`, `latest_event_timestamp`, `latest_readings`, `telemetry_freshness`, `overall_status`, `reason`을 확인한다.
5. [Dashboard 검증](../ops/대시보드-검증.md)으로 device row, Explain Panel, EdgeX KPI와 node/workload 진단의 분리를 확인한다.
6. 자원증강 탭에서 AI HAT/GPU/cache Resource Profile과 실행 인스턴스 상태를 확인한다.
7. 기술 상태가 보인 뒤 KPI 문서를 사용한다.

KubeEdge node readiness와 workload placement는 dashboard에서 볼 수 있지만 물리 availability를 결정하지 않는다. 물리 availability는 EdgeX 관리 상태와 Core Data 최신 Event freshness로만 해석한다.

## 현재 live 판정

2026-07-14 UNO, 2026-07-15 Sense HAT canary와 2026-07-16 G003 HTTPS/outbox smoke는 장비·profile·Reading·durable replay 계약의 과거 근거다. 현재 image, 중앙 server2 Core/PostgreSQL과 state-aggregator/dashboard 조회 전환은 같은 실행의 새 live evidence를 확보할 때까지 pending이다. Sense HAT publisher 교체 여부는 별도다.

## 경계

Ops 문서는 operator assistant, workflow builder, 자원증강 화면이 infrastructure를 변경할 수 있는 것처럼 표현하지 않는다. 별도 승인된 control path가 생기기 전까지 이 기능은 read-only 요약, troubleshooting 안내, dry-run validation/plan preview로 제한한다.
