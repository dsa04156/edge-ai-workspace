# 물리 장비의 가상 디바이스

## 쉽게 설명하면

아두이노가 실제 장비라면 가상 디바이스는 그 장비의 기능과 상태를 모아 놓은 소프트웨어 창구다. 창구를 열면 어떤 장비인지, 어떤 값을 제공하는지, 어떤 서비스가 사용하는지 확인한다. 실제 센서나 계산 장치를 새로 만들지는 않는다.

## 2026-09-08 승인된 표현 계약

사용자는 물리 장비에 대응하는 가상 디바이스를 독립적으로 선택하고 원본·기능·상태·서비스를 확인하는 화면의 구현을 요청했다. 이번의 `가상 디바이스`는 다음 **읽기 전용 논리 장비 표현**을 뜻한다. 기능별 `관측 트윈`과 서버의 `vd-demo-001` 실행체는 원래 계약을 유지한다.

| 필드 | 계약 |
|---|---|
| 논리 ID | `physical-vd:` + 물리 source ID의 `encodeURIComponent` 값 |
| 종류 | `physical-source-representation` |
| 원본 | EdgeX read model의 정확한 `physical_device_id` |
| 권위 | EdgeX 등록 Device·Profile·Core Data Event |
| 접근 방식 | `read-only` |
| 제공 기능 | 같은 원본 ID로 묶인 EdgeX 등록 Device 목록 |
| 관측 트윈 | 원본 ID와 Device 이름이 모두 일치하는 기존 트윈 |
| 이용 서비스 | 기능별 바인딩에서 service ID로 중복 제거한 목록 |

현재 화면은 원본 장비 하나에 가상 표현 하나를 구성한다. 별도 저장소나 Kubernetes CRD에 새 inventory를 등록하지 않으며, API를 새로 만들지 않는다. `physical-vd:*`는 대시보드 논리 식별자이며 EdgeX Device 이름이나 서버 API 호출 대상이 아니다. 기존 `twin:*` ID도 바꾸지 않는다.

원본 ID가 같으면 관측값·수집 실행 노드·기능 순서가 바뀌어도 가상 ID는 유지된다. 원본 ID가 변경되면 다른 가상 ID다. 원본 ID가 없는 등록 항목은 가상 표현을 만들지 않고 미지정으로 표시한다. 정상 inventory 조회에서 원본이 사라지면 해당 표현도 목록에서 빠진다. 조회 실패 때는 이전 표현을 보존하며 현재 상태는 확인 불가로 표시한다.

## 화면과 사용법

1. `디바이스·트윈`의 **가상 디바이스** 탭을 연다. 직접 경로는 `/#physical-virtual-devices`다.
2. 아두이노 또는 Sense HAT 가상 디바이스를 선택한다.
3. 논리 ID와 원본 장비의 연결을 확인한다. **원본 장비 보기**와 **가상 디바이스 열기**로 양방향 이동한다.
4. 기능을 펼쳐 원본 등록 식별자, Profile, 최신 값·단위·시각, 관측 트윈, 이용 서비스와 입력 계약을 확인한다.

검색은 논리 ID·원본 ID·기능·서비스로 장비를 찾으며 형제 기능과 연결 수를 유지한다. 선택·펼침·키보드 위치는 자동 갱신 중 보존한다. 장비의 전체 정상/비정상 상태를 새로 계산하지 않고 기능별 상태와 서비스 입력 상태를 구분한다. 최근 Reading이 Profile의 전체 기능 목록이라고 설명하지 않는다.

## 실행체와의 차이

`vd-demo-001`은 별도 컨테이너에서 Iris 모델을 실행하는 시험 기능이다. 물리 장비의 가상 표현에는 시작·정지 버튼이 없으며 실제 센서 제어, 데이터 생성, desired/reported 상태 조작과 자동 성능 증강을 제공하지 않는다. 가상 표현의 서비스 목록은 기존 기능의 이용 관계이며 새 바인딩을 생성한 결과가 아니다.

## 구현과 검증

`state-aggregator/app/static/nexus/source-view.js`의 `virtualDevice`가 논리 표현을 구성하고 기존 `live-ui.js`·`platform.js`에 가상 탭과 직접 경로를 연결한다. 원본 GET API와 기존 상태 정책을 재사용한다.

자동시험은 논리 ID 안정성·인코딩 충돌 방지·원본 ID 부재·N:M 중복 제거·검색·관측 실패와 원본 이동 표현을 검증한다. 브라우저에서는 실제 장비·가상 표현 간 이동, 새로고침·뒤로가기, 기능 펼침 유지, API 실패 후 복구와 모바일을 확인한다. 이 검증은 simulator나 제어 기능의 검증이 아니다.
