# 가상 디바이스 운영 사이클

2026-09-08. NEXUS에서 기존 `vd-demo-001` 한 개를 시작하고 CPU 모델에 시험 요청을 보낸 뒤 정지하는 첫 운영 사이클을 구현했다.

## 사용 흐름

1. [가상 실행체](http://aggregator.192.168.0.56.sslip.io/#virtual-devices)를 연다.
2. **운영 권한**에 기존 실행 운영 토큰을 입력한다. 토큰은 이 화면의 메모리에만 유지하며 저장소에 쓰지 않는다.
3. **시작**을 누른다. 요청 접수와 모델 준비 완료는 다르다. 관측이 모델 Ready를 확인해야 시험 요청 버튼이 활성화된다.
4. Iris 입력 4개(cm)를 넣고 **시험 요청 보내기**를 누른다. `[5.1, 3.5, 1.4, 0.2]`의 검증 결과는 `setosa`다.
5. 결과·모델 ID/버전·artifact hash·입력 hash·Pod UID·boot ID·요청 ID를 확인한다.
6. **정지**를 누른 뒤 `정지 확인 · 실행체 0개`를 확인한다. 정의와 SQLite 작업 이력·결과는 남는다.

쉽게 말하면 등록부는 남겨 두고 계산 담당자만 출근·퇴근시킨다. 출근 요청을 받았다는 응답과 실제로 계산 준비가 끝났다는 상태는 따로 확인한다.

## 구현 계약

- 대상: `virtual-device-test/vd-demo-001`. CPU Iris 모델과 Server2 배치는 기존 Git 정의를 따른다. 새 정의 생성·모델 업로드·노드 이동·범용 오프로딩은 이 버전에 없다.
- 관측: 기존 `GET /api/virtual-devices`. 등록 정의·실행체·모델·요청·자원을 분리한다.
- 기능·이력: `GET /api/virtual-devices/vd-demo-001/control`.
- 변경: `POST /api/virtual-devices/vd-demo-001/actions`, JSON `action=start|stop|infer`. `infer`에만 `features` 4개를 받는다.
- 인증: `VIRTUAL_DEVICE_CONTROL_ENABLED=true`와 기존 `X-Execution-Token`. 다른 origin의 브라우저 요청과 다른 대상 ID는 거부한다.
- 중복 방지: UUID `Idempotency-Key`. 같은 키·payload는 저장 응답을 반환한다. 다른 payload는 409다. 프로세스 공유 파일 잠금으로 동시 작업을 제한한다.
- 권한: 단일 이름의 Deployment `/scale` get/update. 변경 직전 UID·resourceVersion, 등록 ID·이미지·노드·replica 계약을 확인한다. Pod create/delete 및 Deployment template mutation 권한은 추가하지 않는다.
- 시작·정지 결과는 `accepted`(접수)다. 준비/종료 확인은 기존 관측 API의 현재 상태가 담당한다. 접수 이력을 성공한 준비/종료 시각으로 오해하지 않는다.
- 원장: `DATA_DIR/virtual-device-operations.sqlite3`, aggregator PVC. 원장에는 토큰을 저장하지 않는다. GET 이력은 최근 30건이며 DB에 기록된 이전 행도 유지한다.
- 전송 후 timeout·중단은 `unknown`이다. 자동 재전송하지 않는다. 브라우저 응답 유실 시 같은 키를 유지하는 재전송 버튼을 제공한다. 프로세스 중단의 미완료 요청은 다음 조회/작업에서 unknown으로 복구하며 실행하지 않는다.
- 추론 대상은 정확한 소유 관계로 조회한 Pod IP이며 반환 영수증의 논리 ID·Pod UID·boot ID·모델 identity·입력 hash·요청 ID를 대조한다.
- 발신자는 `nexus-dashboard`다. 기존 Jetson 연결 설정의 실제 사용 증거나 공장 품질 모델 성능으로 표시하지 않는다.

## 검증 결과

- 기존 Python 전체 342개 통과 후 추가 계약·영수증 5개를 포함한 제어 모듈 17개 재검증 통과. 유효한 전체 Python 근거는 347개다. JavaScript 전체 193개 통과.
- 권한 없음, 다른 대상, 다른 origin, 잘못된 입력, 변경된 이미지·노드·ID, UID·resourceVersion 변경은 실행 전에 차단했다.
- 중복 요청/재기동 후 영속 결과, 처리 중 동시 요청, 전송 후 timeout 및 중단된 요청의 비재실행을 검증했다.
- 브라우저에서 POST 응답 단절을 주입하고 재전송 시 동일 요청 키 유지, 토큰 삭제 후 버튼 비활성화를 확인했다. 1440px/390px에서 부모·내부 화면 가로 넘침과 JavaScript 오류는 없었다.
- 운영 브라우저에서 시작 → 모델 Ready → 실제 CPU 추론 → 정지를 수행했다. 반환된 `setosa` 영수증을 동일 키로 재요청했을 때 완전히 같은 응답을 받았다.
- 실제 추론 요청 ID: `nexus-9f7d2aae-f7cd-472c-b788-27cd477391d5`. 실행 Pod UID: `1bd6fa65-917f-4fe1-9747-adfc33b2aba5`.
- 최종 replicas=0, 정상 Pod 조회에서 실행체 없음, 정의 1개와 저장 결과 유지. 브라우저 재접속 후 결과 복원과 토큰 빈 값 확인.
- 실제 RBAC: 해당 이름의 `/scale` update=yes, 다른 이름=no, Deployment patch=no.
- `device-serial-jetson`, `device-sensehat-raspi`, `sensor-anomaly-demo` 세 Deployment의 UID와 spec hash는 전후 동일했다.

코드 커밋 `bea7980a`, aggregator 이미지 `sha256:590dc8a683fe2d5667b23fa2bf341969ecfd7e0ed9ae4ff9cddf096912ecfde5`를 Argo CD `edge-orch-state-aggregator`로 반영했다. 해당 커밋의 Synced/Healthy와 목표 이미지 Ready 1개를 확인했다. runtime은 기존 immutable CPU 시험 이미지를 사용하며 시험 후 정지했다.

## 사용자 직접 시험 링크

2026-09-08 사용자 요청으로 토큰을 직접 입력하지 않는 시험 링크를 추가했다. 운영자가 `app.virtual_device_test_access.issue`로 발급한 서명 capability는 24시간 동안 `vd-demo-001`의 시작·시험·정지 API에만 사용할 수 있다. 일반 실행 운영 토큰을 링크에 넣지 않으며 다른 운영 API에서는 사용할 수 없다.

링크 fragment `#vd-test=...`는 서버 요청에 포함되지 않는다. NEXUS가 fragment를 읽고 주소 기록에서 제거한 뒤 정확한 동일 출처 가상 실행체 iframe에만 전달한다. 브라우저 저장소에는 보존하지 않으므로 새로고침 후에는 원래 시험 링크를 다시 연다. 만료되면 새 링크가 필요하다. 링크를 연다고 실행체가 자동으로 시작되지는 않는다.

화면에서 **시작 → 모델 준비 → 예제 1/2/3 선택 → 시험 요청 보내기 → 결과 확인 → 정지** 순서로 사용한다. 예제 선택은 입력값만 바꾸며 자동 요청하지 않는다. 시험 링크와 서명은 Git·문서·영속 기억에 기록하지 않는다.
