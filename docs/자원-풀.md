# 자원 풀

## 목적

`자원 풀`은 서비스에 필요한 센서 데이터, 컴퓨팅 자원과 AI 서비스를 한 화면에서 찾고
호환성을 검증하는 현재 PoC의 통합 운영 화면이다. 자원 정보를 새 데이터베이스에 복제하지
않고 각 권위 시스템의 현재 관측을 `state-aggregator`에서 읽기 전용으로 합성한다.

## 권위와 데이터 소스

| 자원 분류 | 권위 | 자원 풀 입력 |
|---|---|---|
| 센서·데이터 | EdgeX Core Metadata / Core Data | `/state/devices`의 Device/Profile, latest Reading, freshness와 capability |
| 컴퓨팅 노드 | Kubernetes/KubeEdge | `/state/nodes`의 node health와 pressure |
| 컴퓨팅·가속기 | Kubernetes workload 관측 | `/state/virtual-resources`의 desired/observed/free instance와 capability |
| AI 서비스 | 코드와 함께 배포하는 서비스 카탈로그 | 현재 검증된 고정 `sensor-anomaly-demo` 계약과 workload reference |
| 사용 중인 연결 | 서비스 데모의 읽기 전용 입력 계약 | EdgeX Device → AI input contract 관계 |

자원 풀의 `service_catalog`는 물리 디바이스 inventory나 실행 상태의 권위가 아니다. 서비스의
표시명, 입력 capability 조건과 고정 workload reference만 제공한다. 물리 Device/Profile/Event
권위는 EdgeX, 노드와 workload 상태 권위는 Kubernetes/KubeEdge에 남는다.

## 사용자 흐름

```text
AI 서비스 선택
  -> 이름·노드·capability 검색 및 상태 필터
  -> 센서 데이터와 선택적 컴퓨팅 자원 선택
  -> 입력 capability·ready 상태·실행 요구사항 검증
  -> 비영속 Lease 미리보기와 연결 계획 확인
```

현재 서비스가 고정 Deployment를 이미 사용할 때는 새 컴퓨팅 예약을 요구하지 않고
`not_required`로 표시한다. 센서 입력을 직접 고르지 않으면 `ready` 상태이며 서비스 입력
capability 조건을 만족하는 첫 자원을 결정론적으로 추천한다. 사용 불가·stale·계약 불일치
자원을 직접 선택하면 계획을 차단하고 이유를 표시한다.

## API 계약

### `GET /state/resource-pool`

다음 선택 필터를 지원한다.

- `q`: ID, 이름, 설명, node와 capability 부분 검색
- `category`: `data`, `compute`, `service`
- `status`: `ready`, `degraded`, `unavailable`, `configured`
- `refresh`: service resource observation 갱신 요청

응답은 `mode=read_only`, `reservation_mode=dry_run`, 전체·표시 자원 요약, 자원 목록,
현재 연결과 관측 오류를 분리해 반환한다. 한 권위 소스가 실패해도 다른 분류를 빈 값으로
위장하지 않고 가능한 자원과 `observation_errors`를 함께 반환한다.

### `POST /state/resource-pool/plan`

요청은 `service_id`, 선택적 `data_resource_id`, `compute_resource_id`만 받는다. 응답은 다음을
포함한다.

- 선택 또는 추천된 서비스·센서 데이터·컴퓨팅 자원
- 서비스 계약, 센서 입력, 컴퓨팅, 변경 안전 경계별 `pass`/`fail`/`not_required`
- 호환될 때만 생성하는 15분 `lease_preview`
- 검증 순서와 차단 사유
- 권위와 mutation 금지 guardrail

`lease_preview.persisted`는 항상 `false`다. 이 POST는 상태를 저장하지 않으며 실제 자원 점유,
Kubernetes apply/delete/restart, EdgeX metadata/state mutation, command publish, runtime 이동이나
offloading을 수행하지 않는다.

## 화면 상태

| 표시 상태 | 의미 | 선택 가능 여부 |
|---|---|---|
| 사용 가능 | 센서 입력 ready 또는 node/resource가 현재 사용 가능 | 가능 |
| 확인 필요 | 입력 degraded, node pressure/상태 저하 또는 자원이 모두 할당됨 | 불가 |
| 구성됨 | registry·서비스 계약은 있으나 runtime instance가 관측되지 않음 | 서비스만 선택 가능 |
| 사용 불가 | EdgeX 입력 unresolved, node unavailable 또는 AI 서비스 관측 실패 | 센서·컴퓨팅은 불가, 서비스는 차단 사유 확인 가능 |

화면은 375px, 768px, 1024px, 1440px에서 전체 문서 가로 overflow 없이 동작해야 한다.
모바일에서는 요약, 단계, 서비스, 자원, 계획과 현재 연결이 한 열로 배치된다. 자원 카드의
이름·설명·capability는 긴 식별자에서도 줄바꿈되며 색상 외에 상태 문자열을 함께 표시한다.

## 현재 완료 기준

1. 센서·데이터는 `/state/devices`의 EdgeX 원본 identity와 available/degraded/unavailable, Core Data freshness를 자원 풀 상태로 투영한다.
2. 컴퓨팅은 `/state/nodes`와 `/state/virtual-resources`의 관측값을 사용하고 가짜 용량을 만들지 않는다.
3. 서비스 카탈로그는 현재 검증된 고정 서비스와 설계 템플릿을 명시적으로 구분한다.
4. 검색, category/status 필터와 선택 상태가 함께 동작한다.
5. 호환 계획은 required capability와 자원 상태를 검증하고 실패 이유를 반환한다.
6. Lease는 비영속 미리보기이며 API 호출 전후 권위 시스템과 workload를 변경하지 않는다.
7. 한 데이터 소스가 실패해도 다른 분류와 오류 원인을 함께 표시한다.
8. 자동 테스트와 실제 브라우저에서 375/768/1024/1440px, keyboard focus, console error와
   전체 문서 가로 overflow를 검증한다.

실제 예약·반납, workload 배포, 자동 연결과 runtime offloading은 별도 승인, 인증·인가,
영속 Lease 소유권, 충돌 제어, 보상 처리와 운영 검증을 갖춘 뒤에만 후속 범위로 승격한다.
