# 문서 정리 계획

이 문서는 `docs/프로젝트-범위.md`와 `docs/저장소-구조.md`를 기준으로 최신 문서, 탐색용 요약, 운영 절차, 설계 이력, 보관 자료의 노출 순서를 정한다.
원본 Markdown의 한국어 파일명·제목 통일, 진입점 단순화, 검색 노이즈 축소를 우선하며 원본 삭제는 별도 승인 대상으로 둔다.

전체 문서 목록과 현재 읽는 순서는 [`문서-분류-목록.md`](문서-분류-목록.md)를 기준으로 한다.

## 정리 원칙

1. 원본 Markdown은 계속 기준 자료로 유지한다.
2. Markdown 파일명과 최상위 제목은 한국어로 작성하되 EdgeX, KubeEdge, MQTT, API 같은 고유 기술명은 유지한다.
3. 정적 HTML은 `scripts/build-docs-html.py`로 재생성되는 보기용 산출물로 두고 직접 편집하지 않는다.
4. `docs/wiki/`는 질문과 탐색의 첫 진입점으로 둔다.
5. 최신 기준 문서는 현재 시스템 구축 목표와 직접 연결되는 원본문서로 둔다.
6. 운영 문서는 운영 점검, 장애 대응, 데모 실행에 필요한 원본문서로 둔다.
7. `superpowers/`는 설계·구현 계획 이력이며 현재 완료 상태의 근거로 사용하지 않는다.
8. 보관 문서는 과거 연구·논문·레거시 오케스트레이션 맥락으로만 둔다.
9. 중복 문서는 최신 기준 문서로 내용을 통합한 뒤 원본의 삭제 여부를 별도로 승인한다.
10. 워크플로·오프로딩·에이전트 보조 계획 계열은 현재 방향으로 보이지 않게 분리한다.

## 위키 문서

`docs/wiki/`는 질문 응답과 문서 탐색을 빠르게 하기 위한 합성 계층이다.
최신 기준·운영 원본문서를 대체하지 않고 근거 문서로 연결한다.

| 문서 | 역할 | 조치 |
|---|---|---|
| `wiki/지식-지도.md` | 전체 지식 지도와 원본문서 지도 | 위키 진입점 |
| `wiki/운영-규칙.md` | 에이전트 유지 규칙과 수집·질의·점검 절차 | 유지 규칙 |

## 검색 정책 제안

문서 사이트 검색은 위키, 최신 기준, 운영, 설계 이력, 보관을 분리한다.
보관 문서는 검색 결과에 나오더라도 별도 필터로 확인하는 것을 기본으로 한다.

권장 필터:

- 전체
- 위키
- 최신 기준
- 운영
- 설계 이력
- 보관

권장 기본값:

- 문서 홈: 위키 → 최신 기준 → 운영 → 설계 이력 → 보관 순서
- 보관 포함 여부: 사용자가 직접 선택
- 대형 로그 문서: 기본 검색 제외

## 정적 HTML 홈 개편 방향

정적 HTML 홈은 전체 원본이 아니라 공개 유지 문서만 다음 순서로 묶는다.

1. 시작하기
2. 연결 가이드
3. 운영
4. 정책과 계약
5. 개발 참고

위키·설계 이력·보관 문서는 저장소에는 보존하지만 공개 HTML과 기본 검색에서 제외한다.


## 레거시·보관 자료 처리

레거시 코드의 README와 `docs/archive/` 문서는 현재 PoC 판단 기준이 아님을 명시한다.
문서 파일명과 제목은 한국어로 통일하되, 내용은 이력 보존을 위해 임의로 현재 아키텍처에 맞춰 고쳐 쓰지 않는다.

처리 기준:

- 최신 정책과 구조는 `프로젝트-범위.md`, `원시-텔레메트리-데이터-플레인.md`, `저장소-구조.md`에만 반영한다.
- 과거 문서의 잘못된 현재형 표현은 보관 안내로 차단하고, 역사적 사실 자체는 보존한다.
- 중복 문서와 대형 로그는 기본 검색에서 제외한다.
- 원본 삭제는 링크·인용·실험 재현 필요성을 확인한 뒤 별도로 승인한다.

## 이번 정리 결과

- Markdown 파일명과 최상위 제목을 한국어 중심으로 통일했다.
- 문서 홈과 위키 지식 지도를 최신 중앙 EdgeX 데이터 플레인 기준으로 갱신했다.
- 내부 링크와 HTML 생성 목록을 변경된 파일명에 맞췄다.
- 과거 자료는 `archive/`, 설계·구현 계획 이력은 `superpowers/`에 보존했다.
- 2026-08-18 기준 Markdown을 최신 기준·운영·위키·설계 이력·보관으로 분류하고, 자원 증강
  실험 보고서를 포함한 공개 HTML은 현재 유지 문서 18개로 제한했다.
- 2차년도 옥동 PoC 목표를 `2차년도-ETRI-실행계획.md`로 독립시켜 보고서용 목표·역할·월별 산출물과 현재 구현 근거를 한 문서에서 추적할 수 있게 했다.
- 현재 기준 문서(목표·범위·데이터 플레인·서비스 데모·대시보드·상태 정책)를 실제 코드와 manifest 기준으로 대폭 재작성했다. 설계 이력과 보관 문서는 삭제하지 않고 경계를 유지했다.
- 보관 문서와 설계 이력에는 현재 운영 기준이 아니라는 상태 표지를 추가하고, 생성 HTML과 검색 색인을 다시 만들었다.
