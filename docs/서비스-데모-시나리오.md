# 서비스 데모 시나리오

## 목적

옥동 2차년도 대표 서비스 두 개를 같은 플랫폼 경로에서 시연한다.

1. 생산품질 양품·불량 판별
2. 메인·보조 유압펌프 및 모터 이상 감지

현재 Sense HAT은 입력·상태·대시보드 계약을 검증하는 fixture다. Sense HAT 검증을 옥동 PLC/MES 실증 완료로 표현하지 않는다.

## 공통 시나리오

```text
1. EdgeX Device/Profile 확인
2. Protocol Adapter가 sample 수집
3. edge agent가 SQLite outbox에 commit
4. HTTPS gateway가 Core Data에 persisted
5. service input window 구성
6. AI container 전처리·추론
7. 결과 DB 저장 및 알림 생성
8. dashboard에서 디바이스·서비스·결과·KPI 확인
```

## 시나리오 A: 생산품질 판별

### 입력

- MES 생산 건·공정 상태·생산품 ID
- PLC/센서 공정 변수
- 생산 건의 공통 timestamp와 `production_order_id`

### 처리

1. 수집 adapter가 Event/Reading을 표준화한다.
2. 전처리 단계가 생산 주기 window를 만든다.
3. 품질 모델이 `good`, `defect`, `unknown`과 confidence를 출력한다.
4. 결과와 모델 버전을 저장한다.
5. `defect` 또는 confidence 미달이면 운영 알림을 만든다.

### 성공 증거

- 같은 생산 건의 MES와 센서 입력이 재현된다.
- 입력 누락 시 임의의 양품 결과가 나오지 않는다.
- 결과에 `production_order_id`, `model_version`, `input_window`가 남는다.
- dashboard에서 결과·알림·원본 Device를 역추적할 수 있다.

## 시나리오 B: 펌프·모터 이상 감지

### 입력

- 진동 X/Y/Z
- 전류
- 온도
- 장비 운전 상태와 시간 window

### 처리

1. 3축·전류·온도 입력의 timestamp 정렬과 결측 처리를 수행한다.
2. 모델이 anomaly score와 severity를 계산한다.
3. 결과에 reason code와 모델 버전을 기록한다.
4. warning/critical 결과를 알림과 서비스 상태에 반영한다.

### 성공 증거

- 정상·이상 replay fixture가 동일한 결과를 재현한다.
- 한 축 또는 한 resource가 stale이면 결과가 `unknown/degraded`로 내려간다.
- 이상 결과에서 원본 Device/Profile/Event를 역추적할 수 있다.
- 통신 장애와 모델 장애를 서로 다른 원인으로 표시한다.

## 운영 화면

서비스 상세에서는 다음을 한 번에 확인한다.

| 묶음 | 내용 |
|---|---|
| 입력 | Device, Profile, resource, latest event, freshness |
| 실행 | service id, model version, input window, target node |
| 결과 | good/defect 또는 score/severity, 처리 시간 |
| 운영 | readiness, last success, last error, retry count |
| 영향 | 알림, 생산 건, KPI, 원본 Event 링크 |

## 장애 시나리오

| 장애 | 서비스 결과 | 운영 조치 |
|---|---|---|
| 장비 단절 | 입력 stale/unknown | adapter·케이블·전원 점검 |
| 중앙 연결 단절 | outbox pending, 추론은 정책에 따라 중지/로컬 실행 | gateway와 replay 확인 |
| Core Data 저장 실패 | 결과 확정 보류 | DB/gateway 복구 후 재처리 |
| 모델 container not ready | 서비스 degraded | Pod 로그·image·resource 점검 |
| resource 결측 | 품질/이상 결과 unknown | 입력 schema와 freshness 확인 |

## 현재 구현과 목표 구분

현재 repository에서 실행 가능한 범위는 EdgeX 조회, telemetry history, dashboard 상태, resource profile 관측, workflow dry-run이다. 품질 판별·펌프/모터 모델의 운영 완료는 모델 container, 입력 fixture, 결과 저장, 장애 시험이 추가된 뒤에만 `EVENT_CONFIRMED`와 별도로 판정한다.

Workflow 화면은 실제 Kubernetes apply/delete/restart나 EdgeX mutation을 실행하지 않는다. 동적 offloading과 runtime migration은 현재 서비스 데모의 성공 조건이 아니다.
