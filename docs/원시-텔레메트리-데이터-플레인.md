# 중앙 엣지엑스 원시 텔레메트리 데이터 플레인

## 목적

이 문서는 현재 운영 배포인 엣지 Device Service → 중앙 EdgeX MessageBus → Core Data·PostgreSQL 경로의 책임과 검증 기준을 고정한다.
과거 HTTPS ingest gateway와 SQLite 영속 송신함 설계는 `edgex/telemetry-plane/`에 프로토타입으로 남아 있지만 현재 `edgex/k8s/kustomization.yaml`의 배포 경로가 아니다.

## 현재 권위 경로

```text
물리 센서 / PLC / 장비
  -> Jetson 또는 Raspberry Pi의 EdgeX Device Service
  -> etri-ser0002-cgnmsb의 중앙 EdgeX MessageBus
  -> Core Data -> PostgreSQL
  -> Application Service / AI consumer / state-aggregator / dashboard
```

현재 수직 슬라이스는 MQTT 장비만 대상으로 한다.

- `etri-dev0001-jetorn`: Jetson 로컬 Mosquitto를 southbound로 사용하는 `edgex-device-mqtt`
- `etri-dev0003-raspi5`: Sense HAT MQTT endpoint를 소유하는 `edgex-device-mqtt-sensehat`
- `etri-ser0002-cgnmsb`: Core Keeper, Core Metadata, Core Data, Core Command, 내부 MessageBus, PostgreSQL

southbound MQTT broker는 센서와 Device Service 사이의 프로토콜 endpoint다.
EdgeX 내부 MessageBus는 Device Service와 중앙 Core·consumer 사이의 ClusterIP 메시지 경로이며 외부 broker가 아니다.

## 데이터와 상태 권위

| 영역 | 권위 | 기준 데이터 |
|---|---|---|
| inventory / schema / 관리 상태 | 중앙 EdgeX Core Metadata | Device, Device Profile, Device Service, `adminState`, `operatingState` |
| telemetry / freshness | 중앙 EdgeX Core Data | Event `deviceName`, `sourceName`, `origin`, typed Reading |
| command | Core Command와 담당 Device Service | profile command와 protocol endpoint |
| node / workload | Kubernetes / KubeEdge / Prometheus | 배치, readiness, 자원 상태 진단 |

KubeEdge Device, DeviceModel, DeviceStatus와 MapperFramework는 물리 inventory·telemetry·availability·command의 병행 plane이나 fallback이 아니다.

## 통신 경계

- 모든 EdgeX 서비스는 중앙 `edgex-messagebus`를 사용한다.
- Device Service는 중앙 Core Keeper의 configuration/registry와 Core Metadata에 접근한다.
- MessageBus와 Core API는 public endpoint로 노출하지 않고 ClusterIP와 클러스터 내부 DNS를 사용한다.
- EdgeCore 노드에서 ClusterIP 또는 service DNS 연결이 되지 않으면 배포를 중단하고 별도 승인된 사설 endpoint 설계로 전환한다.
- Application Service는 실제 서비스 데모 consumer 계약을 정의한 뒤 추가한다. 빈 placeholder 서비스는 배치하지 않는다.

## 장애 동작

현재 1차 수직 슬라이스에는 SQLite offline replay가 없다.

- 중앙 MessageBus 또는 네트워크가 끊기면 telemetry가 유실될 수 있다.
- 복구 기준은 연결 회복 뒤 새로운 Event 수집이 재개되는 것이다.
- 기존 샘플의 자동 재전송이나 누락 없는 전달을 주장하지 않는다.
- SQLite replay는 별도 승인된 설계와 구현이 필요하다.
- PostgreSQL 저장 확인까지 요구하려면 direct MessageBus 외에 persisted acknowledgement 계약이 필요하다.

## MQTT 수직 슬라이스

현재 등록과 검증 대상은 다음 두 Device Service instance다.

| Device Service | 배치 노드 | southbound endpoint | 대표 Device |
|---|---|---|---|
| `edgex-device-mqtt` | `etri-dev0001-jetorn` | Jetson 로컬 Mosquitto | `arduino-001` |
| `edgex-device-mqtt-sensehat` | `etri-dev0003-raspi5` | Sense HAT MQTT endpoint | `sensehat-001` |

2026-07-14 UNO 네 source와 2026-07-15 Sense HAT 여섯 source의 typed Event/Reading을 기존 canary에서 확인했다.
이 증거는 장비·profile·Reading 계약의 근거지만 중앙 server2 topology의 live cutover 완료를 자동으로 뜻하지 않는다.

## 프로토콜 확장 기준

현재 완료 범위는 MQTT 하나다.
Modbus, OPC-UA, Serial/I2C custom Device Service와 RTSP workflow Pod는 각각 다음 검증을 통과한 뒤 별도 wave로 승격한다.

- 명시된 protocol connection owner와 실제 endpoint reconnect
- Device Profile과 typed Reading 계약
- Device Service 상태와 command 동작
- 중앙 Core Data·PostgreSQL 저장
- 대시보드 consumer와 freshness 판정

RTSP frame은 Core Data Event로 저장하지 않고 별도 미디어 경로를 설계한다.

## 현재 배포와 프로토타입 구분

| 경로 | 상태 | 처리 원칙 |
|---|---|---|
| `edgex/k8s/kustomization.yaml` | 현재 운영 배포 진입점 | 중앙 Core/MessageBus/PostgreSQL과 엣지 Device Service 배치를 렌더링 |
| `edgex/k8s/core.yaml`, `messagebus.yaml`, `postgres.yaml` | 현재 중앙 데이터 플레인 | `etri-ser0002-cgnmsb`에만 배치 |
| `edgex/k8s/device-mqtt.yaml` | 현재 엣지 Device Service | Jetson과 Raspberry Pi에 각각 배치 |
| `edgex/telemetry-plane/` | 비활성 설계·프로토타입 | HTTPS gateway와 SQLite outbox 구현 참고용, 현재 배포 아님 |
| `edgex/k8s/base/server/`, `base/edge-agent/`, 관련 overlays | 비활성 대안 설계 | root Kustomize 진입점에서 사용하지 않음 |
| `edgex/mqtt-bridge/` | 보존 canary / legacy evidence | 현재 중앙 topology나 fallback으로 설명하지 않음 |

## 완료 검증 기준

- Kustomize render에서 Core, MessageBus, PostgreSQL workload는 `etri-ser0002-cgnmsb`에만 배치된다.
- Device MQTT workload는 각각 지정된 Jetson과 Raspberry Pi에만 배치된다.
- 엣지 노드에는 Core, MessageBus, PostgreSQL workload가 없다.
- 중앙 서비스는 amd64, Device MQTT는 ARM64 EdgeX 4.0.2 image를 사용한다.
- Device Service의 registry, MessageBus, Core Metadata endpoint는 중앙 service DNS를 가리킨다.
- MQTT payload가 Device Service를 거쳐 중앙 Core Data의 typed Event/Reading으로 저장된다.
- `/state/devices`가 중앙 Core Metadata 상태와 fresh Core Data Event를 사용한다.
- 중앙 MessageBus 장애 시 데이터 유실 가능성을 확인하고 복구 뒤 새 Event 수집 재개를 검증한다.

## 범위 밖

- SQLite offline replay와 persisted acknowledgement
- 기존 telemetry 데이터 migration과 backup
- EdgeX Core/PostgreSQL HA
- Modbus, OPC-UA, Serial/I2C, RTSP protocol wave 완료 주장
- Workflow Pod apply/delete/restart
- runtime migration, dynamic offloading, agent-assisted planning
