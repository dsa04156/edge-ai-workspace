# 대시보드 화면 설계

> 상태: 설계 이력. 현재 운영 기능의 완료 근거가 아니며 화면 설계 이력으로 보존한다.

## 목적

- 운영자가 디바이스, 노드, 서비스, telemetry freshness를 리소스 콘솔 흐름으로 읽게 한다.
- 현재 PoC 범위는 통합 운영 가시화와 검증된 Adapter Runtime·EdgeX Device 연결 관리다.
- 화면은 관측값과 판단 근거를 먼저 보여 주고, 검증된 관리 작업만 idempotency와 서버
  검증을 거쳐 실행한다.

## 전체 프레임

- Resource rail: 검은 좌측 레일, Edge AI Resource Console identity, 운영 현황, 디바이스, 장비 관리.
- Command bar: cluster context, global search, 마지막 갱신 시각, refresh.
- Workspace: 현재 선택된 page만 표시하며 카드형 장식 대신 resource row와 flat panel로 구성한다.
- Context detail layer: 선택한 디바이스·지표의 판단 근거와 read-only Qwen assistant를
  배경과 구분된 상세 레이어에 표시한다.
- Dense scroll: table, plan preview와 상세 레이어 내부에만 허용한다. 디바이스
  목록은 내부 고정 높이 scroll을 사용하지 않고 페이지 흐름을 따른다.

## Overview

- 첫 metric row: 엣지 AI 서버, 물리 디바이스, 가상 디바이스, 센서 디바이스의 수와
  Available 비율. 각 항목은 해당 `디바이스` 분류로 이동한다.
- 주 패널: `/state/dashboard`의 node snapshot을 중앙 서버와 물리 디바이스로 분리한다.
  각 패널은 평균 CPU·메모리, GPU 관측 대수와 pressure 주의 대수를 요약하고 노드별
  CPU·메모리·GPU 현재 meter, Available 상태, 최신 관측 시각,
  compute/memory/network pressure를 표시한다.
- 오른쪽 패널: 즉시 확인할 센서 상태와 원인. 상태는 색과 텍스트를 함께 사용한다.
- 서버와 물리 디바이스 상태는 Grafana식 고밀도 현황 표현을 사용하되 현재 snapshot만
  보여 준다. 두 분류를 합치지 않으며 물리 디바이스는 AI 엣지 노드와 경량 엣지 노드
  유형을 함께 표시한다.
  시계열 API 또는 저장소가 연결되기 전에는 과거 추세선을 합성하지 않는다.
- 고정 Jetson 서비스 데모와 플랫폼 기술 지표는 주 운영 판단 아래의 접힌 보조 영역이다.

## 디바이스

- 운영 객체를 `엣지 AI 서버`, `물리 디바이스`, `가상 디바이스`, `센서 디바이스`로
  분류한다. 서버와 물리 디바이스는 `/state/nodes`, 가상 디바이스는
  `/state/virtual-resources`, 센서 디바이스는 `/state/devices`를 사용한다.
- 네 분류를 동시에 카드로 늘어놓지 않고 분류 버튼으로 한 목록씩 전환한다. 각 목록은
  이름, 상태, 최신 관측 또는 Event, `상세보기`의 네 열만 먼저 표시한다.
- `물리 디바이스`는 Jetson·Raspberry Pi 엣지 노드다. EdgeX Core Metadata Device는
  `센서 디바이스`로 표시한다.
- 센서의 Profile, Device Service, protocol, admin/operating state, sourceName과
  Core Data 이력은 `상세보기`에서 확인한다. 서버·물리 디바이스는 CPU·메모리·GPU와
  pressure, 가상 디바이스는 인스턴스·capability·배치 상태를 상세 패널에 표시한다.
- 목록 행의 `상세보기`는 mouse/touch/keyboard로 선택할 수 있고 `aria-expanded`로
  상세 레이어 상태를 노출한다. 상세 레이어는 close, 바깥 영역 click, Escape로 닫고 원래 행으로
  focus를 돌려준다.
- 상세 레이어의 header, 상태 설명, 운영 도우미는 고정 grid row에 끼워 넣지 않고
  자연 높이의 단일 flex flow로 쌓는다. viewport 높이는 바깥 상세 레이어가 스크롤로
  처리하며 내부 section끼리 겹치거나 내용을 잘라서는 안 된다.
- Service Topology는 Assets 안에 둔다. 목적은 서비스 실행이 아니라 디바이스-서비스 연결 구조 확인이다.

## 제거된 AI Pipeline

- 현재 대시보드에는 Workflow Builder, graph canvas, validation과 execution-plan preview가 없다.
- 다시 도입할 경우 별도 범위 문서, 실행 책임, 검증 기준과 runtime control plane을 먼저 정의한다.

## Device Management

- 화면 상단의 노드 선택은 등록 현황과 장비 연결·수정 화면에서 유지되는 공통 운영 범위다. 각 노드 카드에는 관측 상태, Runtime 수, EdgeX Device 수와 등록 protocol 수를 요약한다.
- 기본 `등록 현황`은 `등록 장비`를 가장 먼저 보여 주고 `디바이스 프로필`, 승인 전 `연결 대기`, `수집 서비스`를 한 흐름으로 이어서 표시한다. 장비를 새로 연결하는 주 동작은 `장비 연결` 하나만 둔다.
- `연결 대기`는 onboarding 후보만 표시한다. 발견 Agent online/stale와 현재 관측·승인 대기·등록 완료·차단 수를 요약하고, 검색어·protocol·상태·presence로 목록을 좁힌다.
- USB Serial stable identity와 검증된 I2C chip identity를 node report에서 표시한다. 후보 카드는 source, presence, node, protocol, hardware ID, model, 권장 Profile, 상태, 인증과 차단 이유를 분리한다. I2C 버스 존재만으로 후보나 센서 응답을 만들지 않는다.
- exact binding이 없는 `BLOCKED` 후보에는 거절만 두지 않고 `연결 설정`을 제공한다.
  선택 시 해당 node와 후보 protocol, 차단 사유를 유지해서 보여 주며 관계없는 protocol을
  기본 선택하지 않는다. Git Catalog에 검증된 Profile·hardware binding이 생기기 전에는
  승인·배포를 허용하지 않는다.
- 수동 후보 입력은 `자동 탐색에 장비가 나오지 않나요?`를 펼친 경우에만 `직접 후보 등록`으로 노출한다. 대화상자는 node와 protocol에 따라 Serial path/baud, I2C bus, MQTT broker/topic, Modbus TCP/RTU, OPC-UA, RTSP, REST 필드만 보여 준다. 이는 후보 선언이며 비밀번호·token·URL userinfo, 임의 image/hostPath/command를 받지 않는다.
- 후보 `승인`은 exact Catalog match와 presence를 다시 검사한 뒤 외부 인증, 검증 Runtime 재사용·배포, EdgeX Profile/Device 등록과 첫 Event 확인 Saga를 시작한다. `FAILED` 후보의 같은 동작은 retry이며, 거절은 `REJECTED`로 전이한다. 자동 관측 후보의 일반 삭제는 재관측될 수 있어 `무시`로 보존한다. 등록 연결 decommission 뒤 장비가 계속 연결돼 있으면 같은 stable ID 후보가 다시 승인 대기로 나타나며 자동 재등록하지 않는다.
- 등록 현황의 장비·수집 서비스 영역은 연결 등록, 장비 관측, Device Service 통신, 최신 Event 상태를 분리해 보여 주며 binding이나 발견 후보만으로 장비 감지·통신 성공을 주장하지 않는다.
- 이어서 Runtime, protocol package와 기존 EdgeX Device를 보여 준다. Runtime owner/phase/consumer와 Device identity를 한눈에 확인하고, 신규 등록과 기존 수정은 등록 현황에서 해당 동작을 눌러 별도 화면으로 진입한다.
- protocol package 카드는 선택 노드 기준 `재사용 가능`, `설치 가능`, `연결 등록 필요`, `검증 필요`를 표시한다. 설치/재사용 가능한 카드만 등록 마법사 진입 버튼을 제공하고 미검증 protocol은 `설치 전 확인이 필요한 프로토콜` 안에 둔다.
- `장비 연결`은 `연결 선택 → 디바이스 정보 → 프로필 → 검증 및 연결`의 4단계 마법사다. 연결 선택 안에서는 protocol/Device Service를 가장 먼저 고르고, 선택 노드의 등록 hardware binding과 Device Service 준비 방식을 뒤에서 고른다. 현재 단계만 노출하며 마지막 단계에서 등록 요약, 실행 계획과 first Event 상태를 함께 보여 준다.
- 등록 현황의 `디바이스 프로필` 영역은 전체 등록 수와 웹에서 생성한 프로필을 즉시 표시한다. 기존 프로필과 웹 생성 프로필은 모두 장비 연결 3단계의 선택 목록에서 확인할 수 있다.
- `프로필 생성`은 EdgeX Device Profile을 웹에서 작성하는 별도 대화상자다.
  Profile 이름·제조사·모델·label과 최대 64개의 읽기 전용 DeviceResource
  이름·자료형·단위·설명을 입력하고, 서버 검증을 통과한 동일 payload만 Core Metadata에
  생성할 수 있다. 동일 이름의 다른 resource 계약은 차단하고 동일 계약은 재사용한다.
  후보의 model·capability는 초안에만 채우며 value type과 단위를 자동 추측하지 않는다.
- Profile 편집기는 command, parser, Device Service image, raw device path와 Catalog
  binding을 만들지 않는다. 따라서 Profile 생성만으로 `BLOCKED` 후보가 승인·등록되는
  것으로 표시하지 않고 검증 parser와 exact hardware binding을 별도로 요구한다.
- `기존 디바이스 수정`은 선택 노드의 Device를 먼저 선택해야 활성화한다. 이름·프로필·Device Service는 변경하지 않고 allowlist 필드만 수정한다.
- 설치되지 않았거나 미검증인 protocol도 접힌 현황 영역에서 차단 이유를 확인할 수 있지만 선택할 수 없다. 검증된 template과 등록 binding이 모두 있는 미설치 package만 `설치 가능`으로 선택한다. idempotency key와 기존 Device의 protocol properties JSON은 접힌 고급 영역에 둔다.
- 운영자는 runtime mode, catalog가 허용한 target node와 hardware binding만 선택할 수 있다.
- Serial 선택 시 같은 포트의 추가 resource와 두 번째 승인 USB Serial의 차이를 안내한다. binding이 제공한 `Port`/`BaudRate`/`DeviceID`는 read-only이고 resource route만 선택한다.
- validation은 `REUSE`·`DEPLOY`·`BLOCKED` runtime plan과 EdgeX Profile/Device plan을 마지막 등록 단계에 표시하며 mutation을 수행하지 않는다.
- `디바이스 연결`은 idempotency key가 있고 validation이 유효할 때만 활성화한다. 상태는 runtime, Metadata, first Event와 실패 보상을 분리해 표시한다.
- Argo CD 소유 Runtime은 조회·재사용 전용이다. Controller가 만든 Runtime만 restart할 수 있고 consumer가 0개일 때만 retire할 수 있다.
- 브라우저는 관리자 token을 입력·저장·전송하지 않는다. 관리 mutation은 기능 플래그,
  allowlist 검증과 `Idempotency-Key`를 사용하고 BFF의 Controller 호출은 내부 HMAC으로
  서명한다. 이 구성은 운영자 인증이 아니므로 현재 PoC Ingress 접근 경계를 운영 환경으로
  그대로 확장하지 않는다.

## 가상 디바이스 표시 경계

- `가상 디바이스` 분류는 현재 `/state/virtual-resources` 관측값을 읽기 전용으로
  표시한다.
- AI HAT·GPU·cache 같은 자원증강형 논리 자원의 등록 상태와 가용 인스턴스를 보여 주지만
  생성·삭제·할당·migration 버튼은 제공하지 않는다.
- 이 목록을 동적 Workflow, 자동 offloading 또는 Resource Augmentation 실행 기능
  완료로 설명하지 않는다.

## 표현 경계

- 유지: observed state, read-only explanation, dry-run, 검증된 template 기반 관리와 명시적 상태 추적.
- 금지: raw Kubernetes manifest/image/hostPath 입력, 외부 runtime 변경, MQTT command publish,
  actuator command, EdgeMesh/KubeEdge Device CRD 변경, runtime migration, autonomous orchestration completed.
- 가상 디바이스의 읽기 전용 관측은 제공하지만 자원증강 실행 기능으로 표현하지 않는다.

## 디바이스 트윈 표시 경계

- `디바이스 트윈` 화면은 `/state/device-twins`의 EdgeX Core Metadata Device와
  Core Data 최신 Event/Reading을 읽기 전용으로 묶어 표시한다.
- 각 행은 실제 `물리 디바이스`, EdgeX에 등록된 `관측 트윈`, 해당 트윈을 입력으로
  사용하는 `AI 서비스`의 연결 관계를 보여준다.
- 트윈과 AI 서비스는 N:M 관계로 표시한다. 한 트윈의 `service_bindings`에는 여러
  서비스가 들어갈 수 있으며 `서비스 연결` 요약은 연결된 트윈 수가 아니라 전체
  바인딩 수를 센다.
- 이 트윈은 현재 상태와 telemetry freshness를 나타내는 관측 상태 트윈이다. 가상
  하드웨어나 시뮬레이터가 아니며, desired/reported 제어 상태를 가진 KubeEdge Device
  Twin 또는 액추에이터 제어 기능으로 설명하지 않는다.

## Responsive

- Desktop: dark left resource rail + compact command bar + main workspace로 구성하고,
  선택 항목 상세정보는 최대 720px의 modal side sheet로 표시한다.
- Tablet: resource rail은 가로 tab으로 접고 graph는 세로 stack으로 전환한다.
- Mobile: resource rail은 가로 스크롤 tab으로 접히고, metric row와 panel header는 단일열로 전환한다. 노드 카드, 작업 탭과 등록 단계, Profile resource 편집 행은 세로로 쌓이며 페이지 가로 overflow를 만들지 않는다.
- 디바이스 분류 버튼은 tablet/desktop에서 4열, mobile에서 2열로 전환한다. 목록은
  mobile에서 행별 이름·상태·최신 관측·상세보기로 쌓는다. 760px 이하에서 상세정보는
  전체 viewport를 사용하고 body scroll을 잠그며, 상세정보 자체만 세로로 scroll한다.
- 발견 후보 toolbar와 요약 카드는 tablet에서 2열, mobile에서 1열로 전환한다. 수동 endpoint 대화상자는 viewport 안에서 세로 스크롤하고 action은 키보드 focus 순서를 유지한다.
