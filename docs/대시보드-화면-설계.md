# 대시보드 화면 설계

## 목적

- 운영자가 디바이스, 노드, 서비스, telemetry freshness를 리소스 콘솔 흐름으로 읽게 한다.
- 현재 PoC 범위는 통합 운영 가시화와 검증된 Adapter Runtime·EdgeX Device 연결 관리다.
- 화면은 관측값과 판단 근거를 먼저 보여 주고, 검증된 관리 작업만 idempotency와 서버
  검증을 거쳐 실행한다.

## 전체 프레임

- Resource rail: 검은 좌측 레일, Edge AI Resource Console identity, Overview, Assets, AI Pipeline.
- Command bar: cluster context, global search, 마지막 갱신 시각, refresh.
- Workspace: 현재 선택된 page만 표시하며 카드형 장식 대신 resource row와 flat panel로 구성한다.
- Inspector rail: State Explanation, read-only Qwen assistant.
- Dense scroll: 긴 목록, table, plan preview, inspector rail에만 허용.

## Overview

- Metric rows: node, device, telemetry, service resource, pod usage, binding.
- Current State Visualization: health ring, metric bars, status distribution, resource snapshot.
- Operations evidence: KPI catalog, node pressure, service profiles, latest sensor state.

## Assets

- Edge Nodes와 Devices를 같은 panel 안의 list-detail 구조로 표시한다.
- Service Topology는 Assets 안에 둔다. 목적은 서비스 실행이 아니라 디바이스-서비스 연결 구조 확인이다.

## AI Pipeline

- Summary strip으로 등록 디바이스, availability, telemetry freshness, validation 상태를 먼저 보여준다.
- Palette, graph canvas, inspector를 한 작업면으로 묶는다.
- Validation과 Execution Plan은 dry-run preview로만 표시한다.

## Device Management

- 화면 상단의 노드 선택은 네 작업 탭에서 유지되는 공통 운영 범위다. 각 노드 카드에는 관측 상태, Runtime 수, EdgeX Device 수와 등록 protocol 수를 요약한다.
- 기본 `장비 발견` 탭은 onboarding 후보만 표시한다. 상단에서 발견 Agent online/stale와 현재 관측·승인 대기·등록 완료·차단 수를 요약하고, 검색어·protocol·상태·presence로 목록을 좁힌다.
- USB Serial stable identity와 검증된 I2C chip identity를 node report에서 표시한다. 후보 카드는 source, presence, node, protocol, hardware ID, model, 권장 Profile, 상태, 인증과 차단 이유를 분리한다. I2C 버스 존재만으로 후보나 센서 응답을 만들지 않는다.
- exact binding이 없는 `BLOCKED` 후보에는 거절만 두지 않고 `연결 설정`을 제공한다.
  선택 시 해당 node와 후보 protocol, 차단 사유를 유지해서 보여 주며 관계없는 protocol을
  기본 선택하지 않는다. Git Catalog에 검증된 Profile·hardware binding이 생기기 전에는
  승인·배포를 허용하지 않는다.
- `엔드포인트 직접 추가` 대화상자는 node와 protocol에 따라 Serial path/baud, I2C bus, MQTT broker/topic, Modbus TCP/RTU, OPC-UA, RTSP, REST 필드만 노출한다. 이는 후보 선언이며 비밀번호·token·URL userinfo, 임의 image/hostPath/command를 받지 않는다.
- 후보 `승인`은 exact Catalog match와 presence를 다시 검사한 뒤 외부 인증, 검증 Runtime 재사용·배포, EdgeX Profile/Device 등록과 첫 Event 확인 Saga를 시작한다. `FAILED` 후보의 같은 동작은 retry이며, 거절은 `REJECTED`로 전이한다. 자동 관측 후보의 일반 삭제는 재관측될 수 있어 `무시`로 보존한다. 등록 연결 decommission 뒤 장비가 계속 연결돼 있으면 같은 stable ID 후보가 다시 승인 대기로 나타나며 자동 재등록하지 않는다.
- `노드 현황` 탭의 첫 영역은 `등록 연결과 실제 장비 상태`다. 연결 등록, 장비 관측, Device Service 통신, 최신 Event 상태를 네 칸으로 나눠 보여 주며 binding이나 발견 후보만으로 장비 감지·통신 성공을 주장하지 않는다.
- 이어서 Runtime, protocol package와 기존 EdgeX Device를 보여 준다. Runtime owner/phase/consumer와 Device identity를 한눈에 확인하고, 신규 등록과 기존 수정은 별도 작업 탭으로 진입한다.
- protocol package 카드는 선택 노드 기준 `재사용 가능`, `설치 가능`, `연결 등록 필요`, `검증 필요`를 표시한다. 설치/재사용 가능한 카드만 등록 마법사 진입 버튼을 제공하고 미검증 protocol은 `설치 전 확인이 필요한 프로토콜` 안에 둔다.
- `새 디바이스 등록`은 `연결 선택 → 디바이스 정보 → 프로필 → 검증 및 연결`의 4단계 마법사다. 연결 선택 안에서는 protocol/Device Service를 가장 먼저 고르고, 선택 노드의 등록 hardware binding과 Device Service 준비 방식을 뒤에서 고른다. 현재 단계만 노출하며 마지막 단계에서 등록 요약, 실행 계획과 first Event 상태를 함께 보여 준다.
- 등록 현황의 `프로필 만들기`는 EdgeX Device Profile을 웹에서 작성하는 별도 대화상자다.
  Profile 이름·제조사·모델·label과 최대 64개의 읽기 전용 DeviceResource
  이름·자료형·단위·설명을 입력하고, 서버 검증을 통과한 동일 payload만 Core Metadata에
  생성할 수 있다. 동일 이름의 다른 resource 계약은 차단하고 동일 계약은 재사용한다.
  후보의 model·capability는 초안에만 채우며 value type과 단위를 자동 추측하지 않는다.
- Profile 편집기는 command, parser, Device Service image, raw device path와 Catalog
  binding을 만들지 않는다. 따라서 Profile 생성만으로 `BLOCKED` 후보가 승인·등록되는
  것으로 표시하지 않고 검증 parser와 exact hardware binding을 별도로 요구한다.
- `기존 디바이스 수정`은 선택 노드의 Device를 먼저 선택해야 활성화한다. 이름·프로필·Device Service는 변경하지 않고 allowlist 필드만 수정한다.
- 설치되지 않았거나 미검증인 protocol도 접힌 현황 영역에서 차단 이유를 확인할 수 있지만 선택할 수 없다. 검증된 template과 등록 binding이 모두 있는 미설치 package만 `설치 가능`으로 선택한다. idempotency key와 기존 Device의 protocol properties JSON은 접힌 고급 영역에 둔다.
- 운영자는 runtime mode, catalog가 허용한 target node와 hardware binding만 선택할 수 있다.
- Serial 선택 시 같은 포트의 추가 resource와 두 번째 승인 USB Serial의 차이를 안내한다. binding이 제공한 `Port`/`BaudRate`/`DeviceID`는 read-only이고 resource route만 선택한다.
- validation은 `REUSE`·`DEPLOY`·`BLOCKED` runtime plan과 EdgeX Profile/Device plan을 마지막 등록 단계에 표시하며 mutation을 수행하지 않는다.
- `디바이스 연결`은 idempotency key가 있고 validation이 유효할 때만 활성화한다. 상태는 runtime, Metadata, first Event와 실패 보상을 분리해 표시한다.
- Argo CD 소유 Runtime은 조회·재사용 전용이다. Controller가 만든 Runtime만 restart할 수 있고 consumer가 0개일 때만 retire할 수 있다.
- 브라우저는 관리자 token을 입력·저장·전송하지 않는다. 관리 mutation은 기능 플래그,
  allowlist 검증과 `Idempotency-Key`를 사용하고 BFF의 Controller 호출은 내부 HMAC으로
  서명한다. 이 구성은 운영자 인증이 아니므로 현재 PoC Ingress 접근 경계를 운영 환경으로
  그대로 확장하지 않는다.

## Deferred Resource Augmentation

- Resource Augmentation은 기능 재구상 전까지 dashboard navigation과 active page에서 제외한다.
- 기존 resource augmentation JS/CSS 자산은 재설계 참고용으로 보관할 수 있지만 운영 화면에서 로드하지 않는다.
- 다시 노출하려면 화면 정보 구조, 책임 범위, 검증 기준을 먼저 갱신한다.

## 표현 경계

- 유지: observed state, read-only explanation, dry-run, 검증된 template 기반 관리와 명시적 상태 추적.
- 금지: raw Kubernetes manifest/image/hostPath 입력, 외부 runtime 변경, MQTT command publish,
  actuator command, EdgeMesh/KubeEdge Device CRD 변경, runtime migration, autonomous orchestration completed.
- 자원증강은 재설계 전까지 현재 dashboard 운영 기능으로 표현하지 않는다.

## Responsive

- Desktop: dark left resource rail + compact command bar + main workspace + sticky inspector rail.
- Tablet: resource rail은 가로 tab으로 접고 inspector rail을 본문 아래로 내리며, graph는 세로 stack으로 전환한다.
- Mobile: resource rail은 가로 스크롤 tab으로 접히고, metric row와 panel header는 단일열로 전환한다. 노드 카드, 작업 탭과 등록 단계, Profile resource 편집 행은 세로로 쌓이며 페이지 가로 overflow를 만들지 않는다.
- 발견 후보 toolbar와 요약 카드는 tablet에서 2열, mobile에서 1열로 전환한다. 수동 endpoint 대화상자는 viewport 안에서 세로 스크롤하고 action은 키보드 focus 순서를 유지한다.
