# 대시보드 검증 점검표

## 목적과 현재 경계

이 문서는 `state-aggregator`가 EdgeX Core Metadata와 Core Data를 읽어 만든 dashboard API/UI를 read-only로 확인한다. 2026-07-21 기존 custom Agent와 aggregate `sensehat-001` bootstrap은 퇴역했고, 현재 검증 목표는 **`device-serial-jetson`과 `device-sensehat-raspi`가 만든 가상 Device 각 6개, 총 12개를 정확히 표시하는 것**이다.

물리 디바이스 inventory, 관리 상태와 telemetry의 authority는 EdgeX다. KubeEdge는 node/workload 관찰에만 사용한다.

## API 확인

```bash
kubectl get --raw \
  '/api/v1/namespaces/default/services/http:state-aggregator:8000/proxy/state/devices'
kubectl get --raw \
  '/api/v1/namespaces/default/services/http:state-aggregator:8000/proxy/state/dashboard'
kubectl get --raw \
  '/api/v1/namespaces/default/services/http:state-aggregator:8000/proxy/state/summary'
```

현재 정상 기준:

- source가 EdgeX Core Metadata/Core Data다.
- 삭제한 aggregate `sensehat-001`/`edge-telemetry-agent`가 live inventory로 남지 않는다.
- `virtual-temperature-001`, `virtual-light-001`, `virtual-magnetic-001`, `virtual-acceleration-{x,y,z}-001`이 각각 독립 행이다.
- `env-sensehat-{temperature,humidity,pressure}-01`, `imu-sensehat-{compass,orientation,gyroscope}-01`도 각각 독립 행이다.
- 각 Device의 service/profile/protocol이 `device-serial-jetson`/Serial 또는 `device-sensehat-raspi`/I2C 계약과 일치한다.
- 총 12개 Device가 `UNLOCKED`, `UP`, `connected`, `available`, `fresh`이고 계약된 typed latest Reading을 반환한다.
- aggregate EdgeX Device `arduino-001`과 Profile `etri-arduino-serial`은 없다.
- 과거 Event가 남아 있어도 Metadata에 없는 device를 `available`로 부활시키지 않는다.
- node/workload 상태를 physical device availability로 합치지 않는다.
- workflow builder는 browser-local dry-run/preview 경계를 넘지 않는다.

로컬에서 strict API 계약 검증을 실행할 때는 현재 `default` namespace의 Service를 포트포워드한다.

```bash
kubectl -n default port-forward svc/state-aggregator 8000:8000
python3 tools/check_dashboard_api.py --base-url http://localhost:8000
```

검증기는 현재 EdgeX 단일 권위 계약인 `profile_name`, `device_service_name`, `protocol_names`,
`admin_state`, `operating_state`, `connection_state`, `device_service_available`,
`telemetry_freshness`와 available/degraded/unavailable·Core Data KPI를 확인한다. 퇴역한
Mapper/DeviceStatus의 `mapper_running`, `telemetry_enabled`, `device_status_freshness_ratio`는
필수 field나 physical availability 근거로 검사하지 않는다.

## Dashboard UI 확인

1. 요약 카드가 실제 `registered_device_count`와 일치한다.
2. device 목록이 Core Metadata 응답과 일치한다.
3. 12개 가상 Device detail이 각 Metadata와 latest Event 값을 동일하게 표시한다.
4. stale/no events 상태를 fresh로 보정하지 않는다.
5. KubeEdge node와 workload는 별도 진단 영역에 표시한다.
6. aggregate `sensehat-001`이나 Agent outbox를 현재 점검 대상으로 안내하지 않고, 직접 I2C Device 6개를 현재 inventory로 표시한다.

## 현재 Device Service PASS 기준

| 관찰 대상 | authority/API | PASS 기준 |
|---|---|---|
| inventory/state | Core Metadata → `/state/devices` | Device/Profile/Device Service/protocol과 상태 일치 |
| telemetry/freshness | Core Data Event/Reading | 실제 sample timestamp와 typed reading 일치 |
| physical availability | state-aggregator 정규화 | Metadata 상태와 Event freshness 정책 일치 |
| node/workload | Kubernetes/KubeEdge | 별도 진단이며 physical availability gate가 아님 |
| service binding | dashboard detail | 같은 device identity와 consumer relation 표시 |

## 실패 시 점검 순서

1. physical endpoint와 Device Service 상태
2. Core Metadata binding
3. Core Data latest Event/Reading
4. state-aggregator normalization/freshness
5. frontend rendering
6. Core Metadata에 퇴역 fixture가 남았거나 frontend가 sample payload를 하드코딩하지 않았는지

live API와 UI를 확인하지 않고 repository 문서나 fixture만으로 PASS를 선언하지 않는다.
