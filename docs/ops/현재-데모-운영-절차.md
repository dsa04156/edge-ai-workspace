# 현재 서비스 데모 운영 절차

## 목적

이 문서는 Protocol Adapter -> edge telemetry agent -> SQLite outbox -> HTTPS ingest gateway -> EdgeX Core Data/PostgreSQL -> dashboard 경로를 점검한다. 특정 Sense HAT publisher나 MQTT broker를 데이터 플레인의 정상 조건으로 요구하지 않는다.

## 배치 기준

| 구분 | 기준 |
|---|---|
| 중앙 namespace | `edgex-system` |
| edge agent namespace | `edgex-edge` |
| 중앙 노드 | `etri-ser0002-cgnmsb` |
| 현재 검증 edge node | `etri-dev0003-raspi5` |
| 중앙 workload | ingest gateway, Core Keeper/Metadata/Data/Command, internal MessageBus, PostgreSQL |
| edge workload | `edgex-edge-agent-sensehat` direct mode 1개 |
| 운영 진입점 | `edgex/k8s/kustomization.yaml` |

## 1. render와 Secret preflight

```bash
kubectl kustomize edgex/k8s >/tmp/edgex-https-plane.yaml
kubectl apply --dry-run=server -f /tmp/edgex-https-plane.yaml
edgex/k8s/scripts/preflight-runtime-secrets.sh
```

정상 기준:

- root render에 `edgex-device-mqtt` Deployment가 없다.
- Core/MessageBus/PostgreSQL/gateway는 server2에만 배치된다.
- edge agent는 `TELEMETRY_SOURCE_MODE=direct`, `hostNetwork=true`, `DIRECT_ADAPTER_HOST=127.0.0.1`이다.
- render에 `LOCAL_MQTT_*`, Jetson agent, edge-local broker가 없다.
- TLS, HMAC과 DB credential은 Secret reference다.

## 2. workload와 storage

```bash
kubectl -n edgex-system get deploy,statefulset,job,pod,service,pvc -o wide
kubectl -n edgex-edge get deploy,pod,pvc -o wide
```

정상 기준:

- `edgex-ingest-gateway`, Core 서비스와 PostgreSQL이 Ready다.
- `edgex-edge-agent-sensehat`이 Ready다.
- PostgreSQL PVC는 Bound다.
- agent별 outbox PVC가 서로 다르고 Bound다.
- 중앙 `edgex-messagebus`는 ClusterIP이며 edge namespace에는 MessageBus나 DB가 없다.

kubectl get --raw \

kubectl get --raw \

확인 항목:

- `serviceName=edge-telemetry-agent`
- `profileName=etri-sensehat`
- protocol은 `i2c`, label에는 `mqtt`가 없음
- Device Profile에 11개 Float64 resource가 있음

## 4. Protocol Adapter admission

현재 검증 fixture는 `sensehat-001`이지만 publisher 구현은 교체 가능하다. 물리 노드에서 승인된 adapter가 만든 canonical Event 파일로 loopback admission만 확인한다.

```bash
curl --fail-with-body \
  -H 'Content-Type: application/json' \
  --data-binary @canonical-event.json \
  http://127.0.0.1:18080/v1/events
```

정상 기준:

- local endpoint는 `http://127.0.0.1:18080/v1/events`다.
- 응답은 `202 queued`와 정확한 Event ID를 포함한다.
- adapter와 agent 사이에는 Mosquitto나 MQTT client를 요구하지 않는다.

agent 로그와 metric:

```bash
kubectl -n edgex-edge logs deploy/edgex-edge-agent-sensehat --tail=100
kubectl -n edgex-edge port-forward deploy/edgex-edge-agent-sensehat 18443:8443
```

8443 health endpoint는 mTLS를 요구하므로 단순 curl 실패를 agent 장애로 판단하지 않는다. Pod probe와 로그, outbox DB를 함께 본다.

## 5. Core Data readback

```bash
kubectl get --raw \
  '/api/v1/namespaces/edgex-system/services/http:edgex-core-data:59880/proxy/api/v3/event/device/name/sensehat-001?limit=10'
```

정상 기준:

- `deviceName=sensehat-001`
- `profileName=etri-sensehat`
- source가 여섯 source 중 하나
- `origin`은 publisher sample의 nanosecond 시각
- Reading `valueType=Float64`
- local publisher가 출력한 Event ID가 중앙 응답에 존재

## 6. outbox 장애 복구

이 검증은 telemetry 중단을 허용한 점검 창에서만 수행한다.

1. 중앙 gateway를 일시적으로 0 replica로 만든다.
2. 승인된 Protocol Adapter Event를 한 번 넣는다.
3. agent PVC의 SQLite pending count가 증가하는지 확인한다.
4. gateway를 1 replica로 복구한다.
5. pending count가 0으로 drain되고 같은 Event ID가 Core Data에 있는지 확인한다.

Argo CD self-heal이 replica 변경을 즉시 되돌릴 수 있으므로 실제 live 검증은 Application 동기화 정책과 점검 창을 먼저 확인한다. DB 파일을 복사하거나 직접 수정하지 않는다.

성공 기준은 “연결이 다시 됨”이 아니라 다음 세 항목이다.

- 중단 중 outbox 보존
- 복구 후 exact Event replay
- Core Data persisted ACK 뒤 outbox 삭제

## 7. dashboard

```bash
kubectl get --raw \
  '/api/v1/namespaces/default/services/http:state-aggregator:8000/proxy/state/devices'
kubectl get --raw \
  '/api/v1/namespaces/default/services/http:state-aggregator:8000/proxy/state/dashboard'
```

정상 기준:

- inventory는 중앙 Core Metadata contract와 일치한다. 현재 임시 fixture는 `sensehat-001` 1개다.
- latest Event/Reading과 freshness는 Core Data 값과 같다.
- `profileName=etri-sensehat`, `serviceName=edge-telemetry-agent`다.
- node/workload는 display-only 진단으로 분리된다.
- Serial, Modbus, OPC-UA, RTSP는 검증 전까지 완료로 표시하지 않는다.

## 장애 원인 순서

1. 센서 endpoint와 Protocol Adapter
2. loopback `127.0.0.1:18080`
3. edge agent admission과 SQLite PVC
4. edge -> gateway DNS/TLS/HMAC
5. gateway -> Core Data REST
6. PostgreSQL과 Core Data readback
7. Metadata binding
8. state-aggregator와 dashboard freshness

현재 배포 문제를 local MQTT broker부터 확인하지 않는다. MQTT-only 장비를 별도로 배포한 경우에만 그 adapter와 broker를 독립 점검한다.

## 완료 판정

manifest와 과거 G003 기록만으로 이번 중앙 전환 완료를 주장하지 않는다. 새 image digest, canonical Event ID, Core Data readback, outage replay와 dashboard 관측을 한 실행 기록으로 남긴 뒤 완료로 판정한다. Sense HAT publisher 교체 여부는 이 판정과 분리한다.
