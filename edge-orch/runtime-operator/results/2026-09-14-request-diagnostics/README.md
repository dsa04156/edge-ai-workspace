# 공통 AI 요청 진단 기록 검증 (2026-09-14)

요청이 실패한 구간을 보존하도록 gateway 수신 시점부터 별도 SQLite 진단 원장을 기록한다.
대시보드 OFFLOAD DEMO에서 서비스를 선택하고 `요청 진단 기록`의 실패·미확인 / 전체 요청을 조회한다.
요청 ID를 펼치면 진입 노드·실제 처리 노드·대기/왕복/추론 시간과 실행 ID를 확인한다.
입력·응답 본문, 원시 예외와 비밀은 이 기록에 저장하지 않는다.

## 실제 부하 시험

- 실행 ID: `408c6c0529974d0ab258338e02332343`
- Nano 버튼으로 시작한 부하가 Nano → Orin 이동 후에도 지속됐다.
- 전송 315건: 성공 309, 수동 부하 제거로 전송 전 취소 3, 실패 3, 미확인 0.
- 성공 처리 위치: Nano 104건, Orin 205건. 나머지 6건은 worker 미전송.
- 실패 3건은 모두 `HTTP 503 / admission_timeout`이다. gateway에서 30,012.9~30,031.2ms
  기다렸고 worker로 전송되지 않았다. worker 추론 실패로 해석하지 않는다.
- 진단 API에서 이 실행의 315건 전체를 페이지 조회해 집계와 대조했다.
- 별도 잘못된 입력 시험 1건은 `HTTP 400 / JSON_object_or_contract_required`로 기록됐다.
- 이전 왕복 시험의 실패 2건은 수집 전 발생했으므로 원인을 소급 복원하지 않았다.

부하 제거 UI 검사는 이동 뒤에도 Nano 버튼을 대상으로 해 비활성 버튼 대기로 종료됐다.
기존 UI는 현재 처리 노드로 부하 제거 버튼도 이동시키므로 해당 실행의 정확한 run-ID API로
중단했다. 이 결과를 UI 부하 제거 클릭 성공으로 보고하지 않는다. 실행은 `Stopped`로 확인했다. 이후 Orin → Nano 자동 복귀와 활성 시험 0개를 확인했다.
실시간 EdgeX 입력은 별도 기존 기능으로 계속 유입되며 시험용 부하 제거와 구분한다.

## 자동 검사와 화면 확인

- 실제 운영 runtime 이미지의 패키지에 진단 변경만 덧붙인 버전: 108개 검사 통과.
- 마지막 TTL 조회 필터 보완 후 관련 진단 검사: 7개 통과.
- aggregator Python 검사 14개, dashboard JavaScript 검사 29개 통과.
- 실패 원인 구분, 전송 전 실패 보존, 재시작 미종료 상태, UID 격리, 커서 페이지,
  보존 제한, 민감 본문 비노출, 동일 요청 결과 재조회 시 무재전송을 검증했다.
- 실제 화면에서 25 → 50건 추가 조회, 5초 부모 화면 갱신 이후 상세 펼침 유지 확인.
- 1440×1000과 390×844에서 페이지 가로 넘침 없음. 모바일 표는 내부 가로 스크롤.
- 실제 페이지 console 오류/경고 0건. 스크린샷은 실제 배포 페이지이며 mock 화면이 아니다.

## 배포 재현성과 경계

`images.json`에 변경 파일 SHA-256, 기존 운영 base digest와 새 digest를 보존한다.
운영 중이던 공통 AI 입력 구현과 정책은 유지하고, 기존 이미지 위에 진단 관련 파일만 추가했다.
두 Ready Pod에서 해당 7개 파일의 해시가 빌드 입력과 일치함을 확인했다.
API의 공통 AI 관련 동시 작업은 별도 작업이므로 이 변경의 Git 커밋에 섞지 않았다.
기존 브랜치 `agent/edgex-central-docs`에 커밋했고 별도 브랜치를 만들지 않았다.

진단 종료 기록은 최대 7일, 실패·미확인/기타 각각 10,000건을 60초 주기로 정리한다.
재시작 시 전송 전 중단과 전송 후 결과 미확인을 구분한다. 자동 재전송이나 오프로딩
판단 규칙은 이번 변경에서 추가하지 않았다. 진단 표는 수동 조회 시점의 결과이며 조회 시각을 표시한다.

운영 확인: aggregator Argo CD `Synced / Healthy`, runtime과 aggregator 각 Ready 1개.
기존 `edgex-edge/sensor-anomaly-demo`는 Ready 1개다. 별도
`edge-ai-workloads/sensor-anomaly-demo-replace-17a0d3d0`는 노드 미배정 Pending으로 관측됐으며
이번 진단 변경의 배포 대상이 아니다. 센서 관련 두 배포 모두 정상이라고 보고하지 않는다.
