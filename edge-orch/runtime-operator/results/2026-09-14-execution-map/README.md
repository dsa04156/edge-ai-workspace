# 서비스 실행 맵과 실제 후보 순위 검증

2026-09-14, 기존 `agent/edgex-central-docs` 브랜치에서 반영했다.

- 제어기가 실제 선택에 사용한 정렬 결과를 `placementDecision`에 기록한다.
  초기 배치, 지연, 용량 증강, 복귀, 준비 실패, 중지·재시작 경계를 검증했다.
- 기존 배포 이미지의 모든 Python 모듈을 보존하고 controller.py의 순위 관측 변경만
  겹쳐 배포했다. 실제 배포 패키지 기준 관련 제어기 시험 42개, projection 11개,
  JavaScript 시험 55개가 통과했다. API·정책·부하 제어 로직을 다른 미커밋 작업으로
  덮어쓰지 않았다.
- 브라우저 시험 상태에서 Nano의 현재 요청 경로와 Orin 준비 경로, 1위 후보,
  결정 기준을 확인했다. Llama의 단계 정책에서는 이동 후보가 1개일 수 있다.
  여러 노드·variant 순위는 실제 선택 로직의 로컬 시험으로 확인했다.
- 실배포 페이지의 3개 노드, 중지 시 순위 없음, 상세 접힘, 선택 노드의 5초 갱신 유지,
  1440px·390px 화면을 확인했다. 브라우저 오류·write 요청·모바일 페이지 넘침은 없었다.
- 두 배포의 Ready Pod와 변경 파일 해시가 image manifest의 파일 해시와 일치했다.
  Argo CD는 Synced/Healthy다. 모든 RuntimeService 정책과 suspended 값이 배포 전과 같다.
- 이 작업은 실제 Llama를 실행하거나 부하를 시작하지 않았다. Llama는 Suspended이고
  실행 중·중지 처리 중 시험은 0개다. 이번 브라우저 이동 화면은 시험 데이터이며,
  실제 장비의 새 오프로딩 성능·연속성 시험 결과로 해석하지 않는다.

이미지·파일 해시는 `images.json`, 운영 검증은 `verification.json`을 따른다.
