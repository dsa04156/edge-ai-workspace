# 관측 요청 시간 초과 수정 — 2026-09-08

대시보드의 같은 센서 조회가 중복되어 Core Data 조회 대기열이 길어졌다.
NEXUS는 서로 독립적인 API 여섯 개가 모두 끝나야 화면을 다시 그려 빠른 응답도 늦게 보였다.
매 갱신 때 기존 성공 상태를 loading으로 바꾸어 정상 관측까지 확인 불가로 깜빡였다.

## 변경

- 서비스의 디바이스 조회를 진행 중인 작업 하나로 공유한다. 브라우저 요청 취소가 다른
  대기자의 공통 조회를 취소하지 않는다. 종료 시 진행 작업을 취소·정리한다.
- 성공한 inventory와 원본 Reading을 최대 10초 재사용한다. 반환할 때마다 원래 Event
  시각으로 freshness를 다시 계산한다. 새 수신 시각으로 센서 시각을 덮어쓰지 않는다.
- 전체 snapshot은 기본 15초 deadline을 적용한다. 실패하면 cache를 비우고 명시적 오류를
  반환하며 재시도 backoff를 둔다. 이전 성공을 현재 정상으로 대신 반환하지 않는다.
- NEXUS는 API별 완료 시 즉시 화면을 갱신한다. 갱신 여부를 별도 필드로 두고, 기존
  유효 관측은 수신 시각과 함께 표시한다. 오류·90초 만료 응답은 현재 확인 불가다.
- 브라우저의 기존 20초 요청 제한은 늘리지 않았다. 센서 수집, Lease, 추론 routing은 변경하지 않았다.

설정: `EDGEX_DEVICE_SNAPSHOT_TTL_SECONDS` 기본10(0~30),
`EDGEX_DEVICE_SNAPSHOT_TIMEOUT_SECONDS` 기본15(0초 초과~18),
`EDGEX_DEVICE_ERROR_BACKOFF_SECONDS` 기본5(0~60).
현재 Argo의 기존 TTL10·오류 backoff30 설정을 유지한다.

## 실측

수정 전 같은 여섯 API를 동시에 요청했을 때 devices·device-twins는 모두 25.12초에서
클라이언트 timeout이 발생했다. services/results/resources/recommendations는 0.23~1.51초였다.
aggregator Pod에서 직접 조회한 EdgeX 개별 센서 세 개는 0.09~0.50초, HTTP200이었다.

수정 후 세 차례(총18개 요청) 같은 동시 조회는 모두 HTTP200, observation error 없음이었다.
첫 회 devices 0.208초, twins 0.713초, 전체 최대0.805초.
11초 간격 후속 두 회 전체 최대0.386초와0.638초였다.
이는 현재 테스트베드의 짧은 확인이며 장기 부하 SLO를 보장하는 결과는 아니다.

Python 관련 시험45개, NEXUS 데이터 시험10개 통과.
취소된 독자 격리, 전체 deadline 취소, 실패 backoff, cache의 freshness 재계산,
복구, 빠른 응답 우선 표시와 갱신 중 기존 상태 보존을 검증했다.
실제 데스크톱·390px 브라우저에서 6개 API ready/error=null, 가로 overflow 없음 확인.

## 배포와 근거

기존 state-aggregator 이미지 위에 `config.py`, `service.py`, NEXUS `live-data.js`,
`live-ui.js`만 overlay했다. 기존 Lease 표시 수정도 유지한다.
Argo Application `edge-orch-state-aggregator`의 source CAS image override로 반영했으며
Synced/Healthy를 확인했다. Git commit/push는 수행하지 않았다.

이미지: `192.168.0.56:5000/state-aggregator@sha256:5b6e1ca57ce48c106b0ae7f7eb8b1c4a895dbbecc38ed4bb31f7142810ab02ae`

빌드 context, 반복 측정 스크립트/JSON 및 CAS 원복 패치:
`output/observation-timeout-release/`.
화면: `output/playwright/observation-fixed-desktop.png`, `observation-fixed-mobile.png`.
원복은 `rollback.json`의 source test가 통과할 때만 적용된다.
이후 다른 배포가 있었으면 기존 source를 덮어쓰지 않고 다시 검토한다.

센서 추론 서비스의 Lease 만료·STANDBY는 실제 서비스 상태이며 여전히 표시한다.
이번 수정으로 해당 추론 중단을 복구했다고 해석하지 않는다.
