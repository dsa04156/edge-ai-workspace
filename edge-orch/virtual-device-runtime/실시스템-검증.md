# 컨테이너 가상 디바이스 실시스템 검증

2026-09-07, 사용자 승인 후 실제 테스트베드에 적용·검증했다.
최종 상태는 **등록 정의 1개, 실행체 0개, replicas=0**이다.

## 적용 대상과 소유권

- context: `kubernetes-admin@kubernetes`
- 시험 namespace: `virtual-device-test`
- 실행 서버: `etri-ser0002-cgnmsb` (AMD64)
- 실제 요청 클라이언트: `etri-dev0001-jetorn` (SSH에서 hostname 확인)
- 화면: [기존 운영 대시보드의 가상 디바이스 시험 탭](http://aggregator.192.168.0.56.sslip.io/#virtual-devices)
- 조회: `GET /api/virtual-devices`
- 시험 namespace에는 Deployment, ClusterIP Service, 모델 설정·등록 정의 ConfigMap,
  aggregator용 get/list Role·RoleBinding만 추가했다.
- 기존 `default/state-aggregator`는 Argo Application
  `edge-orch-state-aggregator`의 Kustomize 이미지 override로 갱신했다.
  기존 source·patches는 보존했다. 시험 runtime은 운영 Argo 자동 동기화 경로에 넣지 않았다.

## 네트워크 측정 경계

Jetson 호스트에서 `kubernetes.default.svc.cluster.local` 이름 해석은 실패했다.
현재 생성된 Service의 ClusterIP `10.103.255.142:8080` 경로에서는 실제 요청이 성공했다.
이는 port-forward 터널 시험이 아니라 Jetson→클러스터 Service 경로의 HTTP 시험이다.

해당 IP는 시험 시점에 Kubernetes에서 조회한 주소다. 코드·manifest에 고정하지 않는다.
Service를 다시 만들면 주소가 달라질 수 있으므로 아래 명령으로 매번 조회한다.
초기 시험에서는 Jetson 호스트 DNS 경로가 미해결이었다. 이후 사용자 승인으로 호스트의
클러스터 도메인 DNS 경로를 설정하고, 같은 FQDN으로 실제 추론까지 성공했다.
[호스트 DNS 수정·검증과 복구 절차](Jetson-호스트-DNS-검증.md)를 참고한다.

## 재실행과 정지

아래 namespace와 서버는 이번에 승인된 시험 범위다. 파일 registry와 ConfigMap을
변경하면 같은 계약을 유지하고, 운영 배포 경로에 시험 manifest를 포함하지 않는다.

```bash
# 검토·재등록용 pinned manifest. 기본 replicas=0.
rtk proxy kubectl kustomize edge-orch/virtual-device-runtime/k8s-overlays/system-test

# 기동
rtk proxy kubectl --context kubernetes-admin@kubernetes -n virtual-device-test scale deployment/vd-demo-001 --replicas=1
rtk proxy kubectl --context kubernetes-admin@kubernetes -n virtual-device-test rollout status deployment/vd-demo-001 --timeout=90s
rtk proxy kubectl --context kubernetes-admin@kubernetes -n virtual-device-test get service vd-demo-001 -o wide

# 위에서 조회한 Service IP를 사용해 Jetson에서 실행
python3 jetson_client.py --url http://SERVICE_IP:8080 --expected-label setosa

# 정지·삭제 관측·등록 유지 확인
rtk proxy kubectl --context kubernetes-admin@kubernetes -n virtual-device-test scale deployment/vd-demo-001 --replicas=0
rtk proxy kubectl --context kubernetes-admin@kubernetes -n virtual-device-test wait --for=delete pod -l edge-ai.io/virtual-device-id=vd-demo-001 --timeout=90s
rtk proxy kubectl --context kubernetes-admin@kubernetes -n virtual-device-test get pods -l edge-ai.io/virtual-device-id=vd-demo-001 -o json
rtk proxy curl --fail http://aggregator.192.168.0.56.sslip.io/api/virtual-devices
```

시험 근거는 저장소 로컬 `output/vd-system-release/`의 단계별 JSON·데스크톱/모바일 PNG에 있다.
최종 aggregator 빌드 context도 `aggregator-final-build/`에 보관했다.
기존 Argo source로 되돌리는 CAS 패치는 `argocd-image-rollback.json`이다.
rollback은 현재 source가 최종 배포 source와 같을 때만 적용되며,
이후 다른 배포가 있으면 실패하도록 해 두었다. Git commit/push는 수행하지 않았다.

이번 검증은 작은 CPU 모델의 기능 실행·관리와 관측 연결 검증이다.
하드웨어 에뮬레이션, 자동 오프로딩, GPU 분할·할당 또는 장시간 추론의 무손실 복구를
검증한 것이 아니다. 처리 중 SIGTERM 정리 동작은 앞선 로컬 HTTP 자동시험에서 검증했고,
이번 실제 클러스터 정지는 inFlight=0에서 수행했다.
