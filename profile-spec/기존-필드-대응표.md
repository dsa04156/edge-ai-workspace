# 기존 필드와 Profile v1 대응

| 기존 원본 | 새 표현 | 적용·보류 |
|---|---|---|
| Kubernetes node 이름 | 관측 Device `id`, RuntimeState `metadata.deviceId` | 실제 instance ID. ServiceProfile 호환 장비 목록에 넣지 않음 |
| node `kubernetes.io/arch` | DeviceProfile `spec.hardware.architecture` | `arm64`/`amd64`; 알 수 없는 값은 null |
| node `status.allocatable` | RuntimeState `status.reservation.allocatable` | OS/시스템 예약이 반영된 값이며 물리 총용량이 아님 |
| 현재 Pod requests | RuntimeState `reservation.requested` | 기존 resource_pool reader의 Kubernetes 예약 계산 재사용 |
| allocatable − requests | RuntimeState `reservation.available` | 예약 관점 여유. 물리 RAM free와 구분 |
| Prometheus NodeSchedulingResource.utilization | RuntimeState `status.utilization` | 원래 observedAt 유지; 60초 초과·미래 시각은 null |
| Kubernetes Ready | RuntimeState `status.phase` | node 상태만 표현. 서비스 준비·모델 적합성과 별개 |
| RuntimeService `variants[].architecture/backend/image/modelRuntime` | ServiceProfile `runtime.variants`의 명시적 실행 조합 | 대응 설계. 등록 서비스에서 자동 생성하지 않음 |
| RuntimeService variant requests/limits | 별도 실행 예약 계약 | 실측 minimum/recommended/maximum으로 자동 승격하지 않음 |
| RuntimeService `verifiedNodes`, qualification/성능 결과 | 후속 실행·성능 증거 참조 | capability와 별개로 계속 유지. 이번 비교가 기존 자격을 대체하지 않음 |
| ServiceDescriptor stages/input/output | 후속 Workflow Task 입출력·의존성 | ServiceProfile의 자원 규격과 별도 계약. 기존 dry-run은 유지 |
| EdgeX DeviceProfile resource/command | 기존 센서·물리 입력 계약 | 컴퓨팅 DeviceProfile과 다른 원본. 복제 등록·write 없음 |
| GPU plugin 단위 | RuntimeState 예약 `acceleratorUnits` | 물리 VRAM·vendor/runtime 지원을 추론하지 않음 |
| 서버측 VD 서비스 UID/슬롯 | 후속 VirtualDevice instance/binding | v1 Profile 선언만 정의. 기존 슬롯 수명주기 변경 없음 |

관측 adapter는 현재 **노드와 RuntimeState에만** 구현했다. RuntimeService/ServiceDescriptor 행은
다음 서비스 등록·Workflow 연결을 위한 대응이며 변환 완료가 아니다. 빈 운영 서비스 목록을
예제로 채우지 않는다. 예제의 6 cores/8Gi와 모델 이름·이미지는 실측값이 아니다.

현재 기존 reader에서 확보하지 않은 물리 CPU/RAM 총용량, GPU 공유 방식, 지원 framework/backend,
모델별 메모리·네트워크 요구량·성능 증거는 수동 또는 후속 수집 계약으로 보강한다.
